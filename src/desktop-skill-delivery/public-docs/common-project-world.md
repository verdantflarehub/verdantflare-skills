# 项目与固定资产

## 1. 使用真实项目

制作任务沿用 Studio 已创建或打开的真实 `project_id`。新项目 ID 由服务分配，不从本地目录、文件名或 Prompt 猜测，不建立另一套项目数据库。项目操作、固定修订和跨机恢复使用本发行集合的 `verdantflare-project`；受控字节传输使用 `verdantflare-artifact`。

本地目录是工作副本。服务维护的 `.vf/project.json` 是通用清单投影，不手写或作为普通业务文件上传。保存明确选定的文件及业务关联，不扫描上传整个目录；MD／TXT 承载策划、提示词和审核记录，领域 JSON 只使用实际契约支持的字段。

## 2. 媒体与固定引用

媒体生成结果按对应技能执行内容分级与适用校验，再归档来源项目。原生任务完成、原生 Artifact、中央不可变内容与项目修订分别记录；保存大小、SHA-256 和引用映射，不把媒体原生 ID 填成中央 `ContentRef`。中央引用固定 `store_id + artifact_id + version_id`，需要项目访问路径时同时提供真实项目及固定修订。

已绑定项目的本轮创作保存必要文件、领域关联并回读，用户明确仅本地或只读时沿其范围。只上传文件不能说明角色、Look、镜头或制作版本已关联；同一素材返修保留历史和来源，不用最新候选覆盖已批准基线。工具成功、技术合格、选用批准和作品发布分别报告。

## 3. World 使用与登记

使用 World 输入时先授权并读取固定 `asset_id + asset_version_id`，解析明确文件后再作为输入。不要把展示名、`latest`、临时 URL 或未解析的资产 ID 直接交给生成服务；资产可读不授予来源项目的其他权限。

World 登记只处理用户明确要求沉淀的固定成果。保留来源项目、修订、原始文件与审核；不自动公开整个项目、未选候选、录音或私有审核资料。升级是新修订和明确选择，旧项目继续引用旧版本。短剧、Video 等 Skill 不绕过领域契约自行注册或升级资产。

## 4. 冲突与跨机恢复

换电脑重新打开同一项目及修订，按清单取得所需文件。提交响应丢失使用原提交身份对账；已记录的生成任务沿原服务、模型、渠道、任务 ID 恢复，不以新建收费任务代替查询。

并发修订冲突保留本地正文和待恢复记录，不强制覆盖别人的修订。缺权限、工具或客户端时准确记录未完成环节；不伪造项目或成功回执。接口字段以当前 Studio 工具 Schema 及同版本 Project／Artifact 技能为准，用户无需读取团队私有设计仓库。
