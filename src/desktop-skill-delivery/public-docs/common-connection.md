# Studio 连接与能力发现

## 1. 使用现有连接

业务通过已配置的 Studio MCP 进入。MCP Bearer 代表真实用户，由服务端按其组织与业务权限执行；不要声明用户／组织来替代身份校验，不增加生成批准令牌或再次索取密码。用户选择模型和已授权渠道；供应商账号、渠道凭据和服务部署由 VF 后台维护。

已有宿主 MCP 工具优先直接调用。需要文件读写或独立脚本时，使用发行包提供的受管 helper；其 Studio 连接从受控配置／环境取得 `STUDIO_MCP_URL` 与 `STUDIO_MCP_BEARER_TOKEN`。不要将 Token 放到命令参数、URL、任务正文或日志。工程候选未提供相应运行时或 helper 时，明确报告该项缺失，继续可直接使用的 MCP 操作；不让用户克隆私有仓库或安装供应商 CLI 补齐。

## 2. 区分失败来源

先读取当前连接的真实工具目录和输入 Schema。工具未注册、认证失败、业务无权限、渠道未就绪、输入未适配与任务失败分别报告；媒体工具可见不证明 Project／Artifact 可用，`configured` 不代表业务已实跑。

遇到失效／撤销 Token 或权限拒绝，保留具体错误，使用产品已有的连接修复入口；不伪造主体，不改用管理员或旧共享令牌。服务端身份绑定、渠道账号及注册问题交后台修复，Skill 不执行集群维护或凭据导入。旧工具名与当前目录不符时按实际注册名调用；能力声明与 Schema 冲突时先核对，不试填参数提交收费任务。

## 3. 固定结果与恢复

提交前保存原请求和幂等键，响应未知时查询原任务；不要因换电脑、断线或等待超时重新生成。下载只使用同一 Studio 返回的受控路径，拒绝跨域转发凭据和意外重定向。上传、任务完成、内容下载和项目提交分别核验。

中央 Project／Artifact 与媒体原生任务的引用不同；按同版本 `verdantflare-project`、`verdantflare-artifact` 技能和当前工具 Schema 处理，不从文件名或临时 URL 推断身份。完整规则见[项目与固定资产](common-project-world.md)。
