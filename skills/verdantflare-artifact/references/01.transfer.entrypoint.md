# Artifact 受控传输与恢复（01.transfer）

## 1. 输入与输出

- **输入**：明确待上传的本地文件或小文本、用途与获授权的 `project_id` 或 `world_draft_id`；或用于读取/下载的固定 `ContentRef`（`store_id`、`artifact_id`、`version_id`）及对应作用域访问路径。
- **输出**：不可变内容版本的完整 `ContentRef`、MIME、实际字节数、SHA-256 与校验状态；下载场景另产出经完整性核验的本地目标文件；中断或异常场景产出包含 `write_id`/`upload_id` 与恢复入口的对账记录。

## 2. 分类

按操作方向与载荷特征选择执行分支：

- **小文本直写（`mode=text`）**：合法 UTF-8 文本且大小 `<= 1 MiB` 字节，可直接经 `artifact.write` 写入。
- **二进制或大文本流式上传（`prepare -> PUT -> commit`）**：任意二进制文件或超过 `1 MiB` 的文本，走准备、受控 HTTP 流式 PUT 与提交三阶段，默认上限 `1 GiB`。
- **元数据与小文本读取（`metadata` / `text`）**：基于固定 `ContentRef` 查询版本元数据，或读取合法 UTF-8 且 `<= 1 MiB` 的小文本。
- **受控文件下载（`mode=download`）**：下载二进制或超过 `1 MiB` 的内容，流式校验 SHA-256 与字节数后落盘（当前不支持 Range，默认上限 `1 GiB`）。
- **既有引用复用与中断恢复**：优先在原任务或固定项目修订中查找可授权读取的既有 `ContentRef` 直接交接；响应未知时按原 `write_id`/`upload_id` 或 `workspace resume` 对账恢复。

## 3. 工作流

### 3.1 工具调用与前置准备

1. 优先用宿主 Studio `/mcp` 发现并调用 `artifact.write`、`artifact.read`，按当前在线 Schema 传参；无宿主工具时，使用 Studio 0.5.50 的 `studio-workspace tools` 和 `call --input request.json`（请求形如 `{"name":"artifact.read","arguments":{...}}`，真实参数按 `tools/list` 与实际 `ContentRef` 填入）。
2. 先在原任务或固定项目修订中查找可授权读取的既有 `ContentRef`；服务端已有完整内容时直接交接引用，不先下载到本机再上传一遍。
3. 写入前确认明确文件、用途与获授权的 `project_id` 或 `world_draft_id`（按实际 Schema 恰选一个），核对 MIME、实际字节数与 SHA-256，并在不含凭据的恢复记录中保存原请求、固定小写 UUIDv7 的 `write_id` 及文件摘要。

### 3.2 写入（`mode=text` 与三阶段流式上传）

1. UTF-8 小文本（`<= 1 MiB`）直接调用 `artifact.write`（`mode=text`）；二进制或大文本调用 `artifact.write`（`mode=prepare`），参数带 `write_id`、`source`、`mime`、`size`、`sha256`；替换既有内容身份时仅在任务明确且有权时带 `artifact_id`，不覆盖旧 `version_id`。
2. 保存返回的 `upload_id` 与 `upload.content_path` 后发起 `PUT /v2/artifacts/uploads/{upload_id}/content`，`upload_id` 必须与响应一致；以 Studio origin 解析相对路径，使用 HTTP 流与明确 `Content-Length` 传输，凭据只从环境加入当前 Studio 请求头。
3. PUT 完成后调用 `artifact.write`（`mode=commit`）传入 `upload_id`，从提交结果的 `version` 核对 `size`、`sha256`、`mime`，提取 `store_id`、`artifact_id`、`version_id` 作为不可变 `ContentRef`（`store_id` 是存储实例 ID，不是 URL 或连接别名）。

### 3.3 受控读取与下载

1. 用固定 `ContentRef` 调用 `artifact.read` 的 `metadata`、`text` 或 `download`；采用项目授权路径时 `access` 同时包含 `project_id`、`project_revision_id`，资产路径同时包含 `asset_id`、`asset_version_id`，已支持的 World 草稿路径同时包含 `world_draft_id`、`world_draft_revision_id`。
2. 下载时校验返回的 `version` 与 `content_path`，只接受同一 Studio 的 `/v2/artifacts/{version_id}/content` 且查询中的 `store_id`、`artifact_id` 与 `ContentRef` 一致；下载到新临时文件并按流计算 SHA-256 和总字节数，核验一致后以不覆盖已有不同文件的方式保存（存在冲突时保留两份或报告冲突）。
3. 临时下载地址失效时只更新读取句柄，不更换内容版本；批量回读逐文件保存成功摘要和状态，超时只恢复未验证文件。

### 3.4 响应丢失恢复与业务交接

1. `prepare` 响应丢失：复用原 `write_id` 和完全相同的声明重试。
2. `PUT` 响应丢失：用 `mode=status` 查询原 `upload_id`；`prepared` 不证明字节完整，可按同一路径完整重传原字节（不能宣传分块断点续传）。
3. `commit` 响应丢失：查询原上传状态，重试同一 `upload_id` 的 `commit` 取得原版本。
4. 已有 `workspace journal` 的任务使用 `workspace resume`，不并行维护第二套恢复状态；本地文件变化或摘要不符时停止原上传，保留记录并核对，另建新请求而非复用原 ID 改声明。
5. 业务交接：明确只上传时返回 `ContentRef`；已绑定项目的创作任务自动将 `ContentRef` 交接 `verdantflare-project` 完成项目归档、角色关联与回读；独立 World 草稿写入后交回原 World 保存流程提交并回读固定修订；查询任务从最新项目取得固定引用并按需下载展示，不产生业务写入。

## 4. 规范

- **身份与传输安全**：使用 `STUDIO_MCP_URL` 与 `STUDIO_MCP_BEARER_TOKEN`，无需额外登录，不提交用户/组织头；二进制字节通过 HTTP 流传输，不嵌入 MCP JSON 或 base64，大文件不整文件塞入命令行或日志；只走同一 Studio 的受控路径，不能将 `/mcp` 与相对路径直接拼接，拒绝 `//`、绝对 URL、路径穿越、意外查询、重定向、跨域凭据转发和任意 URL 代理（网络库禁用自动跳转）；不向 S3 直写，不索取 S3、下游服务或供应商凭据；缺客户端时说明依赖，不改用下游公网地址。
- **来源与作用域边界**：外部来源使用 `user_edit` 或 `user_import`，不使用假项目，不冒充 `task_output`、`legacy_import`、`asset_manifest` 或 `world_draft_manifest`；不伪造 `task_output/original_ref`，不把中央 `version_id` 传给要求原生 `source_artifact_id` 的工具；生成服务原生 Artifact 须经对应服务适配或用户明确导入为 `user_import`（保留原任务记录），不能直接当中央 `ContentRef`。三种访问作用域（项目、资产、World 草稿）不混搭，引用与下载路径不是令牌，按资产读到来源指针不代表有权读取来源草稿；旧服务 Schema 缺草稿来源时不伪造项目、不提交未知字段，明确保留未同步状态。
- **不可变与版本隔离**：`write_id` 及声明在发送前固定且不含凭据；内容变化用新版本，旧版本与原始文件不覆盖；只复用已知且有权读取的固定版本，不声称有全库哈希搜索；`studio-workspace import/save-files` 会同时提交项目，不能用于“只上传”任务，独立草稿传输不使用上述项目命令。
- **限额、删除与重试边界**：传输默认上限 `1 GiB`（取客户端、Studio、Artifact 与资源条件共同约束，不擅自放宽），小文本读取与直写限合法 UTF-8 且 `<= 1 MiB`；明确删除候选时交给 Project 清理该候选及引用，不在 Artifact 层物理删除共享字节；保留、释放、删除和跨环境迁移不属于隐含收尾操作；持续不可用时给出固定引用、未验证文件和恢复入口，不无限重试，不删除旧上传掩盖失败，不重跑生成或重提已成功的项目修订；权限撤销或未就绪时准确报告，不自动公开文件。

## 5. 验收

- MCP 响应已检查 `error`、`isError`、`structuredContent` 与业务状态，而非仅检查 HTTP 状态码。
- 管理工具成功、上传完成、版本提交与项目/World 归档已分别核验；交付包含完整 `ContentRef`（`store_id`、`artifact_id`、`version_id`）、MIME、实际字节数、SHA-256 与验证状态。
- 元数据摘要匹配与实际字节回读匹配分开报告；字节与摘要通过仅证明内容完整，不代替人物、空间或表演审核（同版完整性证据可复用，变换产生的新字节另行核验）。
- 上传成功不宣称已加入 Project 或已收录 World 资产，固定修订回读成功前不宣称已归档或登记资产。
