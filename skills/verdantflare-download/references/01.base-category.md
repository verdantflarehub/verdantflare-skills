## 2. 前置取证流程（Classification Pipeline）

在决定调用哪个解析器与下载协议前，严禁仅凭口令文案猜测媒体类型或盲调通用提取器，必须先通过 [`mk_video_download.py`](../scripts/mk_video_download.py)（支持 `--parse-only`）执行以下两步自动化协议取证：

1. **口令提链与首跳 302 协议探针**：运行正则 `URL_EXTRACT_RE` 剥离分享口令中的文案噪音，提取首个合法 `http/https` 链接；发起非跟随或带 Cookie 保持的首跳请求读取 `Location` 响应头，提取真实主域名 `host_domain`、路径模板（如 `/share/video/`、`/share/note/`、`/fw/photo/`）与作品唯一标识 `item_id`。
2. **远端状态树与多模态结构探针**：根据主域名请求对应轻量元数据端点（`slidesinfo`、`__INITIAL_STATE__`、`INIT_STATE`、`syndication` 或 `yt-dlp -J`），实测判定作品资产形态 `media_type`（纯视频 `video`、多图/实况图集 `gallery`、图文视频同帖 `mixed`）、源流标称分辨率 `(expected_width, expected_height)` 及 CDN `Content-Length`（`expected_size`），将取证结果写入 `ParsedMediaResult` 与 `*_metadata.json`。

## 3. 量化分类总表与专册映射

分类器 `classify_platform_and_category()` 根据前置探针提取的 `host_domain` 与协议结构特征，将下载任务确定性划分为以下三个互斥业务子分类：

| 分类代号 | 分类名称与专册入口                                                                                    |
| :------- | :---------------------------------------------------------------------------------------------------- |
| `C1`     | 抖音与字节系无水印原画类，见 [C1.douyin-media-category.md](./C1.douyin-media-category.md)             |
| `C2`     | 小红书与快手状态树直解类，见 [C2.xhs-kuaishou-category.md](./C2.xhs-kuaishou-category.md)             |
| `C3`     | B站/微博/X/YouTube与通用类，见 [C3.bili-weibo-global-category.md](./C3.bili-weibo-global-category.md) |

- **`C1`（抖音与字节系无水印原画类）**：`host_domain` 命中 `v.douyin.com`、`douyin.com`、`iesdouyin.com`、`ixigua.com`、`365yg.com` 且匹配 15~22 位数字 `aweme_id`；绑定 `slidesinfo` 双路接口加 `snssdk 1080p` 原画探针，详见 [C1.douyin-media-category.md](./C1.douyin-media-category.md)。
- **`C2`（小红书与快手状态树直解类）**：`host_domain` 命中 `xhslink.com`、`xiaohongshu.com`、`v.kuaishou.com`、`kuaishou.com`、`chenzhongtech.com` 且页面含 SSR 状态树（`__INITIAL_STATE__` 或 `INIT_STATE`）；绑定状态树直解与 `ci.xiaohongshu.com` 无水印原图重构，详见 [C2.xhs-kuaishou-category.md](./C2.xhs-kuaishou-category.md)。
- **`C3`（B站/微博/X/YouTube与全网通用类）**：合法 `http/https` URL 且未命中 `C1 / C2` 域名集合；细分为 `bilibili`、`weibo`、`twitter`（$\pi$-Token）、`youtube`（Node.js EJS + DASH 8 线程混流）及 `ytdlp_generic` 全网兜底，详见 [C3.bili-weibo-global-category.md](./C3.bili-weibo-global-category.md)。

## 4. 一级路由决策树（优先级顺序）

分类器按以下严格优先级顺序执行判定，命中高优先级分支后立即终止后续匹配：

1. **第一优先级（口令净化与空链红线否决）**：运行正则 `URL_EXTRACT_RE` 提取 URL；若未检出任何合法 `http://` 或 `https://` 链接，直接触发 `Gate G1` 拦截并判 `0.0` 分。
2. **第二优先级（`C1` 字节系专用协议路由）**：检测域名是否属于字节系集合；命中则归入 `C1`，严禁流入默认 `yt-dlp` 抖音提取器（避免因网页端 `403 Forbidden` 或 `videoInfoRes` 缺失导致失败）。
3. **第三优先级（`C2` 社交图文/短视频状态树路由）**：检测域名是否属于小红书或快手集合；命中则归入 `C2`。
4. **第四优先级（`C3` 开放 API 与全网通用路由）**：其余合法域名全部归入 `C3`，优先匹配 B 站、微博、X/Twitter 免登 API 与 YouTube DASH 管线，未命中时自动移交 `yt-dlp` 通用引擎。
