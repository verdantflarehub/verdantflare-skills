## 2. 工作流步骤概览

| 步骤编号 | 步骤名称与输出产物                                                               |
| :------- | :------------------------------------------------------------------------------- |
| `Step 1` | 识别子平台标识并解包短链                                                         |
| `Step 2` | 调用免登 API 或 `yt-dlp --js-runtimes node` 获取最高码率流与原图集               |
| `Step 3` | 流式下载、并发分片 DASH 混流或双路落盘，输出 `.mp4`、`.jpg` 与 `*_metadata.json` |

- `Step 1`：识别子平台标识（`bilibili` / `weibo` / `twitter` / `youtube` / `ytdlp_generic`）并解包短链。
- `Step 2`：调用对应免登 API（`playurl` / `Component_Play_Playinfo` / `syndication` $\pi$-Token）或 `yt-dlp --js-runtimes node` 获取最高码率流与原图集。
- `Step 3`：带防盗链 `Referer` 流式下载、并发分片 DASH 音画合并或图文混合双路落盘，输出 `.mp4`、`_gallery/*.jpg` 与 `*_metadata.json`。

## 3. 分步执行指令与调用协议

### 3.1 Step 1：短链解包与标识提取

1. **B 站分支**：跟随 `b23.tv` 重定向提取 `BV` 号，请求 `api.bilibili.com/x/web-interface/view?bvid=<bvid>` 获取首 P 的 `cid` 与分辨率元数据。
2. **X / Twitter 分支**：跟随 `t.co` 重定向提取数字 `tweet_id`。
3. **YouTube 分支**：从 `watch?v=`、`youtu.be/` 或 `shorts/` 路径提取 11 位 `video_id`，自动探测本机 Node.js 运行时（`--js-runtimes node`）以解锁 EJS 签名挑战。

### 3.2 Step 2：免登直链提取与最高码率排序

1. **B 站免登 1080p DASH 音画分离流获取与多镜像 Range 并发混流**：优先请求 `api.bilibili.com/x/player/playurl?otype=json&fnver=0&fnval=16&qn=80&bvid=<bvid>&cid=<cid>&platform=pc&high_quality=1&try_look=1` 获取免登 `1080P`（`id=80, avc1`）DASH 视频流与 `192kbps`（`id=30280, mp4a`）DASH 音频流（连同 `backupUrl` 多 CDN 镜像）；下载阶段通过 16 线程 HTTP `Range` 分片并发轮询多 CDN 镜像突破单连接限速，再调用 `ffmpeg -c copy -movflags +faststart` 无损混流为标准 `.mp4`（若无 DASH 流则回退 `platform=html5&fnval=0` 的 `durl[0].url`）。
2. **X / Twitter Syndication $\pi$-Token 全模态算子**：计算令牌 $\text{token} = \text{replace}(\text{str}((\text{tweet\_id} / 10^{15}) \times \pi), \{0, .\})$，请求 `cdn.syndication.twimg.com/tweet-result`；遍历 `mediaDetails` 全数组，对 `video` / `animated_gif` 节点在 `variants` 中筛选 `content_type == "video/mp4"` 且 `bitrate` 最大的直链；对 `photo` 节点升级为 `?format=jpg&name=orig` 无损原图；若同一推文同时包含视频与图片，自动标记 `media_type = "mixed"` 双路全量落盘。
3. **YouTube DASH 音画优选与 8 线程并发混流**：调用 `yt-dlp --js-runtimes node` 提取全量 `formats` 清单，按目标画质（`4K/2K/1080p/720p`）优先锁定 H.264（`vcodec^=avc1`）最高码率视频轨与 `m4a` 音轨，通过 `--concurrent-fragments 8 --merge-output-format mp4` 高速拉流并执行无损容器封装。
4. **全网通用兜底**：未命中上述四者的 URL 直接调用 `yt-dlp` 下载并自动调用 `ffmpeg` 混流封装。

### 3.3 Step 3：执行下载与门禁验收

执行以下命令完成下载与自动化门禁校验：

```powershell
$env:PYTHONUTF8="1"; python skills/verdantflare-download/scripts/mk_video_download.py --input "<B站/微博/X或通用视频链接>" --output-dir "./.gdrive/downloads" --evaluate
```

执行完成后，生成符合 [C3.bili-weibo-global-acceptance.md](./C3.bili-weibo-global-acceptance.md) 的最终 `.mp4` 与评测报告。
