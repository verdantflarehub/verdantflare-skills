## 2. 项目目录与命名契约

工作副本位于 `.gdrive/output/music-mv/<创作者>/<MV项目>/`（跨机同步，取代旧 `.output/`），服务端身份由 Studio `project_id` 管理，分为项目全局层与单元执行层：

```text
.gdrive/output/music-mv/<创作者>/<MV项目>/
├── project.json                 # 领域 JSON：项目全局时钟与元数据（须登记到 domain_documents）
├── treatment.md                 # 顶层导演方案与叙事脉络
├── visualbible.md               # 视觉圣经与人物原案
├── review.md                    # 项目全局总审核：Block 规划、跨段连续性与成片交付
├── master.wav                   # 批准 Master 音频（唯一时钟源）
├── .archive/                    # 历史淘汰版本与旧实验归档
├── .vf/                         # project.json（通用 ProjectManifest 投影）与 local.json（本机状态）
└── units/B01/                   # 故事段落单元目录（TV 素材池模式另含 scenes/ 与 shots/<GU_ID>/）
    ├── review.md                # Block 单元审核
    ├── source/                  # character/、scene/、storyboard/、audio/、build/
    ├── input/                   # 01-character-card.png、02-storyboard-grid.png、03-scene-design.png、04-audio-excerpt.wav、manifest.json
    └── output/                  # review/（首尾帧条带图）、generated/、baseline/
```

- **文件命名红线（严禁中文文件名）**：所有契约文件、脚本、图像、音频与视频文件名必须使用纯英文小写短横线（ASCII kebab-case，如 `review.md`、`01-character-card.png`），严禁中文文件名；正文可用中文。
- **双 JSON 职责分离**：根 `project.json` 是领域文档，`.vf/project.json` 是通用清单，互不复制字段。旧 `project.yaml` 仅作一次性导入，导入后停止维护 YAML。
- **B-S-F-GU 四级代号**：
  - **Story（故事单元）**：由同一角色、同一地点、同一时间组成的连续视听情境（三同定律），不等同于单次调用。
  - **B（Block / Beat，`B01`）**：通常 8–15 秒叙事/情绪段落，对齐单元目录名与 `unit_id`。
  - **S（Shot，`S01` / `B01-S01`）**：最终裁切单镜头（通常 1–5 秒）。
  - **F（Frame，`F01` / `S01-F1`）**：多格分镜具体格或 Shot 首尾帧标识。
  - **GU（Generation Unit，`B01-GU01`）**：按三同定律组合提交的渲染批次；H3 契约单次 4–15 秒、内部最多 2–3 个 Shot（1–2 个切点），超出须拆分为多个 GU，不得提交不足 4 秒的 H3 请求。
- **构建脚本契约（`source/build/`）**：`compose_inputs.go`、`split_wav.go` 等必须为确定性、幂等纯函数组装器，只读 `source/`、输出至 `input/` 或 `output/review/`，严禁写回 `source/` 或向工作区根目录丢弃临时文件；拼图参数与 padding 固化为命名常量。

## 3. 核心实战铁律（全模式强制）

1. **人物造型与防串脸**：人物面容在 `visualbible.md` 冻结后全片共享；剧情换装（如 `CHAR-02A` / `CHAR-02B`）必须以主造型派生并单独审定；严禁未经批准引入额外角色，多角色剧情严禁双正脸同框（改用单正脸、OTS 正反打、远景背影或漫画三联分格）。
2. **动漫/影视翻唱 MV 原作分镜致敬**：翻唱动漫、电影或剧集主题曲时，必须在 `storyboard.md` 显式检索并规划 **3–6 个原作 OP/ED 或漫画/剧集经典分镜致敬锚点**，禁止拍成泛泛的风景街拍。
3. **景别节奏与局部特写**：严禁整镜全程全身/全景平拍，10s 动作或情绪单元必须编排局部特写与景别起伏（球鞋急停、小腿发力、胸部以上出击近景、手部/道具特写、眼神大特写等）。
4. **共享纯景与防反物理静态帧**：Google Omni Flash 1.2 等多参考路线彻底禁止设计“人物悬空/失衡动态静态关键帧”，同空间不同时段由 `scenes/` 母图经 `image.edit` 派生以锁死建筑几何。
5. **不可变历史与预算边界**：输入清单记录不可变资产与 SHA-256；候选与批准关系不覆盖旧文件或旧结论；候选失败只重做相关阶段，收费尝试遵循已批准预算；诊断素材与用户资产不作临时垃圾删除；响应未知先对账恢复，不重复收费生成。

## 4. World 资产与 Artifact 关系

- **World 输入解析**：人物形象、歌曲 Master 或动作参考来自 World 时，先调用 `world.get(asset_id, asset_version_id)` 读取固定版本并核对权限与完整文件，禁用展示名或 `latest`；将实际文件以 `ContentRef` 登记至当前 MV Project 的 `asset_refs`/`selections` 与 `input/manifest.json`。`asset_version_id` 变化须产生新领域文档/GU 版本并重新过审核门。
- **Shot Candidate 追溯字段**：每个候选至少关联 `generation_unit_id`、`attempt_id`、`video_task_id`、输出 `artifact_id`、模型与运行时版本、输入摘要、容器/时长/宽高/帧率/音视频编码、首帧/关键帧/尾帧 Artifact、技术检查与人工审核结论。
- **World 发布边界**：交付物先经 `project.commit` 归档到本 MV Project；仅当用户显式确认具备跨项目复用价值时才由上层调用 `world.register`，不自动把视频候选或 `input/manifest.json` 发布为 World 资产。

## 5. 生成后内容分级评估（K09 强制步骤）

凡经 Studio MCP 生成新媒体产物（角色视图、服装人台、分镜格、视频 Shot 候选或新歌曲候选），取得产物后、写入 `review.md` / 展示摘要 / 执行 `project.commit` 之前必须执行（只读查询、复用已评估 Master WAV 或恢复已评估任务不重复评估）：

1. **准备输入**：图像评估原图、正向提示词与标题；视频在本机临时目录按**至少每 2 秒 1 帧、全片至少 8 帧加切镜关键帧**抽帧，结合帧序列、音轨、正向提示词与标题判定，**评估后立即删除临时抽帧**并在 `reasons` 中记录抽帧数（无音轨转写时另注明 `"未转写音频"`）；音乐与歌词评估歌词、正向提示词、标题与转写文本（缺转写注明 `"未转写音频"`）。
2. **判定与提交**：对照[18+ 评估规范（rubric v1.0）](content-rating-rubric.md)判定（`rubric_version` 取自规范文首 `"rubric v1.0"`；不确定即标 `nsfw`），调用对应域 `*.rate_content`（`image.rate_content`、`video.rate_content`、`music.rate_content`）提交，`general` 与 `nsfw` 均须提交；超时用相同内容幂等重试，不重新生成。
3. **脱敏与阻断**：判为 `nsfw` 的产物在摘要与 `review.md` 中只写“已隐藏产物 N 个（已标记为 NSFW）”，不展示预览图、接触表、链接、`ContentRef` 或提示词全文，且不写入 `project.commit`、不进入 Picture Lock、不调用 `world.register`。误标由用户在 Studio 设置页开启本机显示后人工取消。
