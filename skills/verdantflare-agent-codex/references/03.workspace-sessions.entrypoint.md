# Windows VS Code 当前工作区会话列表补丁（03.workspace-sessions）

## 1. 输入与输出

- **输入**：Windows 本地 VS Code `openai.chatgpt` 扩展安装目录（多版本时经 `--extension` 指定）、[workspace_sessions.py](../scripts/workspace_sessions.py) 子命令（`probe`/`status`/`apply`/`rollback`）或 [install.py](../scripts/install.py) 的 `--workspace-sessions` 显式开关。
- **输出**：兼容探测与状态报告（含 `workspace_sessions_check`）、已校验写入的磁盘补丁与用户数据目录备份清单、或安全回滚后的原始扩展文件。
- **公共依据**：[公共规则](00.common.rules.md)、[技能入口](../SKILL.md)。

## 2. 分类

这是可选的实验性本地补丁，适用于 Windows 本地 VS Code `openai.chatgpt` 扩展。该分支不派单、不新建模型轮次，与现有 MCP 调度接口独立。旧基线由包内 `resources/workspace-sessions/adapter.json` 声明，版本为 `26.1106.51428`；新增 `adapter-26.1111.21308.json` 适配 `26.1111.21308` 并已完成本机安装与验收。按实际版本选取独立锚点、绑定与摘要，未知版本不写入。它按当前工作区过滤首页、历史下拉、搜索和数量，并通过双阶段目录观察同步原生改名标题，不删除会话、不修改认证或按 ID 调度能力。

路径按多根工作区并集和完整目录边界匹配，支持子目录、Windows 大小写及宿主规范路径。兄弟 Git worktree 只有加入工作区才显示。无工作区、未知 `cwd`、远端或云端会话不推断归属；本机筛选不是权限隔离。2026-11-12 在适配版本的 Windows 本地 VS Code 完成脚本、打包文件与双项目真实体验验收；用户手工确认移除临时诊断后的启动、会话归属、历史搜索、计数及旧会话恢复；此结论不扩展到其他版本或宿主。

探测与状态检查返回以下五类确定状态：

| 状态标识                | 含义与处置判据                                                   |
| :---------------------- | :--------------------------------------------------------------- |
| `compatible`            | 当前原始文件和依赖摘要符合适配，可以应用                         |
| `installed`             | 当前文件等于预期补丁（含 `already-installed`），不证明窗口已载入 |
| `installed-older-patch` | 磁盘为已知旧补丁，先回滚再应用新修订                             |
| `interrupted`           | 已知的部分写入状态，回滚后重试                                   |
| `blocked`               | 版本、摘要、备份、锁或安装信息不符，保持原文件不盲目写入         |

## 3. 工作流

### 3.1 探测与启用

从本技能目录执行，要求 Python 3.11 或更新版本。先执行只读探测与状态检查（不写扩展或补丁状态），再按已有任务授权显式应用；存在多个未能唯一识别的扩展时通过 `--extension` 指定目标安装目录：

```powershell
python scripts/workspace_sessions.py probe
python scripts/workspace_sessions.py status
python scripts/workspace_sessions.py apply
```

也可在已授权的完整技能安装中显式应用：

```powershell
python scripts/install.py --replace --workspace-sessions
```

安装输出的 `workspace_sessions_check` 始终报告实际补丁兼容与安装状态，即使未请求启用；扩展再次升级为未知版本时明确返回未适配的 `blocked` 原因（此检查发生在命令执行时，不是后台升级监控，不保证 VS Code 自动升级时主动弹窗）。应用返回 `installed-reload-required` 只表示磁盘文件已验证写入；待目标窗口没有活动任务后重载窗口或插件 Webview，再检查页面，不得为检查主动打断其他项目任务。

### 3.2 备份与回滚

备份、清单和操作锁在本机用户数据目录 `verdantflare-agent-codex/workspace-sessions/` 下，按扩展目录分开保存，不随技能分发。锁残留时先查明记录的进程是否仍存在及文件状态，不能自动删除锁后并发写入。

```powershell
python scripts/workspace_sessions.py rollback
```

回滚仅恢复当前仍为已知原始／补丁内容的文件，备份也必须通过摘要检查；扩展升级或用户修改后不覆盖新文件。升级后重新运行 `probe`，不兼容时需要维护适配并重新验证。

## 4. 规范

遵循[公共规则](00.common.rules.md)的兼容与维护红线，并遵守以下补丁约束：

- 普通技能安装仅分发管理工具，不自动修改扩展；`--register-mcp` 仍是独立选项，应用显示补丁不要求重新注册或登录。
- 更新已有安装前核对配置与安装副本独有改动，不能借 `--replace` 覆盖无关配置。
- 修改打包文件须匹配精确版本、适配清单、依赖摘要与唯一锚点，不兼容时停止写入；不因扩展目录自动发现成功而声称补丁兼容。
- 筛选仅影响列表展示，不扩展为存储删除、权限隔离或跨主机会话归属推断；不为加载补丁中断活动任务。

## 5. 验收

运行路径、分页、迟到响应、失败、补丁生命周期及安装选项测试，并检查真实打包文件的锚点、依赖摘要和语法：

```powershell
node --test scripts/test_workspace_sessions.mjs
python -m unittest discover -s scripts -p "test_*workspace_sessions*.py"
```

- **安装与哈希核验**：技能安装后对比维护源与安装副本逐文件 SHA-256 哈希，分别记录脚本测试、磁盘应用、实际加载和双项目 UI 体验。
- **双项目真实体验检查**：同时打开两个项目窗口，确认各自首页只显示本项目会话、历史搜索不出现其他项目、计数与列表一致、旧会话仍可打开；工作区切换和回滚后再次检查。未执行的项目明确记录为未验证。
- **交付门禁**：自包含安装和哈希一致不证明 UI 已加载，脚本测试不能代替人工最终体验结论；原有按 ID 调度回归不通过时不能交付为完成。
