# 分类与边界

## 1. 适用场景

将有明确工作目录、输入、修改范围和验收标准的任务交给 Codex。适用于代码实现、验证、排障与受授权的本地工作区操作。方案不明确时先由上游澄清，不通过执行智能体替用户决定产品边界。

## 2. 模式选择

- `plugin`：用户指定已打开的 Codex 插件会话；能力查询须显示持有者可达，且派单前确认会话空闲。不会创建新插件标签页。
- `managed`：调用者明确选择独立 App Server；创建新的后端会话并复用本机认证，不承诺插件 UI 自动显示。

`codex_capabilities` 返回版本、会话摘要、持有者可达性和分页游标。查询结果只代表当时可达，写操作仍会重新检查。`read_verified` 只证明读取；任务执行结果由具体任务证据判断。

## 3. 环境边界

插件适配自动发现本机最新已安装的 VS Code `openai.chatgpt` 扩展目录、内置 CLI 与 IPC 方法版本，不硬编码锁定特定扩展版本号或文件哈希；当扩展文件缺失或协议不兼容时返回明确错误，不盲目试写。服务为本机 stdio，不提供公网监听。

认证由 Codex 后端读取。技能文件不保存密钥，也不把账号信息加入任务参数。

## 4. 本地插件维护

用户要求只显示当前项目会话时，使用[工作区会话补丁](workspace-sessions.md)。该分支不派单、不新建模型轮次；实验性显示补丁与现有 MCP 调度接口独立。协议目录自动发现继续沿用第 3 章；修改打包文件另须匹配适配清单和依赖摘要。
