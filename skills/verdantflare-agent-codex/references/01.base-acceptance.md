# 验收标准

## 1. 静态与协议验证

技能结构检查、Markdown 检查、自包含单测（使用运行时虚拟环境 Python 执行 `-m unittest discover -s scripts -p "test_*.py"`）及安装文件全量 SHA-256 哈希比对通过。标准 MCP 客户端能够初始化、列出八项工具、调用只读查询；非法字段、超限提示词和错误编号返回结构化错误。

会话命名验证准确 thread_id 与 cwd、原生回读、错误工作目录不写入及超时不重放。源码检查、真实接口调用、全局安装加载和 UI 展示分别记录。

## 2. 行为验证

使用用户指定的验收会话执行以下闭环：提交任务、查询进度、验证实际产物、读取结果、续接原会话并取消指定轮次。记录任务编号与实际轮次，核对重复请求不会新增轮次。

重启前后应匹配同一后端轮次；无法判定时返回未知并保持租约，不能自动重发。断开、失败、审批等待、非法响应和父子工作区并发冲突有对应测试证据。

## 3. 业务完成判定

任务完成须同时满足约定产物存在、内容正确、所需验证执行成功且无未解决问题。退出码缺失或非零不能声明验证通过；模型声称测试通过而命令失败时，以命令与产物证据为准。

插件模式验收不能被独立后端测试替代。技能可见、MCP 已注册、真实工具可调用和人工确认分别报告。跨智能体接入必须至少有另一个宿主在新会话实际调用，脚本客户端测试只证明协议链路。

## 4. 交付记录

交付包含服务与插件版本、模式、任务与轮次编号、产物位置、实际验证结果、未完成项及人工结论。公开报告脱敏账号、认证信息和本机路径，原始执行日志仅保存在授权的本机状态目录。
