# 执行流程

## 1. 接入检查

确认服务已安装，宿主 MCP 列表包含 `verdantflare-agent-codex`。配置入口由 `VERDANTFLARE_AGENT_CODEX_SERVICE` 指定，默认从用户数据目录的 `verdantflare-agent-codex/service.json` 读取。Python 启动器只读取配置并调用安装好的服务，不在调用时下载依赖。

运行 `codex_capabilities`，必要时传入 `cwd` 与分页 `cursor`；选择用户指定的会话编号。找不到在线持有者时让用户打开该会话，不自行改派其他用户会话。

## 2. 任务交接与派单

已授权创建专用验收会话时，可以先创建受管线程，再通过 VS Code 的 `vscode://openai.chatgpt/local/<thread_id>` 路由打开，重新查询插件持有者可达后派单。该路由依赖宿主版本，不等于 MCP start 支持新建插件标签。不得自动选择无关用户会话。

使用 `codex_session_rename` 为明确的 thread_id 设置 name，同时提供准确 cwd。服务先核对原生线程与工作目录，经官方 `thread/name/set` 写入并回读一致后返回 naming=native。此操作不启动模型轮次，不修改权限；超时先读取原线程名称，不自动重放。源码支持不代表旧版全局服务已加载该工具，先检查工具列表。API 回读不代替 UI 目视检查。

交接文本至少包含目标、允许修改的路径、输入材料、不能触碰的内容、验证命令和完成标准。调用 `codex_task_start`，`plugin` 与 `managed` 两种模式均必须传入新的 `request_id`、明确的 `mode`、绝对 `cwd` 与 `prompt`；仅 `plugin` 模式另传 `thread_id`（`managed` 模式禁止传 `thread_id`，切勿将 `thread_id` 与必填的 `request_id` 混淆）。

保存返回的 `task_id`。启动返回 `queued` 仅表示任务已受理，不是执行成功。通信超时后查询原任务或使用同一请求编号重试，不另造编号重发。

## 3. 查询、输入与结果

使用 `codex_task_status` 查询状态、事件游标及待处理请求；下次带 `after_event` 接续读取，直到 `has_more=false`。间隔随任务时长调整，不紧密循环刷请求。

`waiting_approval`：plugin 模式由用户在插件 UI 审批；managed 模式把 `pending[].approval_url` 作为可点击链接交给用户，在同一台机器的浏览器中查看完整请求并选择允许本次、拒绝或取消。无需在 VS Code 打开或接管受管会话，不自动弹窗抢占焦点。链接仅在原服务和对应请求存活时有效；不可用时查询原任务，不重派。调用者不能用 `codex_task_respond` 或自动操作审批页自行批准权限。普通问题的回答可通过 `codex_task_respond` 传入待处理编号与预期轮次，答案结构必须对应原问题。

终态后调用 `codex_task_result`。结果的 `content_json` 是可分页的 JSON 文本片段，按 `next_cursor` 顺序拼接后再解析，检查答复、文件变更、实际命令退出码与未解决事项。不要把模型口头声明等同于验证证据。

## 4. 续接与取消

`codex_task_continue` 需要 `task_id`、新的 `request_id`、`prompt`、上一轮 `expected_turn_id`。仅上一轮终止后受理；同一任务保留旧轮次结果。

`codex_task_cancel` 必须携带当前预期轮次。收到 `cancelling` 后继续观察，只有后端确认才会返回 `cancelled`。取消不能以杀死插件进程替代，也不能扩大为暂停用户整个会话目标。

## 5. 失败恢复

`SESSION_BUSY` 表示同会话租约、涉及 plugin 的工作区租约、会话活动状态或待处理输入不允许新任务。租约冲突返回占用方 task_id，可查询该任务；不会自动排队。不同 managed 任务在同一 cwd 可直接并行，必须事先约定不重叠的修改范围。

`interrupted_unknown` 表示无法确定提交或终止结果，仍保留租约。服务重启会尝试按原会话、轮次及提交标识核对；恢复不会重发任务。仍未知时保存编号和证据，人工核对后再处理，不用删除数据库解锁。

`PERMISSIONS_UNAVAILABLE`／`PERMISSIONS_CONFLICT`／`PERMISSIONS_CHANGED` 表示权限来源无法确认、冲突或在提交前变化；先核对宿主选择及用户数据目录，不改派 managed 绕过问题。`PERMISSIONS_MISMATCH` 表示原生轮次生效权限与已记录选择不符；查看原任务终态、命令结果及权限事件，不能直接重复派单。修复版本可通过 capabilities 的 `permission_inheritance=host-selection-native-turn-context-v1` 识别，但该标记不代替实际轮次验收。

CLI 派单需要 `--wait` 让拥有后端连接的进程保持存活；MCP 客户端保持连接时可异步查询。完整参数使用 JSON 文件：

```powershell
python scripts/launch.py --call codex_task_start --arguments task.json --wait
python scripts/launch.py --call codex_task_status --arguments status.json
```

## 6. 可选会话列表筛选

插件维护任务先执行只读探测，再按已有任务授权显式应用补丁；状态、升级和回滚命令见[工作区会话补丁](workspace-sessions.md)。普通安装不自动启用。验证时分别记录脚本测试、磁盘应用、实际加载和双项目 UI 体验，不为加载补丁中断活动任务。
