# verdantflare-image：多渠道适配与路由（03.provider-adapters）

## 1. 输入与输出

- **输入**：用户指定的目标引擎/模型（或按默认路由判定的渠道）、所属项目 `project_id`、固定 `idempotency_key`、渠道兼容的参数与同项目原生参考图 Artifact ID。
- **输出**：经真实 `image.capabilities` 核验后通过对应渠道生成的图像候选、真实像素与 MIME 核验报告、以及 K09 分级记录。
- **公共依据**：[公共契约、质感与内容分级](00.common.rules.md)、[Google AI Studio 图像调用](google.md)、[Grok 图像调用](grok.md)、[MOSS-Image 自托管调用](moss-image.md)。

## 2. 分类

按目标模型与任务诉求路由到对应渠道，严禁未授权跨渠道静默切换：

| 渠道与引擎      | 定位与专册                                                     |
| :-------------- | :------------------------------------------------------------- |
| `codex`（默认） | GPT Image 2.6，见[公共契约](00.common.rules.md)                |
| `google-flow`   | Google Nano Banana 默认渠道（支持 `2k`/`4k` 超分）             |
| `gemini`        | Google AI Studio（仅显式），见[google.md](google.md)           |
| `grok`          | Grok 1K/2K 文生图与单图编辑，见[grok.md](grok.md)              |
| `moss-image`    | 自托管文字海报/版式/场景编辑，见[moss-image.md](moss-image.md) |

## 3. 工作流

1. **能力发现**：先调用 `image.capabilities` 确认目标 `engine` 已启用、配置完整且支持所需 `model`、画幅、参考数量与 `rate_content`。
2. **按渠道构造参数**：
   - **Google Flow（`engine="google-flow"`）**：默认模型 `nano2`，可选 `nano21`、`nano-pro`；画幅 `1:1`、`16:9` 或 `9:16`，最多 3 张参考图；可选 `upscale="2k" | "4k"`（默认关闭，0 积分免费超分，`4k` 需 Ultra 账号，偶发失败自动降级保留 1K 原图并标 `upscale_status="fallback_original"`）；可通过 `--budget-limit` 指定整数积分上限。
   - **Google AI Studio（`engine="gemini"`）**：仅显式指定时使用，区分展示名与 `model_id`（默认 `gemini-nano-banana-2.1`），支持 1–6 张参考图（`<=24MB`），不支持遮罩重绘，详见[google.md](google.md)。
   - **Grok（`engine="grok"`）**：模型取 `image.capabilities` 声明，`image.edit` 仅接受 1 张同项目 `source_artifact_id` 且继承画幅，不走 REST CLI，详见[grok.md](grok.md)。
   - **MOSS-Image（`engine="moss-image"`）**：传入显式 `width`/`height`（16 倍数、`[512, 2048]`、总像素 `<=2M`）、可选 `layout`（`meta/items`，`box_2d=[x1,y1,x2,y2]`，最多 32 项）、`steps`/`cfg_scale`/`seed` 与独立 `negative_prompt`，详见[moss-image.md](moss-image.md)。
3. **GPU 排队与恢复**：自托管本地 GPU 引擎（`moss-image` 及 CUDA 版 `face-fusion`）由 Image MCP 自动向 Station GPU 调度器（`:5056`）申请显存租约并执行按需冷启动（`0 -> 1`）；云渠道（`codex`、`google-flow`、`gemini`、`grok`）与 CPU 模式 `face-fusion` 不占用本地 GPU 租约。状态返回 `queued`（`waiting_gpu_lease`）或 `ENGINE_NOT_READY` 属正常排队/冷启动，继续轮询原 `task_id`，不重新提单或手动卸载其他 GPU 应用。
4. **下载核验与分级**：下载后按文件头核对真实 MIME（PNG/JPEG）、实际宽高与 SHA-256，执行 K09 `image.rate_content` 分级并归档 `general` 产物。

## 4. 规范

- **不混用渠道专属字段**：`gemini` 不传 `mask` / `image.inpaint` 或 `moss-image` 字段；`grok` 不传 `quality`、`instructions`、遮罩、多参考、透明背景或 4K；`moss-image` 不经渠道应用，严禁传 `channel_account_id`、`budget_limit`、`prefer_4k`、`resolution="4k"`、`mask` 或 `image.inpaint`（传入必报 `INVALID_ARGUMENT`）。
- **角色一致性边界**：`moss-image` 参考图（1–3 张实验性 R2I）不保证人物身份一致，角色 IP 一致性出图不选 `moss-image`；用户明确指定 MOSS 时如实说明限制，不自动切换收费渠道。
- **失败不静默切渠道**：上游返回 `image_safety`、`prohibited_content`、`no_image_returned` 或预算/配额错误时保留原 `reason_code` 并停止，不自动换幂等键重提或试探过滤边界。

## 5. 验收

- 核对实际返回通道、模型编码、真实 MIME（如 `gemini` 原生 JPEG 不冒充 PNG）、实际像素宽高与 SHA-256；Google Flow 开启 `upscale` 时核对是否降级为 `fallback_original`。
- `moss-image` 无人场景 `moss_mode="edit"` 另须核对 `execution.mode=edit`、`conditioning_mode=moss_edit_reference_latents`、`weight_sha256_checked` 及实图结构未被破坏。
- 确认 K09 `image.rate_content` 已提交且费用/预算（未知时记为未知）与任务映射完整落盘。
