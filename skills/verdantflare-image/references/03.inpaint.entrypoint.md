# verdantflare-image：遮罩局部重绘（03.inpaint）

## 1. 输入与输出

- **输入**：原图 `source_artifact_id`（同项目原生 Image Artifact ID）、局部重绘遮罩 `mask`（标明允许修改区域，避开身份锚点）、编辑 Prompt（写明保留项与唯一允许变化）、可选逻辑模型 `model`（默认 `gpt-image-2.6-sunburst`，支持 `inpaint` 的引擎以 `image.capabilities` 为准）、真实 `project_id`（UUIDv7）与固定 `idempotency_key`。
- **输出**：经解码核验、同倍率并排保留项比对与 K09 分级评估的局部重绘候选图，附带原生 `task_id`、Artifact 映射、SHA-256 及候选追加记录。
- **公共依据**：[公共契约、质感与内容分级](00.common.rules.md)、[渠道参数附录](channels.md)、[18+ 评估规范](content-rating-rubric.md)。

## 2. 分类

按修改范围与引擎支持情况分流：

- **支持遮罩的引擎（默认 `codex` / GPT Image 2.6）**：在宿主 `tools/list` 注册了 `image.inpaint` 且目标引擎支持遮罩时，限定局部区域修改并保护非遮罩区。
- **不支持遮罩的引擎回退**：`gemini`（Google AI Studio）、`grok` 与 `moss-image` **均不支持 `image.inpaint` / `mask`**，传入必报参数错误；此类模型或无法精确遮罩的连续返修转 [02.i2i-edit](02.i2i-edit.entrypoint.md) 走常规图生图编辑。

## 3. 工作流

1. **核验工具与基线**：通过 `tools/list` 与 `image.capabilities` 确认 `image.inpaint` 已注册且所选模型支持遮罩；冻结原图 `source_artifact_id`、SHA-256 与保留项清单。
2. **准备遮罩与导入**：确认原图与遮罩尺寸/格式符合当前 Schema；通过 `image.import`（`<=3 MiB`）或分块导入取得同项目原生引用；遮罩严格避开人物面部身份锚点与已认可道具。
3. **提交 `image.inpaint` 并轮询**：立即保存 `task_id` 并轮询 `image.status`；遇到 `needs_attention: true` 或 `submission_unknown` 立即停止无限轮询并保留原幂等键排查。
4. **并排验收、K09 分级与候选追加**：下载校验真实宽高/MIME/SHA-256，同倍率并排原图核对非遮罩保护区无漂移；调用 `image.rate_content` 提交分级；`general` 产物先作为候选追加到原 Project，通过审阅检查点后再晋级当前预览。

## 4. 规范

- 遮罩不是像素级硬锁，保护区出现可见漂移时不得宣称“硬锁定”，不能用局部变好抵消身份、比例或背景退步。
- 严禁向 `gemini`、`grok`、`moss-image` 传入 `mask` 或调用 `image.inpaint`；失败后保留原 `reason_code`，不静默跨渠道切换。
- 仅在用户明确指定或已授权尝试次数/预算内发起新收费尝试。

## 5. 验收

- 核对文件非空、完整解码、真实 MIME、像素宽高与服务端 SHA-256 一致。
- 同倍率并排核对原图与重绘结果，确认非遮罩保护区（五官、姿态、构图、光向）无未授权变化。
- 确认 K09 `image.rate_content` 已提交且 `general` 产物完成 `project.commit` 回读。
