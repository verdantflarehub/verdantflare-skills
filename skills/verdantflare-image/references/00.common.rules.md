# verdantflare-image：公共契约、质感与内容分级（00.common.rules）

本专册汇集跨能力共享的 Studio Image MCP 契约、默认模型与 2K 分辨率边界、中央 Artifact 适配、表面质感控制以及 K09 生成后 18+ 内容分级步骤；各模型到渠道的自动映射与专属参数边界见[渠道参数附录](channels.md)。开始时须使用真实 Studio 会话执行 `tools/list`，认证见[环境说明](../../ENVIRONMENT.md)。

## 1. 工具发现与默认模型契约

| 操作与现有网关注册名                                | 调用说明与参数边界                                             |
| :-------------------------------------------------- | :------------------------------------------------------------- |
| 文生图：`image.create`                              | 传 Prompt、项目、幂等键及已支持的图像参数                      |
| 编辑：`image.edit`                                  | 主参考 `source_artifact_id`，可选附加参考列表                  |
| 局部重绘：`image.inpaint`                           | 主参考与遮罩引用；形状和尺寸按当前契约核对                     |
| 状态：`image.status`                                | 用原始 `task_id` 查询                                          |
| 结果：`image.result`                                | 完成后取得原生 Artifact、摘要及下载信息                        |
| 内容分级标记：`image.rate_content`                  | 生成后提交 `general` / `nsfw` 评估 JSON                        |
| 导入输入图：`image.import` 及 `import_prepare` 系列 | 写入同项目原生 Image Artifact（单次 `<=3MiB`，单张 `<=20MiB`） |

- 历史 `image.generate`、`image.list` 仅在宿主实际注册并明确语义时使用；不假定存在 `artifact.import`，也不发送未注册别名。
- 制作任务一律显式提供服务生成的 `project_id`（UUIDv7）和固定 `idempotency_key`。**技能默认出图模型为 GPT Image 2.6**（`engine="codex"`，默认 `model="gpt-image-2.6-sunburst"`，可选高速变体 `gpt-image-2.6-flare` 及向下兼容 `gpt-image-2.5-sunburst` / `gpt-image-2.5-flare`）。
- 选择 Google 系列图像模型时，**默认一律走 Google Flow（`engine="google-flow"`，`model` 为 `"nano2"` / `"nano21"` / `"nano-pro"`，可选 `upscale="2k" | "4k"`）**；仅当用户显式指定 Google AI Studio（`engine="gemini"`）时才传 AI Studio 模型编码，详见[Google 图像调用](google.md)。
- `resolution` 是请求规格，不能证明返回图片已达到该尺寸，下载后必须解码核验；`quality` 使用宿主支持的枚举，不把历史 `hd`、`xhigh`、`max` 宣称为通用值。`image.edit` 与 `image.create` 的尺寸字段（`aspect_ratio`、`resolution`、`size`）不可无条件互换。
- 响应未知先对账恢复，不重复收费生成；同步不自动批准、选用或发布 World；素材增删查交由 Project 流程处理，不因此启动新生图。

### 1.1 各渠道画幅与分辨率实际行为与防坑指南

服务端已在 `image-mcp-server-v0.2.58`、`google-channel-v0.1.29` 与 `chatgpt-channel-v0.1.19` 中完成 `resolution="2k"` 透传与画幅映射修复。各引擎在请求 `resolution="2k"` 时的实际输出像素如下：

| 引擎与渠道                       | 请求 `resolution="2k"` 时的实际行为                                         |
| :------------------------------- | :-------------------------------------------------------------------------- |
| `codex`（ChatGPT `9:16`/`16:9`） | 注入 `[Aspect Ratio <ratio>]`，Web 端返回 `941×1672` / `1672×941` PNG       |
| `codex`（ChatGPT `1:1`）         | 映射 `size="2048x2048"`，Web 端上限返回 `1254×1254` PNG                     |
| `gemini`（Google AI Studio）     | 透传 `imageSize="2K"`，`9:16` 返回 `1536×2752`、`1:1` 返回 `2048×2048`      |
| `grok`（Grok）                   | 原生支持 `1k` / `2k` 与 `9:16` / `16:9`（`9:16` `2k` 返回 `1584×2816` PNG） |
| `moss-image`（自托管）           | 通过显式 `width` / `height`（16 的整数倍，总像素 `<= 2M`）控制像素尺寸      |

严禁为了掩盖上游 Web 端原生像素上限而在未修改有效参数的情况下盲目换幂等键收费重试，也严禁对低分辨率原图做插值放大后冒充原生 2K 达标。

## 2. 中央素材适配、下载与 Project 归档

中央 Artifact 以 `ContentRef = store_id + artifact_id + version_id` 固定版本；Image 原生 Artifact ID 与之不是同一引用格式，不能直接互换。

1. 本地原图通过 `studio-workspace import` 保存到当前 Project；远端/World 文件先核验权限与固定版本（`asset_id + asset_version_id`）。新内容走中央 Artifact，不让客户端直接写 S3。
2. 用 Image MCP 导入工具获得原生引用：PNG、JPEG、WebP，单张不超过 20 MiB、50 MP。不超过 3 MiB 用 `image.import`（`project_id`、`filename`、`expected_sha256`、`content_base64`）；更大的用 `image.import_prepare`（固定 `idempotency_key`、`size`、`sha256`、`purpose`，可选 `source_content_ref` 只作来源登记）后按返回 `offset` 逐片 `image.import_chunk`，最后 `image.import_commit`。中断时用 `image.import_status` 续传，不换键重来；扩展名须与实际格式一致。浏览器上传入口 `POST /apps/image/api/artifacts/upload` 只认登录会话，MCP 客户端不使用。
3. 兼容导入后记录中央 `ContentRef`、Image 原生 ID、文件大小和 SHA-256 映射。压缩副本单独命名、校验并登记，不覆盖原图哈希。受控下载路径不是匿名公网 URL；禁止把会话令牌放入 URL 或公开上传私有素材。
4. 创建成功后先保存 `task_id` 再轮询（`queued`、`running`、`completed`、`failed`、`canceled`；未知状态不猜成失败）。`image.result` 返回原生结果（`artifact_id`、`project_id`、`filename`、`sha256`、`size_bytes`、`metadata`、`download_path`），不代表中央 Project 已提交。下载通过受控路由 `/apps/image/artifacts/{artifact_id}/content` 或 `artifact.read(mode=download)`，不把 `/image/...` 随意拼到 `/mcp` 后，也不把凭据转发外域。核验 SHA-256、字节数、实际 MIME（PNG/JPEG）与真实像素宽高。
5. 无中央原生输出适配时，在授权范围内可将已下载校验的结果通过工作副本客户端显式导入为 `user_import`，保留原任务 ID 与原生 Artifact 映射，不伪造 `task_output`。通过 `project.commit` 保存文件与 `run_refs`，Prompt 与审核说明存为 MD/TXT，`domain_documents` 只登记服务支持的领域 JSON。候选不自动进入 `selections` 或注册 World。

## 3. 表面质感与过度纹理控制

写实图像出现随机砂砾、重复纹路、边缘光晕、油腻高光或暗部脏斑时按需选用；以下为可选写法，不覆盖用户指定画风：

- 先查看原图与等倍率局部，区分生成缺陷与源图噪声/压缩/低像素/预览缩放；不从聊天缩略图直接判定。
- 明确材质、区域与当前景别下的合理细节尺度；焦点清楚、背景按景深自然衰减；保留真实皮肤毛孔、雀斑、木纹、布纹与剧情污损，干净不等于磨皮或塑料质感。不把 `film grain`、`weathered`、`HDR` 做成禁词。
- **生成时可选补充（按场景替换材质与焦点）**：`画面具有自然摄影质感。人物与关键道具保留当前景别下可辨的真实细节，皮肤、布料与木材各有符合尺度的纹理。墙面、天空和阴影保持连续的明暗层次，背景细节随距离和景深自然衰减。边缘过渡自然，锐度克制；不额外叠加随机斑点、重复纹路或锐化光晕。保留参考中既有的材质磨损、角色特征和剧情污损。`
- **编辑时可选补充（明确实际缺陷与范围后使用）**：只清理目标区域新增的随机砂砾细纹与边缘锐化光晕，声明保留原有接缝、磨损、人物面部毛孔与雀斑、发丝、衣层、道具、构图、机位及光向；普通整图编辑须检查是否重画，失败候选不作新基线。
- **MCP 参数归属**：视觉目标写入 `prompt`，不臆造 `denoise`、`texture_strength` 或锐化参数；`instructions` 不是通用负向词槽；独立 `negative_prompt` 仅用于支持的引擎（如 `moss-image`）；Codex 链路可能清理带负向标题的长块，避免原样贴入 AVOID 长清单。
- **有效性判断**：并排原候选、可信参考与新候选，先看交付尺度再看等倍率原像素局部；出现蜡皮、丢失雀斑、木纹变糊或剧情污损消失须退回，成对试验保持模型/参考/画幅/参数与 seed 一致，不因单样本推导跨模型效果。

## 4. 生成后内容分级评估步骤（K09 强制步骤）

取得生成产物后、在交付摘要展示与 Project/World 同步之前，必须对照[18+ 评估规范（rubric v1.0）](content-rating-rubric.md)（类别 S1–S4、V1）完成分级评估并调用 `image.rate_content`：

1. **逐张评估**：下载并校验产物后，同时评估图像本身、正向提示词（`prompt`）、版式文字（如 `moss-image` 的 `layout` 文本）与标题；多张候选逐张独立评估并提交。只读查询或恢复已评估任务时不重复评估。
2. **判定规则**：`negative_prompt` 或反向排除描述不作为 `nsfw` 依据；正向提示词明确要求成人内容（S1–S4、V1）时即使图像未完全呈现也判 `nsfw`（O3）；无法取得完整输入或无法判定时遵循**不确定即标 `nsfw`**（O2）并在 `reasons` 写明原因。
3. **调用 `image.rate_content`**：`general` 与 `nsfw` 均须提交；`rubric_version` 固定取自[content-rating-rubric.md](content-rating-rubric.md)文首版本（当前 `"rubric v1.0"`）；传入 `task_id` 或 `content_ref`（二选一）以及 `rating`、`rubric_version`、`evaluator_model`、`reasons`、`evaluated_at`。调用幂等，超时或响应未知时用相同内容重试，**严禁重新生成图像**。
4. **交付摘要与同步阻断（H1 已确认）**：判定为 `nsfw` 的产物在摘要中只写“N 个产物已标记为 NSFW 并隐藏”，**严禁展示预览图、下载链接、`ContentRef`、原生 `artifact_id` 或提示词全文**，且**不同步到 Studio 项目（不写入 `project.commit`）、不登记到 World（不调用 `world.register`）**。判定为 `general` 的产物照常交付归档。
5. **不提供撤销**：MCP 与本技能不提供撤销标记；若用户认为误标，提示用户在 Studio 设置页开启本机“显示 NSFW 内容”开关（24 小时有效）后在产物详情人工取消标记。
