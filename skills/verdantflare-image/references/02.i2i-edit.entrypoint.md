# verdantflare-image：图生图、局部重绘与多参考编辑（02.i2i-edit）

## 1. 输入与输出

- **输入**：主参考图 `source_artifact_id`（同项目原生 Image Artifact ID）、可选附加参考 `reference_artifact_ids`、局部重绘遮罩（仅在支持 `image.inpaint` 的引擎使用）、编辑 Prompt（写明保留项与唯一允许变化）、真实 `project_id`（UUIDv7）与固定 `idempotency_key`。
- **输出**：经解码核验、保留项并排比对与 K09 分级评估的编辑候选图，附带原生任务 ID、Artifact 映射、SHA-256 及 Project 归档或候选追加记录。
- **公共依据**：[公共契约、质感与内容分级](00.common.rules.md)、[18+ 评估规范](content-rating-rubric.md)。

## 2. 分类

- **常规图生图与多参考融合（`image.edit`）**：基于已批准身份、造型或场景参考生成新画面或视角；说明每张图负责保留的面容、服装或场景属性。
- **遮罩局部重绘（`image.inpaint`）**：在宿主与引擎支持遮罩时限定修改区（注意 `gemini` 与 `moss-image` 不支持 `inpaint`，`grok` 不支持遮罩与多参考）。
- **连续内容局部返修**：同一角色、场景或镜头已有用户明确局部反馈，且需严格保留其余已认可内容（人物身份、Look、人体尺度、手脚接触、场景布局、机位、相邻镜）；不适用于全新独立探索图。
- **本地 CLI 执行与任务恢复**：通过 `scripts/image_client.py` 走 Studio `/mcp` JSON-RPC 网关执行导入、提交、轮询、下载与分级。

## 3. 工作流

### 3.1 准备与提交轮询

1. **会话与项目核对**：确认真实 Studio 会话与工具名（`image.create` / `image.edit` / `image.inpaint` / `image.status` / `image.result` / `image.rate_content`）；取得当前 `project_id`，通过工作副本客户端核对已有任务与候选，避免重复生成。
2. **素材导入与映射**：本地原图受控导入当前 Project，World 输入解析固定 `asset_id + asset_version_id`；通过 `image.import`（`<=3 MiB`）或 `image.import_prepare/chunk/commit`（`<=20 MiB`）获得同项目原生引用，校验 SHA-256 并登记中央 `ContentRef` 与原生 ID 映射。
3. **提交与状态轮询**：调用 `image.edit` 或 `image.inpaint` 后立即保存 `task_id`，再轮询 `image.status`：
   - `queued` / `running`：按间隔轮询；若 `status="running"` 同时返回 `needs_attention: true` 或 `phase: "submission_unknown"` / `error: "submission_unknown"`，立即停止无限轮询，保留原幂等键与 `task_id` 转排查，不得死等或换键重提。
   - `completed`：调用 `image.result` 取得原生结果。
   - `failed` / `canceled`：记录真实错误（如 `channel_call_failed: image_safety` 需调整敏感措辞后用新幂等键在授权预算内提交）。
   - 等待超时或提交响应未知：保留原幂等键、已知 ID 与最近状态恢复原任务；相同键只用于相同输入，修改 Prompt/参考/规格须建新候选版本。
4. **下载校验、K09 分级与归档**：经 `/apps/image/artifacts/{artifact_id}/content` 下载，校验文件非空、完整解码、字节数、SHA-256、真实 MIME 与像素宽高；调用 `image.rate_content` 完成 K09 分级（`nsfw` 脱敏隐藏且跳过归档）；`general` 产物按当前 Project 流程提交并经 MCP 回读核验角色页消费的图片引用与说明（不打开浏览器；MCP 不可用时如实记录未验证）。

### 3.2 连续内容局部返修四步法

1. **冻结工作基线**：读取当前 Project 修订、当前文件 ID 与摘要，明确最近更接近要求的版本；分项列出身份、脸、Look、人体尺度、手脚接触、场景布局、机位与相邻镜的保留项及本次唯一允许变化；用户否定的版本保留历史但不作基线或下一镜输入。
2. **选择实际控制方式**：优先判断能否用同源裁切、确定性合成或真实可用局部遮罩完成；遮罩不是像素硬锁，须避开身份锚点与已认可物体，记录源图/遮罩/参考职责与摘要。
3. **并排核对全部保留项**：同倍率并排原图与新图，检查五官、头身比、服装、手脚接触、道具、几何、机位、光照及相邻镜；保护区有可见变化时不称“硬锁定”，不能用局部变好抵消其他维度退步。
4. **分开归档与晋级**：K09 合格的新图先作为候选追加到原 Project；用户已指出漂移或存在审阅检查点时，不自动替换故事板当前 `image_file_id`、封面、选用、World 固定版本或视频首帧；保留项核验通过并取得检查点结论后才更新当前预览并回读，失败则恢复上一步可信预览并标记派生候选失效。

### 3.3 本地 CLI（`scripts/image_client.py`）命令手册

`scripts/image_client.py` 自动识别以 `/mcp` 结尾的 `STUDIO_MCP_URL` 走 JSON-RPC `tools/call` 与受控下载路由（自动剥离 `/mcp` 后缀），并配合统一客户端 `studio-workspace`（见[统一客户端](../../_shared/project-world-client.md)）完成中央工程同步：

- **`generate`**：导入参考 + `image.create`/`image.edit` + `status` + `result` + 下载校验 + 可选 `--rate-rating general|nsfw`；默认 `--engine codex --model gpt-image-2.6-sunburst`，必填 `--project-id` 与 `--idempotency-key`；Google 模型默认自动路由 `--engine google-flow`（支持 `--upscale 2k|4k` 与 `--budget-limit`）。
- **`stats`**：Studio `/mcp` 下调用 `image.capabilities`（REST 查 `/api/tasks/stats`），检查支持的渠道、模型与预算规则。
- **`status`**：调用 `image.status`（完成时附带 `image.result`），使用原 `task_id`，查询失败不触发重生成。
- **`download`**：解析 `<studio_root>/apps/image/artifacts/{artifact_id}/content` 下载并校验 SHA-256、真实宽高与 `2k` 规格偏差告警。
- **`rate`**：调用 `image.rate_content` 提交 `general` / `nsfw` 分级评估（`rubric v1.0`）；幂等追加标记，不提供撤销。

调用失败分别记录地址构造、认证与服务响应；未收到 `task_id` 时核查同一幂等键状态，不换键重放。

## 4. 规范

- `image.edit` 与 `image.create` 的尺寸字段不可无条件互换，以当前 Schema 为准。
- 实际输出尺寸低于目标或发生旧模型 `1K` 回退（如 `gemini-2.5-flash-image`）或 Web 端像素上限（`codex` `941×1672` / `1254×1254`）时如实记录真实像素，严禁插值放大冒充原生 2K 或未改参数盲目换键重提。
- 文档 Preview 使用相对路径 `![说明](相对路径)` 附实际状态，未生成图用文字标记不插断链；聊天交付使用宿主支持路径并提供独立打开原图链接，图片显示与点击打开分别检查，不因预览需求将本地媒体自动上传公共 CDN。
- 仅在用户明确指定或已授权尝试次数/预算内发起新收费尝试。

## 5. 验收

- 校验文件非空、完整解码、真实 MIME、像素宽高与服务端 SHA-256 一致；原图与转码/裁切副本分别保留与登记 SHA-256。
- 局部返修须完成同倍率并排核验，确认未授权保护区无明显漂移，且仅在审阅通过后晋级当前预览。
- 确认 K09 `image.rate_content` 已提交且 `general` 产物完成 `project.commit` 与 MCP 回读；不把文件可解码或任务成功等同于视觉与艺术验收通过。
