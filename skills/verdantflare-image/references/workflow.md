# Image生成与恢复流程

适用于角色视图、造型、场景、分镜、编辑和局部重绘。按用户要求或项目用途选择视图模式；明确要求三视图时，不自动补成四视图或五视图。

<a id="准备"></a>

## 1. 准备

1. 通过 [环境说明](https://github.com/verdantflarehub/verdantflare-skills/blob/d52d2ad317ab8cd220c03682b1a88b212b995d45/skills/ENVIRONMENT.md) 确认真实Studio会话、工具名和权限。旧共享令牌可见媒体工具但看不到Project时，先恢复已有授权会话。
2. 从当前项目上下文取得 `project_id`；需要新项目时调用 `project.create`，不从目录名造ID。通过现有工作副本客户端打开项目，检查已有任务与候选，避免重复生成。
3. 本地输入受控导入当前Project；World输入解析固定 `asset_id + asset_version_id`。按 [调用说明](contracts.md) 用 `image.import` 系列工具导入为Image原生引用，核对返回的 SHA-256 与本地一致，并在任务记录登记中央ContentRef与原生ID的映射。
4. 按 [视觉规格](visual-specs.md) 确定视图模式、目标画幅、尺寸、构图与参考职责，复用已有批准身份和造型，登记固定输入与摘要。选用[五视图合成板](visual-specs.md#6-角色五视图合成板)时先遵循用户明确图格；否则固定身份长相优先 3＋2，衣装造型优先 2＋3。记录五格位置、身体裁切和解剖侧别；3＋2 另记左右侧脸相同的目标转角与未包含身体侧视的限制。区分原图已提供的身份/服装信息和需要补全的侧脸或侧背结构，版式参考不改变目标发型和衣装；参考不足不等于不能独立准备Prompt。
5. 保存本次Prompt、参数、输入映射与固定幂等键。未指定时技能默认出图模型为 **GPT Image 2.6**（`engine="codex"` / `gpt-image-2.6-sunburst`），用户明确选择优先；实际字段和枚举以当前宿主为准。提交前核对 [调用契约第 1.1 节](contracts.md#11-各渠道画幅与分辨率实际行为与防坑指南) 中各引擎对 `resolution="2k"` 与 `9:16` / `16:9` 的实际输出像素（如 `gemini` `9:16` `2k` 返回 `1536×2752`、`grok` 返回 `1584×2816`、`codex` 受 Web 端上限返回 `941×1672`），避免因渠道原生像素上限差异而误判或重复收费重试。

<a id="提交与轮询"></a>

## 2. 提交与轮询

使用当前注册的创建/编辑工具：现有网关是 `image.create`、`image.edit`、`image.inpaint`。得到 `task_id` 后立即保存，再查询 `image.status`。

- `queued` / `running`：按宿主或客户端间隔继续查询。若 `status` 为 `"running"` 但同时返回 `needs_attention: true` 或 `phase: "submission_unknown"` / `error: "submission_unknown"`，说明下游提交响应未决且 `image.status` 按需恢复后仍未取得终态，客户端须立即停止无限轮询，保存原幂等键与 `task_id` 转入异常排查或清理，不得仅按 `status in ("completed", "failed", "canceled")` 死等。
- `completed`：调用 `image.result` 获取结果。
- `failed` / `canceled`：记录真实错误或取消状态（如 `channel_call_failed: image_safety` 表示触发上游安全策略拦截，需调整提示词中敏感解剖或擦边措辞后使用新幂等键提交）；新尝试须在授权次数/预算内。
- 等待超时或提交响应未知：保存原幂等键、已知ID与最近状态，恢复原任务；不因为本地等待结束就换键重提。

相同键只用于相同输入。改变Prompt、参考图或规格时保留旧版本，建立新的候选版本与尝试记录；下载故障只重取原结果。

<a id="下载校验分级评估与归档"></a>

## 3. 下载、校验、分级评估与归档

1. 通过Studio宿主的受控下载路径取得原生结果，或用中央Artifact/工作副本读取；不直连下游，不把 `/mcp` 当下载根路径。
2. 核对文件非空、可完整解码、字节数和SHA-256一致，记录真实宽高与实际 MIME 格式（如 Google 渠道原生 JPEG 不冒充 PNG，转码或中心 9:16/16:9 裁切副本须保留原图并分别登记 SHA-256）。若实际尺寸低于目标或发生旧模型 `1K` 回退（如 `gemini-2.5-flash-image` 不支持 `imageSize` 回退 `1K`、或 `codex` 受 Web 端像素上限返回 `941×1672` / `1254×1254`），如实记录真实像素，不插值放大后宣称原生达标，也不在未改变有效参数的情况下换键重提。
3. **生成后内容分级评估（K09 强制步骤）**：在归档与交付摘要前，按 [生成后内容分级评估步骤](content-rating-step.md) 与 [18+ 评估规范（rubric v1.0）](content-rating-rubric.md) 评估图像本身、正向提示词与标题，并调用 `image.rate_content` 提交分级结果（`general` 与 `nsfw` 均须提交，`rubric_version` 取自规范副本文首；不确定即标 `nsfw`；超时用相同内容幂等重试，不重新生图）。若判为 `nsfw`，交付摘要只写“N 个产物已标记为 NSFW 并隐藏”，不展示预览、链接、`ContentRef` 或提示词全文，且**跳过第 5 步 Project 归档与 World 登记**。
4. 检查身份、服装、手脚、道具、构图及参考连续性。五视图按所选模式逐格核对[布局与用途限制](visual-specs.md#6-角色五视图合成板)；3＋2 加查正脸摆正、左右侧脸同角度与真实不对称、两侧身体同尺度及鞋底基线，不用镜像脸补齐。分别记录合格项、失败项及未见侧脸或侧背的推断；不把文件可解码当成视觉通过。原始候选不覆盖，画面返修保存为新候选。
5. 对判定为 `general` 的产物，通过当前Project保存结果、原生任务/Artifact映射、Prompt及审核MD，并按实际创作状态更新角色或成果关联。连续内容的局部返修在[第 4 节](#4-局部返修与当前预览)检查通过前只追加候选文件与来源，不自动把新图设为故事板当前图、封面或角色固定参考。读取[Project流程](https://github.com/verdantflarehub/verdantflare-skills/blob/d52d2ad317ab8cd220c03682b1a88b212b995d45/skills/verdantflare-project/SKILL.md)，自动完成提交及回读，不等待额外同步指令。没有中央原生输出适配时，按调用说明显式导入为 `user_import`，不伪造来源。任务返回成功不等于Project提交成功。助手按[修订与恢复](https://github.com/verdantflarehub/verdantflare-skills/blob/d52d2ad317ab8cd220c03682b1a88b212b995d45/skills/verdantflare-project/references/revisions.md#5-创作中的素材增删改查)经 MCP 回读核验角色页消费的图片引用和对应说明，不打开浏览器；MCP 不可用时准确记录未验证，不能转交用户代验。
6. 输出候选、所选视图模式及检查结果，3＋2 明确告知“未包含身体侧视”，不能称为完整身体三视图；不把技术完成或方法批准标为新候选的人工批准。只有用户实际选用后才更新 `selections`；跨项目复用另经明确授权注册World。

用户要求文档Preview时，文档内的既有图片使用相对路径的Markdown内嵌图片 `![说明](相对路径)`，附实际状态；未生成图片用文字标记，不插入断链或把候选称为批准版。聊天交付使用当前宿主支持的图片资源路径，并提供独立的打开原图链接；文档相对路径不能直接证明聊天端可用。图片显示与点击打开分别检查，文件存在、下载成功或助手能读取图像均不等于这两项通过；无法验证时如实说明。本地媒体仍留在项目工作副本，不因预览需求自动上传公共CDN。

## 4. 局部返修与当前预览

适用于同一角色、场景或镜头已出现用户明确的局部反馈，且仍需保留其他已认可内容的连续创作。常规新图仍按第 1–3 节执行，不因本节增加普遍的人工审批。

1. **冻结工作基线**：读取当前 Project 修订及受影响镜头的当前文件 ID、摘要和已归档候选；指出最近一个用户认为更接近要求的版本。分别列出身份、脸、Look、人体尺度、手脚接触、船／场景布局、机位和相邻镜的保留项，以及本次唯一允许变化的属性与区域。用户否定的版本保留历史，但不能作为身份、船型或下一镜输入。没有可用基线时先说明缺口，不由最近生成时间推定基线。
2. **选择实际控制方式**：先判断能否通过同源裁切、确定性合成或真实可用的局部遮罩完成；仅靠 `image.edit` 的保留提示词或 `image.inpaint` 遮罩不能保证画外像素不变。遮罩应避开身份锚点和已认可物体；若本次目标需要改变与保护区接触的部位，明确接缝和遮挡检查。记录源图、遮罩、参考各自职责与摘要，不将错误全图当作新的权威参考。
3. **核对全部保留项**：生成后按相同倍率并排原图与新图，检查脸部五官与头身比、服装、双手和鞋底接触、栏杆／道具、场景几何、机位、光照及相邻镜。对声称未变的保护区，能比较像素或结构差异时记录结果；有可见变化就不称“硬锁定”，不能用局部改好来抵消其他维度变坏。只看缩略图、自动相似度或遮罩范围不足以判定通过。
4. **分开归档与晋级**：K09 合格的新图和真实来源可以作为候选追加到原 Project，但用户已经退回相关镜头或本轮存在人工审阅检查点时，不改变当前 `image_file_id`、封面、选用、World 固定版本或视频首帧。保留项检查合格且已有检查点取得用户结论后，才更新受影响的当前预览并回读；未受影响镜头继续复用。候选失败或用户认为整体更远时，恢复上一步较可信的当前预览，标记派生候选失效，不从失败版继续改。
