# Image生成与恢复流程

适用于角色视图、造型、场景、分镜、编辑和局部重绘。按用户要求或项目用途选择视图模式；明确要求三视图时，不自动补成四视图或五视图。

<a id="准备"></a>

## 1. 准备

1. 通过 [环境说明](../../ENVIRONMENT.md) 确认真实Studio会话、工具名和权限。旧共享令牌可见媒体工具但看不到Project时，先恢复已有授权会话。
2. 从当前项目上下文取得 `project_id`；需要新项目时调用 `project.create`，不从目录名造ID。通过现有工作副本客户端打开项目，检查已有任务与候选，避免重复生成。
3. 本地输入受控导入当前Project；World输入解析固定 `asset_id + asset_version_id`。按 [调用说明](contracts.md) 用 `image.import` 系列工具导入为Image原生引用，核对返回的 SHA-256 与本地一致，并在任务记录登记中央ContentRef与原生ID的映射。
4. 按 [视觉规格](visual-specs.md) 确定视图模式、目标画幅、尺寸、构图与参考职责，复用已有批准身份和造型，登记固定输入与摘要。选用[五视图合成板](visual-specs.md#6-角色五视图合成板)时先遵循用户明确图格；否则固定身份长相优先 3＋2，衣装造型优先 2＋3。记录五格位置、身体裁切和解剖侧别；3＋2 另记左右侧脸相同的目标转角与未包含身体侧视的限制。区分原图已提供的身份/服装信息和需要补全的侧脸或侧背结构，版式参考不改变目标发型和衣装；参考不足不等于不能独立准备Prompt。
5. 保存本次Prompt、参数、输入映射与固定幂等键。默认模型按入口说明，用户明确选择优先；实际字段和枚举以当前宿主为准。

<a id="提交与轮询"></a>

## 2. 提交与轮询

使用当前注册的创建/编辑工具：现有网关是 `image.create`、`image.edit`、`image.inpaint`。得到 `task_id` 后立即保存，再查询 `image.status`。

- `queued` / `running`：按宿主或客户端间隔继续查询。
- `completed`：调用 `image.result` 获取结果。
- `failed` / `canceled`：记录真实错误或取消状态；新尝试须在授权次数/预算内。
- 等待超时或提交响应未知：保存原幂等键、已知ID与最近状态，恢复原任务；不因为本地等待结束就换键重提。

相同键只用于相同输入。改变Prompt、参考图或规格时保留旧版本，建立新的候选版本与尝试记录；下载故障只重取原结果。

<a id="下载校验分级评估与归档"></a>

## 3. 下载、校验、分级评估与归档

1. 通过Studio宿主的受控下载路径取得原生结果，或用中央Artifact/工作副本读取；不直连下游，不把 `/mcp` 当下载根路径。
2. 核对文件非空、可完整解码、字节数和SHA-256一致，记录真实宽高与格式。请求“2K”而实际尺寸不足时如实标记规格偏差，不放大后宣称原生达标。
3. **生成后内容分级评估（K09 强制步骤）**：在归档与交付摘要前，按 [生成后内容分级评估步骤](content-rating-step.md) 与 [18+ 评估规范（rubric v1.0）](content-rating-rubric.md) 评估图像本身、正向提示词与标题，并调用 `image.rate_content` 提交分级结果（`general` 与 `nsfw` 均须提交，`rubric_version` 取自规范副本文首；不确定即标 `nsfw`；超时用相同内容幂等重试，不重新生图）。若判为 `nsfw`，交付摘要只写“N 个产物已标记为 NSFW 并隐藏”，不展示预览、链接、`ContentRef` 或提示词全文，且**跳过第 5 步 Project 归档与 World 登记**。
4. 检查身份、服装、手脚、道具、构图及参考连续性。五视图按所选模式逐格核对[布局与用途限制](visual-specs.md#6-角色五视图合成板)；3＋2 加查正脸摆正、左右侧脸同角度与真实不对称、两侧身体同尺度及鞋底基线，不用镜像脸补齐。分别记录合格项、失败项及未见侧脸或侧背的推断；不把文件可解码当成视觉通过。原始候选不覆盖，画面返修保存为新候选。
5. 对判定为 `general` 的产物，通过当前Project保存结果、原生任务/Artifact映射、Prompt及审核MD，并更新实际角色或成果字段的图片、参考及说明关联，使当前成果位置展示最新内容。读取[Project流程](../../verdantflare-project/SKILL.md)，自动完成提交及回读，不等待额外同步指令。没有中央原生输出适配时，按调用说明显式导入为 `user_import`，不伪造来源。任务返回成功不等于Project提交成功。助手按[修订与恢复](../../verdantflare-project/references/revisions.md#5-创作中的素材增删改查)经 MCP 回读核验角色页消费的图片引用和对应说明，不打开浏览器；MCP 不可用时准确记录未验证，不能转交用户代验。
6. 输出候选、所选视图模式及检查结果，3＋2 明确告知“未包含身体侧视”，不能称为完整身体三视图；不把技术完成或方法批准标为新候选的人工批准。只有用户实际选用后才更新 `selections`；跨项目复用另经明确授权注册World。

用户要求文档Preview时，文档内的既有图片使用相对路径的Markdown内嵌图片 `![说明](相对路径)`，附实际状态；未生成图片用文字标记，不插入断链或把候选称为批准版。聊天交付使用当前宿主支持的图片资源路径，并提供独立的打开原图链接；文档相对路径不能直接证明聊天端可用。图片显示与点击打开分别检查，文件存在、下载成功或助手能读取图像均不等于这两项通过；无法验证时如实说明。本地媒体仍留在项目工作副本，不因预览需求自动上传公共CDN。
