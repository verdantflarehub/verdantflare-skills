## 2. 跨智能体调度硬约束

1. **默认采用 VS Code 前台面板注入模式（`mode="panel"`）**：除非本机未运行 VS Code Antigravity Hub 或用户显式要求后台无头运行，否则一律使用 `mode="panel"`，确保用户在 VS Code 面板中能直观看到双子座的实时执行动态。
2. **以文档路径传递复杂交接书**：跨智能体派发复杂任务时，上游智能体应先将方案与交接书落盘为工作区文档，在 `prompt` 中传入文档相对路径与核心指令摘要，避免在 MCP JSON 参数中直接拼接数万字符的超长文本。
3. **桌面焦点最小干扰与 CLI 权限显式控制**：`agy_dispatch_task` 的 `focus_panel` 默认值固定为 `False`，利用 Hub 的 `SetBrowserOpenConversation` 与 Reactive Stream 实现零抢焦点面板同步；`mode="cli"` 下默认不附加 `--dangerously-skip-permissions`，仅当调用方显式传入 `skip_permissions=True` 时才启用权限跳过。
4. **续接基线步数校验与超时显式标记**：向已有会话派单前先记录基线步数 `baseline_steps`，轮询等待必须看到 `RUNNING` 或总步数达到 `baseline_steps + 2` 后才判空闲退出（容忍轮询期间瞬时 RPC 抖动）；若超时未完成，显式返回 `timed_out: true` 且 `ok: false`，防止把上一轮旧回复误判为新轮次结果。
5. **禁止递归自调死锁**：当 Antigravity（双子座）自身作为当前执行智能体时，严禁通过 MCP 再次向当前正在运行的同一 `conversation_id` 阻塞派发任务；内部并发子任务应使用原生 `invoke_subagent`。

## 3. 底层 Connect-RPC 协议与安全契约

1. **动态发现端口与 CSRF 令牌**：`agy.exe --hub` 每次随 VS Code 启动时会随机分配本地端口（`--hub-port`）与会话令牌（`--csrf_token`）。脚本必须通过环境变量或进程命令行实时探测，严禁在代码或配置中硬编码端口与令牌。
2. **`StartCascade` 必填枚举契约**：经对 `agy.exe` 内嵌 Protobuf 描述符实测校验，调用 `/exa.language_server_pb.LanguageServerService/StartCascade` 时必须显式传入 `"source": "CORTEX_TRAJECTORY_SOURCE_CASCADE_CLIENT"` 与 `"trajectoryType": "CORTEX_TRAJECTORY_TYPE_CASCADE"`，缺省会触发 HTTP 400 `CortexTrajectorySource is unspecified`。
3. **配置写入隔离**：[install.py](../scripts/install.py) 注册 MCP 时，只更新 `~/.claude.json` 的 `mcpServers.antigravity` 键与 `~/.codex/config.toml` 的 `[mcp_servers.antigravity]` 节，完整保留用户原有的其他 MCP 服务与项目配置，且不在仓库文档中写入本机绝对路径或隐私凭据。
