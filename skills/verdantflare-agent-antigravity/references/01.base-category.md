## 2. 适用与不适用范围

本技能适用于两类请求：

- **跨智能体指挥调用 Antigravity（双子座）**：上游智能体完成诊断或编写好变更交接书后，调用 `antigravity` MCP 工具将任务派发给双子座执行，或查询双子座会话列表、执行状态、产物文件与轨迹日志。
- **维护与扩展 Antigravity MCP 服务**：升级 [agy_mcp_server.py](../scripts/agy_mcp_server.py) 的工具定义、适配新版 `agy.exe` RPC 字段，或通过 [install.py](../scripts/install.py) 同步全局技能并更新本机智能体的 MCP 注册表。

以下场景不适用本技能：

- 在 Antigravity 内部调用自身子智能体（应直接使用宿主内置的 `invoke_subagent` 工具）。
- 管理或发布 Antigravity Marketplace 插件商店条目。

## 3. 执行模式分类与路由判据

[agy_mcp_server.py](../scripts/agy_mcp_server.py) 支持两种底层驱动模式，前置探针通过 `agy_hub_status` 检查本机是否存在活跃的 `agy.exe --hub` 进程（`hub_count >= 1`）：

| 模式标识 | 触发判据与底层通道                                                           |
| :------- | :--------------------------------------------------------------------------- |
| `panel`  | 默认模式（`hub_count >= 1`），通过 `LanguageServerService` 直连 VS Code 面板 |
| `cli`    | 备用模式（`hub_count == 0` 或显式指定），调用 `agy.exe --print` 独立子进程   |

### 3.1 多 Hub 实例自动选路判据

当本机开启多个 VS Code 窗口、存在多个 `agy.exe --hub` 进程时，`select_hub` 按以下确定性优先级选定目标 Hub：

1. **按 `conversation_id` 精确命中**：若调用方传入了 `conversation_id`，遍历各 Hub 的 `GetAllCascadeTrajectories` 摘要，优先选定包含该会话 ID 的 Hub（`matched_by="conversation_id"`）。
2. **按 `workspace` 精确或子目录前缀命中**：将传入的 `workspace` 转换为 `file:///` URI 并归一化比较，优先精确匹配工作区根路径（`matched_by="workspace_exact"`），次选子目录/父目录前缀匹配（`matched_by="workspace_prefix"`）；若传入 `strict_workspace=true` 且未命中则直接报错拦截。
3. **空窗口优先与活跃度兜底**：当工作区未命中已有会话时，优先选择尚无历史会话的新开窗口 Hub（`matched_by="empty_hub_fallback"`），最后回退至活跃主 Hub（`matched_by="default_fallback"`），并在返回 JSON 中显式标注 `workspace_matched: false` 与 `hub_workspaces`。
