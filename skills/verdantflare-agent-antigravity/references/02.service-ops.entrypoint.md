# Antigravity MCP 服务注册、诊断与全局安装（02.service-ops）

## 1. 输入与输出

- **输入**：维护源目录 `verdantflare-agent-antigravity/`、待修改的脚本或安装参数（`--replace`、`--register-mcp`）。
- **输出**：同步到 `~/.agents/skills/verdantflare-agent-antigravity/` 的全局安装副本、本机对端智能体 MCP 注册配置、单测与静态检查验证记录。
- **公共依据**：[公共规则](00.common.rules.md)、[技能入口](../SKILL.md)。

## 2. 分类

按维护意图选择对应操作分支：

| 操作分支     | 适用场景与核心动作                                                          |
| :----------- | :-------------------------------------------------------------------------- |
| 安装并注册   | 首次部署或工具列表更新后，同步全局技能并写入 Claude / Codex / Grok MCP 配置 |
| 仅同步技能   | 仅更新全局技能文档或脚本，不改动本机智能体 MCP 配置文件                     |
| 服务升级诊断 | 升级 [agy_mcp_server.py](../scripts/agy_mcp_server.py) 或排查 Hub 连通故障  |

## 3. 工作流

### 3.1 安装与 MCP 一键注册

首次部署或修改本技能源码后，在仓库根或本技能目录运行以下命令，将技能同步到全局 `~/.agents/skills/verdantflare-agent-antigravity/`，并自动向 `~/.claude.json`、`~/.codex/config.toml` 与 `~/.grok/config.toml` 写入 `verdantflare-agent-antigravity` MCP 服务项：

```powershell
python -X utf8 scripts/install.py --replace --register-mcp
```

仅更新全局技能文件而不改动智能体 MCP 配置文件时，省略 `--register-mcp`：

```powershell
python -X utf8 scripts/install.py --replace
```

### 3.2 服务诊断与单元测试

升级 [agy_mcp_server.py](../scripts/agy_mcp_server.py) 工具定义、适配新版 `agy.exe` RPC 字段或排查连接异常时，按顺序运行单测与本地 Hub 探针：

```powershell
python -X utf8 -m unittest discover -s scripts -p "test_*.py" -v
python -X utf8 scripts/agy_mcp_server.py status
python -X utf8 scripts/agy_mcp_server.py list
```

若返回 `OFFLINE`，核查本机是否存在活跃 `agy.exe --hub` 进程及 `~/.gemini/antigravity/daemon/hub_<port>.json` 状态文件，并核对旧版全局安装是否已同步更新至全部 9 个 MCP 工具。

## 4. 规范

遵循[公共规则](00.common.rules.md)的底层 Connect-RPC 协议与安全契约：

- `discover_hubs` 优先兼容显式环境变量与旧版 `--csrf_token`，缺失时按端口读取 `daemon/hub_<httpPort>.json`，进程回退扫描校验 PID 存活并排除临时 CLI 进程，严禁硬编码端口或令牌。
- `StartCascade` 必须传入 `source` 与 `trajectoryType` 必填枚举；命中 `projectId` 时只传 `projectEnvConfig`、不传 `workspaceUris`，未命中时再回退 `workspaceUris`。
- [install.py](../scripts/install.py) 写入配置必须严格隔离，仅更新 `verdantflare-agent-antigravity` 键（并清理旧版 `antigravity` 键），完整保留用户原有其他配置。
- 全局安装只在实际授权范围内验收，不因源码任务擅自覆盖安装；公开文档严禁写入本机绝对路径或隐私凭据。

## 5. 验收

每次新增或修改本技能文档与脚本后，按顺序执行以下验证：

1. **技能结构与隔离静态检查**：在仓库内及不含兄弟技能的临时隔离目录运行 `verdantflare-meta-skill` 的 `lint_skill.py --style numbered`，确认无断链、无未完成占位符且章节结构合规。
2. **Markdown 格式化与结构检查**：对 `SKILL.md` 及 `references/*.md` 运行 `verdantflare-meta-markdown` 的 `md_format.py --check` 与 `check_md.py`。
3. **脚本单元测试**：运行 [test_agy_mcp_server.py](../scripts/test_agy_mcp_server.py) 与 [test_agy_jobs.py](../scripts/test_agy_jobs.py)，验证 URI 归一化、`daemon/hub_<port>.json` 令牌发现与旧版 `--csrf_token` 兼容、`--add-dir` 工作区选路、CLI `stream-json` 独立输入与失败原因回传、MCP JSON-RPC 双帧格式及临时目录安装注册逻辑。
4. **Live Hub 连通与安装哈希核验**：运行 `agy_mcp_server.py status` 与 `list`，核验全局安装副本与维护源逐文件 SHA-256 一致且对端配置合法。

| 验收维度            | 通过判据（Pass）                                                                        |
| :------------------ | :-------------------------------------------------------------------------------------- |
| 技能与文档静态检查  | `lint_skill.py`（含隔离目录）与 `check_md.py` 均为 `0 errors, 0 warnings`               |
| MCP 协议与单测      | 全部脚本测试 `OK`，`tools/list` 准确返回 9 个工具定义                                   |
| Live Hub 面板注入   | `status` 探测到 `hub_count >= 1`，测试会话成功返回 `PLANNER_RESPONSE` 并清理            |
| 全局安装与 MCP 注册 | `~/.agents/skills/verdantflare-agent-antigravity` 哈希一致，Claude/Codex 配置写入且合法 |

任一静态检查存在 error、断链或本机路径泄露，或 `StartCascade` 报 HTTP 400/500、残留测试脏会话、破坏原有配置项时，均判定为不通过（Fail）。未在实际打开的外部智能体新会话中触发调用前，配置文件写入状态记为“已注册并完成协议自检”，与人工跨智能体联调结论分开记录。
