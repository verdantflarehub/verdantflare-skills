# Antigravity 跨智能体派单与产物回收（01.dispatch）

## 1. 输入与输出

- **输入**：已落盘的交接书路径或核心提示词 `prompt`、目标工作区 `workspace`（或绝对 `cwd`），可选 `conversation_id`、`request_id`、`mode`（`panel` 或 `cli`）、`wait`、`focus_panel` 与 `timeout_sec`。
- **输出**：会话标识 `conversation_id` 或持久任务 `task_id`、实时执行状态、最终回复正文 `last_response`、Artifact 产物路径列表与轨迹日志。
- **公共依据**：[公共规则](00.common.rules.md)、[技能入口](../SKILL.md)。

## 2. 分类

[agy_mcp_server.py](../scripts/agy_mcp_server.py) 支持两种底层驱动模式，前置探针通过 `agy_hub_status` 检查本机是否存在活跃的 `agy.exe --hub` 进程（`hub_count >= 1`）：

| 模式标识 | 触发判据与底层通道                                                                  |
| :------- | :---------------------------------------------------------------------------------- |
| `panel`  | 默认模式（`hub_count >= 1`），通过 `LanguageServerService` 直连 VS Code 面板        |
| `cli`    | 备用模式（`hub_count == 0` 或显式指定），通过独立 `stdin` 调用 `stream-json` 子进程 |

### 2.1 多 Hub 实例自动选路判据

当本机开启多个 VS Code 窗口、存在多个 `agy.exe --hub` 进程时，`select_hub` 按以下确定性优先级选定目标 Hub：

1. **按 `conversation_id` 精确命中**：若调用方传入了 `conversation_id`，遍历各 Hub 的 `GetAllCascadeTrajectories` 摘要，优先选定包含该会话 ID 的 Hub（`matched_by="conversation_id"`）。
2. **按 `workspace` 精确或子目录前缀命中**：将传入的 `workspace` 转换为 `file:///` URI 并归一化比较，优先匹配进程 `--add-dir` 显式挂载的工作区（`mounted_workspaces`），其次匹配历史轨迹记录的工作区；精确命中标记 `matched_by="workspace_exact"`，子目录或父目录前缀命中标记 `matched_by="workspace_prefix"`；若传入 `strict_workspace=true` 且未命中则直接报错拦截。
3. **空窗口优先与活跃度兜底**：当工作区未命中已有会话时，优先选择尚无历史会话的新开窗口 Hub（`matched_by="empty_hub_fallback"`），最后回退至活跃主 Hub（`matched_by="default_fallback"`），并在返回 JSON 中显式标注 `workspace_matched: false` 与 `hub_workspaces`。

## 3. 工作流

### 3.1 MCP 工具清单与参数映射

当前源码提供以下 9 个标准 MCP 工具；旧版全局安装须先核对工具列表，不能把源码增加视为宿主已加载：

| 工具名称                  | 核心职责                                                             |
| :------------------------ | :------------------------------------------------------------------- |
| `agy_hub_status`          | 探测本机运行中的 `agy.exe --hub` 列表、挂载工作区、可用模型与配额    |
| `agy_list_conversations`  | 列出最近会话 ID（`cascadeId`）、标题、状态、步数及已生成的 Artifact  |
| `agy_dispatch_task`       | 默认以 `panel` 模式向 VS Code 前台面板新建或续接会话并注入指令       |
| `agy_get_conversation`    | 查询指定会话的实时状态、最新一轮回复正文、最近工具调用与产物路径列表 |
| `agy_read_transcript`     | 按步数区间读取会话的详细轨迹步骤（优先读 `transcript.jsonl`）        |
| `agy_cancel_conversation` | 终止正在运行的会话轮次，可选清理临时测试轨迹                         |
| `agy_cli_task_start`      | 以持久请求恢复明确的 CLI 会话并异步执行                              |
| `agy_cli_task_status`     | 查询持久 CLI 任务及合成请求轮次                                      |
| `agy_cli_task_result`     | 分页读取该请求的完整 CLI 结果                                        |

### 3.2 跨智能体指挥双子座标准作业流程（SOP）

1. **落盘交接书并定位会话**：上游智能体先将详细任务需求、验收条件写入仓库变更文档（如 `docs/changes/change_YYYYMMDD_xxx.md`），再调用 `agy_list_conversations` 查看当前工作区是否已有正在跟进该主题的会话 ID。
2. **向 VS Code 前台面板注入任务**：调用 `agy_dispatch_task` 派发任务。默认 `mode="panel"` 会在 VS Code 前台 Antigravity 面板实时创建或续接会话并触发双子座执行：
   - **同步等待模式（`wait=True`，默认）**：适合中短耗时任务（`timeout_sec` 默认 `300` 秒），工具直接阻塞至 `CASCADE_RUN_STATUS_IDLE` 并一次性返回双子座的最终回复与产物列表。
   - **异步派单模式（`wait=False`）**：适合长耗时编码、批量出图或训练任务，工具在向面板注入消息后立即返回 `conversation_id`，面板前台实时滚动执行。
   - **显式切换面板视图（`focus_panel=True`，可选）**：默认 `focus_panel=False` 仅通过 Hub 响应式流刷新面板而不抢占窗口焦点；若需让 VS Code 侧边栏主动跳转到该新建会话画面，可传 `focus_panel=True`。
3. **监控进度与回收产物审阅**：异步派单或需复核细节时，依次调用 `agy_get_conversation`（可传 `wait_sec=30` 等待空闲，获取 `status`、`last_response` 与 `~/.gemini/antigravity/brain/<conversation_id>/` 下的 `artifacts`）与 `agy_read_transcript`（发现异常或核查终端命令与文件修改时，按 `start_step` / `end_step` 分页读取轨迹日志）。

命令行等价调用方式：

```powershell
python -X utf8 scripts/agy_mcp_server.py dispatch "请按 docs/changes/change_xxx.md 执行并汇报" --workspace .
```

### 3.3 失败恢复与排障

计划协作的 CLI 异步任务使用 `agy_cli_task_start`：提供 `request_id`、`conversation_id`、绝对 `cwd`、`prompt`，可选 `timeout_seconds`。它只恢复已登记的专用会话；新建会话先用显式初始化取得真实 ID。后台 worker 独立存活，派单客户端可以断开；通过 `agy_cli_task_status` 与 `agy_cli_task_result` 读取原 `task_id`。提示词通过原生 `stream-json` stdin 发送（`event=user`，`message` 包含 `role` 和 `content`），不放入命令行参数；只接收单个终态 result。结果必须匹配原生 `conversation_id`、退出码 0 和 JSON `SUCCESS`；返回的 `turn_id` 是持久请求标识，不是 Hub 原生轮次。

账本默认位于用户 Gemini 目录的 `antigravity/agent-jobs.sqlite`，可用 `VERDANTFLARE_AGENT_ANTIGRAVITY_STATE` 指向受控数据库。相同 `request_id` 同参数复用原任务，异文拒绝；已领取后不确定的任务保留租约，不自动重发。结果按 `next_cursor` 拼接，不拿 latest response 替代该请求结果。`agy_dispatch_task(mode="cli")` 同样通过独立 `stream-json` 输入与 `--log-file` 执行；`wait=false` 会执行启动期存活检查并在进程提前失败时返回 `ok: false` 与明确错误，跨连接持久回收仍统一走 `agy_cli_task_*`。

`panel` 协作冻结提交前的原生基线步数及完整提示词。没有 `request_id` 的原生写请求丢失响应后，通过 `agy_read_transcript` 的 `source=hub` 分页核对唯一用户输入与其后回复，不能因本地 transcript 行数不同而混用游标，也不能盲目重发。已有会话忙碌或基线不可读时拒绝注入。

- **返回结构化错误 `OFFLINE`（无活跃 Antigravity Hub）**：先用 `agy_hub_status` 检查本机是否存在 `agy.exe --hub` 进程及对应的 `~/.gemini/antigravity/daemon/hub_<port>.json` 状态文件；若未打开搭载 Google Antigravity 扩展的 VS Code 窗口，提示用户打开面板或改用 `mode="cli"` / `agy_cli_task_start`。
- **CLI 模式返回 `ok: false` 或 `failed`**：读取返回体中的 `error`、`stderr` 或 `log_path`（`--log-file` 语言服务尾部日志），核查是否由非法模型名、认证失效、无效会话 ID 或短生命周期外层终端强杀子进程引起。
- **会话长时间处于 `CASCADE_RUN_STATUS_RUNNING`**：先用 `agy_read_transcript` 查看末尾步骤是否在等待权限审批或外部长任务；确认卡死时调用 `agy_cancel_conversation` 终止当前轮次后重新派发。

## 4. 规范

遵循[公共规则](00.common.rules.md)的全部调度硬约束与底层协议契约，派单执行重点核对：

- 默认使用 `mode="panel"` 且 `focus_panel=False`，复杂交接书先落盘后传相对路径。
- 续接已有会话前冻结 `baseline_steps`，轮询必须看到 `RUNNING` 或达到 `baseline_steps + 2` 才判空闲；超时必须返回 `timed_out: true` 且 `ok: false`。
- 禁止双子座在当前运行会话上通过 MCP 递归自调；`mode="cli"` 必须独立 `stdin` 并默认不附加 `--dangerously-skip-permissions`。

## 5. 验收

- **Live Hub 面板注入实测**：存在活跃 `agy.exe --hub` 时，运行 `agy_mcp_server.py status` 与 `list`，探测到 `hub_count >= 1`，并实测 `StartCascade -> SendUserCascadeMessage -> GetCascadeTrajectory -> DeleteCascadeTrajectory` 闭环，测试会话成功返回 `PLANNER_RESPONSE` 并清理，无 HTTP 400/500 或残留脏会话。
- **持久 CLI 路径验收**：验证跨连接幂等、单次领取、后台进程结果回收、分页、错误会话拒绝、未知状态保留租约及 CLI 失败显式报错。
- **验收边界**：CLI 实测不替代 Hub 面板实测；专用会话按上游计划的保留与收尾要求管理，未授权删除时保留证据和会话。
