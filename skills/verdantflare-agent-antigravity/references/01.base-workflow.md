## 2. 安装与 MCP 一键注册流程

首次部署或修改本技能源码后，在仓库根或本技能目录运行以下命令，将技能同步到全局 `~/.agents/skills/verdantflare-agent-antigravity/`，并自动向 `~/.claude.json`、`~/.codex/config.toml` 与 `~/.grok/config.toml` 写入 `verdantflare-agent-antigravity` MCP 服务项：

```powershell
python -X utf8 skills/verdantflare-agent-antigravity/scripts/install.py --replace --register-mcp
```

仅更新全局技能文件而不改动智能体 MCP 配置文件时，省略 `--register-mcp`：

```powershell
python -X utf8 skills/verdantflare-agent-antigravity/scripts/install.py --replace
```

## 3. MCP 工具清单与参数映射

注册完成后，上游智能体可直接调用以下 6 个标准 MCP 工具：

| 工具名称                  | 核心职责                                                             |
| :------------------------ | :------------------------------------------------------------------- |
| `agy_hub_status`          | 探测本机运行中的 `agy.exe --hub` 列表、挂载工作区、可用模型与配额    |
| `agy_list_conversations`  | 列出最近会话 ID（`cascadeId`）、标题、状态、步数及已生成的 Artifact  |
| `agy_dispatch_task`       | 默认以 `panel` 模式向 VS Code 前台面板新建或续接会话并注入指令       |
| `agy_get_conversation`    | 查询指定会话的实时状态、最新一轮回复正文、最近工具调用与产物路径列表 |
| `agy_read_transcript`     | 按步数区间读取会话的详细轨迹步骤（优先读 `transcript.jsonl`）        |
| `agy_cancel_conversation` | 终止正在运行的会话轮次，可选清理临时测试轨迹                         |

## 4. 跨智能体指挥双子座标准作业流程（SOP）

### 4.1 步骤一：落盘交接书并定位会话

上游智能体（如负责架构与评审的智能体）先将详细任务需求、验收条件写入仓库变更文档（如 `docs/changes/change_YYYYMMDD_xxx.md`），再调用 `agy_list_conversations` 查看当前工作区是否已有正在跟进该主题的会话 ID。

### 4.2 步骤二：向 VS Code 前台面板注入任务

调用 `agy_dispatch_task` 派发任务。默认 `mode="panel"` 会在 VS Code 前台 Antigravity 面板实时创建或续接会话并触发双子座执行：

- **同步等待模式（`wait=True`，默认）**：适合中短耗时任务（`timeout_sec` 默认 `300` 秒），工具直接阻塞至 `CASCADE_RUN_STATUS_IDLE` 并一次性返回双子座的最终回复与产物列表。
- **异步派单模式（`wait=False`）**：适合长耗时编码、批量出图或训练任务，工具在向面板注入消息后立即返回 `conversation_id`，面板前台实时滚动执行。
- **显式切换面板视图（`focus_panel=True`，可选）**：默认 `focus_panel=False` 仅通过 Hub 响应式流刷新面板而不抢占窗口焦点；若需让 VS Code 侧边栏主动跳转到该新建会话画面，可传 `focus_panel=True`。

命令行等价调用方式：

```powershell
python -X utf8 skills/verdantflare-agent-antigravity/scripts/agy_mcp_server.py dispatch "请按 docs/changes/change_xxx.md 执行并汇报" --workspace .
```

### 4.3 步骤三：监控进度与回收产物审阅

异步派单或需复核细节时，上游智能体依次调用：

1. `agy_get_conversation`（可传 `wait_sec=30` 等待空闲）：获取 `status`、`last_response` 与 `artifacts`（即 `~/.gemini/antigravity/brain/<conversation_id>/` 下产出的报告、图片或视频文件）。
2. `agy_read_transcript`：当发现异常或需核查具体执行的终端命令与文件修改时，按 `start_step` / `end_step` 分页读取轨迹日志。

## 5. 失败恢复与排障

- **报错 `No running Antigravity Hub found`**：说明当前未打开搭载 Google Antigravity 扩展的 VS Code 窗口；可提示用户打开 VS Code 面板，或在 `agy_dispatch_task` 中传 `mode="cli"` 退回无头 CLI 模式执行。
- **会话长时间处于 `CASCADE_RUN_STATUS_RUNNING`**：先用 `agy_read_transcript` 查看末尾步骤是否在等待权限审批或外部长任务；确认卡死时调用 `agy_cancel_conversation` 终止当前轮次后重新派发。
