## 2. 测量与验证流程

每次新增或修改本技能文档与脚本后，必须按顺序执行以下四项验证：

1. **技能结构与隔离静态检查**：在仓库内及不含兄弟技能的临时隔离目录运行 `verdantflare-meta-skill` 的 `lint_skill.py --style numbered`，确认无断链、无未完成占位符且章节结构合规。
2. **Markdown 格式化与结构检查**：对 `SKILL.md` 及 `references/*.md` 运行 `verdantflare-meta-markdown` 的 `md_format.py --check` 与 `check_md.py`。
3. **脚本单元测试**：运行 [test_agy_mcp_server.py](../scripts/test_agy_mcp_server.py)，验证 URI 归一化、轨迹摘要解析、MCP JSON-RPC（NDJSON 与 `Content-Length` 双帧格式）及临时目录安装注册逻辑。
4. **Live Hub 连通与面板注入实测**：在存在活跃 `agy.exe --hub` 的环境下运行 `agy_mcp_server.py status` 与 `list`，并实测 `StartCascade -> SendUserCascadeMessage -> GetCascadeTrajectory -> DeleteCascadeTrajectory` 完整闭环。

```powershell
python -X utf8 -m unittest discover -s skills/verdantflare-agent-antigravity/scripts -p "test_*.py" -v
python -X utf8 skills/verdantflare-agent-antigravity/scripts/agy_mcp_server.py status
```

## 3. 通过与失败判据

| 验收维度            | 通过判据（Pass）                                                                        |
| :------------------ | :-------------------------------------------------------------------------------------- |
| 技能与文档静态检查  | `lint_skill.py`（含隔离目录）与 `check_md.py` 均为 `0 errors, 0 warnings`               |
| MCP 协议与单测      | `test_agy_mcp_server.py` 全部用例 `OK`，`tools/list` 准确返回 6 个工具定义              |
| Live Hub 面板注入   | `status` 探测到 `hub_count >= 1`，测试会话成功返回 `PLANNER_RESPONSE` 并清理            |
| 全局安装与 MCP 注册 | `~/.agents/skills/verdantflare-agent-antigravity` 哈希一致，Claude/Codex 配置写入且合法 |

任一静态检查存在 error、断链或本机路径泄露，或 `StartCascade` 报 HTTP 400/500、残留测试脏会话、破坏原有配置项时，均判定为不通过（Fail）。未在实际打开的外部智能体新会话中触发调用前，配置文件写入状态记为“已注册并完成协议自检”，与人工跨智能体联调结论分开记录。
