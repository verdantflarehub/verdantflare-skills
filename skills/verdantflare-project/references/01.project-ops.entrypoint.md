# 项目操作、修订提交与恢复（01.project-ops）

## 1. 输入与输出

- **输入**：已绑定工作副本（`.vf/project.json`、`.vf/local.json`）或用户明确指定的 `project_id`、待执行的项目/素材操作（创建、打开、提交修订、素材增删改查、固定资产引用、项目删除/恢复或中断恢复）及相关文本/二进制 `ContentRef`。
- **输出**：经回读核验的固定 `revision_id`、修改摘要、失效选用清单、最新领域文档与文件校验结果；中断或异常时产出保留 `commit_id`/`change_id` 与本地状态的可恢复记录。
- **公共依据**：[MCP 授权与工作副本规范](./00.common.rules.md)。

## 2. 分类

按项目生命周期与变更性质选择执行路径：

- **项目创建与打开**：新建项目（`project.create`）或按固定基线修订打开项目（`project.open`），区分所选 `revision_id` 与当前 `head_revision_id`。
- **修订提交与资产引用**：基于 `expected_revision_id` 与稳定 `commit_id` 执行最小 `changes` 或 `manifest` 提交，或经 `project.use_asset` 绑定固定资产版本。
- **创作中的素材增删改查**：在已绑定创作项目中同步新增、修改、查询或明确删除候选素材，保持领域文档、文件索引、选用关系与 MD 展示一致。
- **中断对账与冲突合并**：处理超时（`project.commit_status` / `workspace resume`）、大文件回读超时与 `expected_revision_id` 基线冲突。
- **项目生命周期管理**：仅项目所有者在用户明确要求时执行的 `project.delete`、`project.restore` 与 `project.lifecycle_status`。

## 3. 工作流

### 3.1 定位、打开与基线固定

1. 优先通过宿主中央 Studio `/mcp` 调用；无宿主工具时使用 `studio-workspace call --input request.json`（形如 `{"name":"project.list","arguments":{}}`），参数按在线 `tools/list` 填入。
2. 先读取当前目录 `.vf/project.json` 与 `.vf/local.json` 核对绑定；已有绑定沿用该项目，无绑定时沿用用户明确项目或用 `project.list` 定位（存在无法区分的多个候选才询问）；仅任务确需新项目时调 `project.create`（需 `commit_id`、`name`、`category`、`entry_path`、`entry_text`，入口为 MD/TXT，项目及修订 ID 由服务分配）。
3. 用 `project.open` 固定基线修订，区分 `revision_id` 与 `head_revision_id`，按需取文件并保护本地未提交修改（未下载的文件不是删除指令）。

### 3.2 提交修订与固定资产引用

1. 明确本次修改的文本、文件、选用与任务引用：小文本可直接 upsert（真实 `path`、`role`、`mime`、`text`），二进制先经 `verdantflare-artifact` 获得完整 `ContentRef`；更新同路径既有文件须传当前清单 `file_id`（缺失视为新增，可能因路径重复被拒，不用新路径逃避更新）；改路径保留已有 `file_id`。
2. 发送前持久保存不含凭据的原请求与稳定小写 UUIDv7 `commit_id`，传 `project_id`、`expected_revision_id`、`commit_id` 及 `changes` 或 `manifest`（二者不同时传，优先最小 `changes`），将正文、关联 JSON 与相关选用在同一次提交更新。
3. 固定资产引用按实际请求调用 `project.use_asset`（传 `asset_id`、`asset_version_id`、`purpose`、项目基线与 `commit_id`）；Blender 实例 `project.save` 已在服务内完成上传与项目提交，客户端只回读不重复提交同一检查点。
4. 回读返回的固定修订，核对修改文件、失效选用及实际内容；若涉及“只有名称、内容不显示、位置不对”或视频阶段交付，按[页面展示关联与审阅](./02.display-binding.entrypoint.md)核验消费字段。

### 3.3 创作中的素材增删改查

普通创作指令已包含完成任务所需的项目同步（仅用户明确仅本地、只讨论或暂不上传时跳过远端写入），先打开最新项目定位领域对象与真实 `file_id`，已有上下文能确定的信息不索要技术 ID 或额外提示词：

- **新增**：经 Artifact 保存明确输入或生成成果，提交文件索引并更新同一角色的参考、结果或附件字段（仅文件清单新增不足以证明角色页归位）。
- **修改**：基于最新领域文档更新目标字段或当前图片引用，同步本地当前展示与说明；保留无关字段与本地修改，不用过时全文覆盖。
- **查询**：读取最新领域对象和固定文件引用，核对实际内容，必要时下载并直接展示；仅查询不提交 Project、不新建生成任务。
- **删除**：用户明确指定候选时，删除该候选的当前领域项及专属引用，按在线 Schema 的文件移除操作清理不再需要且未被其他对象引用的文件索引，同步更新 MD 当前展示防断链；共享引用仍有消费者时保留文件；目标不唯一时只澄清目标，不再确认是否同步。

### 3.4 中断恢复、冲突合并与生命周期操作

1. **提交超时恢复**：先查原 `project.commit_status`（原 `project_id` 与 `commit_id`），工作副本用 `resume`；`preparing` 继续等待，`committed` 回读原结果，`conflict`/`failed` 保留原草稿与错误；新建响应完全丢失且 `project_id` 未知时重发原 `project.create` 请求找回结果。
2. **大文件回读超时**：提交已取得固定 `revision_id` 但大文件回读超时时，保留“提交成功”与“回读未完成”双状态，从原修订与 `ContentRef` 继续核验并复用已核验摘要，不重新上传或重提整批文件；先让用户取得已完成的本地交付。
3. **基线冲突处理**：读取最新 `current head`，互不重叠的变更自行合并；工作副本项目规则声明了权威源（如以本地为准）时按其合并并在交付说明覆盖内容，无声明且创作含义真冲突才向用户提问；合并后新建 `commit_id` 提交，不复用旧 ID 改输入（避免 `IDEMPOTENCY_CONFLICT`）。
4. **项目删除与恢复**：仅所有者在用户明确要求时发现 `project.delete`、`project.restore`、`project.lifecycle_status` 在线 Schema，以最新 `head`、`lifecycle_version` 与持久保存的稳定 `change_id` 执行；删除后内容不可打开或编辑，修订与共享素材保留；恢复通过 `project.list(deleted=true)` 定位，沿用同一项目 ID 与 `head`；响应未知先查 `project.lifecycle_status`（`NOT_FOUND` 只重试原请求，`PROJECT_BUSY` 待原操作结束后重试，冲突须刷新并重新确认目标）。

## 4. 规范

- **Schema 与路径约束**：不把 JSON-RPC `id`、`request_id` 或自报组织塞入拒绝未知字段的业务 Schema；逻辑路径为相对路径、使用 `/`，禁止 `..`、绝对路径或保留 `.vf`；字段缺失表示不修改，空集合可能表示清空，不作默认填充；原生任务保留原 `service_id`/`run_id`，不为平台 UUID 改写。
- **AI 短剧与媒体交接红线**：短剧素材须维护 `project-content` 的所属对象、剧情状态、制作版本及固定 `file_refs`（人物身份与关联 Look 分开、返修留同一状态历史、原稿用对应章节或有来源分项摘录、多人拼图不充当每人参考）；仅添加 Manifest 文件只能报告“已归档，素材关联待完成”。媒体交接固定所读修订、目标镜头/制作版本与原运行，保存准备依据的新修订与来源修订分开，在途任务不随最新 head 换输入；只由承担关联的调用方恢复原 commit，页面与助手不竞争写；结果已保存但关联失败时只补关联，同一内容不同生成保留各自 `run_ref`；候选、当前选用与用户批准分别核对，不把最新输出自动升为身份或场景基线。
- **防覆盖与防越界红线**：读取失败、服务不可用或工具发现失败不得作为新建项目或更换绑定的理由；禁止扫描整目录替用户选成果；禁止将旧全文直接套到最新基线强制覆盖；本地有改动或待恢复操作时不切基线；跨电脑只恢复已提交内容，原生生成任务按 `service_id`/`run_id` 查询，下载成功不代表 Blender 已加载工程；删除授权仅限指定项目，不从本地缺失推导删除，不用项目删除代替素材删除，不物理删除 Artifact 或 World 内容；`project.use_asset` 不授予来源项目权限、不自动发布 World、不默认升级版本或改成员；网络暂不可用保留恢复记录并在任务时限内有限重试，不以再次生成替代恢复。

## 5. 验收

- 所有 MCP 调用已检查 `structuredContent` 或工具规定结果、JSON-RPC `error`、`isError` 与业务状态，不以 HTTP 200 为成功判据。
- 普通同步已通过 MCP 回读最新固定修订与页面消费的领域文档，确认新增可读、修改一致、删除无残留引用且无关内容不变，必要时经 Artifact 下载并完整解码核对大小与 SHA-256（无需打开浏览器或把技术验收交给用户；明确前端修复/页面验收任务另按宿主规范做真实页面检查）。
- 仅本地保存或上传完成不报告项目已归档，MCP 回读核验未完成不声称已同步；任务记录包含项目、固定修订、修改摘要、失效选用与验证证据，未完成时明确本地与线上状态、保留位置及恢复入口。
