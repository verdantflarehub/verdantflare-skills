## 2. MCP Token 授权与媒体执行边界

- **调用权限**：有效 MCP Bearer Token 即调用授权，Studio 将其解析为真实用户和组织，按该用户已有业务权限执行。客户端不提交用户映射、不再次登录、不输入密码，不增加独立审批令牌或生成批准清单；失效 Token、伪造身份和业务越权由服务端拒绝。先发现当前工具并确认能力及参数，工具可见不代表有项目写权限。
- **媒体执行**：按用户当前任务及已有选择使用实际工具目录中的 Image、Video、Music 等媒体入口；项目类别、制作准备记录或作品选用状态不增加 MCP 调用审批。沿用真实 `project_id`、固定参考、模型渠道和任务参数；用户明确的范围、次数或费用限制继续有效，未提供的额度不能自行设为零来阻断任务。
- **恢复与保存分离**：响应未知时沿原任务 ID 和幂等键查询，不重复提交生成，不自行切换模型渠道。完成后按 Project/Artifact 契约保存候选、来源、修改记录和固定版本；调用授权、候选选用及 World 发布是各自独立的业务动作，生成成功不自动修改选用或发布作品。

## 3. `studio-workspace` 客户端与配置

- **版本与获取**：复用 Studio 发布的 `studio-workspace`（已核对 0.5.50 支持 `tools`，来源为 Studio release CI 的 `studio-v0.5.50-workspace-windows-amd64` 或 `studio-v0.5.50-workspace-linux-amd64` 产物），执行前用 `--version`、`--help` 确认现有二进制。缺客户端时先用宿主 MCP 处理不依赖本地工作副本的任务，不自动安装软件或改全局配置。
- **凭据与安全**：进程环境提供 `STUDIO_MCP_URL`、`STUDIO_MCP_BEARER_TOKEN`，只使用 HTTPS 或本机 loopback HTTP；不要求 Cookie 或 CLI 登录，不把 Bearer 放入参数、JSON、`.vf` 或输出；配置文件作为数据解析，不通过 shell 执行，子进程输入输出显式使用 UTF-8。

## 4. 本地工作副本操作规范

### 4.1 绑定核对与打开取文件

当前目录已有 `.vf/project.json` 与 `.vf/local.json` 时，先只读核对其 `project_id`、`connection_alias` 与 `base_revision_id`，再用原绑定检查服务最新状态；不根据目录名、旧示例或同名搜索结果替换它，两者不一致时保留原状并核实，服务失败不重建绑定、不新建替代项目，不手写、上传或复制 `.vf/*` 充当服务数据库。

本地目录需先存在，显式传入服务 `project_id`、用户选定目录与连接别名（别名只标识连接，不替代项目或存储 ID）：

```text
studio-workspace tools
studio-workspace open --dir <dir> --alias <alias> --project-id <project-id>
studio-workspace status --dir <dir> --alias <alias> --project-id <project-id>
studio-workspace fetch --dir <dir> --alias <alias> --project-id <project-id> --file-id <file-id>
```

尖括号内容须替换为真实参数，不能原样调用。`open` 建立服务清单投影，不承诺所有文件已下载；读取特定历史修订直接用 `project.open` 的 `revision_id`，不假定 CLI 存在未出现在 `--help` 中的历史 checkout 参数；`fetch` 默认上限 `1 GiB`，仅任务需要且服务允许时调整 `--max-bytes`。

### 4.2 显式保存与导入

```text
studio-workspace save-texts --dir <dir> --alias <alias> --project-id <project-id> --input texts.json
studio-workspace save-files --dir <dir> --alias <alias> --project-id <project-id> --input files.json
studio-workspace import --dir <dir> --alias <alias> --project-id <project-id> --input imports.json
```

- `texts.json`：用户选定的既有文本 `file_id` 数组。
- `files.json`：对象数组，每项为工作副本相对 `path`、`role`、`mime`；替换已有文件时附 `file_id`。
- `imports.json`：对象数组，每项为 `source_path`、目标相对 `path`、`role`、`mime`；目标已存在时拒绝覆盖。

上述命令会保存内容并提交 Project，不适合“只存 Artifact，暂不加入项目”的请求；原文件保留，来源目录不自动扫描，本地文件缺失不自动生成 remove。

### 4.3 工作副本恢复与基线切换

```text
studio-workspace resume --dir <dir> --alias <alias> --project-id <project-id>
```

中断后先运行 `status`，存在待恢复上传或提交时才运行 `resume` 复用原 journal；无待恢复操作时不把 `resume` 当健康检查，正常保存后用 `status` 与固定修订回读确认结果。本地后续编辑须保留，不能用服务回读内容覆盖它制造成功。`switch-head` 仅在无本地变更和待恢复提交时使用，切换基线后按需 `fetch`；使用 `conflict`/`resolve` 前先核对当前版本帮助与冲突预览，明确合并后再提交，不猜测解决参数。
