# Project 修订与恢复

## 1. 实际调用

通过宿主中央 Studio MCP，或工作副本客户端的 `call`：

```text
studio-workspace call --input request.json
```

请求是 `{"name":"project.list","arguments":{}}` 这样的 MCP 工具调用。
参数按当前 tools/list，不把 JSON-RPC id、request_id 或自报组织额外塞入拒绝未知字段的业务 Schema。
读取 `structuredContent` 或工具规定的结果，检查 JSON-RPC error、isError 和业务状态，HTTP 200 不是成功判据。

## 2. 请求与身份

创建需要 commit_id、name、category、entry_path、entry_text。
入口为 MD/TXT，项目及修订 ID 由服务分配。需要客户端生成的 commit_id/write_id 使用小写 UUIDv7，并在发送前固定。

提交使用 project_id、expected_revision_id、commit_id，以及 changes 或 manifest，二者不同时传。
优先最小 changes；字段缺失表示不修改，空集合可能表示清空，不能作为默认填充。

逻辑路径是相对路径，使用 `/`，不得含 `..`、绝对路径或保留的 `.vf`。
新增文件由服务分配 file_id；改路径保留已有 file_id。替换内容后的选用失效需要显式核对。

## 3. 内容与固定资产

文本 upsert 使用真实 path、role、mime、text；二进制引用使用服务返回的完整 ContentRef。
MD 与关联 JSON、选用在同一次提交保持一致；原生任务保留原 service_id/run_id，不为符合平台 UUID 改写它们。

AI 短剧素材提交还须维护 `project-content` 的所属对象、剧情状态、制作版本及固定 `file_refs`。人物身份与关联 Look 分开；每个状态的返修保留在同一状态历史中；原稿依据使用对应章节或有来源的分项摘录。多人拼图不能批量充当每个人物参考。仅添加 Manifest 文件时只能报告“已归档，素材关联待完成”；回读逐项验证分类、对象、状态、版本及实际输出后才报告素材已同步。

`project.use_asset` 需要明确 asset_id、asset_version_id、purpose、项目基线和 commit_id。
它引用固定版本，不授予来源项目权限，也不执行 World 发布或默认升级版本。

## 4. 结果未知与冲突

`project.commit_status` 使用原 project_id 和 commit_id。
preparing 仍在准备；committed 回读原结果；conflict/failed 保留原草稿和错误，不伪装成功。
新建响应完全丢失时，project_id 尚未知，重发原 project.create 请求找回结果。

提交已取得固定revision而大文件回读超时时，保留提交成功与回读未完成两个状态；从原修订和ContentRef继续核验，已核验文件复用摘要结果，不重新上传或commit整批文件。先让用户取得已完成的本地交付，不能因远端回读慢把成片说成尚未生成，也不能把已提交说成全部回读通过。

同 ID 同请求才能幂等；相同 ID 换输入会发生 IDEMPOTENCY_CONFLICT。
修订冲突读取 current head，明确合并后新建 commit_id，不修改旧请求并复用旧 ID。
网络暂不可用保留恢复记录，不无限重试；轮询需有任务范围内的时间上限。

## 5. 创作中的素材增删改查

普通创作指令已包含完成任务所需的项目同步；只在用户明确仅本地、只讨论或暂不上传时跳过远端写入。开始查询或继续创作时先打开原项目最新状态，定位当前领域对象及真实 file_id，按需读取或下载；已有上下文能确定的内容不索要技术 ID 或额外提示词。

- 新增：把明确输入或生成成果通过 Artifact 保存，提交文件索引，并更新同一角色的参考、结果或附件字段；仅文件清单新增不足以证明角色页归位。
- 修改：基于最新领域文档更新目标字段或当前图片引用，同步本地当前展示及说明。保留与任务无关的字段和本地修改，不用过时全文覆盖。
- 查询：读取最新领域对象和固定文件引用，核对实际内容，必要时下载并直接展示。仅查询不提交 Project、不新建生成任务。
- 删除：用户明确指定候选时，删除该候选的当前领域项及专属引用；按在线 Schema 的文件移除操作清理不再需要且未被其他对象引用的项目文件索引。MD 当前展示也同步更新，不能留下断链。共享引用仍有消费者时保留文件；不调用项目删除代替素材删除，不物理删除 Artifact 字节，不扩大到其他项目或必要任务记录。目标不唯一时只澄清目标，不重复确认同步。

字段更新、文件索引及受影响的选择关系在同次提交保持一致；采用服务实际支持的角色结构，不臆造专用工具。必要的二进制导入先完成，再提交完整业务关联。调用前发现 Schema，调用后回读最新结果，检查新增可读、修改一致、删除无残留引用且无关内容不变。页面核验经 MCP 完成：回读角色页消费的领域文档，确认目标条目存在、文字与本轮一致，图片与参考的 file_id 均在当前修订文件索引中，按需经 Artifact 下载并完整解码，大小与 SHA-256 一致，删除后无残留引用。不打开浏览器，不让用户代查；MCP 不可用时保留未验证状态。现有 MCP 不返回真实渲染结果，前端呈现按消费契约推断。

基线冲突先回读最新内容；互不重叠的变更自行合并。工作副本的项目规则声明了权威源（例如以本地为准）时，同一内容冲突按其处理，不向用户提问，交付时说明覆盖了什么；没有声明时，真正冲突的创作含义才向用户提问。超时先按原 commit_id 对账，未确认成功不报告同步完成。失败时保存原请求和本地成果，有限重试后说明具体阻塞及恢复入口，不以再次生成替代恢复。
