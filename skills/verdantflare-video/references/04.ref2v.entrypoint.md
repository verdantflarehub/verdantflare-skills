# verdantflare-video：多参考与全能参考视频（04.ref2v）

## 1. 输入与输出

- **输入**：同项目原生参考素材（图片/视频/音频 Artifact ID 及唯一 `purpose`；H3 最多 9 图、3 视频、3 音频、总计 `<=12`；Google Flow `veo-fast`/`veo-lite` 最多 3 图、`omni-1.2-flash` 最多 7 图 + 1 段 `>=3s` `.mp4` 原片；Higgsfield `seedance_2_5_draft` 最多 4 图 + 1 视频；角色替换 1 视频 + 1 人物图）、真实 `project_id`、固定 `idempotency_key`、已核实 `route` 与 `model`、Prompt（H3 须按六段式编译）、可选后置 `regenerate_2k` / `interpolate` 及 `title`。
- **输出**：经 `video.preflight` 确认、下载完整解码与 SHA-256 核验、逐秒接触表与动态验收及 K09 分级评估（`video.rate_content`）的视频候选及映射记录。
- **公共依据**：[公共 MCP 契约](00.common.rules.md)、[公共校验与 K09 分级](00.common.acceptance.md)、[提示词编译规范](01.t2v.entrypoint.md)、[渠道差异指南](channels.md)。

## 2. 分类

- **H3 全能参考（Ref2VA，`model=minimax-h3-ref2va`）**：支持本地 5090 路由（默认 `h3-fasth3` 8-NFE、`h3-singularity` 4-NFE）与云端 `route=fal`（服务端锁定 `minimax/h3/reference-to-video`，`480P`、5–15s）。支持多图、多视频与多音频组合参考，音频可作唯一参考。
- **SD2 全能参考与历史恢复**：仅用户指定 SD2 或恢复已有 SD2 任务时使用；Studio 下 fal SD2 当前业务标识为 `bytedance-seedance-2.0-reference-to-video`（仅在 `video.capabilities` 包含该组合时可用）；历史公共 API/S3 协议见[历史 SD2 API 说明](api.md)。
- **Google Flow / Higgsfield 多参考与原片编辑**：Google Flow `veo-fast`/`veo-lite`（最多 3 图）、`omni-1.2-flash`（最多 7 图及 `video_editing` 1 段 `>=3s` `.mp4` 原片 + 最多 7 图）；Higgsfield `wan3_0` R2V 与 `seedance_2_5_draft`（480p、4–15s、最多 4 图 + 1 视频）。
- **角色替换（`video.character_swap`）**：CLI `character-swap`，同项目 1 段源视频 + 1 张目标人物图，独立音频配额 0，复制源片 AAC 音轨。

## 3. 工作流

### 3.1 通用 Ref2V 执行与恢复流程

1. **会话与项目核对**：确认真实 Studio 会话，执行 `python scripts/video_client.py check` 发现 `video.create/status/result/preflight/capabilities` 及宿主默认渠道与适配器限制（不把 `configured` 当就绪）。打开当前 Project 读取已保存 Generation Unit。
2. **素材导入与映射**：本地 `--file` 或中央 `--content-ref-file`（JSON 含 `content_ref` 及访问 `access`，UUIDv7）经 `video_client.py import` 优先走分块协议导入，固定导入键支持断点续传，映射保存在 `mcp-imports/`（不等同已提交项目修订）。
3. **预检与提示词校验**：调用 `video.preflight` 核对参数、参考编号（`reference_mapping`）、输出网格、条件消费帧数（`conditioning_frames`）与报价；`can_submit=false` 保留原因并停止。新建 H3 任务必须运行 `python scripts/validate_h3_prompt.py request.json preflight.json` 并固定不可变 `attempt_id`、幂等键与请求。
4. **提交与轮询**：将 Attempt 置为 `submitting` 后调用创建工具并立即保存原始 `task_id`。未收到明确结果记 `submission_unknown` 并按原幂等键/任务 ID 对账（`retryable=true` 不授权再次 create）；`queued`/`running` 继续轮询（含本地 GPU `waiting_gpu_lease`）；开启 2K/插帧时等待 `delivery.status` 终态。
5. **下载、K09 分级、归档与重试**：使用 `video_client.py result <task_id> --output <out.mp4>` 下载（含 `delivery` 时自动下 `delivery.final_artifact_id`，`delivery.status=failed` 拒绝写出并提示对保留的 `M2`/`M1` 重试）。完成解码、SHA-256、接触表与 K09 本机临时抽帧和 `video.rate_content` 提交后，将 `general` 产物归档至 Project。下载故障只重取；Prompt/引用/规格变更建新单元版本，不复用旧幂等键。

### 3.2 `scripts/video_client.py` 命令边界（需 Python 3.10+）

运行前确认 Python `>=3.10`（系统默认低于 3.10 时显式调用 `python3.10`）：

```sh
python scripts/video_client.py check
python scripts/video_client.py import --project-id <项目ID> --content-ref-file reference.json --filename reference.png --sha256 <固定摘要>
python scripts/video_client.py generate --project-id <项目ID> --idempotency-key unit_v1/attempt_01 --route <已核实渠道> --prompt "<已保存提示词>" --duration 15 --ratio 16:9 --image-ref <Video原生ID>=identity
python scripts/video_client.py regenerate-2k --project-id <项目ID> --idempotency-key rk_01 --source-artifact-id <M1_ID> --grid-mode budget_1440p --interpolate
python scripts/video_client.py result <原任务ID> --output <目标.mp4>
```

- `generate`：显式 `--model`/`--route`/`--mode`/`--resolution`/`--ratio`/`--duration`、`--image-ref`/`--video-ref`/`--audio-ref ARTIFACT_ID=PURPOSE`、`--title`、`--budget-limit`、`--channel-account-id`（Higgsfield 另用 `--price-ceiling` 表示 Credits 上限）；本地 H3 支持 `--quality-profile`、`--regenerate-2k`、`--grid-mode {budget_1440p,exact_2x}`、`--interpolate`。
- `status` / `result` / `resume`：查询、下载或恢复原任务；`resume` 识别 MCP/旧 SD2 记录，不改原渠道，后置失败时附 `recovery_guidance`。`list` / `recover` 仅用于历史 SD2 查询恢复。
- `character-swap`：传源视频、角色图 ID、提示词、固定种子及可选 `--preflight-only`。

### 3.3 SD2 当前入口与历史兼容恢复

- 新 SD2 任务通过 Studio 统一 Video MCP 经动态能力匹配进入（fal SD2 标识 `bytedance-seedance-2.0-reference-to-video`，显式传已授权 `--budget-limit` 与可选 `--channel-account-id`，`verdantflare-sd2` 仅宿主明确注册时可用）；宿主未声明 SD2 接入时报告能力缺口，不退回历史公共 `/v1/videos` 或 S3 上传脚本，也不因缺旧变量运行 `install-config-macos.sh` / `install-config-windows.ps1`。
- 历史 SD2 任务恢复沿原模型、渠道、Task ID 与提交 ID，保留 `PREPARED`、`SENDING`、`CONFIRMED`（仅此状态有已确认 Task ID）、`REJECTED`、`UNKNOWN`（不等于失败，不可重 POST）及 `queued`/`in_progress`/`completed`/`failed`/`failure` 语义；不输出供应商 ID、S3 对象键、签名 URL 或凭据。

## 4. 规范

- **参考素材分工与去冲突**：
  - 动作参考视频可短于目标时长，注明参考动作或节奏，不静默循环、变速或拉长；头肩身份卡只定脸，全身造型加全身卡；参考冲突时减少输入或建新版本，不堆更多参考掩盖冲突。
  - **带脸服装卡冲突处理**：服装卡带脸须与唯一身份参考并看；若产生身份竞争且该图只负责服装，可保留原卡并派生去脸服装参考，确认领口/袖口/衣层/鞋未裁掉后绑定新摘要。
  - **越障等方向混淆处理**：先对照动作参考与目标首帧机位、支撑脚与起态，优先换用同侧且支撑点接近的动作参考，不靠堆叠“左/右”否定词解决。
- **静音与音频条件边界**：纯画面或后期叠旁白镜头不为静音默认加入时序音频条件；允许无音频参考时可省略并在剪辑弃用原生声音；已有对白/口型任务不得删已批准音轨绕错；运行时音频潜变量形状错误须保留具体错误与采样数另修，不裁对白强过。
- **天龙 L5 对比试验**：同一组素材、提示词与固定种子运行 V1.5/V1 与两款 Turbo 四组合时，每版用独立幂等键，中断沿原任务 ID 恢复。
- **fal 边界**：`route=fal` 仅调 `minimax/h3/reference-to-video`（`480P`、5–15s、最多 12 文件），关闭 Prompt Expansion，不传 fal endpoint/API Key/LoRA。

## 5. 验收

- 汇报分别标明代码/Git 完成、素材接入、任务 ID 与状态、结果下载校验及人工批准；仅参考图完成不写“视频制作完成”。
- 按[公共验收](00.common.acceptance.md)完成解码、SHA-256、逐秒接触表、1 倍速动态验收、2K/插帧三产物核验及 K09 `video.rate_content` 提交；剧情与选段另按[叙事动作与选段验收](shot-acceptance.md)核对。
- 新制作批次不恢复用户已停止的旧任务，旧请求与摘要保持不可变。
