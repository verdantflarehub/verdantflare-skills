# H3 输入与媒体校验

本页的数量和规格描述现有 H3 适配器；实际提交还须符合当前网关与所选渠道的能力。工具注册不代表渠道已就绪，Provider 能力也不等于宿主已接入能力。声明不一致时先核实，不绕过校验试投任务。

## 输入

- `project_id` 必须来自当前项目上下文，且所有引用 Artifact 都属于该项目；
- 使用 World 输入时，Project 必须同时记录固定的 `asset_id + asset_version_id`；解析出的每个文件必须来自该资产版本的授权集合；
- `model` 必须为 `minimax-h3-ref2va`；
- `route` 必须显式传入，并且存在于宿主 MCP 当前能力声明中；
- `duration_seconds` 和 `aspect_ratio` 必须满足所选渠道的已批准契约；
- 图片不超过 9 张；
- 视频不超过 3 段，视频参考总时长不超过 15 秒；
- 音频不超过 3 段，音频参考总时长不超过 15 秒；
- 每个引用包含 Video 可读的原生 Artifact ID 和用途，不接受裸文件路径；中央 `ContentRef` 或 Image 原生 ID 先经受控适配，并保存来源、摘要与目标引用的映射；
- Prompt 非空，并能将编号媒体引用对应到实际列表顺序；
- 当前 Generation Unit 的 Master 片段不得越过其声明时码。

`route=fal` 还必须满足：

- 时长为 5–15 秒；画幅为 `adaptive`、`21:9`、`16:9`、`4:3`、`1:1`、`3:4` 或 `9:16`；
- 输出分辨率由 Video MCP 固定为 `480P`，请求中不传分辨率字段；
- 图片、视频和音频总计不超过 12 个，且至少存在一种参考；音频可以作为唯一参考；
- 每段视频和音频为 2–15 秒，视频总时长与音频总时长分别不超过 15 秒；
- 不传 fal endpoint、URL/Base64、供应商 request ID、结果 URL 或 API Key；只传项目 Artifact ID。

Singularity du-0 接受至少一种参考，包括音频单参考；总文件最多 12，单类最多 9 图／3 视频／3 独立音频。音频单参考要求显式画幅，adaptive 必须有视觉参考。其他渠道根据实时能力检查，不从本路线推断支持。

分块导入支持 PNG/JPEG/WebP、MP4/H.264/H.265、WAV/PCM、MP3；单文件最多 1 GiB、单块最多 512 KiB。图片最多 16 Mi 像素，视频最多 4096×2160 像素积、120 FPS、十亿解码像素预算；声音为单声道或双声道。每段音视频 2–15 秒、视频与独立音频分别总计最多 15 秒，完整解码后发布输入。限制属于当前适配实现，不能写成模型本身限制。

参考视频按实际时间戳转换 24 FPS；固定上游节点会向下取参考帧桶，配对声音使用相同区间。预检记录 resampled_frames、conditioning_frames 和 conditioning_duration_seconds，不把源文件时长当实际参与条件的时长。

任何限制失败都停在提交前，不裁切、丢弃或重排参考素材来暗中修复请求。

## 人物参考选择

- 干净的单人头肩身份卡适合作为面部 Identity Anchor，优先用于特写、车内近景和办公桌前中近景；
- 头肩身份卡主要定义脸；需要锁定全身比例和服装时优先增加当前造型全身卡；
- 驾驶、奔跑和复杂表演可增加动作或姿态参考，提高控制程度；图片加文字也是合法输入，不强制动作视频；
- 带文字、边框和装饰 UI 的社交人物卡不得作为生产参考；
- 多视图合成图中任何一格存在身份或身体比例错误时，不得把整张图作为 H3 唯一人物参考；
- 每个 Generation Unit 只选择当前镜头需要的身份、造型、场景和动作输入，不混入其他服装或无关场景。

## 输出

Singularity 先由预检解析原生空间网格与向上 17k+5 帧桶，记录请求与实际规格。本案 Mengsk 已选择上游常用网格：请求 16:9／15 秒，实际 1344×768（7:4）、362 帧、24 FPS、视频流约 15.083333 秒；不裁切、补帧或变速。这不是所有项目默认接受偏差的授权。结果精确核对尺寸、帧数、帧率、SHA-256、H.264 与双声道 AAC，并完整解码；视频流时长容差一帧，音轨尾差最多 0.1 秒，记录实际封装时长。

结果至少检查：

- 文件可完整下载并解码；
- 记录实际编码与帧率；项目要求 H.264 / 24 FPS 时逐项核验，不从请求参数推断输出已达标；
- 实际时长与请求时长在批准容差内；
- 宽高与画幅方向一致，不是零尺寸；
- 不含全程黑帧、空文件或无法读取的尾部；
- 若存在音频，应记录编码、采样率和声道，但不将它登记为最终 Master；
- Artifact 摘要、字节数和媒体探测结果完整；
- 首帧、关键帧和尾帧均能解码并登记为 Artifact。

## 动态有效性

媒体契约通过只证明文件可用，不证明它是合格视频。人物动作或移动摄影候选还必须：

- 以约 1 秒间隔生成覆盖全时长的接触表，并以 1 倍速完整播放，不能只看首、中、尾三帧；
- 核对 Prompt 中每个可观察动作是否真实发生，包括足部触地、身体位移、背景视差、物体交互和相机轨迹；
- 拒绝用数码推近、拉远、轻微摆臂或表情渐变冒充行走、奔跑、驾驶、转身或越过镜头；
- 拒绝无导演依据的景别跳变、主体尺寸突变、居中吸附、姿势保持、照片溶解和循环抖动；
- 对行走和奔跑至少观察两个完整步态周期，确认对侧摆臂、左右脚交替、重心转移和相对地面的连续位移；
- 将动态结论和接触表路径写入 Candidate。动态失败属于创作失败，即使编码、时长和三张抽帧均通过也不能标为可审核推荐。

历史成都技术冒烟记录为 768x1344、H.264、24 FPS、AAC 32 kHz 双声道。该记录不代表当前所有渠道和画幅的固定输出规格，也不是 MV 画面质量验收标准。
