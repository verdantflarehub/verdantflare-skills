# verdantflare-video：公共 MCP 契约与交付规则（00.common.rules）

本专册汇集 Studio Video MCP 工具发现、动态渠道解析、分块素材导入、本地 5090 加速档位与 GPU 调度、2K IC 重生成与插帧交付、角色替换以及任务 Title 契约。认证与旧共享令牌排查见[环境说明](https://github.com/verdantflarehub/verdantflare-skills/blob/verdantflare-video-v0.4.0/skills/ENVIRONMENT.md)。

## 1. 工具发现、创建与渠道解析

- **工具发现**：现有网关注册 `video.create`、`video.status`、`video.result`、`video.rate_content`、`video.capabilities`、`video.preflight`、`video.import_prepare/import_chunk/import_status/import_commit`（及兼容 `video.import`）、`video.regenerate_2k`、`video.interpolate`、`video.character_swap`。历史 `video.generate` 仅在宿主实际注册时使用；`artifact.import` 属中央 Artifact 域，不可作 Video 导入入口。
- **创建必填上下文**：每次创建显式提供真实 `project_id`（UUIDv7）、固定 `idempotency_key` 与已解析的 `route`。业务模型 `minimax-h3-ref2va` 与推理渠道分开，不把 `h3-vdn`/`h3-sol`/`h3-singularity` 填成模型。
- **能力核验与预检**：通过 `video.capabilities` 精确匹配 `route + model`（含 `models[]` 别名）`+ mode`，同时核对 `parameter_schema`、`reference_limits`（含 `by_mode`、`minimum_total`、`total`、`required_media_any_of`）与 `defaults.by_mode`。已注册 `video.preflight` 时在创建前调用（同参数但不含 `idempotency_key`），`can_submit=false` 必须停止。`configured=true` 不等于 GPU 就绪，`readiness=not_checked` 不承诺推理成功。
- **渠道解析原则**：用户指定模型/渠道时保留选择，不可用时不静默切换；未指定时解析宿主明确配置，不将历史 `h3-vdn`/`h3-sol` 或 Schema 中的 `fal` 当全局默认。fal 适配器端点、凭据与供应商 ID 归服务端，Skill 不读取或发送 `FAL_KEY`。面向用户展示注册记录显示名，CLI `--model` 传技术标识。已有任务按原模型、渠道与任务 ID 恢复。
- **画幅规格与适配缺口**：H3 模型规格支持 `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`（Omni 另含 `Auto`）；若 `routes[].aspect_ratios`（`limit_scope=adapter`）受限（如仅 `9:16`），如实记录“本地多画幅适配缺口”，不改写模型规格或降低目标。

## 2. 素材引用转换与分块导入

中央 `ContentRef`（`store_id + artifact_id + version_id`）与 Video 原生 Artifact ID 不可直接互换；World 输入先解析已授权固定 `asset_id + asset_version_id`。

- **分块导入协议**（单文件最多 1 GiB，每块最多 512 KiB，不接受任意下载 URL）：
  - `video.import_prepare`：传 `project_id`、固定 `idempotency_key`、`filename`、`size`、`sha256`、`purpose`（可选 `source_content_ref` 标注 `caller_supplied`，不作授权证明），返回 `import_id`、`offset`、`chunk_max_bytes`。
  - `video.import_chunk`：按 `offset` 逐片传 `content_base64` 与分块 `sha256`；重复块仅字节一致时接受。
  - `video.import_status`：查询已确认偏移，中断后复用原键续传。
  - `video.import_commit`：整文件大小、摘要、媒体格式与完整解码通过后发布 Video Artifact。
- 兼容 `video.import` 内联字节仍限 3 MiB PNG/JPEG/WebP，非完整 Omni 导入方案。中央 `artifact.read(mode=download)` 需带同源鉴权，下载 403、摘要不符或超限禁止导入。

## 3. 状态、结果、归档与角色替换

- **状态与恢复**：创建成功立即保存原始 `task_id` / `video_task_id`（不改写为 UUID）。状态含 `queued`、`running`、`succeeded`、`failed`、`cancelled`；未收到明确响应记 `submission_unknown` 并按原幂等键/任务 ID 对账，不换键重放或切换渠道；失败信息脱敏落盘。
- **受控下载与归档**：只对成功任务调 `video.result`。中央结果沿固定 `content_ref` 经 `artifact.read` 下载；原生结果经同一 Studio origin 的精确 `/artifacts/<artifact_id>/content` 路径鉴权读取，拒绝重定向与任意 URL，核对 MIME、大小、SHA-256 与完整解码。取得产物后先完成[K09 内容分级评估](00.common.acceptance.md#5-生成后内容分级评估步骤k09-强制步骤)，仅 `general` 产物归档当前 Project（无原生输出适配时经工作副本显式导入为 `user_import`，不伪造 `task_output`；MD 作普通文件，`domain_documents` 仅存领域 JSON）。
- **角色替换（`video.character_swap`）**：CLI `character-swap` 传入同项目 1 段源视频 `source_artifact_id`、1 张目标人物图 `character_image_artifact_id`、提示词与固定种子（独立音频配额 0，源片 AAC 音轨随输出复制）；`--preflight-only` 读取参数与引擎就绪状态，提交后按返回任务 ID 查询。

## 4. 本地 5090 路由、GPU 调度与 2K/插帧交付

- **基础模型独立路由**：默认 `route=h3-fasth3`（`video-minimax-h3-fasth3`）固定唯一档位 `quality_profile=fasth3-nvfp4`（8-NFE QAD，无 `du-0` 回退）；冷备 `route=h3-singularity`（`video-minimax-h3-singularity`，默认 `replicas: 0`）固定唯一档位 `quality_profile=du-0`（4-NFE）。省略 `quality_profile` 自动匹配路由唯一档位，跨路由混传返回 `quality_profile_not_available`。
- **本地 GPU 调度**：本地推理路由（`h3-fasth3`、`h3-singularity`、`regenerate_2k`、`interpolate` 及本地超分/深度阶段）由服务端经 Station GPU 调度器（`:5056`）统一申请显存租约、按需冷启动（`0 -> 1`）并在 `P2 -> P3` 原地降级显存锁。严禁智能体手动关停 ComfyUI 或 Blender 腾挪显存；状态返回 `queued`（含 `waiting_gpu_lease` 或 `queue_reason`）属正常等待，继续轮询原 `task_id`，严禁取消重建或静默切往付费云渠道。
- **后置 2K IC 重生成与 48 FPS 插帧**：先核对 `video.capabilities.postprocess.regenerate_2k` 与 `interpolate` 的 `configured=true` 及 `readiness=ready`。生成集成支持 `h3-fasth3` / `h3-singularity` 自由组合 `postprocess.regenerate_2k`（`open_h3_2k_ic`，`grid_mode` 默认 `budget_1440p` 可选 `exact_2x`）与 `postprocess.interpolate`（`rife_2x`）；CLI 为 `generate --regenerate-2k [--grid-mode {budget_1440p,exact_2x}] [--interpolate]`（未开 `--regenerate-2k` 单独传 `--grid-mode` 本地拒绝）。也支持对已有 24 FPS H3 视频独立调用 `video.regenerate_2k`（CLI `regenerate-2k`，`budget_1440p` 各画幅 `<=3,686,400 px` 如 `2464×1408`/`1408×2464`/`2560×1120`，`exact_2x` 严格 2 倍如 `2688×1536`/`3072×1344`，省略 `prompt` 继承父任务提示词）与 `video.interpolate`（`backend=rife`，默认 `target_fps_num=48,target_fps_den=1`，30 FPS 源显式传 `60/1`，仅接受源帧率 2 倍且 `<=120 FPS`、最大边 `3072 px`）。
- **后置交付与精准重试**：开启后置阶段时等待 `delivery.status=succeeded` 后下载 `delivery.final_artifact_id`，同时完整保留 `M1`（`source_artifact_id`）与 `M2`（`regenerate_2k_artifact_id`）。`delivery.status=failed` 时 `final_artifact_id` 严格为 `null`（绝不拿 24 FPS `M2` 冒充 48 FPS 成片）：`stage=interpolation` 失败只对保留的 `M2` 用新幂等键调 `video.interpolate` 重试，`stage=regenerate_2k` 失败只对 `M1` 调 `video.regenerate_2k` 重试，**严禁重跑已成功的 `P1` 生成**。

## 5. 任务 Title 契约

创建前沿用用户名称或从创作上下文生成简洁中文 Title（建议 8–16 字，单行 1–64 字），允许同名。仅在真实发现 create `inputSchema` 的 `properties` 含 `title` 时发送（CLI `--title`）；旧宿主不发送未知字段，无法保存时报告 `title_warning`。Title 独立于生成请求、preflight 与幂等摘要，重放不同 Title 返回原任务不隐式改名；改名仅在发现 `video.title_update` 后按 `video_task_id/title/expected_title_revision` 提交，409 冲突先回读最新标题，不重试 create。面向用户展示服务端 Title，技术 ID 保留在结构化 journal 与恢复记录。
