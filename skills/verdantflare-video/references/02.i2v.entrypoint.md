# verdantflare-video：单图生视频与首帧条件工作流（02.i2v）

## 1. 输入与输出

- **输入**：1 张同项目已导入的写实首帧图像 Artifact ID、动作与运镜 Prompt、真实 `project_id`、固定 `idempotency_key`、支持 I2V 或 `image_guidance="first_frame"` 的已核实 `route` 与 `model`、时长及画幅。
- **输出**：沿首帧起幅展开连续动态的视频候选、输入像素适配与预检摘要、解码与动态核验结论及 K09 分级记录。
- **公共依据**：[公共 MCP 契约](00.common.rules.md)、[公共校验与 K09 分级](00.common.acceptance.md)、[渠道差异指南](05.channel-guides.entrypoint.md)。

## 2. 分类

- **适用场景**：上层需要固定开场构图并向后发展动态（I2V / I2VA），包括：
  - **本地 H3 首帧条件（`h3-fasth3` / `h3-singularity`）**：显式传 `image_guidance="first_frame"`，由服务端将 `references.images[0]` 绑定至第 `0` 帧 `PackedLayout` 条件槽位。
  - **Grok 图生视频（`route=grok`）**：`mode=image_to_video`，单张同项目图片 `purpose=first_frame`，省略画幅继承原图。
  - **Google AI Studio（显式 `route=google`） / Higgsfield（支持首帧的模型）**：在对应能力声明支持首帧时传 `--image-ref <Artifact ID>=first_frame`。
- **不适用场景**：
  - `route=google-flow` 当前 `reference_to_video` **不接受** `purpose=first_frame` 或 `purpose=last_frame`（请转[04.ref2v.entrypoint.md](04.ref2v.entrypoint.md)）。
  - `route=fal` H3 适配器仅开放 Ref2VA，不开放 fal I2V，严禁把 Ref2VA 图片冒充首帧。
  - 需要严格起止双帧控制请转[03.fl2v.entrypoint.md](03.fl2v.entrypoint.md)；3D 白模首帧叠写实人物/服装参考试图直接转写实不属于可靠硬锁（须走两步工作流）。

## 3. 工作流

1. **能力核对与两步前置判断**：
   - 先查 `video.capabilities` 确认目标渠道支持 `image_to_video` 或 `image_guidance="first_frame"`。
   - **固定机位写实定妆两步红线**：若原始输入为 3D 白模或异画风参考且要求固定机位写实定妆，必须先在图像阶段产出同构图写实首帧定妆图并完成并看核验（定妆交接保留完整 Look 与实际首帧并看证据，裁去袖口不构成消除袖长冲突），再进入本工作流。
2. **首帧像素网格适配与导入**：
   - 先对照本次 `video.preflight` 的实际输出宽高（不能只按“9:16”名义画幅判断）。
   - 本地 H3 `image_guidance="first_frame"` 要求 `references.images[0]` 分辨率与目标输出像素网格**精确一致**，且不得与 `references.videos` 混用。
   - 需要适配尺寸时保持人物纵横比，记录等比缩放、补边与最终裁区，实际查看后重新导入并绑定新摘要；**严禁直接拉伸脸和身体**。尺寸不符属输入问题，先修输入，不据通用 `invalid_request` 误报模型不支持。
3. **预检与提交**：
   - 核对真实 `image_guidance` 参数与预检回显（普通 `reference` 模式不得因 `purpose` 写有“first-frame anchor”而宣称首帧锁定）。
   - 提交 `video.create` 或 CLI（如 Grok：`generate --route grok ... --image-ref <Artifact ID>=first_frame`；本地 H3 另传 `image_guidance="first_frame"`），保存 `task_id`。
4. **轮询、下载、分级与动态核验**：
   - 等待终态（开启本地 2K/插帧时等 `delivery.status=succeeded`），受控下载并核验解码与 SHA-256。
   - 完成 K09 临时抽帧与 `video.rate_content`，再检查首帧一致性及后续动作真实性。

## 4. 规范

- **本地 H3 `first_frame` 实证控制边界**：端到端核查未发现参数丢失证据，单图静止保持对照实验（第 `0` 帧边缘 `IoU 0.9983`）证明第 `0` 帧条件消费路径有效；但在多参考跨画风下属于软条件引导（`hard_geometry_lock=false`、`conditioning_strength="soft_under_multi_reference_cross_style"`），不保证硬几何透视锁定或逐像素强制覆盖。
- **控制任务隔离**：单图原外观保持与白模转写实、多参考人物替换属不同控制任务，前者通过不能替代后者验收；首帧控制只约束起点，不是图像局部编辑，也不证明后续帧保留场景或服装。
- **混合输入排障**：混合输入失效时先用最小输入检查条件是否有效，再按实际差异缩小问题；一次同时改动多个条件只能用于排查，不能宣称唯一根因；不能靠增加定妆图或否定词弥补未证明的空间控制。
- **静帧退化防线**：I2V 场景须重点防范照片插值、数码推近与姿势保持，在 Prompt 中写清正向运动因果与相机视差。

## 5. 验收

- 核对第 `0` 帧与输入首帧的构图、身份、服装与比例一致，同时核查后续连续帧是否发生未授权换脸、换装、场景漂移或擅自切镜。
- 按[公共验收第 2 节](00.common.acceptance.md#2-输出动态与后置交付验收)完成 1 秒接触表与 1 倍速播放，确认存在真实物理动作与位移，而非静态图微动或数码推拉。
- 核对预检实际 `image_guidance` 回显与输入像素适配记录，并确认 K09 `video.rate_content` 已提交且仅 `general` 产物归档。
