# verdantflare-video：公共校验、控制证据与 K09 分级（00.common.acceptance）

本专册汇集视频输入/输出媒体校验、动态有效性门禁、2K/插帧交付验收、H3 控制项证据等级与 K09 生成后 18+ 内容分级评估步骤；剧情动作、跨镜连续性与剪辑选段细则见[叙事动作与选段验收](shot-acceptance.md)，18+ 判定类别见[18+ 评估规范](content-rating-rubric.md)。

## 1. 输入与媒体预检门禁

- **基础上下文**：`project_id` 来自当前项目且引用同项目原生 Artifact；World 输入记录固定 `asset_id + asset_version_id`；H3 `model=minimax-h3-ref2va`，`route` 显式传入并在 `video.capabilities` 声明；Prompt 非空且编号与列表顺序一致；Master 片段不越声明时码。
- **数量上限**：H3 最多 9 图、3 视频（总时长 `<=15s`）、3 音频（总时长 `<=15s`），本地 H3 与 `route=fal` 总文件最多 12 且至少 1 项参考（可音频单参考，本地音频单参考需显式画幅，`adaptive` 须有视觉参考）；`route=fal` 时长 5–15s、画幅 `adaptive/21:9/16:9/4:3/1:1/3:4/9:16`、分辨率服务端锁定 `480P`（不传分辨率）、音视频每段 2–15s，不传 endpoint/URL/Base64/API Key。
- **全局分块导入解码约束**（PNG/JPEG/WebP、MP4/H.264/H.265、WAV/PCM、MP3）：文件 `1–1,073,741,824 B`（1 GiB），单块 `1–524,288 B`（512 KiB）；图/视频宽高 `>=32 px`；图 `<=16,777,216 px` 单静帧无音频；视频像素积 `<=8,847,360`、`<=120 FPS`、`宽×高×帧率×时长 <= 10^9`；每段音视频 2–15s（封装尾差容差 `<=1 ms`，视频流自身须达标）；音频单/双声道、`<=192,000 Hz` 且无视觉流。
- **帧桶与时序音频陷阱**：参考视频按时间戳转 24 FPS 并向下取帧桶，动作依赖尾部事件时对照预检 `conditioning_frames`（如 17k+5 桶 72 帧可能只消费 56 帧），必要时另存末帧短停派生参考并重预检。本地 H3 `audio_guidance=timeline` 按实际输出帧桶算采样数（如 FastH3 17k+5 24 FPS 请求 4s 解析 107 帧需 48 kHz 214,000 采样帧 ≈ 4.458333s），仅在外部补静音不截字变速；24-bit PCM 若封装为 `WAVE_FORMAT_EXTENSIBLE`（65534）被预检拒绝时仅无损重封装为标准 PCM（1）并核对解码 PCM 摘要。任何限制失败停在提交前，不静默裁切或丢弃参考。
- **人物参考选择**：单人头肩身份卡主定脸，全身造型加全身卡；带文字/边框/UI 的社交卡不可作生产参考；多视图合成板任一格出错不可作唯一人物参考。

## 2. 输出、动态与后置交付验收

- **基础媒体核验**：文件可完整下载解码，核对编码、帧率（要求 H.264 / 24 FPS 时逐项实测）、宽高方向非零、时长在容差内（Singularity 预检原生网格如 16:9/15s 实出 `1344×768`、362 帧、24 FPS、约 15.083333s，视频时长容差 1 帧，音轨尾差 `<=0.1s`）、无全程黑帧或损坏尾、音频编码/采样率/声道记录（不作最终 Master）、SHA-256 与首/关键/尾帧完整可解码。
- **动态有效性门禁**：以约 1 秒间隔生成覆盖全时长的接触表并以 1 倍速完整播放（无法播放时如实记录未验证项）。核对 Prompt 每个可观察动作（触地、位移、视差、交互、相机轨迹）；拒绝数码推拉/摆臂/表情渐变冒充位移、无依据景别跳变、尺寸突变、居中吸附、姿势保持、照片溶解与循环抖动；行走/奔跑至少核对 2 个完整步态周期。动态失败属创作失败，不可标为推荐。
- **2K IC 与 RIFE 插帧验收**：分别核验保留的 `M1`（768p 24 FPS）、`M2`（严格等比 2K 24 FPS：`budget_1440p` 或 `exact_2x`，帧桶与原片 AAC 音轨无损一致）及 `M3`（`2N` 帧 / 48 FPS，2K 宽高与时长不变），逐一校验 SHA-256、字节数与完整解码。独立 RIFE 仅支持 CFR、8-bit SDR、YUV420、方形像素、无旋转、起点零、单视频流、最多一路音轨、正偶数尺寸且最大边 `<=3072 px`、目标严格 2 倍帧率（`<=120 FPS`，不支持 24→60）。对比原片与成片流畅度、嘴/手指/遮挡鬼影及切镜；技术通过仍为候选。
- **Title 验收**：核对列表、详情与报告 Title 一致，同名按原 ID 验源；Title 不证明媒体成功或艺术通过。

## 3. 控制项分类与经验等级

设计或评审 Prompt 时区分四类控制，不混称“模型参数”：

- **硬控制**：模型、时长、画幅、Prompt、引用及官方本地 `task/conditions/target/seed`；只保证请求规格，不保证构图或动作质量，不虚构未暴露的步数/CFG/灯光数值。
- **参考控制**：I2VA 锚首帧、FL2VA 锚首尾、L2VA 锚尾帧；本地 H3 `image_guidance="first_frame"` 单图静止保持有效（边缘 `IoU 0.9983`），但多参考跨画风属软条件（`hard_geometry_lock=false`）；Ref2VA 图片/视频/音频须写明唯一职责与保留策略。
- **Prompt 软控制**：切点、动作、运镜、灯光、声音、对白、身份保留与负面约束；一次聚焦一个主动作链与一个主运镜，可观察状态变化优于抽象风格词，官方语法不保证帧级兑现。
- **非直接控制**：精确剪辑点、歌词字幕、最终歌曲同步、调色与 MV 节奏归上层后期，原生音轨仅作审核。

| 控制维度                       | 经验等级与执行决策                       |
| :----------------------------- | :--------------------------------------- |
| 时长、画幅、分辨率、输入模式   | 高；按接口硬校验                         |
| 首帧/首尾帧锚定                | 中高；使用官方对齐格式，仍须审核中间过程 |
| 简单身份、单一状态链、总体光色 | 中高；可用于生产候选，必须人工审核       |
| 2–3 个内部 Shot（1–2 个切点）  | 中高；可用，切点只作意图而非帧级保证     |
| 单一跟拍/环绕/推拉行为         | 中；完整播放并核对视差与主体尺度         |
| 复杂步态、驾驶物理、多物体交互 | 中；优先等长视频参考，失败即停止批量     |
| 多人物、多造型、密集动作蒙太奇 | 中低；外部拆分，减少每单元职责           |
| 精确文字、数字、歌词字幕       | 低；不在 H3 画面内生成，交给后期         |
| 负面 Prompt 独立纠错           | 低；只作辅助，不能替代正向路径与参考     |

## 4. 短剧交接与通用验收边界

- 接收短剧交接时消费已冻结的实际请求、参考顺序/角色、起末状态、必要事件与配对音轨，不从项目最新候选重建输入；输入未变复用对应证据，新视频只增加动态与声画联合检查。
- 剧情动作、接触动作因果证据、跨景别接动作、删帧/插镜时间基准对齐及局部材质/天气修复细则按[叙事动作与选段验收](shot-acceptance.md)执行。

## 5. 生成后内容分级评估步骤（K09 强制步骤）

取得新生成或插帧视频（`video.result` 下载完成）之后、交付摘要展示与 Project/World 同步之前，必须对照[18+ 评估规范（rubric v1.0）](content-rating-rubric.md)执行评估并调用 `video.rate_content`：

1. **本机临时抽帧（H1 O5 已确认）**：在本机临时目录（如 `.tmp/` 下独立子目录）抽帧，密度**至少每 2 秒 1 帧且全片不少于 8 帧，另补镜头切换处关键帧**；**评估完成后立即删除全部临时帧图片，严禁上传 Artifact、写入 Project 或提交 Git**；在 `reason` 中记录实际抽帧数量。
2. **多模态联合判定**：结合连续帧序列（单帧不露骨但连续动作构成性行为/性化强调按 S2/S4 判）、音轨（无转写能力注明“未转写音频”）、正向 `prompt` 与 `title` 判定；反向提示词不作 `nsfw` 依据；任一项触发即整片判 `nsfw`；无法完整解码抽帧或不确定时遵循**不确定即标 `nsfw`**（O2）。
3. **调用 `video.rate_content`**：先查 `tools/list`，传 `version_id`（Video 原生 `art_*` 或已完成 `video_task_*`，不可传中央 `ContentRef.version_id`）、`rating`（`general` 与 `nsfw` 均须提交）、`reason`（合并后的摘要字符串，含抽帧数与音轨判断）、`rubric_version`（固定取[content-rating-rubric.md](content-rating-rubric.md)文首 `"rubric v1.0"`）及可选 `project_id`。超时或响应未知用相同内容幂等重试，**严禁重新生成或重复扣费**。
4. **交付脱敏与同步阻断（H1 已确认）**：判 `nsfw` 的视频摘要只写“N 个产物已标记为 NSFW 并隐藏”，**严禁展示预览、联系表、下载链接、`ContentRef`、原生 `artifact_id` 或提示词全文**，且**不同步 Studio 项目（不写 `project.commit`）、不登记 World（不调 `world.register`）**。不提供撤销；误标提示用户在 Studio 设置页开启本机“显示 NSFW 内容”开关（24 小时有效）后人工取消。
