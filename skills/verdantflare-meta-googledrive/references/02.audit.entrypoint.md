# 引用审计、摘要核验与冗余清理（02.audit）

## 1. 输入与输出

- **输入**：项目绝对路径、可选的 `--doc` 目标 Markdown 文件或目录、可选的 `--key` 抽检受管文件键，或待移除旧版受管键 `<bucket>/<old-versioned-file>`。
- **输出**：[gdrive.py](../scripts/gdrive.py) 输出的结构化 JSON 报告（`audit` 含 `missing`/`unmanaged`/`git_exempt`/`human_owned`/`references`，`verify` 含 `verified`/`invalid`/`needs_review`，`remove` 含预览或实际删除结果与可选 `.tmp/gdrive-removed/` 副本）。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的引用保护、零冗余与人工目录只读保护规则。

## 2. 分类

`audit` 解析器自动提取 Markdown 图片、普通链接、引用式链接及 HTML `src/href/poster/srcset`（代码围栏内示例链接不算实际引用，扫描不进入软连接目录），按 `owner` 归类：

| 归属分类（`owner`） | 判定条件与合规状态                                                   |
| :------------------ | :------------------------------------------------------------------- |
| `assistant`         | 位于 `.gdrive/managed/`，标记 `managed=true`，保持受管引用           |
| `human`             | 位于 `.gdrive/` 下非 `managed/` 目录，标记 `human_owned`，保留原路径 |
| `git`               | 项目内命中 `git ls-files`，标记 `git_exempt`，豁免入库               |
| `outside`           | 位于 `.tmp/` 或其他未跟踪本地路径，计入 `unmanaged`，须入库改链      |

说明：`.gdrive/output/` 工作产出目录归入 `human`（合规且助手可写，无需入库或改名）；人工目录只读限制仅适用于 `output/`、`managed/` 以外的目录。

动态模板、CSS 内嵌 URL 与非标准 wiki 引用不在自动解析范围内，须先检查原文并人工补充；遇到不明语法不能把零条扫描结果当作没有素材。

## 3. 工作流

### 3.1 引用审计（`audit`）

```powershell
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' audit
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' audit --doc docs/review.md
```

`--doc` 可重复传入相对项目的 Markdown 文件或目录，只审计本次处理范围，退出码只反映该范围。

### 3.2 同步与内容摘要核验（`verify`）

```powershell
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' verify
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' verify --key 'pending/<versioned-file>'
```

跨机同步由 Google Drive 客户端完成，脚本不做复制。`verify` 校验受管文件名中的内容摘要：未传 `--key` 时扫描 `approved/`、`pending/`、`references/` 三个素材目录；流式模式下全量校验会触发下载，大型目录优先传 `--key` 抽检。同一资产的审核与移除由一台电脑顺序执行，其他电脑恢复联网后先 `audit` 再继续维护。

### 3.3 移除被替代旧版（`remove`）

```powershell
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' remove 'pending/<old-versioned-file>'
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' remove 'pending/<old-versioned-file>' --apply
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' remove 'pending/<old-versioned-file>' --apply --keep-tmp
```

默认仅预览，加 `--apply` 才实际删除。脚本先扫描全仓 Markdown（含归档、技能及 `.tmp` 内文档），仍有引用即拒绝；校验摘要无误后删除该文件及其 `receipts/` 回执，删除操作经客户端传播到所有电脑。加 `--keep-tmp` 时先复制到项目 `.tmp/gdrive-removed/` 暂留，不再存入 `.gdrive`。

## 4. 规范

- **云端冲突副本**：Google Drive 客户端生成的冲突副本（如 `copy (1).png`）在 `verify` 中列入 `needs_review`，须人工核对摘要，严禁自动覆盖或删除。
- **跨分支引用确认**：执行 `remove --apply` 前须确认其他 Git 分支没有仍需要该文件的引用，不批量清空云端。
- **挂载缺失保护**：映射盘未挂载导致软连接悬空时，所有命令拒绝执行，不创建伪挂载目录。
- **扫描边界披露**：自动解析不支持的语法与扫描范围须在交付报告中单独说明。

## 5. 验收

- **引用完整性**：`audit` 报告中 `missing == 0` 且 `unmanaged == 0`（退出码 `0`），处理范围内每条实际引用均归属 `assistant`、`human` 或 `git`。
- **内容完整性**：`verify` 报告中 `invalid == []` 且 `needs_review == []`（任一非空以退出码 `1` 拦截）。
- **存储边界**：`remove` 执行前目标 `key` 的全仓 Markdown 引用计数为 `0`，`.gdrive/managed/history` 不存在，且删除后不破坏任何现存文档引用。
