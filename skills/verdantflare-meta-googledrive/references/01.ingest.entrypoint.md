# 素材入库与引用保护（01.ingest）

## 1. 输入与输出

- **输入**：待入库的本地源文件路径、项目绝对路径、`--bucket` 目标分桶、项目内逻辑名称 `--name`、入库原因 `--reason`（`approved` 另需真实 `--reviewer` 与 `--evidence`），以及需改写引用的授权 Markdown 文档。
- **输出**：写入 `.gdrive/managed/<bucket>/<logical-name>--<sha256>.<ext>` 的不可变版本文件、对应 `receipts/` 回执、更新为相对路径的 Markdown 链接，以及局部 `audit --doc` 零违规报告。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的双域分离、零冗余、人工目录保护与 Git 职责边界。

## 2. 分类

### 2.1 适用与排除边界

- **适用**：未跟踪或被 `.gitignore` 排除的本地图片、视频、生产与设计素材，凡被任意 Markdown 引用或经用户显式指定跨机复用，均须入库。
- **排除**：已被 `git ls-files` 跟踪的文件豁免入库；外部 `http/https` URL 不自动下载；源码及纯配置文本链接不当作大型素材；未被任何 Markdown 引用且未显式指定跨机复用的临时过程产物仅留项目 `.tmp/`；本技能不生成素材也不代替人工审美裁决。

### 2.2 入库分桶（`bucket`）判据

按实际 Markdown 引用语境、用户指令与审核记录确定分桶，严禁根据文件名、清晰度或模型打分推断人工通过：

| 分桶（`bucket`） | 适用场景与必填参数                                                                  |
| :--------------- | :---------------------------------------------------------------------------------- |
| `pending`        | 最新生成、待审或普通文档引用的过程/成品素材；传 `--bucket pending` 与 `--reason`    |
| `approved`       | 有真实人工审核通过记录的定稿；传 `--bucket approved --reviewer --evidence`          |
| `references`     | 上游作者原图/原片、输入参考帧与设计参考素材；传 `--bucket references` 与 `--reason` |

## 3. 工作流

`--project` 参数位于子命令之前，使用项目绝对路径：

```powershell
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' put '<source-file>' --bucket pending --name shots/scene-01.png --reason markdown-reference
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' put '<approved-file>' --bucket approved --name delivery/poster.png --reviewer '<reviewer>' --evidence '<review-record>'
```

1. **前置审计**：先按 [02.audit.entrypoint.md](02.audit.entrypoint.md) 执行 `audit --doc`，识别归属为 `outside` 的未入库本地引用。
2. **生成不可变版本并写入**：调用 `put` 按内容 SHA-256 生成不可变版本名，经软连接写入 `.gdrive/managed/<bucket>/<logical-name>--<sha256>.<ext>` 并返回摘要（入库不删除原文件）。`--name` 指定项目内逻辑名称，素材类型不限于图片和视频；目录需枚举普通文件逐项入库，不打包整个项目。
3. **改写 Markdown 相对链接**：由助手编辑本次授权范围内的 Markdown，计算相对文档目录的路径，更新图片链接、可点击外层链接、视频 `src` 和文字下载链接（含空格路径使用尖括号或 `%20` URL 编码）；脚本不做全仓字符串替换。
4. **局部复审**：以 `audit --doc` 限定本次处理的文档重新审计，逐条核实引用存在且合规；仓库其他存量问题独立报告。
5. **版本晋升与迭代**：审核通过时重新以 `approved` 入库并更新引用；相同逻辑素材生成新版后，先入新版、更新引用，再按 [02.audit.entrypoint.md](02.audit.entrypoint.md) 移除无引用旧版，不在原内容摘要路径直接覆盖文件。

## 4. 规范

- **长路径告警**：Windows 路径超过 `240` 字符时 `put` 输出 `path_length_warning`，应开启系统长路径支持或缩短 `--name`。
- **挂载缺失保护**：映射盘未挂载时软连接悬空，所有命令拒绝执行，不创建伪挂载目录。
- **I/O 与冲突中止**：断网、权限错误、磁盘不足和摘要冲突均保留源文件，立即停止当前操作并报告具体路径；修复后重跑会跳过相同摘要。
- **禁止推断通过**：严禁无真实审核人及证据记录而使用 `approved` 分桶。

## 5. 验收

- **内容完整性**：`put` 复制前后 SHA-256 摘要一致；运行 `verify --key '<bucket>/<versioned-file>'` 返回 `invalid == []` 且 `needs_review == []`。
- **引用完整性**：对本次编辑文档运行 `audit --doc <target.md>` 返回退出码 `0`，且 `missing == 0`、`unmanaged == 0`。
- **报告口径**：仅在本机完成验证时报告“映射盘读写验证通过”，不提前宣称“多机同步验收通过”。
