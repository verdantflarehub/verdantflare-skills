## 2. 适用与排除边界

本技能专职管理需要跨机同步的项目图片、视频、生产和设计素材，覆盖素材入库、Markdown 引用审计、新机软连接接入、旧版无引用素材清理及本技能全局安装维护。

不纳入本技能职责的输入与场景：

- **已被 Git 跟踪的文件**：职责边界以 `git ls-files` 状态判定，不按目录名或文件类型推断；已进 Git 的文件豁免入库。
- **外部网络资源与非素材链接**：外部 `http/https` URL 不自动下载；源码及纯配置文本链接不当作大型素材处理。
- **未被引用的临时过程产物**：未被任何 Markdown 引用且用户未显式指定跨机复用的临时或可抛弃文件，仅保留在项目 `.tmp/`，绝不存入 `.gdrive`。
- **素材生成与审美裁决**：本技能不负责生成图片/视频，也不代替人工做审美通过判定。

## 3. 前置取证与引用归属判据

执行入库或清理前，先运行 [gdrive.py](../scripts/gdrive.py) 的 `audit`（或 `audit --doc`）探针。解析器自动提取 Markdown 图片、普通链接、引用式链接及 HTML `src/href/poster/srcset`（代码围栏内的示例链接不算实际引用，扫描不进入软连接目录），为每条引用输出存在性、是否入库（`stored`）、是否合规（`compliant`）与归属分类（`owner`）：

- `assistant`：位于 `.gdrive/managed/`，标记 `managed=true`，保持受管引用。
- `human`：位于 `.gdrive/` 下非 `managed/` 目录，标记 `human_owned`，保留原路径。
- `git`：项目内命中 `git ls-files`，标记 `git_exempt`，豁免入库。
- `outside`：位于 `.tmp/` 或其他未跟踪本地路径，计入 `unmanaged`，必须入库并改写相对链接。

`.gdrive/output/` 工作产出目录也归入 `human`：合规，助手可写，不需要入库或改名；人工目录只读的限制只适用于 `output/`、`managed/` 以外的目录。

动态模板、CSS 内嵌 URL 与非标准 wiki 引用不在自动解析范围内，须先检查原文并人工补充；遇到不明语法不能把零条扫描结果当作没有素材。

## 4. 入库分桶（`bucket`）判据

待入库素材按实际 Markdown 引用语境、用户指令与审核记录确定目标分桶，严禁根据文件名、清晰度或模型打分推断人工通过：

- `pending`：最新生成、待审或普通文档引用的过程/成品素材；传 `--bucket pending` 与 `--reason`。
- `approved`：有真实人工审核通过记录的定稿；传 `--bucket approved --reviewer --evidence`。
- `references`：上游作者原图/原片、输入参考帧与设计参考素材；传 `--bucket references` 与 `--reason`。

## 5. 任务场景路由

本技能按操作阶段在底座内划分为六类标准流程，不拆分独立矩阵文件：

1. **技能全局安装与更新**：见 [执行流程第 2 节](01.base-workflow.md#2-环境准备与全局安装维护)。
2. **项目初始化与旧版目录接入**：见 [执行流程第 3.1 节](01.base-workflow.md#31-初始化与新机接入)。
3. **素材入库与 Markdown 链接改写**：见 [执行流程第 3.2 节](01.base-workflow.md#32-素材入库与引用改写)。
4. **内容摘要同步核验**：见 [执行流程第 3.3 节](01.base-workflow.md#33-同步与内容摘要核验)。
5. **被替代无引用旧版移除**：见 [执行流程第 3.4 节](01.base-workflow.md#34-移除被替代旧版)。
6. **VS Code 单目录预览接入**：本地可信工作区的内置 Markdown Preview 通过 `.gdrive` 引用图片或音视频时，见 [预览安装](01.base-workflow.md#5-vs-code-单目录预览)。远端工作区、浏览器版编辑器、外部 URL、CSS 背景图与 srcset 不在此桥接范围。
