## 2. 环境准备与全局安装维护

使用 Python 3.11+、Google Drive 桌面客户端及 [依赖清单](../scripts/requirements.txt)。执行前先确认目标云端硬盘已登录、挂载并可读取；不把盘符根当作“我的云端硬盘”，不自动安装客户端或索取 API 密钥。挂载路径按机器实际发现，中文和英文目录名均可。

Windows 优先创建目录符号链接（需开发者模式或管理员权限），无权限时自动回退为目录联接（`junction`）；其他系统使用符号链接。

在本技能源码目录执行以下命令；全局调用时把脚本替换为已发现的安装位置，不假设业务项目包含 `skills/`：

```powershell
python -m pip install -r scripts/requirements.txt
python scripts/install.py
python scripts/install.py --skills-root '<skills-root>'
```

[install.py](../scripts/install.py) 默认安装到统一安装根 `~/.agents/skills`，各智能体按一次性接入读取该目录；`--skills-root` 可重复传入，传入后只安装到指定位置。更新仍从仓库运行同一命令，逐文件 SHA-256 校验，旧版移到安装根同级的 `skill-backups/`；同内容重复安装不产生备份。安装不携带项目素材、机器路径或凭据。全局依赖须在实际运行脚本的 Python 环境安装。

## 3. 核心操作步骤

### 3.1 初始化与新机接入

[gdrive.py](../scripts/gdrive.py) 的 `--project` 参数放在子命令之前，使用项目绝对路径。下列路径均为示例，执行时替换为实际项目及映射盘根：

```powershell
python scripts/gdrive.py --project '<project-abs-path>' init --drive-root '<drive-root>' --namespace github.com/<group>/<project>
python scripts/gdrive.py --project '<project-abs-path>' init --drive-root '<drive-root>' --namespace github.com/<group>/<project> --adopt-local
python scripts/gdrive.py --project '<project-abs-path>' status
python scripts/gdrive.py --project '<project-abs-path>' audit
python scripts/gdrive.py --project '<project-abs-path>' audit --doc docs/review.md
```

- **标准初始化**：`init` 在远端建立 `managed/` 各目录与 `config.json`（已存在时核对命名空间一致），并在 `.gitignore` 中加入 `/.gdrive`，再把本地 `.gdrive` 创建为指向远端项目目录的软连接。重复执行时若已指向同一目录则不做改动，指向其他目录时报错。每台电脑 Git 拉取后各自执行一次 `init`，即可通过软连接直接读取全部受管素材。
- **旧版实体目录迁移（`--adopt-local`）**：本地 `.gdrive` 若是旧版实体目录，`init` 默认拒绝执行；显式加 `--adopt-local` 后，脚本逐个校验内容摘要并将 `approved/`、`pending/`、`references/` 与 `receipts/` 复制到远端（同路径异内容即报错且不改动本地）。旧 `history/`、旧本机配置与其他杂项不上云，整个旧目录移到 `.tmp/gdrive-local-backup-<时间>/` 后再创建软连接；旧目录含人工目录时拒绝执行，先由人工迁移。
- **范围审计（`audit`）**：`--doc` 可重复传入相对项目的 Markdown 文件或目录，只审计本次处理范围，退出码只反映该范围。

### 3.2 素材入库与引用改写

```powershell
python scripts/gdrive.py --project '<project-abs-path>' put '<source-file>' --bucket pending --name shots/scene-01.png --reason markdown-reference
python scripts/gdrive.py --project '<project-abs-path>' put '<approved-file>' --bucket approved --name delivery/poster.png --reviewer '<reviewer>' --evidence '<review-record>'
```

1. **生成不可变版本并写入**：按内容 SHA-256 生成不可变版本名，经软连接写入 `.gdrive/managed/<bucket>/<logical-name>--<sha256>.<ext>` 并返回摘要（入库不删除原文件）。`--name` 指定项目内逻辑名称，素材类型不限于图片和视频；目录需枚举普通文件逐项入库，不打包整个项目。
2. **改写 Markdown 相对链接**：由助手编辑本次授权范围内的 Markdown，计算相对文档目录的路径，更新图片链接、可点击外层链接、视频 `src` 和文字下载链接（含空格路径使用尖括号或 `%20` URL 编码）；脚本不做全仓字符串替换。
3. **局部复审**：以 `audit --doc` 限定本次处理的文档重新审计，逐条核实引用存在且合规；仓库其他存量问题独立报告。
4. **版本晋升与迭代**：审核通过时重新以 `approved` 入库并更新引用；相同逻辑素材生成新版后，先入新版、更新引用，再按第 3.4 节移除无引用旧版，不在原内容摘要路径直接覆盖文件。

### 3.3 同步与内容摘要核验

```powershell
python scripts/gdrive.py --project '<project-abs-path>' verify
python scripts/gdrive.py --project '<project-abs-path>' verify --key 'pending/<versioned-file>'
```

跨机同步由 Google Drive 客户端完成，脚本不做复制。`verify` 校验受管文件名中的内容摘要：未传 `--key` 时扫描 `approved/`、`pending/`、`references/` 三个素材目录；流式模式下全量校验会触发下载，大型目录优先传 `--key` 抽检。同一资产的审核与移除由一台电脑顺序执行，其他电脑恢复联网后先 `audit` 再继续维护。

### 3.4 移除被替代旧版

```powershell
python scripts/gdrive.py --project '<project-abs-path>' remove 'pending/<old-versioned-file>'
python scripts/gdrive.py --project '<project-abs-path>' remove 'pending/<old-versioned-file>' --apply
python scripts/gdrive.py --project '<project-abs-path>' remove 'pending/<old-versioned-file>' --apply --keep-tmp
```

默认仅预览，加 `--apply` 才实际删除。脚本先扫描全仓 Markdown（含归档、技能及 `.tmp` 内文档），仍有引用即拒绝；校验摘要无误后删除该文件及其 `receipts/` 回执，删除操作经客户端传播到所有电脑。加 `--keep-tmp` 时先复制到项目 `.tmp/gdrive-removed/` 暂留，不再存入 `.gdrive`。执行前须确认其他 Git 分支没有仍需要它的引用，不批量清空云端。

## 4. 失败恢复与异常处理

- **长路径告警**：Windows 路径超过 `240` 字符时 `put` 输出 `path_length_warning`，应开启系统长路径支持或缩短 `--name`。
- **挂载缺失保护**：映射盘未挂载时软连接悬空，所有命令拒绝执行，不创建伪挂载目录。
- **I/O 与冲突中止**：断网、权限错误、磁盘不足和摘要冲突均保留源文件，立即停止当前操作并报告具体路径；修复后重跑会跳过相同摘要。
- **云端冲突副本**：Google Drive 客户端生成的冲突副本（如 `copy (1).png`）在 `verify` 中列入 `needs_review`，须人工核对摘要，严禁自动覆盖或删除。

## 5. VS Code 单目录预览

扩展需要本地 VS Code 1.85+、可信工作区与可读 `.gdrive`。从技能目录执行：

```powershell
python scripts/install.py --vscode
python scripts/install.py --vscode --code-bin '<editor-cli>'
python scripts/install.py --check-vscode --code-bin '<editor-cli>'
```

`--vscode` 安装技能并在系统临时目录构建确定性 VSIX，调用编辑器 CLI 安装后回读扩展版本；退出临时目录即清理包。`--code-bin` 覆盖 PATH 与标准位置探测，便携版可显式指定 `bin/code.cmd`。`--check-vscode` 只读检查，不更新技能或扩展；两种模式互斥，失败返回非零退出码。

安装后重载 VS Code 窗口，以单文件夹打开项目并打开内置 Markdown Preview。安全级别按项目根目录 URI 保存：同一目录的 Markdown 共用且重启后保留；新项目、目录迁移或新电脑须重新确认，不是全局放行。扩展在每个编辑器安装环境安装一次即可供多个项目使用。首次媒体渲染会提供“预览安全设置”操作；如果 HTTP 媒体被拦截，在宿主选择 `Allow insecure local content`，不自动修改设置。加载错误也可能由文件缺失、映射盘离线或格式不支持引起，先检查实际文件。安装版本回读只证明扩展登记成功，桌面效果按验收专册另测。

卸载使用编辑器扩展面板或 `code --uninstall-extension verdantflare.gdrive-markdown-preview`；不影响 Markdown 原路径与 `.gdrive`。更新失败保留技能备份，先核对 CLI 和扩展版本再重试；不修改 VS Code 内置文件。
