# 新机软连接接入、预览与全局安装（03.setup）

## 1. 输入与输出

- **输入**：Python 3.11+ 环境、已登录并挂载的 Google Drive 映射盘根 `<drive-root>`、项目绝对路径与项目命名空间 `github.com/<group>/<project>`、可选旧版实体 `.gdrive` 目录或本地 VS Code 1.85+ 编辑器 CLI。
- **输出**：指向远端项目目录的 `.gdrive` 软连接、远端 `managed/` 结构与 `config.json`、更新的 `.gitignore`、同步至 `~/.agents/skills/verdantflare-meta-googledrive` 的全局安装副本，以及可选的本地 VS Code 单目录预览扩展。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的软连接契约、命名空间规范与本地预览只读边界。

## 2. 分类

| 接入子场景               | 适用条件与边界                                                        |
| :----------------------- | :-------------------------------------------------------------------- |
| 标准新机初始化（`init`） | 新克隆项目或尚未建立 `.gdrive` 软连接；每台电脑拉取后各自执行一次     |
| 旧版实体目录迁移         | 本地 `.gdrive` 为旧版实体目录且不含人工目录；须显式传 `--adopt-local` |
| 技能全局安装维护         | 从维护源同步至 `~/.agents/skills` 或 `--skills-root`，逐文件哈希校验  |
| VS Code 单目录预览接入   | 本地可信工作区内置 Markdown Preview 引用 `.gdrive` 图片或音视频       |

说明：VS Code 单目录预览桥接不含远端工作区、浏览器版编辑器、外部 URL、CSS 背景图与 `srcset`。

## 3. 工作流

### 3.1 环境准备与全局安装

确认目标云端硬盘已登录、挂载并可读取；不把盘符根当作“我的云端硬盘”，不自动安装客户端或索取 API 密钥。挂载路径按机器实际发现，中文和英文目录名均可。Windows 优先创建目录符号链接（需开发者模式或管理员权限），无权限时自动回退为目录联接（`junction`）；其他系统使用符号链接。依赖见 [requirements.txt](../scripts/requirements.txt)：

```powershell
python -m pip install -r scripts/requirements.txt
python -X utf8 scripts/install.py
python -X utf8 scripts/install.py --skills-root '<skills-root>'
```

[install.py](../scripts/install.py) 默认安装到 `~/.agents/skills`，`--skills-root` 可重复传入且传入后只安装到指定位置。更新仍从仓库运行同一命令，逐文件 SHA-256 校验，旧版移到安装根同级 `skill-backups/`，同内容重复安装不产生备份；安装不携带项目素材、机器路径或凭据，全局依赖须在实际运行脚本的 Python 环境安装。

### 3.2 项目初始化与旧版目录接入

```powershell
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' init --drive-root '<drive-root>' --namespace github.com/<group>/<project>
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' init --drive-root '<drive-root>' --namespace github.com/<group>/<project> --adopt-local
python -X utf8 scripts/gdrive.py --project '<project-abs-path>' status
```

- **标准初始化**：`init` 在远端建立 `managed/` 各目录与 `config.json`（已存在时核对命名空间一致），在 `.gitignore` 中加入 `/.gdrive`，再将本地 `.gdrive` 创建为指向远端项目目录的软连接；重复执行若已指向同一目录则无改动，指向其他目录则报错。
- **旧版实体目录迁移（`--adopt-local`）**：本地 `.gdrive` 若为旧版实体目录，`init` 默认拒绝；显式加 `--adopt-local` 后逐个校验摘要并将 `approved/`、`pending/`、`references/` 与 `receipts/` 复制到远端（同路径异内容即报错且不改动本地），旧 `history/`、旧本机配置与其他杂项不上云，整个旧目录移至 `.tmp/gdrive-local-backup-<时间>/` 后再建软连接；旧目录含人工目录时拒绝执行，先由人工迁移。

### 3.3 VS Code 单目录预览安装与排障

扩展源码见 [package.json](../resources/vscode-preview/package.json)，要求本地 VS Code 1.85+、可信工作区与可读 `.gdrive`：

```powershell
python -X utf8 scripts/install.py --vscode
python -X utf8 scripts/install.py --vscode --code-bin '<editor-cli>'
python -X utf8 scripts/install.py --check-vscode --code-bin '<editor-cli>'
```

`--vscode` 安装技能并在系统临时目录构建确定性 VSIX，调用编辑器 CLI 安装后回读扩展版本并清理临时包；`--code-bin` 覆盖 PATH 与标准位置探测（便携版可指定 `bin/code.cmd`）；`--check-vscode` 只读检查，与 `--vscode` 互斥，失败返回非零退出码。

安装后重载 VS Code 窗口，以单文件夹打开项目并打开内置 Markdown Preview。安全级别按项目根目录 URI 保存，新项目、目录迁移或新电脑须重新确认。首次媒体渲染提供“预览安全设置”操作，HTTP 媒体被拦截时在宿主选择 `Allow insecure local content`（不自动修改设置）；加载错误先排查文件缺失、映射盘离线或格式不支持。卸载用扩展面板或 `code --uninstall-extension verdantflare.gdrive-markdown-preview`，不影响 Markdown 原路径与 `.gdrive`；更新失败保留技能备份，不修改 VS Code 内置文件。

## 4. 规范

- 挂载盘未挂载时软连接悬空，所有命令拒绝执行，不创建伪挂载目录。
- 命名空间须在所有协作者机器完全一致，不拿 GitLab `origin` 冒充 GitHub；`config.json` 仅存 `schema` 与 `namespace`，严禁写入本机路径。
- 预览扩展安装版本回读只证明扩展登记成功，不代表桌面预览或云端同步已验收。

## 5. 验收

- **软连接与状态**：`status` 返回 `mount_available == true` 且 `.gdrive` 解析为远端 `drive_target`；`.gdrive/managed/history` 不存在。
- **Python 回归测试**：运行 `python -X utf8 -m unittest discover -s scripts -p test_gdrive.py -v`（覆盖 [test_gdrive.py](../scripts/test_gdrive.py) 中的软连接初始化、旧目录接入、Windows `junction` 回退、直写入库、引用解析、Git 豁免、审计隔离、摘要核验、移除拒绝、人工目录保护、挂载缺失保护、全局安装备份保留与确定性 VSIX / CLI 检查）。
- **VS Code 预览四层验证**：自动化回归使用 Node 18+ 与开发依赖 `markdown-it 14.1.0`，从 `resources/vscode-preview/` 执行 `npm install --ignore-scripts` 后运行 `npm test`（集中临时目录时用 `npm install --prefix <temporary-dir> markdown-it@14.1.0 --ignore-scripts` 并设 `NODE_PATH`），覆盖回环 HTTP（令牌、Host、GET/HEAD、ETag、单段 Range、416、中文空格、目录联接、链接逃逸）与真实 Markdown 解析；安装后 `--check-vscode` 回读匹配版本并重载宿主再测桌面（单文件夹资源管理器无额外根目录、`managed`/`output` 媒体加载与安全设置提示），控制链路不可用时明确标为未验证。
- **多机同步验收**：等待客户端同步完成，在第二台电脑执行 `init`、`audit` 与 `verify` 且抽样 SHA-256 一致，方可报告“多机同步验收通过”。
