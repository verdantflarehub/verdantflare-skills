# Markdown 文档分类、取证与适用边界

## 1. 当前依据

- [技能入口](../SKILL.md)：编码规范、范围与工具入口。
- [执行流程](01.base-workflow.md)：识别、格式化、小改豁免与交付步骤。
- [规则约束](01.base-rules.md)：规则优先级与通用排版约束。
- [验收标准](01.base-acceptance.md)：量化结构检查与门禁判据。

## 2. 适用与排除边界

### 2.1 适用场景

- 任意仓库中自主维护的 Markdown 新增、实质修改与章节重构。
- 三层及以上嵌套列表、列表内长段落/代码块/表格、超宽文字表格的结构治理。
- 编辑器保存时自动 Format 触发大段缩进或重折行的根因排查与配置调整。

### 2.2 排除与豁免场景

- **保留既有格式**：第三方原文、外部规范引文、代码示例内容和机器生成区域保留原样，不重排。
- **历史归档只修断链**：位于 `docs/archive/` 对应子目录的计划、变更、缺陷等归档文档视为历史记录，只做必要的相对链接修复，不重排正文结构。
- **存量小改豁免**：编辑前 `md_format.py --check` 已显示不符合格式化结果，且本次仅改错字、链接、少量字句或个别列表项（不新增或重排章节）时，按[执行流程](01.base-workflow.md#4-存量文件小改豁免)豁免全文格式化。
- **范围边界**：只加载当前类型所需规范；不把文档整理扩展为业务设计重做或全仓重排。

## 3. 前置取证与主类型判定

在动手编写或整理前，按以下两步完成取证与路由：

1. **路径与内容特征核对**：先查目标文件的相对路径，再核对文首元数据字段（如负责人、助手、状态、YAML front matter）与章节特征。路径与内容特征矛盾时以实际内容为准，并在交付说明中写明判定依据。
2. **仓库契约与格式化基线探针**：读取目标仓库及目标目录的 `AGENTS.md`，记录强制模板、脚本同步区域与媒体表格契约；编辑存量文件前先运行 `md_format.py --check` 记录原始格式化状态。

文档兼有多种职责时只确定一个主类型，其余职责通过相对链接拆到对应类型的独立文档。

## 4. 文档类型与主题专册索引

| 路径与内容特征                                   | 主类型与主题专册            |
| :----------------------------------------------- | :-------------------------- |
| `README.md`；用途、快速开始、常用操作、目录导航  | [README 规范](readme.md)    |
| `docs/plan/*.plan.md`；负责人、任务清单、勾选    | [计划文档规范](plan.md)     |
| `docs/changes/change_*.md`；执行记录、验证证据   | [变更文档规范](change.md)   |
| `docs/bugs/bug_*.md`；现象、复现、根因、修复验证 | [缺陷文档规范](bug.md)      |
| `skills/*/SKILL.md` 及 `references/`；触发与流程 | [技能文档规范](skill.md)    |
| 多轮素材持续评审；待审/不合格标记、媒体预览表格  | [评审文档规范](review.md)   |
| 其他 `docs/*.md`；背景、方案、契约、取舍、研究   | [设计文档规范](design.md)   |
| 以上均不适用的稳定新文档类型及跨类型规范沉淀     | [业务规范沉淀](business.md) |

本技能不设 `Cx.<slug>` 分支矩阵；共享排版规则、执行流程与量化检查由四份底座维护，八类文档的职责、必填字段与类型专属验收由上表主题专册维护。
