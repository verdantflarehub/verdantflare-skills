# 评审文档规范

## 1. 职责与适用范围

评审文档承载多轮制作的分镜、素材与成品的持续评审：随做随放、标注评审状态、记录讨论与待决问题。适用于图片、视频等媒体产出需要人工逐轮审阅的任务；纯文字方案评审按设计文档处理。

依据为用户明确约定：评审素材集中放进一份文档，点击表格小图直接打开原图，同行图片等宽对齐。目标仓库另有媒体或对比表格模板时从其规定。

## 2. 持续评审流程

- 同一任务多轮产出的素材统一放进一份评审文档，产出即放入，不等整批完成。
- 未评审素材标“待审”；不合格素材标“不合格”并保留，直到下一轮替代产出放入。
- 新素材产出后直接替换原位置，删除被替换的旧图，不在文档中累积历史版本。
- 讨论记录与待决问题统一写在文档末尾 FAQ。

## 3. 媒体表格

媒体表格的首行单元格全部为图片或视频，不受通用规范文字表格列数与宽度的限制；文字表格仍按通用规范执行。

### 3.1 两行结构

表格严格只分两行：第一行放可点击图片，第二行只放等长简短的纯文本编号，不加超链接、不写长标题或描述，使同行图片等宽对齐。详细说明与路径列表写在表格下方，不在表格下方重复堆放大图。

### 3.2 单图与点击直跳

每个单元格放一张独立单图，并以同一相对路径包裹超链接，点击小图即打开原图。不以合成的多宫格拼图代替独立单图文件。

```markdown
| [![A01](img/A01.png)](img/A01.png) | [![A02](img/A02.png)](img/A02.png) | [![A03](img/A03.png)](img/A03.png) |
| :--------------------------------: | :--------------------------------: | :--------------------------------: |
|                A01                 |                A02                 |                A03                 |
```

### 3.3 视频体积

交付预览的视频单文件严格小于 `18MB`，超限先压制再放入文档；编辑器内置预览存在约 `20MB` 的单文件显示上限。视频编码与表格模板以目标仓库规则为准。

## 4. 例外

目标仓库规则规定的对比表格（如第二行使用带超链接的标题、固定左右两列）优先于本专册的第二行纯文本要求。

## 5. 验证

- `check_md.py` 对首行全部为图片或视频的表格不报 `table-columns` 与 `table-width`；混有文字列的表格仍按通用规范报错。
- 人工在 Markdown 预览中确认同行图片等宽、点击小图可打开原图；预览效果未查看时如实标记未验证。
