# Markdown 编写、格式化与交付流程

## 1. 当前依据

- [技能入口](../SKILL.md)：范围与路由。
- [分类与边界](01.base-category.md)：前置取证与文档类型路由。
- [规则约束](01.base-rules.md)：通用排版规则与设置边界。
- [验收标准](01.base-acceptance.md)：量化结构检查与交付门禁。

## 2. 识别与编写

读取目标文件、目标仓库规则、[规则约束](01.base-rules.md)和对应文档类型专册。明确本次交付文件清单，记录原有改动、代码块内容、链接锚点及生成器契约。生成文档优先修改来源，再重新生成。

编辑存量文件前先执行一次 `md_format.py --check`，记录该文件原本是否已符合格式化结果，用于第 4 节的豁免判断。

按目标业务规范完成内容并落盘，长内容用标题分层。格式化处理排版，不代替事实核验或章节设计。

## 3. Format 工具探测与命令

以下脚本位于本技能安装目录的 `scripts/` 下；从其他目录调用时使用已发现的实际路径，不假定目标仓库包含本技能。Python 依赖见 [requirements.txt](../scripts/requirements.txt)：

```text
python -m pip install -r scripts/requirements.txt
python -X utf8 scripts/md_format.py --check docs/example.md
python -X utf8 scripts/md_format.py docs/example.md
python -X utf8 scripts/md_format.py --prettier /path/to/prettier docs/example.md
python -X utf8 scripts/check_md.py docs/example.md
python -X utf8 scripts/install.py [--skills-root ~/.agents/skills] [--replace]
python -X utf8 -m unittest discover -s scripts -p "test_*.py"
```

统一通过 [md_format.py](../scripts/md_format.py) 调用 Prettier，脚本按以下顺序探测，首个可用者生效，并输出实际路径与版本：

1. 命令行参数 `--prettier` 或环境变量 `VERDANTFLARE_PRETTIER` 指定的可执行文件或 `prettier.cjs`。
2. 目标文件所在仓库自下而上找到的 `node_modules/.bin/prettier`。
3. `PATH` 中的 `prettier`。
4. 编辑器 Prettier 扩展自带的 `prettier.cjs`（VS Code、Cursor、Antigravity 等用户扩展目录），取版本最高者，用 `node` 执行。

目标仓库有 Prettier 配置时由 Prettier 自行解析；没有配置时脚本附加 `--prose-wrap preserve --embedded-language-formatting off --end-of-line lf`，减少正文重折行、代码示例被改写，并在 Windows、Linux 与 macOS 上将换行符统一强制为 `LF (\n)`。这些参数不能消除列表嵌套，结构问题仍需先修正文档。Prettier 3 默认静默跳过 `.gitignore` 命中的文件，脚本对显式文件只遵循 `.prettierignore`，避免把未处理误报为通过。

只格式化本次交付的明确文件列表，不使用全仓通配符。不得通过无版本的自动下载引入格式化器。全部探测失败时脚本以退出码 `2` 结束，交付时明确标记“Format 未完成”及原因，不冒充已完成。关闭保存时自动格式化不影响本流程要求的显式 Format。

## 4. 存量文件小改豁免

同时满足以下条件时，不对整个文件执行 Format，交付说明写明“存量文件未格式化，按小改豁免”：

- 编辑前 `--check` 显示该文件原本就不符合格式化结果。
- 本次只改错字、链接、少量字句或个别列表项，不新增或重排章节。

此时只确保本次修改的区域符合通用规范，不顺带重排全文。新建文件、实质修改或用户要求整理的文件不适用豁免。

## 5. 落盘后格式化与复核

落盘后执行 Format，再执行 `md_format.py --check` 与 [check_md.py](../scripts/check_md.py)，确认输出稳定且无错误。若修改任何内容或接受人工反馈，重新执行后再交付。

检查格式化差异，核对事实、命令、代码块内容、配置片段、媒体路径和同步标签未被误改。目标仓库存在生成脚本同步区域时，格式化后执行其提供的仅预览或仅同步检查，确认匹配不受影响。发现格式化重新产生大段列表缩进，调整父项为标题再格式化，不机械删空格或全文件忽略。

`check_md.py` 的错误必须修复；警告逐条判断，属于目标仓库强制模板等合理例外时在交付说明中注明。解析器通过只证明结构，不代表编辑器视觉效果已验收。

## 6. 人工查阅、最终提交与全局安装

交给人类查阅的必须是已落盘、已 Format、已检查的版本，并说明路径、修改内容、验证结果和待决问题。工具受限时可呈现草稿，但必须明确 Format 尚未完成。

仅在任务确有人工检查点时等待人工结论，不为普通文档修改额外增加审批。人工反馈修改后重复流程，不能把格式化前版本当作最终版本。

最终提交前，对本次最终文件清单再次执行格式化检查和结构检查，包含归档或移动后的路径。只提交本任务改动，保留无关工作区修改。提交、推送和发布遵循已有授权及仓库流程；如未实际执行则如实说明。

修改本技能源码后，运行 [install.py](../scripts/install.py) 按 `verdantflare-meta-skill` 安装规范复制到统一安装根 `~/.agents/skills/verdantflare-meta-markdown` 并逐文件哈希校验；已安装副本与源码不同时，须先确认无仅存于副本的修改，再加 `--replace` 覆盖。
