# 计划文档规范

## 1. 职责与位置

计划维护任务分解、依赖、完成勾选及必要审批记录。进行中计划放 `docs/plan/YYYY.MM.<主题>.plan.md`，完成或废弃后移入唯一归档根下的 `docs/archive/plan/`，不在 `docs/plan/` 下另建 `archive/`。主题使用小写英文、短横线或点分隔，描述稳定对象，不用版本、状态或 `draft` 等后缀；存量文件名不因本规则批量改名。

文首填写负责人和助手及职责。负责人即计划维护人，对推进、文档维护与交付负责，默认只有一人，不等于审批人；从用户规定的开发人员名单中按用户指定填写；未指定时按用户全局规则的默认负责人填写，没有默认时先询问，不能自行选定，也不能用 AI 或“待定”等占位值替代。

助手是实际参与工作的 AI，按“助手（职责）”逐个登记，多个用顿号分隔，例如 `Claude（计划编制）、Codex（T2.1 执行）`。职责写计划编制、变更设计、设计文档、执行、审阅等实际工作，同一助手多项职责合并在一个括号内；参与即登记，只追加不删除，尚无助手时写“暂无”。助手接手时先读计划与关联变更再续做。存量计划与变更在下次实质修订时补齐文首字段，不为补字段批量改写。

## 2. 内容结构

推荐章节：当前依据、目标与范围、任务清单、依赖与检查点、完成条件、审批记录。每个任务应有稳定标识、可验证产物与完成条件，开始执行后链接对应变更。

任务清单用浅层复选列表，复杂子任务另设标题。依赖明确指向任务标识；需要人工决定的检查点说明决策对象和所需证据，复用已有授权，不新增无依据审批；独立的准备工作不等待审批。

计划仅维护勾选与关联进展入口。命令输出、调试过程、停点与阻塞细节写入变更，避免两处维护同一执行状态。更换负责人时在审批记录写明日期、原负责人、新负责人及用户指示。

涉及 Agent 间委托时，应用 `verdantflare-meta-agent` 定义协作行为。本专册只规定文档归属：文首明确计划名称与稳定计划标识，任务清单或计划说明登记稳定任务键及当前编号映射；目标仓库固定章节优先，不另增执行状态台账。任务重编号更新映射，稳定身份不变；归档同步运行登记中的文档路径。

执行、审阅、统筹和结项维护者写入职责安排，AI 仍登记为助手。每次委托必须有计划末级任务及关联变更；没有计划的普通直接任务可以沿用仓库规则，但不能据此向其他 Agent 临时派活。具体 Session 地址、外部任务收据、通知状态和恢复事实仅写在变更。

## 3. 完成与归档

只有任务完成条件满足才勾选；不得删除未完成项或拆分任务来提高完成率。整体完成条件及必要人工检查全部满足，或用户明确废弃后，标记相应状态并移至 `docs/archive/plan/`，并确认无本任务遗留的进行中变更。

归档后修正相对路径和所有关联引用，再执行格式化与检查。技术通过、人工批准、发布完成分别记录。
