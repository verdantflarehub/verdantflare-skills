# Markdown 通用编写与排版规则

## 1. 当前依据

- [技能入口](../SKILL.md)：编码规范与适用范围。
- [分类与边界](01.base-category.md)：适用与豁免边界。
- [验收标准](01.base-acceptance.md)：`check_md.py` 量化检查规则与阈值定义。

## 2. 规则优先级

本技能把用户“不喜欢自动 Format 后层层缩进”的偏好落实到 Markdown 源码结构。规则冲突时按以下顺序取舍：

1. 用户在当前任务中的明确要求。
2. 目标仓库及目标目录的 `AGENTS.md` 等规则，包括其强制模板、生成脚本同步区域和媒体排版契约。
3. 用户全局规则中的文档编制与计划变更规范。
4. 本技能的通用规则与类型专册。

第三方原文、历史归档、代码示例内容和机器生成区域保留既有格式。

## 3. 编写规则

### 3.1 用标题承载长内容

一级标题不编号；二级起依次使用 `1.`、`1.1`、`1.1.1` 连续编号；文件名沿用目标仓库或模块约定。长篇规则、模板说明、多个段落和带代码示例的主题使用标题分层，不使用“有序列表 → 无序列表 → 子列表 → 代码块”的结构承载章节。

普通列表默认仅一层。确有父子语义时允许第二层短条目；出现第三层或条目包含长段落、表格、围栏代码块时，优先将父条目改成小标题。不要为一句话制造多级标题。

### 3.2 顶格代码块与表格

独立围栏代码块、表格和正文从第 1 列开始，前后留空行。代码块标注语言。代码本身所需的 Python、YAML 等缩进原样保留。

不能直接删除列表续行缩进：先将其父项改为标题或独立引导段，再移动内容，确保归属关系仍然明确。仅加空行不能可靠地让缩进内容脱离列表。

确需属于某个步骤的代码块，以及目标仓库规则强制的“列表项加代码块”模板，保留必要的列表缩进。修改脚本同步区域前先核对生成器与匹配规则，不擅自改变其标签和结构。

文字表格仅用于简短索引或对照，可用 2～4 列，单元格只放词组、编号、命令或链接；说明写在表格下方，步骤、条件与证据使用段落或列表。不要用换行标签塞入长段落。

表格须在源码与预览中同样可读。格式化器按每列最长单元格补齐空格，一个长单元格会把整列拉宽，使源码出现整排空格。判据为格式化后每行不超过 120 显示列（中文等全角字符计 2）。超限时依次缩短文字、把解释移到表格下方、减少列数；仍超限就改用小标题加段落或列表，不要强行制表。

首行全部为图片或视频的媒体表格不受列数与宽度限制，写法见[评审文档](review.md)；目标仓库另有媒体或对比表格规范时从其规定。

### 3.3 链接、路径与跨平台 LF 换行符

仓库内引用使用相对链接和 `/`，外部资源使用完整 URL。文档中不写本机绝对路径、`file://` 或编辑器专用链接；需要说明用户目录时写 `~/` 形式。移动文件或修改标题后同步修正引用与锚点。

无论在 Windows、Linux 还是 macOS 上，所有自主维护的 Markdown 文档统一使用 `UTF-8`（无 BOM）编码与 `LF (\n)` 换行符，严禁写入 `CRLF (\r\n)`；Python 等脚本写文件时须显式指定 `encoding="utf-8", newline="\n"`，目标仓库根目录建议配置 `.gitattributes`（`* text=auto eol=lf`）与 `.editorconfig`（`end_of_line = lf`）统一跨平台换行行为。

设计、计划、变更与缺陷文档把依据集中列于“当前依据”章节：每份依据独占一个列表项，使用相对链接并简述用途。

### 3.4 格式化设置的边界

先核对实际文件、默认格式化器、工作区配置和保存时动作，区分语法缩进、软换行的视觉缩进与表格对齐空格。不要仅凭截图认定是 Prettier，也不要通过全局替换行首空格处理 Markdown。

`tabSize` 不能取消列表的语义缩进；Prettier 的 `proseWrap: preserve` 控制正文换行，也不能消除嵌套层级。默认通过结构调整解决，不主动关闭其他语言的格式化。

用户要求关闭 Markdown 自动格式化时，将以下字段合并至现有工作区 `settings.json` 的 `[markdown]` 对象，保留其余配置：

```json
{
  "[markdown]": {
    "editor.formatOnSave": false,
    "editor.formatOnPaste": false,
    "editor.formatOnType": false
  }
}
```

这些设置不阻止手动“格式化文档”，也不保证禁用扩展独立的保存修复。局部忽略语法只有在确认格式化器支持后使用，不默认全文件忽略。

## 4. 重构示例

以下独立示例将“规则列表中的模板”改为标题下的顶格模板。示例标题编号在实际使用时跟随目标章节。

````markdown
### 1.1 媒体排版

第一行放媒体，第二行放标题。

#### 1.1.1 标题命名

- 图片：作者原图(编号) | 本地输出(编号)
- 视频：作者原片(编号) | 本地输出(编号)

#### 1.1.2 表格模板

```markdown
|    左侧媒体    |    右侧媒体    |
| :------------: | :------------: |
| 作者原图(编号) | 本地输出(编号) |
```
````
