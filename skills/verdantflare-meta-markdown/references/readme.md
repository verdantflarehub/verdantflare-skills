# README 文档规范

## 1. 职责与结构

README 是项目或模块的使用入口，回答“是什么、如何开始、去哪里找详情”。先检查真实目录、依赖声明与现有命令，再写入口说明。

建议按需组织为：用途与边界、前置条件、快速开始、常用操作、目录与文档导航。标题编号遵循通用规范；小模块无需生造空章节。

## 2. 必须表达的内容

- 用途和适用对象，以及实际存在的能力边界。
- 可复制的最短启动或使用命令，说明工作目录、必要配置及预期结果。
- 真实的依赖与配置入口；敏感值使用说明，不写入凭据。
- 指向当前设计、使用指南和活跃计划的相对链接。

## 3. 验收与例外

逐项核对命令来源、入口路径和链接。执行过的命令记录结果；未运行则明确注明，不能声称可运行。涉及远端副作用的命令不因文档验证自动执行。

README 不复制设计全文、变更流水或全部历史；通过链接导航。归档文档链接可以作为历史资料，但必须标明历史性质。
