# 缺陷文档规范

## 1. 职责与位置

一份缺陷记录一个可独立复现的问题，从发现、定位到修复验证。未关闭缺陷放 `docs/bugs/bug_YYYYMMDD_<缺陷对象>.md`，关闭后移入 `docs/archive/bugs/`。目标仓库未设缺陷目录时，按其规则记录在变更或议题中，不擅自新建目录体系。

文首包含负责人、助手及职责、状态、发现日期，以及关联计划或变更链接。

## 2. 内容结构

推荐章节：当前依据、现象与影响、复现步骤、根因分析、修复方案、验证证据、关闭条件。

- 现象写清环境、输入、期望结果与实际结果，附日志或截图路径。
- 复现步骤可直接照做；无法稳定复现时写明概率与已尝试条件。
- 根因区分已证实结论与待验证假设，附定位证据。
- 修复由对应变更执行；缺陷文档链接变更，不复制执行流水。

## 3. 关闭与归档

修复在原复现条件下验证通过、证据齐备后标记已关闭，立即移入 `docs/archive/bugs/` 并修正关联计划、变更中的链接。确认不修复或不是缺陷时写明理由与决定人后关闭。
