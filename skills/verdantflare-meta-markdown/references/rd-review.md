# 研发评审文档规范（rd-review）

## 1. 职责与适用边界

研发评审文档（主类型 `rd-review`）用于记录复杂研发计划在 `T1`（方案成型与验收流程审定）、`T2`（全量影响面扫描）与 `T4`（Codex 全面核验与 Claude 抽查）阶段的多智能体审核过程、问题分级与闭环结论：

- **受控目录与命名**：活动期驻留 `docs/reviews/`，随计划结项或废弃同构移入 `docs/archive/reviews/`；文件名严格匹配 `^review_\d{8}_[a-z0-9.-]+_(t1|t2|t4)(-r(?:[2-9]|[1-9]\d+))?\.md$`（目录内的 `AGENTS.md` 与 `README.md` 为目录规范与导航索引，不按评审报告校验）。
- **与媒体看片文档正交隔离**：多轮图片、分镜或视频选片表格（如 `*.review.md`，遵循 [评审文档规范](review.md)）归属业务创作或设计目录，严禁混入 `docs/reviews/`。
- **目标仓库规则叠加**：本专册提供跨仓库可移植默认契约；目标仓库存在 `docs/reviews/AGENTS.md` 时，其负责人白名单与归档要求优先叠加生效。

## 2. 文首必填字段与状态契约

一级标题不编号，标题下、第一章前固定包含以下七个非空字段（禁止重复键）：

- **负责人**：项目允许的维护负责人昵称，默认沿用关联计划负责人。
- **评审助手**：按“助手（评审角色）”登记参与核验、细节审或复核的 AI 助手（如经计划特批采用同源隔离会话，须紧随声明 `同源隔离会话评审：是`）。
- **关联计划**：指向所属计划文档的精确相对链接。
- **关联阶段**：标明 `T1`、`T2` 或 `T4`（重审附 `-rN`）并链接被审设计或验收文档。
- **评审对象哈希**：记录被审冻结切片的确定性 `sha256:<64hex>` 摘要。
- **评审结论**：仅允许取四个标准值之一——`待修订`、`复评中`、`已通过`、`已废弃`。
- **更新时间**：`YYYY-MM-DD`。

## 3. 五章固定正文与量化检查

正文二级标题必须严格固定为以下五章且顺序不变（存量报告沿用旧章名 `2. 总体架构核验与符合性审计`、`3. 工程细节与防漏评审` 时等效）：

1. `1. 当前依据`：逐行相对链接列出本次评审依据的计划、专题设计、验收文档与变更文档。
2. `2. 架构核验与抽查`：记录 Claude 的总体与技术架构核验及验收流程修订定稿（`T1`），或 Codex 通过后抽查其评价 `1～2` 项的结论（`T4`，不做全面复核），附原生会话收据；`T2` 未改变总体架构时固定说明免调 Claude。
3. `3. 工程细节、防漏与验收核验`：记录 Codex（或非 Claude 非作者研发替补助手）在工程细节审与验收流程修订、全仓防漏审或逐景对照锁卷流程的验收结果全面核验（客观合规评价，不重跑、不重拉产物）中的分级发现、返修核验与原生会话收据。
4. `4. 架构疑难升级裁定`：仅记录跨系统架构冲突经 `<= 800` 字卡片升级 Claude 的裁定结论，及三方无法收敛上报人类的候选项与裁定；无升级时写明本轮无需上报的分歧。
5. `5. 问题闭环与放行结论`：必须包含 `未闭环 HIGH/MEDIUM：<整数>` 汇总行及逐条 `[CLOSED]` / `[OPEN]` 状态记录。

`scripts/check_md.py` 对 `docs/reviews/` 与 `docs/archive/reviews/`（排除 `AGENTS.md`、`README.md`）实行失败闭合识别，自动校验命名正则、七项必填元数据、四态结论枚举、五章固定标题及第 5 章汇总行。
