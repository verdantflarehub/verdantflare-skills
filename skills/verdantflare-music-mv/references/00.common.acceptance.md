## 2. 审核基本原则与载体规范

- 同一版本与同一范围的既有批准直接复用，不重复索取确认；审核只暂停依赖该决定的阶段，本地整理、检查与修复可继续。
- 决定绑定具体资产版本（World 的 `asset_id + asset_version_id` 与文件 `ContentRef`），不把笼统执行授权写成尚未发生的艺术终审；资产版本升级须重新记录影响范围，不得静默替换。
- 审核状态为 `待审核`、`已批准`、`需修改` 或 `已否决`；工具成功、自动检查通过与 Agent 建议均不能代替用户批准。每次决定追加记录时间、审核门、版本、审核资产与用户原始决定，不改写历史。
- 面向用户的审核 Markdown 是审核唯一入口，必须在候选条目中直接呈现媒体，不能只列裸路径。

## 3. 两级审核文档体系与逐镜审核单

项目使用固定英文文件名 `review.md` 通过目录层级区分职责（杜绝 `Draft` 碎片与中文文件名）：

- **项目全局总审核（`根目录/review.md`）**：总导演与总制片视角，负责锁定 Master WAV 高潮时码、记录 `visualbible.md` 与 `treatment.md` 批准结论、维护全片 Block 规划矩阵与各单元 `review.md` 跳转、审查跨 Block 连续性，并执行 Picture Lock 与成片交付。
- **段落单元制作审核（`units/<Block_ID>/review.md`）**：单段执行导演视角，落地本段角色服装（无脸三视图 + `01-character-card.png`）、剧情细化、本段分镜（`02-storyboard-grid.png` + `03-scene-design.png` + `output/review/Shot-*-F1-F2.png` 首尾帧条带图）与生成批次/质检记录。
- **Review Strips（审阅条带图）标准**：内部 Shot 首尾帧必须合成为左首右尾并排条带图存入 `output/review/`（如 `Shot-1-S01-F1-F2.png`），严禁只贴孤立单帧。
- **逐镜专属审核单（`shots/<GU_ID>/review.md`，Omni / TV 素材池模式强制）**：与 `spec.json`、`output/` 同目录，固定 5 个分区——① 镜头定位与审核状态（`待审输入` → `输入已批准` → `待审视频` → `已批准`）、② 输入参考清单（两行等宽预览表 + `Slot`/`purpose`/`Artifact ID` + 零遗漏核验）、③ 完整提示词（分秒景别节拍 `0–2.5s / 2.5–5.5s / 5.5–8s / 8–10s` 与负向约束）及 CLI/MCP 参数、④ 输出视频与质检证据（`task_id`、`artifact_id`、预览 `< 18MB`、1 秒 1 帧 `contact-sheet.png`、K09 抽帧结论）、⑤ 追加式人工审核决定记录。

### 3.1 项目全局总审核模板要点

根 `review.md` 头部声明当前阶段、关联母带时码与 `visualbible.md` 状态，正文含三节：1. 故事圣经与 Block 规划清单（各 Block 时码、时长、一句话圣经、叙事职责、单元 `review.md` 链接与状态）、2. 跨 Block 连续性审查记录（相邻 Block 尾帧/首帧、服装与光影衔接）、3. 全片 Picture Lock 与成片交付检查（覆盖率、全片拼装预览、Master 同步、LRC 字幕与无黑帧检查）。

### 3.2 Block 单元审核模板要点

单元 `review.md` 头部写明当前状态与本版 1–3 条核心改动摘要，正文顺序呈现：Picture 1 Character Card、Picture 2 Storyboard Grid（含 `F01~F08` 与 `S01~S04` 映射）、Picture 3 Scene Design、逐 Shot 设计与首尾帧条带图（故事/动作/运镜/负向约束）、编号防泄漏规则、素材合成映射与后续 GU 执行结构。

## 4. 阶段审核门定义

1. **人物审核门（Character Gate）**：呈现人物胸部以上四视图（30s 模式）或人物五视图（TV 素材池模式），核验五官三维结构、鼻骨立体度、眼神自然度与皮肤真实毛孔；批准后冻结写入 `visualbible.md`。
2. **故事审核门（Story Gate，三维一体审核）**：在单元 `review.md` 集中审核——① 角色（人物 + 服装无脸三视图 + `01-character-card.png`）、② 剧情（是否忠实还原一句话故事圣经）、③ 分镜（`02-storyboard-grid.png` + 首尾帧条带图 + 跨镜连续性 + 负向防溢出）。无底图参考纯文本生成含人物关键帧一律标 `Warning`，未经人类显式批准严禁进入渲染。
3. **渲染任务确认门（Render Submission Gate）**：呈现 Generation Unit Task Manifest，核验三同定律、4–15 秒时长、内部 Shot 数量（<= 2–3 个）、`frozen` 状态、不可变引用与 H3 六段式/Omni 7 槽位提示词；批准后冻结 `input/manifest.json` 或 `spec.json` 并调用 Video Skill。
4. **逐镜质检门（Shot Gate）**：先完成 K09 内容分级并过滤 `nsfw`，再为每个 `general` 候选提供可播放视频、全时长 1 秒 1 帧接触表与 `output/baseline/` 对比；按 1 倍速完整播放核对身份稳定性、肢体表演、位移连贯性、动作周期、背景视差、相机轨迹与技术参数，在 `review.md` 就地记录选用、定向重做或否决。
5. **锁定与交付门（Picture Lock & Release Gate）**：全部目标音频区间由批准素材无缝覆盖且无 `storyboard_placeholder` 后，静音生成素材内生音轨，从零时码统一挂载批准 Master WAV 并按批准 LRC 生成字幕；完整播放核验无黑帧、无抽搐、无错位、音画同步与字幕无越界，交付主视频、无字幕版、字幕版、封面与元数据，先 `project.commit` 归档，不自动触发 `world.register`。
