# 执行流程

## 1. 接入检查

确认服务已安装，宿主 MCP 列表包含 `verdantflare-agent-claude`。配置入口由 `VERDANTFLARE_AGENT_CLAUDE_SERVICE` 指定，默认从用户数据目录的 `verdantflare-agent-claude/service.json` 读取。

运行 `claude_capabilities`，必要时传入 `cwd` 与分页 `cursor`；核对目标 `session_id`（或 `thread_id`）及 `panel_reachable`、`panel_status`。`panel` 模式找不到在线空闲面板会话时，先请用户打开或等待该面板空闲，或显式改用 `managed` 模式。

## 2. 任务交接与派单

`claude_session_rename` 接受明确的 session_id、cwd、name；仅操作已有且当前无活动占用的会话。服务校验工作区后通过原生 CLI 控制请求改名，不发模型提示词；回读最新 customTitle 一致才返回 native。在线面板及未知任务占用时拒绝另开命名连接，使用逻辑名并保留未验证项。先检查当前 MCP 是否已加载该工具，不把源码支持当成全局安装已更新。

交接文本至少包含目标、涉及路径、输入材料、边界约束、验证命令和完成标准。调用 `claude_task_start`，`panel` 与 `managed` 两种模式均必须传入新的 `request_id`、明确的 `mode`、绝对 `cwd` 与 `prompt`；`panel` 模式必须传入在线空闲的 `session_id`（或 `thread_id`）。

保存返回的 `task_id` 与 `session_id`。启动返回 `queued` 仅表示任务已入队受理。通信超时后先查原任务或用同一 `request_id` 重试，不另造编号重发。

## 3. 查询与结果回收

使用 `claude_task_status` 查询状态、当前 `turn_id` 与增量事件；下次携带 `after_event` 接续读取，直到 `has_more=false`。

进入终态后调用 `claude_task_result`。结果的 `content_json` 是可分页的 JSON 文本片段，按 `next_cursor` 顺序拼接后解析，核对 `answer`、`file_changes`、`commands` 与 `unresolved`。

## 4. 续接与取消

`claude_task_continue` 需要 `task_id`、新的 `request_id`、`prompt` 和上一轮 `expected_turn_id`。仅上一轮终态后受理；同一任务保留历史轮次结果。

`claude_task_cancel` 必须携带当前 `expected_turn_id`。`managed` 模式安全终止受管 CLI 子进程并收敛为 `cancelled`；`panel` 模式禁止强杀用户 VS Code 面板宿主进程，需在面板 UI 停止。

## 5. 失败恢复

start/continue 在事务入队时绑定受理服务的 worker；保持该连接存活，其他只读连接不会抢领其执行轮次。owner 丢失后，只有数据库证明命令从未领取的 queued 请求可重新领取；已领取或提交的不确定任务保留租约和原轮次，不重发。interrupted_unknown 不能靠 cancel 直接改成 cancelled，必须先取得后端终态证据；禁止清库解除占用。

`SESSION_BUSY` 表示工作区父子路径租约或目标会话正忙。等待当前任务结束，或使用隔离工作区与独立会话。

CLI 派单需要 `--wait` 让后台执行进程保持存活直到当前轮次完成；MCP 常驻连接下可异步轮询：

```powershell
python scripts/launch.py --call claude_task_start --arguments task.json --wait
python scripts/launch.py --call claude_task_status --arguments status.json
```

受管模式的 CLI 轨迹可有原生 customTitle，但当前 Claude Code 扩展默认过滤 entrypoint 为 sdk-cli、sdk-ts 或 sdk-py 的会话。因此“原生标题回读”“默认插件列表展示”“在线 panel 通信”须分别验证；不得用修改来源字段或用户设置伪造可见性，也不因面板未展示而否定已验证的 managed 通知回传。
