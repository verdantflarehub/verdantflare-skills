# 验收标准

## 1. 静态与协议验证

技能结构检查、Markdown 检查、自包含单测（使用运行时虚拟环境 Python 执行 `-m unittest discover -s scripts -p "test_*.py"`）及安装文件全量 SHA-256 哈希比对通过。标准 MCP 客户端能够初始化、列出八项工具、调用 `claude_capabilities`；非法字段、超限提示词和错误编号返回结构化错误码。

原生命名验证 UUID 和工作区、控制请求不产生 user 消息、最新自定义名称回读、在线会话拒绝；多连接测试验证 start/continue 由受理连接领取、未领取任务的安全恢复和未知任务保留租约，不能用请求取消代替后端确认。

## 2. 行为验证

使用验收会话完成闭环：提交任务（`claude_task_start`）、查询进度（`claude_task_status`）、读取结果（`claude_task_result`）与同会话续接（`claude_task_continue`）。核对 `.claude/projects/<encoded-cwd>/<sessionId>.jsonl` 轨迹落盘及 VS Code 面板可见性。

重复 `request_id` 幂等、父子目录并发冲突拦截、递归防护与取消流程有对应测试证据。

## 3. 业务完成判定

任务完成须同时满足约定产物存在、内容正确、验证命令通过且无未解决问题。模型口头声明不能代替真实文件与命令退出码证据。

技能可见、MCP 已注册、真实工具可调用和人工确认分别报告。跨智能体接入须至少由另一个宿主或 CLI 调用实测留证。

## 4. 交付记录

交付记录包含扩展与 CLI 版本、运行模式、任务与会话编号、产物位置、验证结果及人工结论。公开报告脱敏账号、`peerToken` 和本机个人路径。
