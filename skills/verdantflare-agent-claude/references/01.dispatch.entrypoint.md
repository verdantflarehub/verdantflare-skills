# Claude Code 跨智能体派单与结果回收（01.dispatch）

## 1. 输入与输出

- **输入**：明确的工作目录绝对路径 `cwd`、新的 `request_id`、明确的 `mode`（`panel` 或 `managed`）、包含目标/涉及路径/输入材料/边界约束/验证命令/完成标准的 `prompt`；`panel` 模式另须传入在线空闲的 `session_id`（或 `thread_id`）；续接与取消传入 `task_id` 与 `expected_turn_id`。
- **输出**：持久任务编号 `task_id`、会话编号 `session_id`、轮次编号 `turn_id`、增量事件流与分页 `content_json`（含 `answer`、`file_changes`、`commands`、`unresolved`）及 `.claude/projects/<encoded-cwd>/<sessionId>.jsonl` 轨迹证据。
- **技能入口**：[SKILL.md](../SKILL.md)。

## 2. 分类

将有明确工作目录、输入材料、分析或修改范围和验收标准的任务交给 Claude Code（克劳德），适用于问题诊断、方案设计、执行交接书编制、代码评审及受授权的本地工作区操作。

- **`panel`**：指定 VS Code 中已打开且在线的 Claude Code 面板会话；`claude_capabilities` 须显示 `panel_reachable=true` 且 `panel_status="idle"`。通过本机 Named Pipe 注入消息并实时同步至面板与 `.jsonl` 轨迹，不会擅自新建插件标签页。
- **`managed`**：调用者明确选择受管 CLI 流式执行（`claude.exe -p --output-format stream-json --verbose`）；自动写入 `.claude/projects/<encoded-cwd>/<sessionId>.jsonl`，VS Code 面板 Past Conversations 可直接加载查看。

`claude_capabilities` 返回版本、会话摘要、面板在线状态、过滤计数和分页游标；`read_verified` 只证明当前会话探测可达，任务成败以真实返回与文件证据判定。

## 3. 工作流

### 3.1 接入检查

确认服务已安装，宿主 MCP 列表包含 `verdantflare-agent-claude`。配置入口由 `VERDANTFLARE_AGENT_CLAUDE_SERVICE` 指定，默认从用户数据目录的 `verdantflare-agent-claude/service.json` 读取。运行 `claude_capabilities`，必要时传入 `cwd` 与分页 `cursor`；核对目标 `session_id`（或 `thread_id`）及 `panel_reachable`、`panel_status`。`panel` 模式找不到在线空闲面板会话时，先请用户打开或等待该面板空闲，或显式改用 `managed` 模式。

### 3.2 会话命名与任务派单

- **会话命名（`claude_session_rename`）**：接受明确的 `session_id`、`cwd`、`name`，仅操作已有且当前无活动占用的会话。服务校验工作区后通过原生 CLI 控制请求改名，不发模型提示词；回读最新 `customTitle` 一致才返回 `native`。在线面板及未知任务占用时拒绝另开命名连接，使用逻辑名并保留未验证项。先检查当前 MCP 是否已加载该工具，不把源码支持当成全局安装已更新。
- **任务派单（`claude_task_start`）**：交接文本至少包含目标、涉及路径、输入材料、边界约束、验证命令和完成标准。`panel` 与 `managed` 两种模式均必须传入新的 `request_id`、明确的 `mode`、绝对 `cwd` 与 `prompt`；`panel` 模式必须传入在线空闲的 `session_id`（或 `thread_id`）。保存返回的 `task_id` 与 `session_id`。启动返回 `queued` 仅表示任务已入队受理；通信超时后先查原任务或用同一 `request_id` 重试，不另造编号重发。

### 3.3 查询、续接与取消

- **查询进度（`claude_task_status`）**：查询状态、当前 `turn_id` 与增量事件；下次携带 `after_event` 接续读取，直到 `has_more=false`。
- **读取结果（`claude_task_result`）**：进入终态后调用。结果的 `content_json` 是可分页的 JSON 文本片段，按 `next_cursor` 顺序拼接后解析，核对 `answer`、`file_changes`、`commands` 与 `unresolved`。
- **续接任务（`claude_task_continue`）**：需要 `task_id`、新的 `request_id`、`prompt` 和上一轮 `expected_turn_id`。仅上一轮终态后受理；同一任务保留历史轮次结果。
- **取消轮次（`claude_task_cancel`）**：必须携带当前 `expected_turn_id`。`managed` 模式安全终止受管 CLI 子进程并收敛为 `cancelled`；`panel` 模式禁止强杀用户 VS Code 面板宿主进程，需在面板 UI 停止。

### 3.4 失败恢复与 CLI 派单

`start` / `continue` 在事务入队时绑定受理服务的 worker；保持该连接存活，其他只读连接不会抢领其执行轮次。owner 丢失后，只有数据库证明命令从未领取的 `queued` 请求可重新领取；已领取或提交的不确定任务保留租约和原轮次，不重发。`interrupted_unknown` 不能靠 `cancel` 直接改成 `cancelled`，必须先取得后端终态证据；禁止清库解除占用。

`SESSION_BUSY` 表示工作区父子路径租约或目标会话正忙。等待当前任务结束，或使用隔离工作区与独立会话。

CLI 派单需要 `--wait` 让后台执行进程保持存活直到当前轮次完成；MCP 常驻连接下可异步轮询：

```powershell
python scripts/launch.py --call claude_task_start --arguments task.json --wait
python scripts/launch.py --call claude_task_status --arguments status.json
```

受管模式的 CLI 轨迹可有原生 `customTitle`，但当前 Claude Code 扩展默认过滤 entrypoint 为 `sdk-cli`、`sdk-ts` 或 `sdk-py` 的会话。因此“原生标题回读”“默认插件列表展示”“在线 panel 通信”须分别验证；不得用修改来源字段或用户设置伪造可见性，也不因面板未展示而否定已验证的 `managed` 通知回传。

## 4. 规范

1. **授权与权限**：上游任务授权与 Claude Code 面板权限确认分别记录。`panel` 模式下的工具权限确认保留在 VS Code 面板 UI（调用 `claude_task_respond` 或 `claude_task_cancel` 均返回 `APPROVAL_REQUIRES_UI`，不篡改运行态或强杀用户面板）；`managed` 模式面向无人值守子进程，默认启用 `--permission-mode bypassPermissions` 自动放行工具调用。
2. **禁止递归委托**：`managed` 模式通过注入 `VERDANTFLARE_AGENT_CLAUDE_DEPTH=1` 环境变量硬拦截；`panel` 模式因复用已启动的面板进程，通过防递归提示词前缀与工作区写租约双重拦截。不在忙碌会话上强行注入消息。
3. **参数与幂等**：提示词非空且 UTF-8 不超过 64 KiB；任务超时为 30～86400 秒，默认 3600 秒；未知字段直接拒绝。同一 `request_id` 与相同参数幂等返回原任务；相同 `request_id` 不同内容报 `REQUEST_CONFLICT`。续接和取消绑定 `expected_turn_id`，过期轮次报 `STALE_TURN`。
4. **工作区与存储**：工作目录须为有效绝对路径（配置 `allowed_roots` 为 `["*"]` 或 `[]` 时支持任意绝对工作区路径；配置具体路径列表时限定在允许根内），按真实路径校验父子目录写任务互斥与同一 `session_id` 租约互斥。任务、命令队列、轮次、事件和租约保存在用户数据目录 SQLite 中，技能目录只保存静态指导与启动器。

## 5. 验收

- **行为验证**：使用验收会话完成闭环——提交任务（`claude_task_start`）、查询进度（`claude_task_status`）、读取结果（`claude_task_result`）与同会话续接（`claude_task_continue`），核对 `.claude/projects/<encoded-cwd>/<sessionId>.jsonl` 轨迹落盘及 VS Code 面板可见性。重复 `request_id` 幂等、父子目录并发冲突拦截、递归防护与取消流程均有对应测试证据。
- **命名与多连接验证**：原生命名验证 UUID 和工作区、控制请求不产生 user 消息、最新自定义名称回读、在线会话拒绝；多连接测试验证 `start`/`continue` 由受理连接领取、未领取任务的安全恢复和未知任务保留租约，不能用请求取消代替后端确认。
- **业务完成判定**：任务完成须同时满足约定产物存在、内容正确、验证命令通过且无未解决问题；模型口头声明不能代替真实文件与命令退出码证据。技能可见、MCP 已注册、真实工具可调用和人工确认分别报告；跨智能体接入须至少由另一个宿主或 CLI 调用实测留证。
- **交付记录**：包含扩展与 CLI 版本、运行模式、任务与会话编号、产物位置、验证结果及人工结论；公开报告脱敏账号、`peerToken` 和本机个人路径。
