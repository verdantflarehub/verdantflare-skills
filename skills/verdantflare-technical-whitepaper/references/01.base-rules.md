# 技术图与文档规则

## 1. 当前依据

- [技能入口](../SKILL.md)：适用范围。
- 用户于 2026-11-16 最终明确：总体架构图不渲染图名简介和审核状态；图例属于图的一部分，采用图块加解释，新建、首期、利旧由图例解释。此最新纠正替代此前图例放在图外的要求。本技能将该要求作为此类交付的默认规范，用户后续明确要求可调整。

## 2. 总体架构图内保留什么

图片保留架构所需的主体名称、模块名称、功能、协议、关系、连线，以及解释视觉样式的图例。通用参与者使用“用户”，不把项目负责人的昵称写入角色节点，除非用户明确要求展示具体身份。

图内不出现整图标题、图名、介绍、摘要或说明性页脚；不出现“已通过”“待审核”“CP0 未通过”等审批或进度状态。图例置于图内独立区域。模块名称不是整图标题，协议标签不是简介，不得为清理装饰文字而删除必要架构信息。

节点不附加“新建”“利旧”“首期”“后续”等解释性标签。用有确定含义的视觉样式表达，在图内图例解释。不要把这些词换成角标、徽章或水印继续贴在业务节点上。

## 3. 图内图例：图块加解释

图例属于架构图的一部分，须随 PNG、SVG 或其他导出文件完整输出。图例在图内独立区域排布，与业务节点分开，不覆盖连线。审核状态仍单列在文档状态区域，不属于图例。

每个图例项由一个可见示意图块及紧邻的简短解释组成；图块复现图中实际填色、边框或连线样式。不只列颜色名称，不在图块中塞长说明。图片应自带必要的功能性图例，读者无需离开图片猜测功能样式含义。

图例只保留有解释必要的功能性样式。主体名称已在节点中明确，不再添加“个人助理”“VF Center”“VF Station”等描述性图例；普通数据线和箭头含义直观，不另加数据流方向、双向交互图例。确有非标准连线语义时才解释其特殊含义。

本类图的功能性图例保留利旧能力、新建能力、首期接入、后续扩展；标签省去“平台”等可从上下文判断的前缀，不扩充无关图例。

业务归属和建设状态分开编码：不同主体用不同色系；同一主体色系中饱满色表示利旧，浅色表示新建。利旧需改造时另用边框等样式，并提供对应图例。没有事实依据的复用不能画为已有能力。

实施阶段另用独立样式，如实线框表示首期、虚线框表示后续；这是一种可调整选择，确定后在同一套图中保持一致。不得同时用浅色表示新建和后续，否则无法区分“首期新建”与“后续新建”。组合图例应能解释实际出现的组合，不为不存在的类别添图例。

图例图块与主图使用同一套样式定义，在可编辑图源中作为图的一组元素维护。导出图片包含该区域；插入 Word、PDF、HTML 或 Markdown 时不裁掉图例，也不另造与主图脱节的外置图例。

## 4. 图文边界与真实性

图名置于文档标题或图题；简介置于图前或图后段落；审核状态置于文档状态栏；图例置于图片内的独立区域。部署图沿用该分离原则，除非用户对该图明确另有要求。

已有模块、拟新增能力、待核定事项以事实为准。尚未解决的关键位置或接口在文档记录，不用装饰性标签掩盖不确定性；可以继续完成不依赖该问题的图稿。图已生成、视觉检查、技术核验与人类审核分别说明，“继续”不自动构成检查点通过。
