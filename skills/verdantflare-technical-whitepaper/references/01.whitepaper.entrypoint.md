# 技术白皮书编制与图文一致性核验（01.whitepaper）

## 1. 输入与输出

- **输入**：当前项目需求、有效设计文档、接口与数据约定、部署现状、待决事项以及配套架构图（如有）。
- **输出**：结构完整、可审阅的图文技术白皮书，含文档级图名/图题、必要简介、独立审核状态栏、可访问的图文引用及明确的未完成项清单。
- **公共依据**：[技能入口](../SKILL.md)；配套架构图绘制见 [02.architecture-diagram.entrypoint.md](./02.architecture-diagram.entrypoint.md)。

## 2. 分类

按交付物职责区分文档与配图边界：

- **技术白皮书文档**：将问题、方案、技术选型、接口、数据、部署、验证与待决事项组织成可审阅文档。按任务需要选择配图，不机械扩充页数。
- **文档承载元素 vs 图片承载元素**：图名、简介和审核状态属于文档内容；功能性图例属于架构图本身，随图片完整导出，不在文档中另造与主图脱节的外置图例。
- **项目独立性**：具体技术栈、FAQ 与证据必须依据当前项目事实，不能从上一项目照搬。

## 3. 工作流

1. **需求与事实盘点**：读取当前需求与有效设计，恢复已有文档、图源及人工反馈，严格区分有效决定与历史草稿。列出系统主体、功能、关系及证据，再决定需要配哪些图。用户明确暂停绘图时停止对应制作任务；整理技能不自动恢复原图制作。
2. **结构编排与图文分离**：围绕问题、方案、技术选型、接口、数据、部署、验证与待决事项起草正文；在文档中设置图名（文档标题或图题）、图前或图后简介段落、以及独立审核状态栏。
3. **嵌入配图与同步修订**：将导出且包含内置图例的架构图插入 Markdown、Word、PDF 或 HTML，确保不裁掉图例。图的修订同步更新文档引用与说明，不覆盖需保留的批准原件。
4. **图文一致性检查与交付**：检查文档中的图题、简介和审核状态是否与最终导出图片一致，核实所有引用可访问；修改后只重验受影响内容。交付包含说明的文档入口与配图，明确未完成项。缺少用户决定时保留问题并继续独立工作，不重复索取已有批准，不把等待答复写成方案通过。

## 4. 规范

1. **图文边界红线**：图名置于文档标题或图题；简介置于图前或图后段落；审核状态置于文档状态栏；图例置于图片内的独立区域。插入文档时不得裁掉图片内置图例，也不得另造与主图脱节的外置图例。
2. **事实真实性**：已有模块、拟新增能力、待核定事项以事实为准；没有事实依据的复用不能写成已有能力。尚未解决的关键位置或接口在文档中如实记录，不用装饰性标签掩盖不确定性；可以继续完成不依赖该问题的章节与图稿。
3. **状态分列汇报**：图已生成、视觉检查、技术核验与人类审核必须分别说明，“继续”不自动构成检查点通过，不因技能执行增加审批或恢复已暂停的研发。
4. **工具中立**：本能力不固化某项目的系统名称、技术栈、配色或负责人；Markdown、PDF 等格式交付按实际环境选用对应工具或技能。

## 5. 验收

- 文档清晰覆盖当前任务所需的问题、方案、技术选型、接口、数据、部署、验证与待决事项，无照搬上一项目的技术栈或 FAQ。
- 文档提供图名、必要简介与独立审核状态栏；引用的架构图均完整保留图内图例，未在文档侧另造脱节外置图例。
- 文档所有图文引用均可访问，图题、简介、状态说明与最终导出图内容一致。
- 已生成、已视觉检查、技术核验及人工审核结论分别报告，未把等待答复写成通过。
