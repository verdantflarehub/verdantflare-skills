# 技术图与白皮书验收

## 1. 当前依据

- [规则约束](01.base-rules.md)：唯一图文规则来源。
- [执行流程](01.base-workflow.md)：检查顺序。

## 2. 可观察检查

- 总体图与部署图职责分明；同机服务仍有独立业务边界。
- 架构图片中整图标题、简介、审核状态的数量均为零；图例随图片完整导出。
- 节点内不残留新建、利旧、首期等状态文字或同义徽章；业务模块名称及必要协议仍完整。
- 文档提供图名、必要简介与独立审核状态；图内图例项均为实际示意图块加解释。
- 图例仅解释必要的功能性样式；不重复主体名称，不解释普通数据线。首期接入、后续扩展等标签无冗余前缀，建设状态与阶段语义不冲突。
- 实际查看最终渲染，文字不裁切、节点不重叠、箭头不误指，图片与可编辑源对应。
- 文档引用可访问，已生成、已检查及人工结论分别报告。

## 3. 规则辨识样例

不合格：图片顶部写“总体架构图”，右上写“CP0 未通过”，即使主体结构正确也不合格；图内独立图例本身是正确组成，不是违规项。

不合格：节点写“服务 A〔新建·首期〕”，或把这段文字改成角标；仍将图例解释混入业务节点。

合格结构：文档标题为总体架构图；图片画用户、业务主体、模块及协议箭头，并在图内独立图例区域用饱满色图块说明利旧、浅色图块说明新建，再以实线和虚线图块说明首期与后续。

本节样例用于规则辨识，不证明任何既有图片已修正或获得人工认可。静态检查只验证技能结构；实际图稿必须另做视觉核验。
