# Prettier 格式化与量化检查（01.format-check）

## 1. 输入与输出

- **输入**：本次交付的明确 Markdown 文件路径列表、可选的 `--prettier` 路径或环境变量 `VERDANTFLARE_PRETTIER`，以及编辑前采集的 `md_format.py --check` 原始基线状态。
- **输出**：经 [md_format.py](../scripts/md_format.py) 稳定格式化的 Markdown 文件、`md_format.py --check` 退出码与 Prettier 路径/版本，以及 [check_md.py](../scripts/check_md.py) 输出的逐条 `E`/`W` 诊断与 `PASS`/`FAIL` 结论。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的规则优先级、浅层列表、跨平台 LF 与格式化设置边界。

## 2. 分类

| 检查与处理分支 | 判定条件与处理策略                                                                            |
| :------------- | :-------------------------------------------------------------------------------------------- |
| 标准全量格式化 | 新建文件、实质修改或用户要求整理的文档；落盘后执行 `md_format.py`、`--check` 与 `check_md.py` |
| 存量小改豁免   | 编辑前 `--check` 已不合格式且仅改错字、链接、少量字句或个别列表项；只保改动区合规，免全量重排 |
| 生成器同步区域 | 含生成脚本同步区域的文档；格式化后须运行目标仓库 `--sync-md-only --dry-run` 或预览检查        |
| Prettier 缺失  | 四级探测全部失败返回退出码 `2`；交付说明如实标“Format 未完成”及原因，不无版本自动下载         |

## 3. 工作流

### 3.1 Format 工具探测与命令

依赖见 [requirements.txt](../scripts/requirements.txt)；从其他目录调用时使用已发现的安装路径：

```text
python -m pip install -r scripts/requirements.txt
python -X utf8 scripts/md_format.py --check docs/example.md
python -X utf8 scripts/md_format.py docs/example.md
python -X utf8 scripts/md_format.py --prettier /path/to/prettier docs/example.md
python -X utf8 scripts/check_md.py docs/example.md
```

[md_format.py](../scripts/md_format.py) 按以下顺序探测 Prettier，首个可用者生效并输出实际路径与版本：

1. 命令行参数 `--prettier` 或环境变量 `VERDANTFLARE_PRETTIER` 指定的可执行文件或 `prettier.cjs`。
2. 目标文件所在仓库自下而上找到的 `node_modules/.bin/prettier`。
3. `PATH` 中的 `prettier`。
4. 编辑器 Prettier 扩展自带的 `prettier.cjs`（VS Code、Cursor、Antigravity 等用户扩展目录），取版本最高者，用 `node` 执行。

### 3.2 落盘后格式化与复核闭环

1. **编辑前探针**：编辑存量文件前先执行 `md_format.py --check`，记录原始格式化状态用于小改豁免判断。
2. **落盘后格式化**：仅对本次交付的明确文件列表运行 `md_format.py`（不使用全仓通配符）；如满足小改豁免条件则跳过全文格式化并在交付说明写明“存量文件未格式化，按小改豁免”。
3. **差异复核**：检查格式化差异，核对事实、命令、代码块内容、配置片段、媒体路径和同步标签未被误改；发现重新产生大段列表缩进时将父项改为标题再格式化，不机械删空格或全文件忽略。
4. **量化检查与同步校验**：运行 `md_format.py --check` 与 `check_md.py`；含生成脚本同步区域时执行其预览/同步检查。
5. **人工反馈与提交前复验**：接受人工反馈修改后重新执行全流程；最终提交前对最终文件清单（含归档或移动后路径）再次执行格式化检查和结构检查。

## 4. 规范

- **默认参数与 `.prettierignore`**：目标仓库有 Prettier 配置时由 Prettier 自行解析；无配置时脚本附加 `--prose-wrap preserve --embedded-language-formatting off --end-of-line lf`，减少正文重折行与代码改写并跨平台强制 `LF (\n)`。脚本对显式文件只遵循 `.prettierignore`（规避 Prettier 3 静默跳过 `.gitignore` 命中文件导致误报通过）。
- **禁止无版本下载与隐瞒失败**：全部探测失败以退出码 `2` 结束，必须如实标记“Format 未完成”；关闭编辑器保存时自动格式化不影响本流程要求的显式 Format。
- **错误清零与警告说明**：`check_md.py` 所有 `E` 级错误必须清零；`W` 级警告逐条核实，属强制模板等合理例外时在交付说明注明。

## 5. 验收

量化阈值唯一定义于 [check_md.py](../scripts/check_md.py)：

| 规则代号（级别）        | 量化判据与阈值                                                     |
| :---------------------- | :----------------------------------------------------------------- |
| `eol-crlf`（`E`）       | 跨平台统一 `LF (\n)`，文件中 `\r`（`CR/CRLF`）数量为 `0`           |
| `list-depth`（`E`）     | 列表嵌套深度 `<= 2`（`MAX_LIST_DEPTH = 2`）                        |
| `table-columns`（`E`）  | 文字表格列数 `<= 4`（`MAX_TABLE_COLUMNS = 4`；媒体表格豁免）       |
| `table-width`（`E`）    | 文字表格格式化行宽 `<= 120` 显示列（全角计 2；媒体表格豁免）       |
| `table-br`（`E`）       | 表格单元格内 `<br>` 标签数为 `0`                                   |
| `heading-number`（`E`） | 一级标题不编号；启用编号的文档二级起按 `1.`、`1.1` 连续递增不跳级  |
| `broken-link`（`E`）    | 本地相对链接目标文件存在（断链数为 `0`）                           |
| `local-path`（`E`）     | 正文与链接目标中盘符路径或 `file://` 出现次数为 `0`                |
| `block-in-list`（`W`）  | 列表项内嵌代码块或表格提示警告，仅强制模板或步骤内必要代码块可保留 |
| `anchor`（`W`）         | Markdown 标题锚点未命中提示警告，须核对目标标题或说明例外原因      |

- **通过门禁**：`md_format.py --check` 返回 `0`（或明确豁免），`check_md.py` 返回 `0`（`E` 级错误为 `0`，汇总 `PASS`）；[review.md](review.md) 中预览单文件视频严格 `< 18MB`（编辑器预览上限约 `20MB`）。
- **交付报告口径**：静态检查通过只证明源码结构合规，不替代事实核验、编辑器预览视觉效果或业务审批；交付报告须如实记录文件清单、实测结果、保留的 `W` 级警告、小改豁免与未完成人工验证项。
