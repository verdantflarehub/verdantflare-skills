# 研发验收文档规范（acceptance）

## 1. 职责与适用边界

研发验收文档（主类型 `acceptance`）承载复杂研发计划“T1 三方审定验收流程、CP0 锁卷、T4 执行者取证与 Codex 核验 Claude 抽查、CP1 人类批准”全周期证据台账：

- **受控目录与命名**：活动期驻留 `docs/acceptance/`，随计划结项或废弃同构移入 `docs/archive/acceptance/`；文件名严格匹配 `^accept_\d{8}_[a-z0-9.-]+\.md$`（排除目录规范 `AGENTS.md` 与索引 `README.md`）。简单计划免建独立验收文档，验证记录收口于 `docs/changes/`。
- **目标仓库规则叠加**：本专册提供跨仓库可移植默认契约；目标仓库存在 `docs/acceptance/AGENTS.md` 时叠加其细化约束。

## 2. 文首必填字段与六态状态机

一级标题不编号，标题下、第一章前固定包含以下六个非空字段（禁止重复键）：

- **负责人**：默认沿用关联计划负责人。
- **执行助手**：在 `T1` 起草验收流程、在 `T4` 亲自取证的执行智能体及职责（协同取证者同样登记，视为作者）。
- **验真助手**：`T4` 全面核验执行者验收结果的研发智能体（默认 Codex 或 `D4-A` 非作者替补）与抽查 Codex 评价 `1～2` 项的 Claude（`T1–T3` 可写 `待 T4 登记`）。
- **关联计划**：指向所属计划文档的精确相对链接。
- **验收状态**：仅允许取六个标准状态之一——`考卷草案`、`考卷已锁定`、`实跑取证中`、`智能体已验真`、`CP1已通过`、`已废弃`。
- **更新时间**：`YYYY-MM-DD`。

## 3. 五章固定正文与量化检查

正文二级标题必须严格固定为以下五章且顺序不变：

1. `1. 当前依据`：逐行相对链接列出所属计划、专题设计、阶段评审报告与适用规范。
2. `2. 锁定验收场景与判据`：开头为“验收流程审定记录”（加粗标签 **执行者起草**、**研发核验修订**、**Claude 修订**、**分歧上报**），随后每个待验收对象一个 `### 2.x Sn` 场景，写明取证流程、证据内容、充分性判据与判定，作为 `CP0` 哈希锁卷切片。
3. `3. 智能体实跑与演示证据`：执行者按锁卷流程亲自取证，逐景记录真实退出码、核心指标摘要与受管证据相对链接，禁止堆放未整理的原始长日志。
4. `4. 防伪锚点与双轨验真`：依次记录工作区基准（`4.1`）、运行环境（`4.2`）、源码与测试脚本 `SHA-256`（`4.3`）、安装态或线上制品 `SHA-256` 及前期评审收据（`4.4`）、`T4` 核验与抽查原生会话收据（`4.5`）。
5. `5. CP1 呈报包`：提供结论与查看入口（`5.1`，含 Codex 核验摘要、Claude 抽查项与不超过 3 条入口）与人类决定（`5.2`，批准或不批准并附意见）；存量文档沿用旧章名 `5. CP1 双抽检核验单` 时等效。

`scripts/check_md.py` 对 `docs/acceptance/` 与 `docs/archive/acceptance/`（排除 `AGENTS.md`、`README.md`）实行失败闭合识别，自动校验命名正则、六项必填元数据、六态状态枚举及五章固定标题。
