# 分类与边界

## 1. 适用场景

将有明确工作目录、输入素材、高清化或修改目标及验收标准的任务交给 Grok（古若科）。专职系统图片、地图、界面素材重置高清化，以及受授权的工作区辅助研发任务。

## 2. 模式选择

- `acp`（默认推荐）：通过 `grok.exe agent --no-leader stdio` 运行 JSON-RPC 2.0 ACP 会话（`session/new`、`session/load`、`session/prompt`），生成非 `headless` 的标准会话目录（`summary.json`、`chat_history.jsonl`、`updates.jsonl`），并同步更新 `~/.grok/client-state/session-meta.json`，确保会话在 VS Code **AFK Pilot** 的 `grok.chat`（Recent）和 `grok.projects`（Projects）面板直接展示与点击回放。
- `headless`：调用者显式指定的无头单次模式（`grok.exe -p --output-format json`）。因 `summary.json` 会标记 `session_kind="headless"`，AFK Pilot 默认将其归入后台隐藏，不用于需要面板展示的任务。

`grok_capabilities` 返回 CLI 与 AFK Pilot 扩展版本、会话列表、`afk_pilot_visible` 与 `afk_pilot_registered` 状态。

## 3. 环境边界

当前适配面向 Windows、Grok CLI（`~/.grok/bin/grok.exe`）与 VS Code 扩展 **AFK Pilot**（`pawelhuryn.grok-vscode-phuryn-*`）。运行时跳过 `.obsolete` 动态探测最新有效扩展版本，不锁定单一扩展号；服务为本机 stdio，不提供公网监听。

认证由 `~/.grok/config.toml` 或环境变量管理。技能文件不保存 API 密钥，也不把凭据写入任务参数。
