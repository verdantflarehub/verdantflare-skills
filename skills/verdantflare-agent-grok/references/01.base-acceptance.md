# 验收标准

## 1. 静态与协议验证

技能结构检查、Markdown 检查、自包含单测（使用运行时虚拟环境 Python 执行 `-m unittest discover -s scripts -p "test_*.py"`）及安装文件全量 SHA-256 哈希比对通过。标准 MCP 客户端能够初始化、列出七项工具、调用 `grok_capabilities`；非法字段、超限提示词和错误编号返回结构化错误码。

## 2. 行为与 AFK Pilot 展示验证

使用 `acp` 模式完成闭环：提交任务（`grok_task_start`）、查询进度（`grok_task_status`）、读取结果（`grok_task_result`）与同会话续接（`grok_task_continue`）。

核对三项落盘证据：

- `~/.grok/sessions/<urlencoded-cwd>/<sessionId>/` 下存在 `summary.json`、`chat_history.jsonl`、`updates.jsonl`，且 `summary.json` 的 `session_kind` 不为 `"headless"`。
- `~/.grok/client-state/session-meta.json` 中存在对应 `<sessionId>` 条目，且 `provider="grok"`、`providerCwd` 与 `activeAt` 已更新。
- `grok_capabilities` 返回该会话 `afk_pilot_visible=true` 且 `afk_pilot_registered=true`。

## 3. 业务完成判定

任务完成须同时满足约定产物存在、内容与尺寸符合规范、验证命令通过且无未解决问题。模型口头声明不能代替真实文件校验。

技能可见、MCP 已注册、真实工具可调用、AFK Pilot 会话同步和人工确认分别报告。跨智能体接入须至少由另一个宿主或 CLI 调用实测留证。

## 4. 交付记录

交付记录包含 CLI 与 AFK Pilot 版本、运行模式、任务与会话编号、产物位置、验证结果及人工结论。公开报告脱敏账号、密钥和本机个人路径。
