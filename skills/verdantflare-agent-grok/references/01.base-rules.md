# 规则约束

## 1. 授权与权限

上游任务授权与视觉母版人工审定分别记录。首轮基准母版必须先经人工审定通过，严禁未经审定直接批量衍生。`acp` 模式面向后台无人值守派单，默认启用 `--always-approve` 并在收到 `session/request_permission` 时自动选择 `allow` 放行工具调用；人工接管交互在 AFK Pilot 面板内完成。

禁止递归委托同一个服务（服务向子进程注入 `VERDANTFLARE_AGENT_GROK_DEPTH=1` 并在入口硬拦截，同时附加防递归提示词前缀）。

## 2. 参数与幂等

提示词非空且 UTF-8 不超过 64 KiB；任务超时为 30～86400 秒，默认 3600 秒。未知字段直接拒绝。

同一 `request_id` 与相同参数幂等返回原任务；相同 `request_id` 不同内容报 `REQUEST_CONFLICT`。ACP 会话通过 session/load 恢复，headless 使用 --resume；--session-id 只表示新会话 ID，不用于续接。续接和取消绑定 `expected_turn_id`，过期轮次报 `STALE_TURN`。

## 3. 工作区、存储与 AFK Pilot 同步

工作目录须为有效绝对路径（配置 `allowed_roots` 为 `["*"]` 或 `[]` 时支持任意绝对工作区路径；配置具体路径列表时限定在允许根内），按真实路径校验父子目录写任务互斥与同一 `session_id` 租约互斥，interrupted_unknown 同样保留占用，不能以 cancel 无证据释放。新建和续接受理后固定由该连接 worker 领取；仅原命令未领取时可以在 owner 丢失后恢复。

`acp` 模式下，服务在 `initialize` 阶段将 `clientCapabilities.fs` 与 `terminal` 声明为 `false`，使 `grok.exe` 使用内置工具直接落盘 `~/.grok/sessions/<urlencoded-cwd>/<sessionId>/`，并由服务原子更新 `~/.grok/client-state/session-meta.json`（保留用户自定义的 `customName` 与 `pinned` 字段）。

## 4. 兼容与维护

本规则基于 Grok CLI `1.0.77` ACP stdio 协议与 VS Code 扩展 `pawelhuryn.grok-vscode-phuryn` `4.15.8` 实测。扩展或 CLI 升级后须重新运行探测脚本校验会话目录结构与 `session-meta.json` 字段。

技能源码在仓库 `skills/verdantflare-agent-grok/` 唯一维护，安装副本更新通过安装脚本同步。公开文档严禁写入本机绝对路径、用户名或 API 密钥。
