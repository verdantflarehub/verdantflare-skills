# 技能设计与编写公共规范

## 1. 当前依据

- [技能入口](../SKILL.md)：范围、原子能力清单与工具入口。
- [检查器](../scripts/lint_skill.py)：静态上限常量的唯一定义处。

## 2. 入口 SKILL.md 硬约束

入口只回答三个问题：这个技能管什么、提供哪些原子能力入口、用什么工具。固定三个二级标题，顺序不变：

1. **范围与边界**：一到两段，写能力定位、适用请求、不做什么、上下游协作对象。
2. **能力清单与按任务读取**：标题保留「读取」关键字以兼容检查；两列路由表**只列出真正的原子能力**（左列为极简短名，右列直指对应 `references/NN.<capability>.entrypoint.md`）。左列命名必须经过**减字迭代**（反复检查“能否再减 1 字而不丢语义”），控制在 **2～8 字**（如 `T2V`、`FL2V`、`架构设计`、`新建技能`），超过 12 字检查器将给出超长告警。禁止把 `00.common.*.md` 伪装成原子能力写进表格——公共专册由各能力入口引用，如需在 `SKILL.md` 提及只在表格下方用一句话带过。所有 `NN.<capability>.entrypoint.md` 均须出现在表中。
3. **工具与命令**：主脚本链接与最常用的最短命令；完整参数、示例与排障写进对应能力入口或工作流子专册。

目标仓库规则要求的「编码规范」等章节可作为可选首节，其余章节一律不得出现在入口。front matter 的 `description` 说明提供哪些原子能力、何时触发、不做什么，不写实现细节。

| 入口上限        | 数值                      |
| :-------------- | :------------------------ |
| 正文字符数      | 4000（不含 front matter） |
| 代码块总行数    | 20                        |
| 三级标题        | 3 个，禁止四级及以下      |
| 根目录 Markdown | 仅 `SKILL.md`             |

以下内容禁止写进入口：分类判据与分支细节、步骤清单、阈值与门禁定义、评分表、长命令速查、上下游数据包字段、经验教训、试错过程、版本历史、FAQ。

## 3. 能力专册与公共层约束

- **扁平前缀成组**：单个原子能力优先单文件自包含在 `references/NN.<capability>.entrypoint.md`；当单文件超过 10000 字符（检查器给出警告）或某维度独立复杂时，按需拆出同前缀子专册 `NN.<capability>.{category,workflow,rules,acceptance}.md`，并由对应 `entrypoint.md` 链接。
- **公共层按需存在**：`references/00.common.{category,workflow,rules,acceptance}.md` 仅在多个原子能力共享内容时创建，不强求建齐 4 份空壳；单能力技能通常无需 `00.common.*`。
- **禁止无主与复制**：同一条阈值或规则只在一处定义，其他位置用相对链接引用；新增专册必须在入口或对应 `entrypoint.md` 登记。
- **经验不堆历史**：验证前留在项目变更或设计文档，验证通过后提炼为规则、步骤或验收判据写入对应能力；不设 `lessons.md`、`FAQ.md`，常见问题拆进工作流的失败恢复或规范的例外。

## 4. 指令质量与可移植性

- 优先写能改变执行决策的信息：输入输出、前提、关键步骤、约束、异常处理和完成条件。只有确定性、安全性或真实操作脆弱点使用强制措辞；默认值写明可调条件，不把单次成功案例、固定模型、分辨率或个人偏好提升为通用硬约束。
- 依赖和最低版本写清楚，脚本相对自身定位资源，业务路径通过参数或配置传入，凭据不进入模板。发生外部写入、付费调用或不可逆操作时按实际授权处理；有重试的流程定义停止条件。
- 全局安装的技能不链接其他技能或仓库资产，协作对象只以名称提及；仓库内技能可链接本仓库资产并在入口写明仅限该仓库使用。

## 5. 文风与排版

一级标题不编号、二级起连续编号；表格写法以 Markdown 治理技能（如 `verdantflare-meta-markdown`）为准，`--style numbered` 检查其中可自动验证的部分。历史文献与第三方原文保留原格式，不为了 lint 通过篡改引用内容。
