# 技能架构与原子能力设计（01.design）

## 1. 输入与输出

- **输入**：目标领域的业务需求、已有脚本/工作流或待梳理的技能范围。
- **输出**：技能目录规划方案、原子能力清单（`NN.<capability>` 编号与边界）及可选公共层清单（`00.common.*`）。
- **公共依据**：[公共规范](./00.common.rules.md)。

## 2. 分类

按技能包含的原子能力数量与跨能力共享程度规划目录：

- **单能力技能**：仅需 `references/01.<cap>.entrypoint.md` 一份能力入口，无需 `00.common.*`。
- **多能力技能**（如 `vf-video` 含 `T2V / I2V / FL2V / REF2V`）：每个原子能力分配唯一两位编号（`01`~`99`）并建立 `NN.<cap>.entrypoint.md`；仅当多个能力共享规则、前置流程或门禁时，按需创建 `00.common.<维度>.md`。
- **长能力拆分**：某能力单文件超 10000 字符或某维度高度复杂时，按需拆出 `NN.<cap>.{category,workflow,rules,acceptance}.md`，其余短维度保留在 `entrypoint.md`。
- **按角色分型（Profile）**：底层技术与模型驱动归 `atomic`（默认）；面向业务的剧组单工种执行员（`*-crew-*`）归 `crew`，必须严守零底层渗透红线与对外独立交付粒度（详见[专员规范](./06.crew.entrypoint.md)）；后续按需平滑扩展 `expert`（纯领域知识/创作决策专家，如运镜设计）与 `director`（整片统筹导演）。

## 3. 工作流

1. **界定原子能力**：按“一次明确输入 → 一次可独立交付的输出”切分能力，命名使用小写 kebab-case（如 `01.t2v`、`02.i2v`、`03.fl2v`、`04.ref2v`）。
2. **明确能力五段式结构**：每个 `NN.<cap>.entrypoint.md` 固定包含「输入与输出 → 分类 → 工作流 → 规范 → 验收」，使执行者一跳看清函数签名并进入本能力闭环。
3. **提取跨能力公共层**：将多个能力重复引用的共享规则、公共术语或统一门禁提取到 `00.common.{category,workflow,rules,acceptance}.md`（按需建单个或多个）。
4. **设计数据驱动分类**（仅在输入来源不确定且分错会导致下游失败时）：在能力的「分类」章节定义前置取证探针、可复现的数值/布尔判据，以及分类到下游工作流/参数预设的确定性绑定。

## 4. 规范

统一扁平前缀目录结构如下（根目录仅允许 `SKILL.md` 一份 Markdown）：

```text
<skill-name>/
├── SKILL.md                           入口：范围与边界、能力清单与按任务读取、工具与命令
├── references/
│   ├── 00.common.<维度>.md            可选：跨能力共享（category/workflow/rules/acceptance 按需建）
│   ├── 01.<cap>.entrypoint.md         必备：原子能力 01 入口（输入/输出 + 分类/工作流/规范/验收）
│   ├── 01.<cap>.<维度>.md             可选：能力 01 篇幅超长时按需拆出的子维度专册
│   ├── 02.<cap>.entrypoint.md         可选：原子能力 02 入口
│   └── <主题>.md                      可选：接口、数据格式等独立主题专册
├── scripts/                           可选：脚本与测试
└── resources/ 或 assets/              可选：模板、样例与静态资源
```

四维职责划分：决定“适用哪类输入”归**分类**，决定“怎么做与失败恢复”归**工作流**，决定“能不能做与硬约束”归**规范**，决定“做得对不对与门禁”归**验收**。`00.` 仅保留给 `00.common.*`，能力编号从 `01` 起连续编排且不得重复。

## 5. 验收

- 人类或 Agent 打开 `SKILL.md` 可在 5 秒内盘点全部原子能力并一跳进入目标 `NN.<cap>.entrypoint.md`。
- 执行单个能力时，只需读取该能力的 `NN.<cap>.*` 与其引用的 `00.common.*`，无需加载其他无关能力上下文。
- 每个能力入口均具备明确的输入/输出与四维闭环，不存在未登记文件或空壳公共专册。
