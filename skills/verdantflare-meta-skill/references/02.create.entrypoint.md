# 新建技能与骨架初始化（02.create）

## 1. 输入与输出

- **输入**：技能目录名（小写 kebab-case，≤64 字符）、原子能力列表（如 `01.t2v,02.i2v,03.fl2v,04.ref2v`）及可选公共专册列表（如 `rules,acceptance`）。
- **输出**：通过 `lint_skill.py` 校验的完整技能目录与可复用脚本/模板。
- **公共依据**：[公共规范](./00.common.rules.md)、[架构设计](./01.design.entrypoint.md)。

## 2. 分类

- **单文件能力骨架（默认）**：适合中小型能力，每个能力只生成一份自包含的 `NN.<cap>.entrypoint.md`。
- **拆分能力骨架（`--split`）**：适合单个能力内容庞大的场景，额外为每个能力生成 `NN.<cap>.{category,workflow,rules,acceptance}.md` 并由 `entrypoint.md` 索引。
- **带公共层骨架（`--common`）**：多能力共享约束时，按需追加 `00.common.{category,workflow,rules,acceptance}.md`。

## 3. 工作流

1. 先按[架构设计](./01.design.entrypoint.md)确认确实需要技能而非普通项目文档，并定好能力编号清单。
2. 运行初始化命令生成非覆盖式合规骨架（命令在本技能安装目录运行，从其他目录调用时使用实际脚本路径）：

```text
python -m pip install -r scripts/requirements.txt
python -X utf8 scripts/lint_skill.py init /path/to/vf-video --capabilities 01.t2v,02.i2v,03.fl2v,04.ref2v --common rules
python -X utf8 scripts/lint_skill.py init /path/to/vf-video --capabilities t2v,i2v --split
python -X utf8 scripts/lint_skill.py lint /path/to/vf-video --style numbered --allow-placeholders
```

3. 依次填写每个 `NN.<cap>.entrypoint.md`（输入与输出、分类、工作流、规范、验收）及按需创建的 `00.common.*.md`，最后补全 `SKILL.md` 的 `description`、范围边界与最短命令。
4. 运行 `lint_skill.py lint <skill_dir> --style numbered` 清除全部 `TODO` 与结构错误，再按[评审与验收](./04.review.entrypoint.md)做真实样例行为验证。

## 4. 规范

- `init` 采用非覆盖模式：已存在文件一律保留；向已有技能追加新能力后，需手工将新能力行合入 `SKILL.md` 路由表。
- 名称不得包含保留词 `anthropic`、`claude`（`verdantflare-agent-*` 宿主调度技能除外）；非法能力编号（如 `00.`、重复编号、路径穿越）在预检阶段直接拦截，不产生半成品目录。
- 模板清单：[SKILL.template.md](../resources/templates/SKILL.template.md)、[NN.cap.entrypoint.template.md](../resources/templates/NN.cap.entrypoint.template.md)、[NN.cap.entrypoint-split.template.md](../resources/templates/NN.cap.entrypoint-split.template.md)、[NN.cap.dim.template.md](../resources/templates/NN.cap.dim.template.md)、[00.common.dim.template.md](../resources/templates/00.common.dim.template.md)。

## 5. 验收

- `lint_skill.py lint <skill_dir> --style numbered` 返回 `PASS`（0 errors），无未完成占位符。
- 技能自带脚本测试通过，且至少用 1 个真实或隔离样例验证触发、能力入口读取、命令执行与失败处理。
