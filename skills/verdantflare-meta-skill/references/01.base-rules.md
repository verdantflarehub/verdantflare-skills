# 入口与专册编写规则

## 1. 当前依据

- [入口](../SKILL.md)：授权范围和协作关系。
- [结构与分类](01.base-category.md)：统一目录与四维职责。
- [检查器](../scripts/lint_skill.py)：上限常量的唯一定义处。

## 2. 入口 SKILL.md 规则

入口只回答三个问题：这个技能管什么、遇到某类任务读哪份专册、用什么工具。固定三个二级标题，顺序不变：

1. **范围与边界**：一到两段，写能力、适用请求、不做什么、上下游协作对象。
2. **按任务读取**：两列路由表，左列任务或判定特征，右列专册链接；四份底座必须出现在表中，分支与主题专册按需追加。
3. **工具与命令**：主脚本链接与最常用的最短命令；完整参数、示例与排障写进执行流程。

目标仓库规则要求的「编码规范」等章节可作为可选首节，其余章节一律不得出现在入口。front matter 的 `description` 说明做什么、何时触发、不做什么，不写实现细节。

| 入口上限        | 数值                      |
| :-------------- | :------------------------ |
| 正文字符数      | 4000（不含 front matter） |
| 代码块总行数    | 20                        |
| 三级标题        | 3 个，禁止四级及以下      |
| 根目录 Markdown | 仅 `SKILL.md`             |

以下内容禁止写进入口：分类判据与分支细节、步骤清单、阈值与门禁定义、评分表、长命令速查、上下游数据包字段、经验教训、试错过程、版本历史、FAQ。

## 3. 专册规则

专册按[四维职责](01.base-category.md#3-四维职责)归位，单份超过 10000 字符时检查器给出警告，应按分支拆分或删减历史叙述。专册之间用相对链接引用，不复制同一段规则。新增 `<主题>.md` 须在入口路由表登记，不登记的文件视为无主资料。

经验与试错记录不进技能：验证前留在项目的变更或设计文档，验证通过后提炼为规则、步骤或验收判据写入对应专册，原始过程不搬入。`lessons.md`、`FAQ.md` 一类文件不设立；常见问题按性质拆进流程的失败恢复或规则的例外。

## 4. 指令质量

优先写能改变执行决策的信息：输入输出、前提、关键步骤、约束、异常处理和完成条件。保留解释取舍所需的简短原因，删去冗长试错记录。允许条件分支与有依据的推荐；推荐不代表替用户批准。

只有确定性、安全性或真实操作脆弱点需要强制措辞。默认值写明可调整条件，不将单次成功案例、固定模型、分辨率、100 分制或个人偏好提升为通用硬约束。

## 5. 可移植性与范围

依赖和最低版本写清楚，脚本相对自身定位资源，业务路径通过参数或配置传入。凭据不进入模板。平台差异影响执行时提供对应命令。

脚本仅在可复用逻辑或可靠性需要时创建；临时验证产物与长期运行依赖分开。发生外部写入、付费调用或不可逆操作时按实际授权处理；有重试的流程定义停止条件。全局安装的技能不链接其他技能或仓库资产，仓库内技能可链接本仓库资产并在入口写明仅限该仓库使用。

## 6. 文风与排版

一级标题不编号、二级起连续编号；表格写法以 Markdown 治理技能（如 `verdantflare-meta-markdown`）为准，`--style numbered` 检查其中可自动验证的部分。历史文献与第三方原文保留原格式，不为了 lint 通过篡改引用内容。
