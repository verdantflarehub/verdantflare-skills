# 整改存量技能与经验沉淀（03.refactor）

## 1. 输入与输出

- **输入**：待整改的存量技能目录（如旧版 `01.base-*` 结构、入口超限或缺少能力入口），或项目中已验证的新增经验/缺陷复盘。
- **输出**：升级为扁平前缀能力入口架构（或完成经验沉淀）的目标技能，以及更新后的仓库引用与验证报告。
- **公共依据**：[公共规范](./00.common.rules.md)、[架构设计](./01.design.entrypoint.md)。

## 2. 分类

- **存量结构整改**：把入口超限、根目录有多余 Markdown 或旧版横向 `01.base-*` 结构的技能迁为 `NN.<cap>.entrypoint.md` + 可选 `00.common.*.md`。
- **经验沉淀（先验证、再沉淀）**：将真实任务中通过验证的新分类判据、工作流步骤、硬约束或门禁阈值写入对应能力入口或公共层；仅纠错字、修链接、调格式等不改变行为的微调可直接处理。

## 3. 工作流

### 3.1 存量技能整改

1. **盘点**：运行 `lint_skill.py lint <target>` 记录全部错误与警告；列出入口章节与 `references/` 下全部文件，按原子能力归组，标出跨能力公共约束及应删除的试错叙述。
2. **拆分与搬移**：为每个原子能力建立 `NN.<cap>.entrypoint.md`（超长维度拆至 `NN.<cap>.<dim>.md`），跨能力共享约束归入 `00.common.<dim>.md`；将 `FAQ.md`、`lessons.md` 拆进对应工作流的失败恢复与规范的例外。
3. **重写入口**：按三节格式重写 `SKILL.md`，第二章路由表逐项列出原子能力并指向 `NN.<cap>.entrypoint.md`。
4. **修引用与复验**：搜索仓库内指向旧文件名或旧锚点的活动文档链接逐一更新；运行 `lint_skill.py` 与技能自带测试，核对关键约束、阈值与命令无遗漏。

### 3.2 经验沉淀闭环

1. **界定取证与分类**：分析问题在旧流程中为何漏检或做错，提炼可前置识别的探针与判据。
2. **设计流程与配套改动**：设计端到端处理步骤，脚本与配置改动一并纳入版本管理。
3. **真实案例验证**：在典型真实案例走通取证、执行、测量与评审，在项目变更或缺陷文档留下可追溯证据；需要人工确认的环节取得真实结论。
4. **验证后再沉淀**：只把通过验证的判据、步骤、规范与门禁写入对应能力或 `00.common.*`；试错过程留在项目文档，未验证推测记为待验证项。

## 4. 规范

- 存量结构整改只做搬移、重组与精简，不顺手改变业务执行行为；搬移中发现的规则冲突或过时内容登记为待确认项。
- 每条拟沉淀规则应能回答：来源与证据是什么；适用范围与工具版本；是硬约束、默认值还是个人偏好；有哪些例外；什么条件下更新或废弃。
- 静态检查器兼容旧版 `01.base-*` 技能，允许存量技能分批平滑迁移至能力入口架构，但不对新技能开放旧版骨架初始化。

## 5. 验收

- 整改后 `lint_skill.py lint <target> --style numbered` 返回 `PASS`（0 errors），全仓活动文档无断链。
- 整改前后核心命令、参数阈值与硬约束逐项核对无丢失；涉及行为变更的经验沉淀已附真实案例验证证据。
