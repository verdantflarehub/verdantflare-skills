# 技能通用静态检查、评审与门禁验收基准

## 1. 当前依据

- [技能入口](../SKILL.md)：工具调用方式。
- [检查器](../scripts/lint_skill.py)：静态不变量与分型防渗透校验实现。
- [回归测试](../scripts/test_lint_skill.py)：可重复验证样例。

## 2. 静态检查与分型校验

- **强制结构不变量**：入口三节标题与顺序（可选首节编码规范）、正文 ≤4000 字符、代码块 ≤20 行、H3 ≤3 且禁用 H4+、根目录仅 `SKILL.md`、合法 YAML 且无重复键、`name` ≤64 且与目录一致、`description` 非空 ≤1024 且无 XML 标签、禁止将 `00.common.*.md` 写进第二章原子能力表格、每个 `NN.<cap>.entrypoint.md` 均被 `SKILL.md` 链接且具备五段式（输入与输出 / 分类 / 工作流 / 规范 / 验收）、两位编号 `01~99` 无冲突、子专册无孤立、本地链接与标题锚点存在、无未完成占位符（忽略代码区）。
- **分型命名**：`craft / crew / director / meta / write / agent` 名称须恰为三段且第二段为分型词，否则报错；`atomic` 二段、三段均可。
- **静态告警项**：单份专册超过 10000 字符提示拆分；`SKILL.md` 路由表左列原子能力名超过 12 字提示减字迭代；`craft / crew / director` 三类上层技能检出 `.safetensors/.ckpt/.gguf`、`Node \d+`、LoRA 数值权重配比或 `KSampler/sigmas/cfg_scale/denoise_strength` 时触发底层渗透告警。
- **链接与隔离边界**：本地链接允许指向本技能、兄弟技能（同父目录且含 `SKILL.md`）及同一 Git 仓库内资产，逃出仓库根目录报错；全局安装技能交付前须在无兄弟技能的隔离目录复验零断链。
- **存量兼容**：不存在 `*.entrypoint.md` 但存在 `01.base-*.md` 时自动兼容旧版检查，不阻断存量技能平滑迁移。

## 3. 行为验证与评分门禁设计

- **检查器与模板回归**：改动 `lint_skill.py` 或模板后，回归测试须覆盖默认/多能力/拆分骨架、`00.common.*` 可选生成与禁入路由表、能力名超长、缺入口/缺五段/编号冲突/孤立子专册、分型防渗透（`craft / crew / director`）、分型三段式命名与 `meta / write / agent` 分型识别、存量兼容、YAML 与链接锚点边界及跨目录 CLI 执行。
- **业务评分门禁三件套**（目标技能含自动门禁或候选排序时）：
  1. **测量流程**：规定打分或提交人工审阅前必跑的探针、导出的局部证据与采集指标。
  2. **文字评分规则**：说明每个维度的业务语义与常识合理性，防止纯数值达标但结果违背意图。
  3. **数据评分准则**：给出可量化变量的通过区间与否决阈值；阈值只在一处定义并注明来源与适用条件。

## 4. 评审与交付原则

评审请求直接输出按严重程度排序的发现、位置、影响与建议，不擅自改写被审对象。静态检查通过不代表业务正确或用户批准；分别报告静态检查、行为验证与实际人工确认，未运行的环境测试记为未验证。
