# 技能安装与本机智能体接入

## 1. 当前依据

- [入口](../SKILL.md)：维护源与安装约定。
- [验收范围](01.base-acceptance.md)：安装前的隔离检查。

## 2. 两类工作

**安装技能**是每个技能、每次更新都要做的事：把维护源整个目录复制到统一安装根 `~/.agents/skills/<name>/`，并在安装位置运行静态检查。安装只写这一个位置，不为各智能体分别复制。

**智能体接入**是每台机器、每个智能体只做一次的环境配置：让各智能体读取统一安装根。接入完成后，安装新技能无需再动任何智能体配置。接入属于环境变更，首次执行或改动前按用户授权确认。

## 3. 安装与更新步骤

1. 在维护源运行静态检查与回归测试，并在不含兄弟技能的隔离目录复制一份运行检查，确认没有跨技能链接。
2. 若安装根已有同名目录，先核对它与维护源的差异，确认没有只存在于安装副本的修改，再按确切名称删除旧目录。
3. 复制整个技能目录到 `~/.agents/skills/<name>/`，排除 `__pycache__` 等缓存。
4. 在安装位置运行静态检查，并与维护源逐文件比对一致。

安装副本不直接修改；发现副本被改过时，把有效修改合回维护源后重新安装。

## 4. 智能体接入方式

各智能体读取技能的位置随版本变化。下表为已核实的接入方式，接入前应以当前版本的文档或程序为准重新核对。

| 智能体      | 接入方式                                                  |
| :---------- | :-------------------------------------------------------- |
| Codex       | 原生读取 `~/.agents/skills`，无需配置                     |
| Grok        | 原生读取各层 `.agents/skills`，无需配置                   |
| Antigravity | 全局 `~/.gemini/config/skills.json` 指向统一安装根        |
| Claude Code | `~/.claude/skills` 建为指向统一安装根的目录联接或符号链接 |

### 4.1 Antigravity

Antigravity 的全局自定义根为 `~/.gemini/config/`，默认只扫描其下 `skills/`。在该目录创建或合并 `skills.json`，加入统一安装根条目；已有文件时只追加条目，不覆盖其他配置：

```json
{
  "entries": [{ "path": "~/.agents/skills" }]
}
```

该条目扫描一层子目录，安装根下的全部技能都会加载；不需要的技能用条目的 `exclude` 排除。修改后新开会话或重启后生效。

### 4.2 Claude Code

Claude Code 只读取 `~/.claude/skills`，没有额外技能目录配置，因此用目录联接让该位置指向统一安装根。先确认原目录中的每个技能在统一安装根中都有一致副本，再删除原目录并建立联接：

```text
# Windows（目录联接无需管理员权限）
cmd /c mklink /J "%USERPROFILE%\.claude\skills" "%USERPROFILE%\.agents\skills"

# macOS / Linux
ln -s ~/.agents/skills ~/.claude/skills
```

Grok 同时扫描 `~/.claude/skills` 与 `~/.agents/skills`，联接后会看到同名技能，它按名称去重，不产生冲突。

## 5. 接入验证

逐个确认联接或配置指向正确，再在各智能体新开会话，核对技能列表中出现目标技能。未实际打开会话核对的智能体记为“已配置、未验证”，不报告为可用。
