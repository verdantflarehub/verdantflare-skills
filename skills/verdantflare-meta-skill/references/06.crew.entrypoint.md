# 业务专员（Crew）技能设计规范（06.crew）

## 1. 输入与输出

- **输入**：剧组单个工种或业务专员的交付诉求（如换脸专员、穿搭专员、封面修复专员、头像策展专员，命名约定为 `*-crew-*`）。
- **输出**：遵循三层信息隔离契约、零底层实现渗透、具备制片交付要素的 `*-crew-*` 技能目录，并通过 `lint_skill.py --profile crew --style numbered` 校验。
- **公共依据**：[公共规范](./00.common.rules.md)、[架构设计](./01.design.entrypoint.md)、[检查器](../scripts/lint_skill.py)。

## 2. 分类

所有技能共用同一套 `SKILL.md` + `NN.<capability>.entrypoint.md` 扁平前缀骨架，按职责边界分为四层可扩展分型（`--profile`）：

| 技能分型（Profile）  | 定位与边界                                                                             |
| :------------------- | :------------------------------------------------------------------------------------- |
| `atomic`（原子技能） | 底层模型与技术算子（如 `mk-image-*`、`vf-video`），自管底模、LoRA、采样器与显存账本    |
| `crew`（专员技能）   | 剧组单个工种执行员（`*-crew-*`），零底层模型渗透，负责选引擎、兜底路由、检查点与交片   |
| `expert`（预留扩展） | 领域专家大脑（如运镜设计、灯光色彩、剧作节奏），纯方法论与决策输出，可被专员与导演复用 |
| `director`（预留）   | 作品级统筹导演，掌管整部短剧/MV 的世界观与节奏，调度多个 `expert` 与 `crew` 协作交片   |

## 3. 工作流

1. **判定对外可独立交付能力**：只为“人类可以直接下达并拿到完整成品”的独立交付物建 `NN.<cap>.entrypoint.md`。多数 Crew 初期仅需 `01.<cap>.entrypoint.md` 一个入口，内部串行阶段（如“取证 → 出图 → 复检 → 打包”）作为同一入口下的小节或同前缀子专册组织，待未来拓展第二个独立交付物（如从单人换脸扩展多人换脸）时再追加 `02.*`。
2. **建立三层信息隔离与委托链接**：
   - **人类层**：只表达业务效果、角色/审美要求与审批结论，不关心底层模型与参数。
   - **专员层（`*-crew-*`）**：负责输入取证、场景分流、跨技能选引擎、失败兜底策略、人工检查点与成品验收打包。
   - **底层原子层（`atomic`）**：通过相对链接委托底层原子能力入口执行，由底层自管底模权重、LoRA 矩阵、互斥表、采样器、ComfyUI 节点编号与 GPU 显存账本。
3. **补齐制片交付要素**：按需在专员入口或 `resources/templates/` 中配齐人工检查点（如 `H1~H5` / `CP1~CP3`）、单镜/单批止损重试上限、持续审核页模板与交付包清单契约。
4. **运行专员静态检查**：执行 `python -X utf8 scripts/lint_skill.py lint /path/to/mk-crew-demo --profile crew --style numbered`（目录名含 `-crew-` 时 `--profile auto` 自动启用）。

## 4. 规范

- **严禁把内部流水线拆成假原子能力**：内部串行阶段（如策划 / 制备 / 打包）严禁拆为多个平级 `NN.*.entrypoint.md`；篇幅超过 10000 字符时拆为同前缀四维子专册 `01.<cap>.{category,workflow,rules,acceptance}.md`。
- **零底层渗透红线**：`*-crew-*` 的 `SKILL.md` 与 `references/*.md` 严禁硬编码以下底层实现细节，违者由 `lint_skill.py --profile crew` 告警拦截：
  - 模型权重文件名（`.safetensors`、`.ckpt`、`.gguf` 等）。
  - LoRA 数值权重配比表（如 `lora weight: 0.8`）。
  - ComfyUI 节点编号（如 `Node 6`、`Node #16`）。
  - 采样器与噪声调度参数（如 `KSampler`、`sigmas`、`cfg_scale`、`denoise_strength`）。
- **解耦演进原则**：底层模型、LoRA 或工作流升级时，只需更新对应 `atomic` 技能，不得迫使上层 `crew` 技能同步改写。

## 5. 验收

- `lint_skill.py lint <target> --profile crew --style numbered` 返回 `PASS`（0 errors），且无底层实现泄露警告（若历史遗留参考文件确有告警，须将底层细节下沉至对应 `atomic` 技能后清零）。
- 抽查 `SKILL.md` 确认仅列出对外可独立交付的能力入口，未把内部串行阶段拆为平级入口；制片交付要素（检查点、止损上限、审核页/交付包契约）齐备且不越权替人类拍板。
