# 剧组专员技能设计与治理（04.crew）

## 1. 输入与输出

- **输入**：剧组单个工种或业务专员的成品交付诉求（如换脸专员 `*-crew-faceswap`、穿搭专员 `*-crew-outfit`、封面修复专员 `*-crew-cover`、头像策展专员 `*-crew-avatar`）。
- **输出**：遵循三层信息隔离契约、零底层实现渗透、具备制片交付要素的 `*-crew-*` 技能目录，通过 `lint_skill.py --profile crew --style numbered` 校验。
- **公共依据**：[公共规范](./00.common.rules.md)、[公共流程](./00.common.workflow.md)、[公共验收](./00.common.acceptance.md)。

## 2. 分类

专员技能（`--profile crew`，目录名含 `-crew-` 时自动识别）是电影工业管线中负责**单个工种端到端成品交付**的执行员：

- **单交付物专员（常见）**：对外仅交付一种完整成品，只需 `01.<cap>.entrypoint.md` 一个入口，内部串行阶段（取证 → 方案 → 制作 → 复检 → 打包）收口在同一入口或同前缀四维子专册中。
- **多交付物专员**：当同一工种扩展出第二个可独立交付的完整成品（如从单人换脸扩展多人换脸）时，再顺延追加 `02.<cap>.entrypoint.md`。

## 3. 工作流

1. **判定对外独立交付粒度**：只为“人类可直接下达并拿到完整成品”的交付物建 `NN.<cap>.entrypoint.md`，严禁把内部串行阶段拆成多个平级能力入口。
2. **建立三层信息隔离与跨层委托**：
   - **人类层**：只提业务效果、角色/审美要求与审批结论，不关心底层模型与参数。
   - **专员层（`*-crew-*`）**：负责输入取证、场景分流、调用 `craft` 工艺技能获取专业方案、调度 `atomic` 原子技能产出素材、执行失败兜底路由、组织人工检查点与打包交付。
   - **底层原子层（`atomic`）**：通过相对链接委托执行，自管底模权重、LoRA 矩阵、互斥表、采样器、ComfyUI 节点编号与显存账本。
3. **补齐制片交付要素**：按需在专员入口或 `resources/templates/` 中配齐人工检查点（如 `H1~H5` / `CP1~CP3`）、单镜/单批止损重试上限、持续审核页模板与交付包清单契约。
4. **运行专员分型校验**：执行 `python -X utf8 scripts/lint_skill.py lint /path/to/mk-crew-demo --profile crew --style numbered`（目录名含 `-crew-` 时 `--profile auto` 自动启用）。

## 4. 规范

- **严禁把内部流水线拆成假原子能力**：内部串行步骤严禁拆为平级 `NN.*.entrypoint.md`；篇幅超 10000 字符时拆为同前缀四维子专册 `01.<cap>.{category,workflow,rules,acceptance}.md`。
- **零底层渗透红线**：`*-crew-*` 的 `SKILL.md` 与 `references/*.md` 严禁硬编码模型权重文件名（`.safetensors/.ckpt/.gguf`）、LoRA 数值权重配比、ComfyUI 节点编号（`Node \d+`）或采样器底层参数（`KSampler/sigmas/cfg_scale/denoise_strength`），违者由 `lint_skill.py --profile crew` 告警拦截。
- **解耦演进原则**：底层模型、LoRA 或工作流升级时只需更新对应 `atomic` 技能，不得迫使上层 `crew` 技能同步改写。

## 5. 验收

- `lint_skill.py lint <target> --profile crew --style numbered` 返回 `PASS`（0 errors），无底层实现泄露警告。
- 核对 `SKILL.md` 确认仅列出对外可独立交付的能力入口；检查点、止损上限、持续审核页与交付包契约齐备，且不越权代替人类做最终审美拍板。
