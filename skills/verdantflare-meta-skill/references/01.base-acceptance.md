# 技能质量检查与验证范围

## 1. 当前依据

- [入口](../SKILL.md)：工具调用方式。
- [检查器](../scripts/lint_skill.py)：静态检查实现。
- [回归测试](../scripts/test_lint_skill.py)：可重复验证样例。

## 2. 静态检查

结构检查默认开启、没有关闭开关：入口三节标题与顺序、正文字符与代码块行数、三级标题数量与禁用四级标题、四份底座存在且被入口链接、根目录无多余 Markdown、分支矩阵四维齐全；专册超长给出警告。上限数值见[规则约束](01.base-rules.md#2-入口-skillmd-规则)，常量定义在检查器中。存量技能不合规时如实报告 FAIL，按[整改流程](01.base-workflow.md#4-整改存量技能)处理，不以放宽常量通过。

此外检查入口 YAML 的合法性、重复键、名称与目录一致性、平台元数据限制，以及入口和 `references/` 下递归 Markdown 的本地链接、常见标题锚点及未完成标记。名称最长 64 个字符且不含保留词 `anthropic`、`claude`；描述非空、最长 1024 个字符且不含 XML 标签。链接目标通过 Markdown 解析器读取，支持引用式链接、带标题和带空格的链接。外部 URL 不发起网络请求。

本地链接允许指向本技能目录、同一技能根目录下其他含 `SKILL.md` 的技能，以及技能所在 Git 仓库内的项目资产（如设计文档、工作流、数据与脚本），目标文件与锚点仍须存在；逃出仓库根目录（最近含 `.git` 的上级目录）的链接报错。这类链接只适用于仓库内技能，且须在入口写明仅限该仓库使用。全局安装的技能不链接、不依赖其他技能或仓库资产，协作对象只以名称提及；交付前在不含兄弟技能的隔离目录复制一份运行检查，确认没有断链。目录内符号链接指向外部也视为外部依赖。

未完成标记包括常用英文待办词（按 ASCII 边界匹配，紧邻中文也能识别）、双花括号模板变量以及旧式已知模板占位符；具体匹配规则见脚本的 `PLACEHOLDER` 常量。代码块与行内代码中的命令参数示例不检查，不把合法 HTML 标签误判为未完成内容。`--allow-placeholders` 仅用于骨架检查，以警告和非交付状态显示未完成项。

模板、assets、scripts 中的文档不是默认运行指引，不递归 lint。模板通过初始化后校验生成结果进行回归验证。链接到这些文件时仍检查目标存在。代码块与 HTML 内嵌链接不作为 Markdown 链接解析；检查器不验证外部服务、命令是否成功或业务语义。

锚点支持 ATX/Setext 标题、常见 GitHub 风格 slug 与重复标题后缀；HTML 自定义 ID、编辑器特有 slug 不保证覆盖。遇到差异应核对实际渲染，不靠创建无意义标题绕过检查。

### 2.1 可选严格检查

`--style numbered` 检查每份指引单一无编号一级标题、下级连续编号及正文非代码区域的换行标签。表格列数与源码行宽归 Markdown 治理技能（如 `verdantflare-meta-markdown` 的 `check_md.py`）检查，本工具不重复。它不推断文风或主观判断是否正确。

## 3. 行为验证与数据驱动评分准则

对初始化器和校验器的改动，回归测试至少覆盖：默认骨架即标准结构、矩阵骨架、入口三节与顺序、入口各项上限、缺底座与缺链接、根目录多余 Markdown、专册超长警告、引号与多行 YAML、非法 YAML、未完成骨架、断链与锚点、跨目录运行、重复初始化不覆盖、非法分类不产生文件、外部路径拒绝、技能间链接放行、代码内参数示例不误报、中文紧邻待办词、以及名称与描述长度边界。

对实际技能，使用与任务相关的真实或隔离样例验证触发、分支选择、命令、结果和失败处理。不要用格式通过替代业务验证。只有有真实必要且允许时才委派独立执行评估。

### 3.1 评分与门禁设计

目标技能包含自动门禁拦截或候选排序时，验收章节同时具备测量流程、文字评分规则与数据评分准则。没有门禁或排序需求时，写明可观察的完成与失败条件即可。

1. **测量流程**：规定打分或提交人工审阅前必须运行的探针、导出的局部证据与采集的指标，并把测量结果记入审计报告。缺失时，执行者容易跳过实测、凭印象打分。
2. **文字评分规则**：用自然语言描述每个维度的业务语义、合理性与合规要求，回答“看什么、为什么合格或不合格”。缺失时，纯数值指标可能全部达标而产物仍违背常识或业务意图。
3. **数据评分准则**：为可量化的维度给出测量变量、通过区间与否决阈值；确有排序需求时再定义扣分梯度或分制。缺失时，判定依赖主观裁量，不合格产物可能被当作合格交付。

阈值只在一处定义，并注明来源样例与适用条件（输入尺寸、工具版本、环境等）。难以量化的维度用人工判定加正反样例锚定，不为凑数字而编造指标。示例：文档生成技能以“必填章节齐全、链接零断链”为数据准则，以“术语与目标读者匹配”为文字规则；图像生成技能以“主体占画面比例落在指定区间”为数据准则，以“姿态符合物理支撑”为文字规则。领域专属阈值写入该领域技能，不写进本技能。

## 4. 人工或语义审阅

确认描述可准确触发，资料能按需读取，简单任务没有无用阶段，业务经验未污染通用模板，约束有来源与边界，未扩大授权。需要人工决定的事项沿用用户角色与已有授权，不内置固定人名或额外检查点。

分别报告静态检查、行为验证和实际人工确认。未运行的环境测试记为未验证；未经用户确认不得标记人工批准。
