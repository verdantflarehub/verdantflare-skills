# 元治理技能设计与治理（06.meta）

## 1. 输入与输出

- **输入**：服务负责人个人工作流、与产品项目业务无关的元治理技能诉求，如技能治理、协作机制、素材同步与资料下载（命名约定为 `*-meta-*`）。
- **输出**：独立于电影工业四层调用链、可跨仓库全局安装的 `*-meta-*` 技能目录，通过 `lint_skill.py --profile meta --style numbered` 校验。
- **公共依据**：[公共规范](./00.common.rules.md)、[公共流程](./00.common.workflow.md)、[公共验收](./00.common.acceptance.md)。

## 2. 分类

元治理技能（`--profile meta`，目录名第二段为 `meta` 时自动识别）不属于 `atomic / craft / crew / director` 四层，与 [文档编写技能](./07.write.entrypoint.md)、[助手调度技能](./08.agent.entrypoint.md) 同为四层之外的个人工具技能：

| 子类     | 典型技能                        |
| :------- | :------------------------------ |
| 技能治理 | `verdantflare-meta-skill`       |
| 协作机制 | `verdantflare-meta-agent`       |
| 素材同步 | `verdantflare-meta-googledrive` |
| 资料下载 | `verdantflare-meta-download`    |

## 3. 工作流

1. **判定归类**：管理工作机制、换个仓库仍然成立、不交付影视成品的技能归入本分型；产出文档规范的归 `write`，向助手会话派单的归 `agent`，交付影视素材或成片的按四层分型处理。
2. **按三段式命名**：`<前缀>-meta-<对象>`，多词对象合并为一个词。
3. **剥离项目业务依赖**：规则、模板与脚本不依赖任何产品业务资产（Studio、业务目录、业务技能），目标仓库差异通过“目标仓库规则优先”声明吸收。
4. **运行分型校验**：执行 `python -X utf8 scripts/lint_skill.py lint /path/to/verdantflare-meta-demo --profile meta --style numbered`（命名合规时 `--profile auto` 自动启用）。

## 4. 规范

- **三段式命名强制**：名称须恰为三段且第二段为 `meta`，二段或四段及以上由 `lint_skill.py` 报 `ERROR`。
- **不进入制作链路**：`director / crew` 可按需借用元治理技能做流程治理，但不得把它们列为制作派单对象；元治理技能反向不得把四层业务技能作为自身运行前提。
- **不做底层渗透检查**：元治理技能常需在规则与样例中引用底层术语（如本技能的防渗透规则），不启用 `craft / crew / director` 的底层渗透告警。
- **全局安装独立性**：须能在无项目兄弟技能的隔离目录安装与复验，安装与发布按 [安装技能](./01.install.entrypoint.md) 执行。

## 5. 验收

- `lint_skill.py lint <target> --profile meta --style numbered` 返回 `PASS`（0 errors），无三段式命名错误。
- 核对规则、模板与脚本不引用产品业务资产，在隔离目录安装后零断链；技能入口未声明任何影视成品交付能力。
