# 助手调度技能设计与治理（08.agent）

## 1. 输入与输出

- **输入**：服务负责人个人工作流的助手调度技能诉求，即通过 MCP 服务或 CLI 向指定 AI 助手会话派单、查询、续接、取消与回收结果（命名约定为 `*-agent-*`）。
- **输出**：独立于电影工业四层调用链、按宿主一技能一目录的 `*-agent-*` 技能目录，通过 `lint_skill.py --profile agent --style numbered` 校验。
- **公共依据**：[公共规范](./00.common.rules.md)、[公共流程](./00.common.workflow.md)、[公共验收](./00.common.acceptance.md)。

## 2. 分类

助手调度技能（`--profile agent`，目录名第二段为 `agent` 时自动识别）不属于四层，与 [元治理技能](./06.meta.entrypoint.md)、[文档编写技能](./07.write.entrypoint.md) 同为个人工具技能。一个宿主对应一个技能，对象段写宿主名，如 `verdantflare-agent-claude`、`verdantflare-agent-codex`、`verdantflare-agent-grok`、`verdantflare-agent-antigravity`。

委托协议、会话命名与多智能体分工由元治理技能 `verdantflare-meta-agent` 统一规定；`*-agent-*` 只封装对应宿主的调用接口，不另立协作规则。

## 3. 工作流

1. **判定归类**：封装某个助手宿主调用接口的技能归入本分型；规定跨助手如何协作的归 `meta`。
2. **按三段式命名**：`<前缀>-agent-<宿主>`，宿主名合并为一个词。
3. **对齐标准动作**：对外提供派单、查询状态、续接、取消与读取结果等标准动作，错误如实回传宿主原始信息，不伪造完成状态。
4. **运行分型校验**：执行 `python -X utf8 scripts/lint_skill.py lint /path/to/verdantflare-agent-demo --profile agent --style numbered`。

## 4. 规范

- **三段式命名强制**：名称须恰为三段且第二段为 `agent`，否则由 `lint_skill.py` 报 `ERROR`。
- **只调度不决策**：不代替上游方案设计、业务审美评审与人工审批；不进入制作链路，`director` 借用其派单时，派单内容仍按四层分型契约组织。
- **凭据与隐私**：宿主凭据从环境或受控配置读取，技能文档、日志与会话索引不写入凭据、主机名或个人绝对路径。
- **不做底层渗透检查**：不启用 `craft / crew / director` 的底层渗透告警。

## 5. 验收

- `lint_skill.py lint <target> --profile agent --style numbered` 返回 `PASS`（0 errors），无三段式命名错误。
- 标准动作齐备且与 `verdantflare-meta-agent` 的协作协议一致，未内嵌凭据或另立协作规则。
