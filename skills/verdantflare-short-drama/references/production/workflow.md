# 影视制作流程

## 1. 剧本拆解

确认交付是短片、场景、预告片还是纪录片段落。提取用户已给定的角色目标、阻碍、转折、场景边界、对白和禁用元素；按可观察的进入状态、动作、离开状态拆场景。完整短剧使用剧本做生产输入时，先读取 `verdantflare-short-drama-review` 的固定版本与审核结论；未解决的 P0/P1 所影响的剧情、镜头和资产保持草案状态。纪录片不能编造被摄者行为或采访事实，预告片遵守用户指定的剧透边界。

原始剧本事实密集时，可先逐场使用 `verdantflare-short-drama` 的本机模型提取原文锚定候选；人工核对拒收项、推断和语义分类后，再使用 `verdantflare-short-drama` 编写 `treatment.md` 和 `plan.json`，并运行其校验器。Shot 时间线连续覆盖目标段落；每镜有叙事目的、主要动作、起落状态、相机与声音。Generation Unit 是模型调用提案，与 Shot 分开；同一角色造型、地点和连续时间才考虑组合，模型上限以当前 Video Skill 为准。

## 2. 资产与生成

先核对已批准的身份、当前 Look、场景和道具 Artifact。需要跨镜复用时，按[数字资产圣经模板](asset-bible-template.md)分别建立地点及场次变体、道具与状态链、服装 Look、逐镜引用；文字设定与已审图像的状态分开记录。没有资产时列需求并通过 Image Skill 制作候选；候选通过项目审核后再作为 Video Skill 的引用。逐张注明身份、造型、空间、动作的职责，不把一张头肩图当成全身动作参考。

将已冻结的 Generation Unit 交给 Video Skill 编译目标模型 Prompt，预检真实 `project_id`、route、时长、参考 Artifact、预算和幂等键。用户只要前期方案时到此为止；请求成片时沿 Video Skill 提交、查询、恢复和下载，不在本 Skill 另造 API 客户端。缺少已批准的输入或宿主能力时保存计划与缺口。

## 3. 验片与交接

候选逐秒检查叙事动作、表演、重心与接触、背景视差、身份和造型、道具状态、光线方向、声音与剪辑点。技术解码和时长合格不等于创作合格。仅返修有问题的 Shot 或 Generation Unit，保留旧候选、任务 ID 和输入版本；跨镜头身份或场景事实变更需上游新版本。最终成片装配、字幕、授权和发行由项目既有流程验收，不以本 Skill 的计划校验代替。
