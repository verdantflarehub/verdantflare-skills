# 取证分类与验收

## 1. 先取证再选择分支

先固定身份参考、目标清单、已有批准范围与现有任务。对明确图片清单运行脚本，记录解码尺寸、字节摘要、缺失和重复编号。视频由Video工具或可用解码器读取真实帧率、时长、帧数；抽帧记录帧号及时间码，变帧率用时间戳。观看覆盖动作起止的时序帧；采样检查与完整播放分别记录，不互相冒充。

对每张候选看全图，再导出或打开脸部局部放大，与原始身份基准及原帧对照。仅背影或脸部遮挡时，身份可见性记为不足，不能因文件有正脸参考就宣称锁脸通过。保持实际左右的坐标定义，并逐项记录身体、头部、视线与相机；不把头姿估计器输出当相机俯仰角。

| 取证结果 | 对应流程 |
| --- | --- |
| 已有合格视频和可用姿态帧 | 从抽帧或纠正接续，新增生成数为0 |
| 姿态可用，脸型、肤质或表情偏离 | 原帧＋身份基准局部纠正，保留其他图 |
| 实际方向、动作阶段或机位不符 | 查同片其他帧；仍缺才补相应视频 |
| 仅请求入库且批准范围已明确 | 只做内容校验、Project关联与回读 |
| 身份基准错误或多组系统性漂移 | 提供影响清单，再按用户决定重建 |

同图可存在多类缺陷。机位错误不能靠皮肤修复掩盖。分类理由写实际观察位置、原帧和时间码，不从文件名中的left/low/15倒推结论。

## 2. 可复现测量

创建UTF-8 JSON，`images`为非空数组，每项包含唯一`id`、相对该JSON的`path`、已知来源`sha256`及可选`expected_dimensions`（宽、高）；可选`expected_ids`列出本轮应有编号。路径是本地输入，不提交凭据。例：

```json
{"expected_ids":["A01"],"images":[{"id":"A01","path":"images/A01.png"}]}
```

```text
python scripts/audit_images.py /path/to/manifest.json --output /path/to/audit.json
```

报告仅输出编号、尺寸、摘要和错误代码，不输出输入绝对路径。退出码0表示清单技术检查通过，1表示有失败，2表示清单或依赖不可用。未提供期望摘要时只记录实测摘要，不能声称来源一致。Pillow缺失时使用当前环境依赖管理方式安装，不更换已有文件。

技术验收采用确定的逐项通过条件，不制造综合美学分数：

- 可读取与完整解码：失败文件数为0；坏图或缺图不计成果。
- 来源一致：提供期望哈希的每项摘要完全相等；不符项不得入库。尺寸按解码值记录；提供期望尺寸时必须相等，提示词“4K”不作为实测值。
- 覆盖：完成数／当前目标数，目标编号缺失数、额外编号数及重复编号数均为0才叫齐套；数量齐全不证明姿态正确。
- 归档：领域引用悬空数为0；指定修订的文件回读哈希与本地一致。与任务无关的字段、引用变化数为0；授权修改单独列明。
- 批准：入库图片必须落在当前真实授权范围内；批准覆盖数等于本次入库数，不能把旧单图批准扩展到新批次。

## 3. 视觉规则与测量边界

身份看眼型、眉形、鼻翼、嘴形、脸部体积是否相对原型漂移；皮肤看新增皱纹、颗粒、锐化和蜡化；表情看嘴角、嘴唇、脸颊与眼周是否满足要求；姿态看头肩关系、左右和动作阶段；机位看全图透视及视频运动，不把抬头当相机降低。逐项填写“观察符合／观察不符／证据不足”，附原帧、纠正图与局部对照。

这些视觉规则尚无跨人物验证的数值阈值，不宣称量化评分或自动放行。需新增身份相似度、脸宽比、皮肤指标或机位评分时，先固定测量方法、适用姿态、人工通过与失败样本，验证阈值和误判后再采用；不能直接比较正脸与侧脸像素宽度来判胖。无法校准时角度只记生成目标与视觉估计，`target_angle`不能写入实测字段。

## 4. 经验升级与停止条件

先分类与设计工作流，再用真实变更考题验证，考过后沉淀；失败保留原因与输入。已有成功案例可复核证据，不为写技能重跑付费任务。静态走查、脚本实跑、用户审阅及线上验证分别标注。

同类失败先核对输入和实际视频，不无上限重复提示词；沿用户批准批次和生产技能重试边界执行，响应未知先恢复原任务。已证明不适合的输入应调整或报告缺口，不用额外生成冒充恢复。
