# 局部补图、表情肤质修复与项目归档（02.local-repair）

## 1. 输入与输出

- **输入**：现有参考库清单与图片、待排查的原视频／原帧／修复图、任务 ID、用户缺陷反馈或入库批准范围、目标 Studio 项目固定修订。
- **输出**：取证分流结论、仅覆盖受影响编号的补图或局部修复图、更新后的 `character.reference_groups` 项目固定修订回读证据，以及 `audit_images.py` 技术审计报告。

## 2. 分类

先采集字节、解码尺寸、原视频时间码与视觉证据（全图＋脸部局部放大），再按取证结果进入唯一对应分支，绝不从文件名中的 `left`/`low`/`15` 倒推结论：

| 取证结果                       | 对应流程                           |
| :----------------------------- | :--------------------------------- |
| 已有合格视频和可用姿态帧       | 从抽帧或纠正接续，新增生成数为 0   |
| 姿态可用，脸型、肤质或表情偏离 | 原帧＋身份基准局部纠正，保留其他图 |
| 实际方向、动作阶段或机位不符   | 查同片其他帧；仍缺才补相应视频     |
| 仅请求入库且批准范围已明确     | 只做内容校验、Project 关联与回读   |
| 身份基准错误或多组系统性漂移   | 提供影响清单，再按用户决定重建     |

同图可存在多类缺陷，机位错误不能靠皮肤修复掩盖；只有错误身份母版或系统性失败才提出整体重建，说明影响范围并保留旧库，等待用户决定。

## 3. 工作流

### 3.1 局部修复与补图

1. **表情／肤质／脸型局部修复**：只针对指出的缺陷图建立返修输入（如两张表情不符只修两张，读回验证其余引用不变），使用目标图＋原始正脸参考执行局部编辑，不批量重做合格图。
2. **回头／高低机位补图**：先核查同片其他可用帧；确属缺失方向、动作阶段或机位时，按[多角度参考库制作](01.multi-angle-lib.entrypoint.md)仅为缺失姿态补拍与抽帧纠正。同一姿态的多个机位目标可并存，按任务分组并赋予不同编号（例如“回头 · 仰视15°”的 `U15-01` 与“回头 · 仰视30°”的 `U30-01`），记录新旧编号映射，不复用同一编号误认不同结果。

### 3.2 保存至现有 Studio 项目

1. 沿 `verdantflare-project` 与 `verdantflare-artifact` 技能读取目标固定修订与最新 Schema，保留原角色属性。
2. 更新可选 `character.reference_groups`（组数组，每组含 `key/title/images`，每图含 `key/label/file_id`；当前契约每组最多 32 图、组 key 唯一、组内图片 key 唯一，文件须属于目标修订 Manifest）。跨项目复用经授权 `ContentRef` 复制或规范导入，不能照搬源 `file_id`。
3. 仅更新指定组／图片引用，保留旧产物与历史修订。保存前核对并发变化，必要时重读合并；保存后读回固定修订、核验每张图片可读取及字节哈希。既有单图批准不能自动覆盖多组，用户明确要求两组入库后直接执行不再重复审批；项目展示不自动发布 World 资产或覆盖角色基线。

### 3.3 中断与故障恢复

保存已有任务 ID、幂等身份、已完成编号、错误原因与恢复入口。网络超时先查询旧任务并下载已产生结果再判断缺项，禁止重发；复用未变输入与验证证据。仅要求编写技能时交付技能与设计，不提交媒体任务。

## 4. 规范

### 4.1 局部去笑提示词

适用于用户明确要求“不笑”的图（目标图＋正脸参考，不批量重做合格图；编辑约束仍须看图核验，不能声称模型保证其他像素不变）：

> 将目标图人物表情改为自然中性、不笑。嘴唇自然闭合，嘴角放松、不上扬，脸颊放松，眼睛自然睁开，不做微笑或眯眼表情。正脸参考仅用于保持身份与五官比例。严格保持目标图的脸型、肤质、头肩姿态、视线、机位、发型、服装、背景和构图。只修改表情，不改变其他内容。

### 4.2 图像记录与展示规范

- **完整溯源记录**：每图记录稳定编号、身份基准哈希、源视频任务与时间码、原帧哈希、编辑输入及提示词、实际模型与任务 ID、输出哈希与解码尺寸、用户评价及批准范围；编号变更保留旧新映射，不能按新编号误认历史帧。角度是生成目标时在制作证据中明确，不在系统添加未经支持的实测字段。
- **文档展示**：按正面／平视回头／俯视／仰视等实际类别组织，使用 `[![编号](图片路径)](图片路径)` 可点击缩略图，不重复堆大图；图少时不强建空组；原帧、正脸纠正、纯提示词对照放历史区，成果区仅展示获准图片；用户要求单表多图时遵循指定布局，默认遵守所在仓库表格约定。
- **Studio 角色页展示**：在原角色设定下追加参考图组，同页滚动，点击共用全局灯箱；不引入 Tab、审阅状态或“查看可复用版本”，不将制作记录变成产品新业务。

## 5. 验收

按[公共规则第 2–3 节](00.common.rules.md#2-可复现测量audit_imagespy与技术验收条件)执行 `audit_images.py` 验证五项技术通过条件（可读取解码失败数为 `0`、来源哈希与解码尺寸一致、目标编号缺失／额外／重复数为 `0`、项目修订悬空引用与无关变更数为 `0` 且回读哈希一致、入库图片 100% 落在当前真实授权范围内），并附全图与局部放大视觉对照结论。
