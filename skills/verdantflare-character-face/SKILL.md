# 角色锁脸与多角度参考

## 1. 确认输入与接续位置

先读[取证与验收](references/evidence.md)，按实际输入和缺陷分支接续。新建、补角度、局部修复、仅入库分别处理，不让每次请求重新走完整生产链。先采集字节、尺寸、原视频时间码和视觉证据，再判断问题；文件名和提示词不能证明实际左右或仰俯机位。

读取用户当前要求、原始正脸、已有视频／原帧／修复图、任务ID及目标项目修订。优先复用合格素材。区分仅设计提示词、抽帧、生成、返修和入库；只执行当前授权阶段，已有授权不重复询问。

列清身体朝向、头部朝向、视线、表情、平视／俯视／仰视及缺失角度。左右沿用已定义的坐标；缺少且会影响生成时先澄清。相机高低不等于人物抬头低头，侧身不等于回头，镜像不等于另一侧参考。角度未经测量只能标为目标或视觉估计。

角色年龄、体型、表情和图数取当前任务，不把案例参数写成默认基线。新要求覆盖旧要求但保留历史记录。两张笑脸通常只修两张，不重置全库。

## 2. 组合生产能力

按需要读取已安装的 `verdantflare-image`、Studio版 `verdantflare-video`、`verdantflare-artifact`、`verdantflare-project` 技能。核对Video的Studio客户端契约标识；不要混用公共API同名技能。依赖缺失时说明缺少哪项，继续不依赖它的整理，不臆造工具或绕过Studio。

执行顺序：原始正脸 → 必要时增强或延展正脸 → 视频姿态候选 → 抽帧 → 目标帧＋原始正脸编辑 → 核验 → 获准成果库。增强图须与原始身份核对，不能让漂移图替代基准。默认图像路线沿Image技能的GPT Image设置；视频按用户选择、实际能力与预检，不能硬编码H3时长或参考上限。

生成前记录实际中文提示词、输入素材角色和批次范围。实时Schema、渠道能力和预检优先；不可提交即停止创建并保留原因。提交结果未知时恢复原任务／幂等身份，禁止重复生成。生成后沿生产技能完成内容分级与结果核验。

## 3. 抽帧与纠正

按动作矩阵选择清晰、无遮挡、姿态可辨的帧，保留原视频和原帧，记录时间码、帧号与帧率；变帧率用实际时间戳。先筛已有帧，仅为缺失姿态补拍。用户要求硬切时不添加回正动作。

编辑前读取[中文提示词](references/prompts.md)。目标帧负责姿态／机位／构图，正脸负责身份。只纠正指出的问题；瘦脸必须针对偏胖漂移或明确要求，不自动改变身份基线。保持细腻皮肤同时保留自然纹理，避免磨皮和年龄漂移。

需要实验对照时：图1原帧；图2原帧＋正脸＋提示词；图3仅原帧＋提示词。图3隔离正脸输入及隐藏会话参考，不能误称为无图生成。模型参数尽量一致并记录差异。

每张核验身份、脸部体积、年龄感、肤质、表情、视线、头肩关系、相机高度和构图。编辑可能改变其他区域，不能保证像素不变。实际解码尺寸，不把“高清”或提示词中的4K当成输出规格。

## 4. 交付与局部更新

读取[交付和恢复](references/delivery.md)。保留原编号和来源映射，成果只展示用户允许的图片，对照放历史区域；缩略图链接独立原图，不重复堆大图。修复仅更新受影响图片引用，保留旧产物和批准证据。

只有错误身份母版或系统性失败才提出整体重建，说明影响范围并沿用户决定执行。技术完成、允许展示和World发布授权不得互相替代。

## 5. 验证与适用边界

使用[图片取证脚本](scripts/audit_images.py)对明确清单实测解码尺寸、SHA-256、编号重复与缺图；运行方式见取证指南。脚本不识别人脸、不判定相机角度，也不代替内容分级或用户批准。视觉维度使用原图与局部放大对照，注明观察或估计；没有经过验证的阈值不生成百分制、身份相似度结论或实测角度。

本技能依赖按阶段可用的Image、Studio版Video、Project与Artifact技能；安装时一并提供需要的依赖。离线取证仅依赖Python 3.10+与Pillow。历史考题证明这条制作与归档路线曾成功，不保证新人物、新姿态或新模型同样成功。年龄、姓名、表情、图数、目标角度均取当前任务，案例参数不成为默认硬约束。
