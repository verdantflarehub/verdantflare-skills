# 复杂研发计划五阶段与双门禁（02.complex-plan）

## 1. 输入与输出

- **输入**：命中复杂判据或经用户指定的研发任务、负责人与主题 `slug`，以及专题设计、受管配图与三方审定流程所需材料。
- **输出**：基于 [plan-complex.template.md](../resources/templates/plan-complex.template.md)、[rd-review.template.md](../resources/templates/rd-review.template.md) 与 [acceptance.template.md](../resources/templates/acceptance.template.md) 维护的四受控目录文档（`plan / changes / reviews / acceptance`）、`CP0 / CP1` 门禁放行与呈报包，以及 `T5` 同构归档交付。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的反自审（`PL-REV-INDEP` / `D4-A` / `D4-B`）、锁卷防篡改（`PL-CP1-LOCK`）与审批铁律。

## 2. 分类

### 2.1 法定五阶段结构（T1–T5）

第 4 章阶段安排（`4.1.1`～`4.1.5`）与第 5 章任务分组（`5.1`～`5.5`）严格固定为以下五项标准名称，不得跳步、改名、倒置或合并：

| 阶段编号 | 法定阶段名称与核心交付物                                                    |
| :------- | :-------------------------------------------------------------------------- |
| `T1`     | `完善计划与方案`：深化设计、补齐 TXT 图与受管配图、审定验收流程、闭环 `t1`  |
| `T2`     | `分析影响范围`：跨仓/DB/集群/提示词扫描、刷新落点、闭环 `t2` 防漏审报 `CP0` |
| `T3`     | `实施子计划`：获 `CP0` 批准后分切片完成源码实现、单元集成测试与受控部署     |
| `T4`     | `验收子计划`：执行者按流程取证，Codex 全面核验，Claude 抽查，签署 `t4`      |
| `T5`     | `人类验收子计划`：只设 `T5.1` 一项，人类批准或退回意见，批准后助手直接收尾  |

### 2.2 验收的三个环节与多方职责

验收不以怀疑执行者造假为前提；关键是流程事先审定、结果按流程客观评价：

- **环节 1 — 验收流程审定（`T1`，`CP0` 前）**：每个待验收对象在验收文档第 2 章写一个 `S` 场景，写清四项——**取证流程**（谁、何环境、何步骤，默认执行者本人）、**证据内容**（日志/退出码/截图/哈希/页面及路径）、**充分性判据**（量化通过条件与充分性说明）、**判定**（Codex 全面核验、Claude 抽查）。审定固定三步且每步可直接改文档：1) 执行者起草；2) 研发核验修订（Codex，或冲突时按 `D4-A` 换非作者研发智能体）；3) Claude 修订定稿。审定结果记在第 2 章开头“验收流程审定记录”，随 `CP0` 锁卷，不另设人类审批。
- **环节 2 — 取证（`T4`）**：谁做谁取证，按锁卷流程执行并将结果填入第 3～4 章；确需 Codex 协同取证时，协同者计入作者不得再核验该场景。
- **环节 3 — 核验与抽查（`T4`）**：Codex 逐项核对结果是否符合锁卷流程、证据是否充分、结论是否成立（不重跑、不重拉产物、不另起取证）；通过后 Claude 挑 `1～2` 项抽查 Codex 评价并核对对应证据（不做全面复核），抽查不过退回 Codex 重核或执行者补证。三方无法收敛时才整理候选项上报人类裁定。
- **多方职责边界**：执行智能体（如 Gemini）负责方案与 `TXT` 原理图、配图入库、影响扫描、编码、起草本人验收流程与 `T4` 取证；Codex 负责 `T1` 工程细节审与流程修订、`T2` 全仓防漏审、`T4` 全面核验（任作者时按 `D4-A` 替补，严禁拉 Claude 替补）；Claude 负责 `T1` 总体架构核验与流程定稿、`T4` 抽查 `1～2` 项、跨系统架构冲突单次裁决；人类在 `CP0` 与 `CP1` 各只做一个决定（批准，或不批准并给意见）。

## 3. 工作流

### 3.1 T1–T2 方案深化、验收流程审定与 CP0

1. 使用模板或 `init --level complex --with-core-docs` 建立骨架；在专题设计补齐非空 `text` 原理图，调用批准的 ChatGPT Image 渠道生成高清架构配图并经 `.gdrive/managed/pending/` 入库嵌入正文。
2. 按第 2.2 节在 `accept_*.md` 第 2 章逐个 `S` 场景完成三步审定并记入“验收流程审定记录”；同步完成 `t1` 评审（Codex 写第 3 章，Claude 写第 2 章），闭环落盘 `review_*_t1.md`（`已通过`）。
3. `T2` 只读扫描代码仓、存量计划、数据库/部署清单与提示词预算，刷新计划第 4.2 节与 `T3 / T4` 落点；未改 `T1` 总体架构时直接由 Codex 执行 `T2` 防漏审，计算 `review-hash --stage t2` 写入 `review_*_t2.md`（`已通过`）。运行 `--gate cp0` 返回 `0` 后呈报人类；获批后将 `lock-hash` 写入第 7 章并将验收文档置为 `考卷已锁定`。

### 3.2 T3–T4 实施、取证、核验与抽查

1. **受控实施（`T3`）**：未获 `CP0` 批准前严禁偷跑正式业务改造；获批后逐子任务建 `change_*.md`，编码与单测通过即归入 `docs/archive/changes/` 并勾选复选框。
2. **实跑取证（`T4`）**：验收状态置为 `实跑取证中`，执行者按锁卷流程逐景取证并填入 `accept_*.md` 第 `3` 章与第 `4.1–4.4` 节锚点（严禁触碰第 2 章字符）。
3. **核验与抽查（`T4`）**：计算 `review-hash --stage t4`，交 Codex 全面核验写入 `review_*_t4.md` 第 3 章；通过后 Claude 挑 `1～2` 项抽查写入第 2 章并注明抽查项与结论；均通过后签署 `review_*_t4.md`（`已通过`），将原生会话收据补入 `accept_*.md` 第 `4.5` 节并置为 `智能体已验真`。跨智能体审核须优先阻塞等待（如 `launch.py --wait`），禁止高频轮询或重复派发同一轮次。

### 3.3 T5 人类验收与收尾

1. 运行 `--gate cp1` 返回 `0` 后，按验收文档第 5 章整理 `CP1` 呈报包提交人类。
2. 人类不批准时将意见记入计划第 7 章，验收状态回退 `实跑取证中`，追加 `-r2` 返修任务修复后重走 `T4` 核验抽查再呈报。
3. 人类批准后助手直接收尾不再请示：验收状态置 `CP1已通过`，`.gdrive` 配图由 `pending` 迁入 `approved`，设计转正；通过 `archive-preflight` 后把 `plan / reviews / acceptance` 同构移入 `docs/archive/`，全仓修正入链，勾选 `T5.1` 并通过 `--gate archive`，统一提交推送。

## 4. 规范

### 4.1 研发评审文档契约（docs/reviews/）

- **文件名**：匹配 `^review_\d{8}_[a-z0-9.-]+_(t1|t2|t4)(-r(?:[2-9]|[1-9]\d+))?\.md$`；多轮 `-rN` 时门禁取最大 `N`。
- **七项文首必填字段**：`负责人`、`评审助手`、`关联计划`（精确相对链接）、`关联阶段`（`T1 / T2 / T4` 及被审文档链接）、`评审对象哈希`（`sha256:<64hex>`）、`评审结论`（`待修订 | 复评中 | 已通过 | 已废弃`）、`更新时间`（`YYYY-MM-DD`）。
- **五章固定正文**：`1. 当前依据`、`2. 架构核验与抽查`（Claude）、`3. 工程细节、防漏与验收核验`（Codex 或 `D4-A` 替补）、`4. 架构疑难升级裁定`、`5. 问题闭环与放行结论`（存量旧章名等效）；第 5 章须同时含 `未闭环 HIGH/MEDIUM：<整数>` 汇总行与逐条 `[CLOSED] / [OPEN]` 状态，且逐条 `[OPEN]` 高/中危数与汇总行一致并为 `0` 方可签 `已通过`。

### 4.2 研发验收文档契约（docs/acceptance/）

- **文件名**：匹配 `^accept_\d{8}_[a-z0-9.-]+\.md$`。
- **六项文首必填字段与六态状态机**：`负责人`、`执行助手`、`验真助手`、`关联计划`、`验收状态`、`更新时间`。状态限定为 `考卷草案`、`考卷已锁定`、`实跑取证中`、`智能体已验真`、`CP1已通过`、`已废弃`（支持驳回逆向回退：`智能体已验真 -> 实跑取证中`、`考卷已锁定 -> 考卷草案`）。
- **五章固定正文与五维防伪锚点**：`1. 当前依据`、`2. 锁定验收场景与判据`（`CP0` 锁卷切片：审定记录 + 各 `### 2.x Sn` 四要素）、`3. 智能体实跑与演示证据`、`4. 防伪锚点与双轨验真`（`4.1` 工作区基准、`4.2` 运行宿主环境、`4.3` 源码与测试脚本 `SHA-256`、`4.4` 安装态或线上制品 `SHA-256` 及 `T1/T2` 收据、`4.5` `T4` 核验与抽查原生会话收据签后追加区）、`5. CP1 呈报包`（存量旧章名等效）。

### 4.3 CP0 硬门槛与废弃同构约束

- **`CP0` 硬门槛**：`PL-CP0-TXT`、`PL-CP0-IMG`、`PL-CP0-ACC`、`PL-CP0-PROC`、`PL-CP0-REV` 缺一不可。
- **已废弃同构归档**：用户终止复杂计划并标为 `已废弃` 时，反向关联的全部 `reviews` 与 `acceptance` 须同步标为 `已废弃` 后方可同构归档。

## 5. 验收

规则码见 [00.common.acceptance.md](00.common.acceptance.md)，五档门禁放行标准如下：

| 门禁档位            | 复杂研发计划核心放行判据                                                      |
| :------------------ | :---------------------------------------------------------------------------- |
| `draft`             | 具备固定 `T1–T5` 阶段与 `CP0 / CP1` 定义、文首无重复键、复选框计数闭合        |
| `cp0`               | 设计含 TXT 图与合规配图、验收流程四要素与三方审定记录齐备、`t1/t2` 通过且鲜活 |
| `cp1`               | `T1–T4` 全 `[x]`、`lock-hash` 未变、锚点齐备、`t4` 核验与抽查均通过且哈希鲜活 |
| `archive-preflight` | `CP0/CP1` 已通过、`accept` 为 `CP1已通过`、仅 `T5.1` 可 `[ ]`（或全套废弃）   |
| `archive`           | 四目录已同构归入 `docs/archive/`、`100% [x]`、活动目录零残留、入链 100% 可达  |

**`CP1` 人类验收呈报包**（验收文档第 5 章）仅交付三项，不规定人类查法也不要求重跑或分项抽检：1) **结论**（各 `S` 场景是否通过，一句话一项）；2) **核验与抽查**（Codex 全面核验评价摘要、Claude 抽查了哪 `1～2` 项及结论）；3) **查看入口**（不超过 3 条可直接打开的页面、命令或文档位置）。
