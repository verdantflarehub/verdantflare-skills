## 2. 双轨计划等级与四受控目录边界

### 2.1 适用边界与必填等级字段

- **适用场景**：新研发任务立项定级、编制或升级 `docs/plan/*.plan.md`、创建或维护 `docs/reviews/` 与 `docs/acceptance/` 文档、执行存量未分级计划受控冻结与单向迁出。
- **不适用场景**：单次对话即答即结且无代码或配置落盘的普通技术咨询；纯创作分镜看片与选片评审表（如 `*.review.md`，仍归属创作或设计目录）；具体业务架构细节设计本身。
- **必填字段**：所有新建研发计划必须在文首 `助手` 字段之后、`计划状态` 字段之前声明 `计划等级`，取值仅限 `复杂研发计划` 或 `简单计划`。

命中以下任一条件时，必须定级为 `复杂研发计划`：

- **用户显式指定**：用户在立项或审阅时明确要求按复杂研发计划管控。
- **跨仓与多域耦合**：改动跨越 2 个及以上仓库或微服务，或同时触及后端逻辑、数据库迁移、部署清单与前端交互，或新建完整技能包并联动修改全局提示词。
- **公共契约与并发状态机变更**：新增或实质修改跨服务契约、并发锁仲裁状态机、持久化数据模型或安全权限边界。
- **高风险实境验收**：涉及 GPU 显存调度、多宿主异步协同或集群滚动切换，需要事先审定验收流程并由非作者智能体核验验收结果。

### 2.2 跨等级迁移与目标仓存量冻结

- **升级与特批降级**：简单计划推进中若范围扩展命中复杂判据或评估需要 `>= 2` 个检查点，必须升级为 `复杂研发计划`（保留已归档前序变更，重组为 `T1–T5`，补建 `docs/reviews/` 与 `docs/acceptance/`，在计划第 7 章登记升级依据）。命中复杂判据却拟按简单计划执行时，必须取得用户显式批准并记入第 7 章，否则门禁以 `PL-LVL-DOWNGRADE` 阻断。
- **存量冻结清单**：制度生效前已存在的未分级历史在途计划，由 `plan_lint.py freeze` 在目标仓库一次性生成 `docs/plan/.legacy-plans.json` 受控豁免（不向全局技能目录写入单仓状态）。未迁出计划（`migrated: false`）在 `--gate draft` 下豁免 `PL-LVL-REQ`，一旦补齐 `计划等级` 或调用 `migrate-legacy` 即永久单向退出豁免。

### 2.3 四大研发核心受控目录

| 受控目录           | 生命周期职责与归档去向                                                  |
| :----------------- | :---------------------------------------------------------------------- |
| `docs/plan/`       | 维护 `YYYY.MM.<主题>.plan.md`，结项或废弃移入 `docs/archive/plan/`      |
| `docs/changes/`    | 维护单子任务 `change_YYYYMMDD_*.md`，完成即移入 `docs/archive/changes/` |
| `docs/reviews/`    | 驻留复杂计划 `review_YYYYMMDD_<主题>_<阶段>.md`，随计划同构归档         |
| `docs/acceptance/` | 驻留复杂计划 `accept_YYYYMMDD_<主题>.md`，随计划同构归档                |

复杂计划在途期间，`reviews` 与 `acceptance` 持续驻留核心目录并通过文首 `关联计划` 反向相对链接绑定所属计划；计划在 `T5` 结项或废弃时，四类受控文档同步归入 `docs/archive/` 对应子目录并全仓修正入链引用。

## 3. 角色决策与审批铁律

- **客观量化不越权拍板**：涉及产品边界、公共契约或重大取舍时，AI 助手只按量化评分倒序呈现候选项，严禁自封“首推”或替人类做主；非关键、可逆的底层技术参数由研发智能体按量化标准先行定案，不反抛人类逐项勾选。
- **严禁伪造批准或测试通过**：未获人类明确批复不得把 `CP0 / CP1` 标为 `已通过`；立项选型授权（如 `A01`）属立项输入，不顶替执行期 `CP0` 或 `CP1`。
- **驳回返修不抹除历史勾选**：`CP0` 或 `CP1` 未通过需返工时，严禁取消已结项归档子任务的 `[x]` 勾选，必须在对应阶段追加 `-r2`（及 `-r3`）返修子任务并新建独立 `change_*.md`，同时将受控评审或验收状态按状态机逆向回退。

## 4. 多智能体主责专精与反自审规则（PL-REV-INDEP）

### 4.1 验收三方分工与 Claude 边界

- **验收流程**：执行者起草，Codex 直接修订，Claude 直接修订定稿；三方定不下来才上报人类，详见 [02.complex-plan.entrypoint.md](02.complex-plan.entrypoint.md)。
- **验收执行**：执行者亲自取证；Codex 全面核验执行者的验收结果是否符合流程，是客观评价，不是怀疑真实性，禁止重跑或重拉产物；Claude 只抽查 Codex 评价 `1～2` 项，禁止全面复核。
- **Claude 职责**：`T1` 总体架构核验与验收流程修订定稿、`T4` 抽查、跨系统架构冲突单次裁决；`T2` 未推翻 `T1` 总体架构时默认 `0` 次调用。
- **Claude 严禁事项**：严禁让 Claude 承担源码、CLI 参数、正则、测试脚本等工程细节审，也不得让 Claude 替补 Codex 的全面核验。

### 4.2 工程细节审独立性与替补铁律（D4-A）

- **作者提取边界**：被审阶段产物的作者集合（`author_agents`）按该阶段交付物关联的 `change_*.md` 文首 `助手` 字段提取（排除评审/核验子任务自身变更）；`T4` 协同取证的智能体同样计入作者。
- **异构研发替补（D4-A）**：默认强制执行智能体身份级互斥（`author_agents ∩ reviewer_agents == ∅`，且同一替补者不得兼任同阶段双评审角色）。当 `Codex` 担任主力编码作者触发冲突时，必须换用非作者的其他研发智能体（如 `Gemini` 独立新会话）替补 `codex_detail` 工程细节审与验收结果核验，**严禁拉 Claude 替补代码或测试脚本细节审**。
- **特批同源隔离（D4-B）**：仅当计划第 7 章审批记录存在人类显式批准 `D4-B` 时，方允许按物理会话 ID 互斥（`author_session_ids ∩ reviewer_session_ids == ∅`）并在评审文首显式声明 `同源隔离会话评审：是`。

## 5. 确定性哈希与双棘轮防逃逸规则

- **锁卷防篡改（PL-CP1-LOCK）**：复杂计划在 `CP0` 批准时将 `accept_*.md` 第 2 章 `lock-hash` 写入计划第 7 章审批记录；`T3 / T4` 期间严禁删减场景、改弱阈值或用 `or` 模糊断言绕过单变量校验，否则 `--gate cp1` 立即阻断。
- **冻结切片陈旧检测（PL-REV-STALE）**：`review-hash` 自动归一化 CRLF/行尾空白与 `.gdrive/managed/<bucket>/` 桶名，并豁免文首可变状态行及验收文档 `4.5` 节与第 `5` 章追加区；凡篡改被审设计正文或验收第 `2～4.4` 节冻结证据而未重过评审，一律阻断。
- **双棘轮防删字段逃逸（PL-LVL-REQ）**：不在目标仓 `.legacy-plans.json` 内的计划、已标记 `migrated: true` 的计划，或 Git 历史提交曾出现过 `计划等级：` 后又在工作区删掉该字段的计划，一律触发 `PL-LVL-REQ` 阻断。
