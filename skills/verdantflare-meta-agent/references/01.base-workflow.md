# Agent 协作执行流程

## 1. 当前依据

- [分类与边界](01.base-category.md)：适用场景和角色。
- [规则约束](01.base-rules.md)：身份、消息与恢复约束。
- [验收标准](01.base-acceptance.md)：可观察的通过与失败条件。

## 2. 准备委托

读取计划、关联变更及设计，核对已有授权和负责人。确认任务已纳入计划，并登记稳定任务键、当前展示编号和变更路径；发现设计或输入缺口先按计划处理，不临时扩范围。

确认执行、审阅、统筹与结项维护者及回传目标。核对原生 Session ID、工作区、宿主模式和在线能力。名称使用“计划名称｜任务编号或统筹｜职责｜Agent”，同角色多会话增加序号；投递仍使用实际地址。

将范围、输入、交付物、验证命令、完成条件和回传目标写入变更任务边界；具体会话、任务与轮次收据写执行记录。填写交接 JSON 后执行只读检查：

```text
python scripts/check_handoff.py --workspace /workspace --input handoff.json
```

工作区参数由受控环境提供，不复制个人绝对路径到交接正文。检查器验证字段、目标类型、相对路径和文件存在；不能证明授权真实、计划内容正确或会话在线，这三项必须由调用方读原始证据核对。

## 3. 派单与执行

按对应宿主调度技能调用工具，保存原 request_id、task_id、原生 Session ID 和 turn_id。返回 queued 只代表受理。不能因为查询超时就创建新请求或替换会话。

执行方先核对交接及当前工作区，在同一子任务变更记录操作、验证和证据。发现范围外需求回到计划，返修留在原任务；需要修改同一工作区时遵守租约及文件范围。

## 4. 回传与统筹

执行结果先持久保存，再通知约定目标，包含稳定任务键、委托及修订、证据、实际验证、未解决事项和建议动作。支持服务观察时由持久观察器收集终态并产生唯一结果事件，防止执行方退出造成遗漏。

统筹确认收到并识别消息后核验结果。单项可验收则推进其依赖；需审阅则提交审阅；前置条件必须全部满足的汇总任务等待所有前置成果。失败与阻塞只影响实际依赖，独立工作继续。

审阅未通过时把具体问题送回原任务，递增修订号；通过不等于用户批准。结项维护者在全部完成条件满足后按仓库规范收尾，不能凭通知送达勾选任务。

## 5. 恢复与退出

使用本机账本和持久 worker 时按[运行时接口](runtime.md)登记、投递、查询与接管；仅使用静态交接检查器不会启动通知服务。

退出前将外部任务及通知收据、停点、未验证项和恢复条件写入变更。核对负责连接的进程确实仍存活，才能说明任务会继续后台执行。

恢复先读计划与变更，查询原任务及通知状态。目标忙碌或离线时保留队列并按规则退避；结果不确定时核对原收据，不盲目重发。需换统筹会话时核对接管授权、更新路由代数并显式迁移未处理消息，不能按标题自动选择另一会话。

无法自动恢复时报告具体接口或宿主缺口、已保存证据和恢复入口；只把必须由人决定或操作的事项交给人类，不要求人工搬运普通 Agent 消息。
