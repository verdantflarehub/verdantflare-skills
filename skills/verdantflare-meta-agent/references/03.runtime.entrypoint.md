# 本机协作运行时与故障恢复（03.runtime）

## 1. 输入与输出

- **输入**：工作区路径、受控本地 SQLite 数据库路径、交接 JSON（[handoff.example.json](../resources/handoff.example.json)）、服务配置 `services.json`（含 `agent` 与 `argv`），以及绑定/消息/回执/接管 CLI 参数。
- **输出**：由 [agent_runtime.py](../scripts/agent_runtime.py)、[store.py](../scripts/verdantflare_agent/store.py) 与 [worker.py](../scripts/verdantflare_agent/worker.py) 维护的持久账本状态、消息投递收据、终态结果事件与精确错误码。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的身份稳定键、脱敏与接管边界。

## 2. 分类

| 宿主适配器 (`agent`) | 支持模式与核心机制                                                                          |
| :------------------- | :------------------------------------------------------------------------------------------ |
| `codex`              | `plugin`（明确 `thread_id`）与 `managed`（须先 `bind` 已有 `task_id` 和 `turn_id` 再续接）  |
| `claude`             | `panel`（明确 `session_id`）与 `managed`（有绑定续接 `task_id` 与预期轮次，无绑定恢复会话） |
| `antigravity`        | `cli`（`agy_cli_task_start/status/result`）与 `panel`（Hub 只读核对 `source=hub` 原生步骤） |
| `grok`               | `acp`（固定受理 worker、AFK Pilot 索引同步）与 `headless`（原生 `--resume` 续接）           |

## 3. 工作流

### 3.1 登记、查询与重链接

Python 3.10 及以上标准库即可运行账本及测试。以下路径为通用示例，实际数据库放目标环境批准的本地状态目录：

```text
python -X utf8 scripts/agent_runtime.py --workspace . --database .tmp/agent/state.sqlite register --input handoff.json
python -X utf8 scripts/agent_runtime.py --workspace . --database .tmp/agent/state.sqlite sessions
python -X utf8 scripts/agent_runtime.py --workspace . --database .tmp/agent/state.sqlite status --message-id message-1
python -X utf8 scripts/agent_runtime.py --workspace . --database .tmp/agent/state.sqlite run --input services.json
```

- `register`：使用交接检查器的完整对象，验证文件与路径后登记端点和委托。首次 `revision` 必须为 1，返修依次递增；同修订、同内容可幂等重复，稳定任务键和计划身份不随返修改变。
- `sessions` 与 `rename`：`sessions` 返回原生地址及 `display_name`（逻辑名，不代表宿主标签已改）；`rename` 输入 `session_key`、`name`，仅改本机逻辑名。
- `bind`：输入 `session_key`、`receipt`（含真实 `session_id`、`task_id`、`turn_id`）和 `expected_turn_id`（首次绑定为 `null`，更换已有绑定须匹配先前轮次）。只登记已获得收据，不创建会话；适配器调用前仍会向服务核对会话、模式和当前轮次。
- `relink`：输入 `plan_id`、`plan_name`、`plan_path` 和 `tasks` 数组（含 `task_key`、`task_label`、`change_path`）。核对新文件存在后更新当前映射，保留旧交接和消息快照，不递增任务修订或重新执行任务；编号变化后按需 `rename`。

### 3.2 消息、回执与结果

- `enqueue`：输入包含 `message_id`、`kind`、`plan_id`、`task_key`、`assignment_id`、`revision`、`sender`、`sender_generation`、`recipient`、`recipient_generation`、`causation_id` 和 `payload` 的消息对象。`sender`/`recipient` 为已登记 `session_key`，`payload` 为对象；类型和路由必须符合该委托。
- `status`：返回持久消息、状态、尝试数、有效路由代数、后端收据及处理回执；含任务正文的结果只在受控环境查看，对外报告须脱敏，不直接复制整个状态到 Git 文档。
- `ack`：使用 `--message-id` 指定消息，输入 `recipient`、`generation`、`assignment_id`、`revision`、`turn_id` 和 `action`。必须匹配该次投递收据；相同回执幂等，异文回执拒绝，旧代数和旧修订只留历史。`ack` 不产生新消息，也不意味着业务已验收。
- `report`：使用 `--message-id` 指定已投递的 `assignment`/`review_request`，输入 `terminal`（`completed`、`failed`、`cancelled` 或 `timed_out`）和 `result`（含证据对象）。服务观察器使用同一事务入口生成唯一结果消息，防止执行方与观察器重复回传；后端完成不改变 `business_accepted=false`，业务验收仍由统筹核对。

### 3.3 接管与故障恢复

1. 恢复先读计划与变更，查询原任务及通知状态。目标忙碌或离线时保留队列并按规则退避；结果不确定时核对原收据，不盲目重发。
2. `takeover` 输入 `endpoint`（交接地址结构）、`expected_generation` 和 `authorization`（真实接管依据，不自造用户批准），`generation` 必须递增 1。
3. `migrate` 使用 `--message-id` 与 `expected_generation`，只迁移 `queued`/`retry_wait` 的明确未投递消息，原信封保持可追溯，实际 `route_generation` 更新；旧路由未迁移时 worker 留下 `MIGRATION_REQUIRED`，不自行选择替代会话。
4. `delivering` 租约到期变为 `unknown`，先核对原请求，不自动重新派单。已投递消息仅查询原任务；观察失败保留收据和游标，显示 `OBSERVATION_UNAVAILABLE`。等待人工审批不作终态，不自动批准。

## 4. 规范

### 4.1 数据库、锁与服务配置

- 数据库路径由调用方显式提供，放当前操作系统用户控制的本地目录，不提交 Git，不放云同步目录；数据库绑定解析后的工作区真实路径，另一工作区不能借用。
- 同数据库只能运行一个 worker，操作系统文件锁阻止第二个存活 worker 启动；崩溃释放锁并保留 SQLite 及审计事件。删除 lock 文件不是解锁方式，不能删库绕过不确定状态；工作区迁移须核对外部任务和路由，不能简单改数据库 `workspace` 字段。
- `run` 的输入为 `services` 对象，键为已登记服务标识，值含 `agent`（仅 `codex`、`claude`、`antigravity`、`grok`）与 `argv`（显式字符串数组启动对应 MCP stdio 服务，禁用 shell 拼接）。路径与本机信息留受控配置，消息不能提供或覆盖 `argv`；缺适配模块返回 `ADAPTER_NOT_IMPLEMENTED`，不降级换 Agent。
- 本运行时不注册开机启动、不全局安装、不改宿主权限；通过已授权进程管理保持 `run` 存活，数据库保留不代表 worker 存活，进程已退出不宣称继续自动回传。

### 4.2 消息生命周期与幂等退避

- 相同 `message_id` 不同内容拒绝；重试沿用同一 ID 避免重复业务。
- `queued` 表示持久接收，`delivering` 表示投递中，`delivered` 表示后端受理，`acknowledged` 表示接收方确认处理；业务完成与验收通过须另行举证。回执匹配消息、接收方、路由代数及委托修订，不对回执再次发通知。
- 明确未受理的忙碌/离线可退避重试；可能已受理的超时进入 `unknown`，先核对原请求和轮次，无幂等保证时禁止重放写操作。默认退避 5 秒倍增至 300 秒，有效期 24 小时、尝试上限 20 次，可按场景配置；到期留证，不删后重派掩盖失败。
- worker 持久保存消息、游标和收据，启动恢复时核对未完成 `delivering`；重复结果与过期修订只记历史，不重复推进依赖。

### 4.3 四宿主适配器规范

- **Codex**：`plugin` 用明确 `thread_id` 启动一轮，`managed` 须先 `bind` 已有 `task_id` 和 `turn_id` 再调用 `task_continue`，不自动建替代会话、不改模型或权限。外部写入前保存工具名与参数，`request_id` 在重试期间固定；`queued` 的 `task_id` 立即保存，`turn_id` 未确认前不记 `delivered`。恢复有收据先查原任务，无收据仅在同键幂等契约允许时重发完全相同参数。结果只读收据对应 `turn_id`，完整拼接分页并验证每页身份与游标推进；最终答复须含匹配 `VF_AGENT_ACK` JSON 行，普通“完成”不接受；通知中工作区与用户目录按占位符脱敏。原生命名用 `codex_session_rename`（传 `thread_id`、`cwd`、`name`），原生 API 回读一致才返回 `native`，不把缺失工具降级为成功；在线读取、真实受管投递和插件写入分别验证，`read_verified` 不代表插件写入成功。
- **Claude**：`panel` 用明确 `session_id`；`managed` 有绑定续接 `task_id` 和预期轮次，无绑定以明确 `session_id` 恢复既有会话，不创建替代目标。`panel` 取消保留 UI 要求，不切换模式或自动批准权限；结果及回执沿用精确轮次和分页核验。原生命名通过 `claude_session_rename` 独立执行并读取最新 `customTitle` 验证；受理连接须保持在线，未知后端任务保留原收据；源码独立服务验收与已安装共享服务、面板 UI 验收分别记录。
- **Antigravity**：`cli` 模式用 `agy_cli_task_start/status/result` 恢复明确 `conversation_id`，合成 `turn_id` 对应唯一请求，原生会话 ID 须回读匹配；取消无可验证原生终态接口时拒绝，不靠杀进程冒充成功。`panel` 模式提交前冻结基线与提示词，响应丢失后只读核对 `source=hub` 原生步骤，仅唯一匹配输入之后、下一条用户输入之前的回复属该轮，重复匹配或游标变化拒绝结项，无匹配输入也不自动重发；忙碌不改派 `cli`，保持 `focus_panel=false`。当前未验证原生命名入口，不声称宿主标题已改；CLI 目录由 `cwd` 与 `--add-dir` 指定，原生历史归属未由 CLI 输出独立证明，须用已核对来源的登记会话。
- **Grok**：使用 `acp` 或 `headless` 明确 `session_id`；有绑定以 `expected_turn_id` 续接，无绑定恢复指定原生会话。`headless` 续接用原生 `--resume`，`--session-id` 仅用于新会话，不得混用；结果与回执同精确轮次与分页核验。新任务与续接固定给受理 worker，仅未领取命令允许 owner 丢失后恢复；已提交未知结果继续占用工作区与会话，不用 `cancel` 强标完成。`acp` 专用初始化提示词首行可作 AFK Pilot `autoName`，同步保留 `customName` 与 `pinned`；元数据与三份原生轨迹存在不单独证明 UI 已渲染，`headless` 会话不作 AFK Pilot 面板展示验收。

## 5. 验收

- 运行 `python -X utf8 -m unittest discover -s scripts -p "test_*.py"`（覆盖 `test_runtime.py`、`test_transport.py` 及四宿主适配器单测）全部通过。
- 验证消息重复不重复执行业务、旧修订不覆盖当前结果、回执不产生通知循环；分别验证目标忙碌、离线、投递响应丢失和 worker 重启时的外部调用次数与持久记录。
- 失效 CLI 输入返回非零退出码和固定错误码，不回显原始异常路径；对每种支持模式分别验证精确 Session 投递、可见逻辑名称和可用原生命名，隔离模拟不替代真实跨宿主证据。
