# Agent 协作验收标准

## 1. 当前依据

- [规则约束](01.base-rules.md)：身份、投递和权限判据。
- [执行流程](01.base-workflow.md)：交接、回传与恢复。
- [交接检查器](../scripts/check_handoff.py)：只读静态前置检查。

## 2. 静态与交接检查

入口和四份底座可独立读取，元数据正确、无断链及跨技能文件依赖。交接中计划、任务、变更、Session 地址、范围、验证及回传字段齐全；不存在的文件、越界路径、未知模式或缺少原生会话 ID 必须拒绝。检查器通过不证明计划批准或宿主可达。

测量时先运行交接检查器和单元测试，保留命令退出码与明确拒绝原因。通过标准为有效输入正常受理，缺字段、错误类型和越界路径均非零退出且不触发外部写入，不以主观评分替代。

## 3. 协作行为验收

用真实计划任务验证一次执行、回传、审阅退回、原任务返修、审阅通过及统筹推进。任务身份与变更保持一致，只有实际满足完成条件才勾选。汇总依赖未齐时不得启动；单项已满足时不得无故等待无关任务。

消息重复不重复执行业务，旧修订不覆盖当前结果，回执不产生通知循环。分别测试目标忙碌、离线、投递响应丢失和 worker 重启，检查实际外部调用次数与持久记录。

## 4. 宿主与人工结果

对每种实际支持的模式验证精确 Session 投递、可见逻辑名称和可用原生命名。隔离模拟只能证明本地机制，不能作为真实跨宿主证据。调用方结束当前轮次后的结果回传必须由仍在运行的机制实际完成。

报告静态检查、模拟行为、真实宿主、UI、安装、发布及用户确认各自结果。未测的能力明确为未验证；缺少自动回传不能由人工转达替代。必要人工检查只沿用计划既有检查点。
