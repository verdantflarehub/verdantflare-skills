# Agent 协作分类与边界

## 1. 当前依据

- [技能入口](../SKILL.md)：适用范围与协作对象。
- [规则约束](01.base-rules.md)：身份、授权及状态语义。

## 2. 适用判定

用户或已授权统筹要求另一个 Agent 执行或审阅具体任务时应用。接收委托、报告结果、处理阻塞、恢复中断和接管统筹同样应用。普通问答和方案讨论无需生成委托，也不因此建计划。

先取证计划、末级任务、变更、目标宿主能力及回传地址。缺少计划依据时不派单，先在授权范围内落实任务；目标能力未知时只做读取探测，不能凭历史文件存在认定在线可控。

## 3. 角色判定

- 统筹：分配任务、接收证据、安排审阅、处理依赖与协调收尾。
- 执行：落实单项任务、记录验证与阻塞，向已登记目标回传。
- 审阅：按完成条件检查产物，给出通过或具体返修意见。
- 结项维护者：按仓库要求统一勾选、归档、提交和推送，避免重复收尾。

一个 Session 可承担多个已登记职责，但 AI 不替代人类负责人或审批人。需独立审阅时不能由执行者自行冒充另一审阅者。

## 4. 能力分级

名称分原生标题与逻辑名称；回读成功才能声称原生标题已修改。地址必须包含服务、模式和原生 Session ID。受管会话、插件会话和面板会话分别确认，不能自动切换。

派单接口受理、接收方处理、任务完成及验收分别取证。只有持久运行机制和真实宿主闭环均验证后，才承诺调用方退出后的自动通知。缺少该能力时记录缺口和恢复入口，不让人类转达后声称自动闭环已完成。
