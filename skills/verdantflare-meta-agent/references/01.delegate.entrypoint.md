# 跨 Agent 派单与交接（01.delegate）

## 1. 输入与输出

- **输入**：计划文档与稳定 `plan_id`、末级任务 `task_key` 与关联变更路径、目标宿主模式与原生 Session ID、任务范围与验证命令、已有授权依据及回传目标。
- **输出**：通过 [check_handoff.py](../scripts/check_handoff.py) 校验的 20 字段交接单（参考 [handoff.example.json](../resources/handoff.example.json)）、写入变更执行记录的外部请求与轮次收据、可追溯的结果回传与统筹收尾记录。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的计划绑定、身份稳定键、权限边界与反自审红线。

## 2. 分类

### 2.1 适用判定

用户或已授权统筹要求另一个 Agent 执行或审阅具体任务时应用；接收委托、报告结果、处理阻塞、恢复中断和接管统筹同样应用。普通问答和方案讨论无需生成委托，也不因此建计划。

先取证计划、末级任务、变更、目标宿主能力及回传地址。缺少计划依据时不派单，先在授权范围内落实任务；目标能力未知时只做读取探测，不能凭历史文件存在认定在线可控。

### 2.2 角色判定

- **统筹**：分配任务、接收证据、安排审阅、处理依赖与协调收尾。
- **执行**：落实单项任务、记录验证与阻塞，向已登记目标回传。
- **审阅**：按完成条件检查产物，给出通过或具体返修意见。
- **结项维护者**：按仓库要求统一勾选、归档、提交和推送，避免重复收尾。

### 2.3 能力分级

- **名称分级**：区分原生标题与逻辑名称；回读成功才能声称原生标题已修改。
- **地址分级**：地址必须包含服务、模式和原生 Session ID；受管会话、插件会话和面板会话分别确认，不能自动切换。
- **证据分级**：派单接口受理、接收方处理、任务完成及验收分别取证，不混同汇报。

## 3. 工作流

### 3.1 准备委托

1. 读取计划、关联变更及设计，核对已有授权和负责人；确认任务已纳入计划，并登记稳定任务键、当前展示编号和变更路径。发现设计或输入缺口先按计划处理，不临时扩范围。
2. 确认执行、审阅、统筹与结项维护者及回传目标；核对原生 Session ID、工作区、宿主模式和在线能力。名称使用“计划名称｜任务编号或统筹｜职责｜Agent”，同角色多会话增加序号；投递仍使用实际地址。
3. 将范围、输入、交付物、验证命令、完成条件和回传目标写入变更任务边界；具体会话、任务与轮次收据写执行记录。填写交接 JSON 后执行只读检查：

```text
python -X utf8 scripts/check_handoff.py --workspace /workspace --input handoff.json
```

### 3.2 派单与执行

1. 按对应宿主调度技能调用工具，保存原 `request_id`、`task_id`、原生 Session ID 和 `turn_id`；返回 `queued` 只代表受理，不能因为查询超时就创建新请求或替换会话。
2. 执行方先核对交接及当前工作区，在同一子任务变更记录操作、验证和证据。发现范围外需求回到计划，返修留在原任务；需要修改同一工作区时遵守租约及文件范围。

### 3.3 回传与统筹

1. 执行结果先持久保存，再通知约定目标，包含稳定任务键、委托及修订、证据、实际验证、未解决事项和建议动作。支持服务观察时由持久观察器收集终态并产生唯一结果事件，防止执行方退出造成遗漏。
2. 统筹确认收到并识别消息后核验结果：单项可验收则推进其依赖；需审阅则提交审阅；前置条件必须全部满足的汇总任务等待所有前置成果。失败与阻塞只影响实际依赖，独立工作继续。
3. 审阅未通过时把具体问题送回原任务，递增修订号；通过不等于用户批准。结项维护者在全部完成条件满足后按仓库规范收尾，不能凭通知送达勾选任务。
4. 退出前将外部任务及通知收据、停点、未验证项和恢复条件写入变更；核对负责连接的进程确实仍存活，才能说明任务会继续后台执行。需要持久账本与故障恢复时转 [03.runtime.entrypoint.md](03.runtime.entrypoint.md)。

## 4. 规范

- 工作区参数由受控环境提供，不复制个人绝对路径到交接正文。
- [check_handoff.py](../scripts/check_handoff.py) 验证字段、目标类型、相对路径和文件存在；不能证明授权真实、计划内容正确或会话在线，这三项必须由调用方读原始证据核对。
- 仅使用静态交接检查器不会启动通知服务；无持久运行机制和真实宿主闭环验证前，不承诺调用方退出后的自动通知。
- 无法自动恢复时报告具体接口或宿主缺口、已保存证据和恢复入口；只把必须由人决定或操作的事项交给人类，不要求人工搬运普通 Agent 消息。

## 5. 验收

- **静态与交接检查**：交接中计划、任务、变更、Session 地址、范围、验证及回传字段齐全；不存在的文件、越界路径、未知模式或缺少原生会话 ID 必须拒绝。运行交接检查器和单元测试，保留命令退出码与明确拒绝原因；有效输入正常受理，缺字段、错误类型和越界路径均非零退出且不触发外部写入，不以主观评分替代。
- **协作行为验收**：用真实计划任务验证一次执行、回传、审阅退回、原任务返修、审阅通过及统筹推进。任务身份与变更保持一致，只有实际满足完成条件才勾选；汇总依赖未齐时不得启动，单项已满足时不得无故等待无关任务。
- **分项报告**：分别报告静态检查、模拟行为、真实宿主、UI、安装、发布及用户确认结果；未测能力明确标为未验证，缺少自动回传不能由人工转达替代，必要人工检查只沿用计划既有检查点。
