# 多智能体评审分工与低 Token 门禁（02.review-division）

## 1. 输入与输出

- **输入**：待评审计划、设计、验收或变更文档路径、目标评审智能体（Claude / Codex / 独立替补智能体）、评审阶段（`review_stage`）及评审文档路径（`review_doc_path`）。
- **输出**：通过 `HO-CLAUDE-SCOPE` 机器门禁检查的评审交接单、符合主责边界的架构核验 / 细节评审 / 验收核验 / 抽查结论，以及退回原任务返修或推进下一阶段的统筹指令。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的反自审、计划绑定与低 Token 评审主责总纲。

## 2. 分类

| 评审阶段 / 主责对象                 | 适用场景与字符上限                                                        |
| :---------------------------------- | :------------------------------------------------------------------------ |
| `claude_arch`                       | `T1` 总体与技术架构核验；递归累计字符串与路径 `<= 1,200` 字符             |
| `claude_acceptance_revision`        | `T1` 直接修订并定稿 `accept_*.md` 验收流程，`<= 1,200` 字符               |
| `claude_spot_check`                 | `T4` 在 Codex 通过后抽查其评价 `1～2` 项（不做全面复核），`<= 1,000` 字符 |
| `claude_escalation`                 | 跨系统架构级分歧单次短卡裁决，`<= 800` 字符                               |
| `codex_detail` / `acceptance_audit` | 工程细节审、`T1` 流程修订、`T2` 防漏审与 `T4` 全面核验                    |

说明：`claude_arch`、`claude_acceptance_revision`（`review_doc_path` 须为 `docs/acceptance/accept_*.md`）、`claude_spot_check`（存量 `claude_arch_audit` 为等效别名）与 `claude_escalation` 均仅发往 Claude；`total_text_chars` 按递归累计全部字符串与路径字段计算；`T2` 架构未变时 `0` 次 Claude 调用。

## 3. 工作流

1. **判定主责与独立性**：按上表先判定属于架构/抽查/裁决还是具体工程细节/验收全面核验。若 Codex 为被审作者（含协同取证），按独立性规则换用其他非 Claude 研发智能体（如 `Gemini` 独立会话）替补，严禁拉 Claude 替补代码或脚本细节审，也不得让 Claude 代替 Codex 全面核验。
2. **组装精简交接单**：发往 `agent="claude"` 时填写成对可选字段 `review_stage` 与 `review_doc_path`，确保 `inputs`、`deliverables`、`plan_path`、`change_path` 全部落在白名单文档内，不携带源码、脚本、日志或媒体路径。
3. **执行静态门禁校验**：运行只读检查器核验 `HO-CLAUDE-SCOPE`、字符限额、标识符格式与路径白名单：

```text
python -X utf8 scripts/check_handoff.py --workspace . --input handoff.json
```

4. **长轮次守护与退避**：调用宿主长轮次工具（含 `launch.py --wait` 守护规程）时复用已登记原生 `session_id / thread_id`；遇会话忙碌按退避间隔等待，查询超时先回读原收据核对终态，禁止新建平行会话绕过互斥。
5. **回收结论与返修闭环**：评审未通过时将具体问题送回原任务递增 `revision`；评审通过只代表技术审阅完成，不替代人类检查点批准。

## 4. 规范

- **成对字段与阶段绑定**：发往 `agent="claude"` 的交接单必须携带成对可选字段 `review_stage` 与 `review_doc_path`；`review_stage` 仅允许 `claude_arch`、`claude_acceptance_revision`、`claude_spot_check`（含等效别名 `claude_arch_audit`）或 `claude_escalation`；任何 `claude_*` 阶段也只能发往 Claude。标识符字段限定为 `[A-Za-z0-9._:-]{1,64}`。
- **只读与全路径白名单**：发往 Claude 的交接单强制 `allowed_write_paths == []`（唯一例外：`claude_acceptance_revision` 只可写其 `review_doc_path` 指向的那份验收文档）。
- **受控文档路径限制**：发往 Claude 时，`plan_path` 与 `change_path` 必须指向受控 `docs/[archive/]{plan,changes}/` 下的 `.md` 文档，`deliverables` 仅允许指向 `docs/reviews/` 或 `docs/acceptance/` 下的 `.md` 报告，`inputs` 仅允许 `docs/{design,plan,reviews,acceptance}/` 下的既有 `.md` 文档；严禁通过任何字段传入源码、测试脚本、配置清单、日志或媒体文件（如 `.py`、`.ts`、`.go`、`.sh`、`.yaml`、`scripts/`、`tests/`）。
- **Codex 全面核验边界**：具体 CLI 参数、正则、字节数、单测矩阵、`T1` 验收流程直接修订、`T2` 全仓影响防漏（架构未变时 `0` 次 Claude 调用）及 `T4` 对照锁卷流程全面核验执行者验收结果（是否按流程取证、证据是否充分、结论是否成立；不重跑、不重拉产物）统一归 `codex_detail` / `acceptance_audit`。

## 5. 验收

- 运行 `python -X utf8 scripts/check_handoff.py --workspace . --input handoff.json` 返回 `0` 退出码；超字符上限、写路径越界、传入非白名单源码/脚本或将 `claude_*` 发往非 Claude 均非零退出并输出明确 `HO-CLAUDE-SCOPE` 拒绝原因。
- 运行 `python -X utf8 -m unittest discover -s scripts -p "test_handoff.py"` 全部通过。
- 实际协作中满足：架构未变时 `T2` 调用 Claude 次数为 `0`；`T4` 抽查仅覆盖 Codex 评价的 `1～2` 项而非全面复核；被审作者未自审且未拉 Claude 替补细节审。
