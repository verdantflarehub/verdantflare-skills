# 重复失败后的表演返修

## 1. 适用范围

同一动作、对白或连续性缺陷在多个候选中重现时使用。本页补充[表演规范](performance.md)、[对白交接](dialogue.md)与[场景连续性](../production/scene-keyframe-video.md)，不替代实际 Video/Speech 能力发现。

## 2. 先区分失败来源

每次返修写出“实际缺陷及源时码 → 本次改变的输入或控制 → 通过所需画面/声音证据”。同一失败重复出现时，不只增加负面词或反复宣称“严格保持”；检查以下层次：

- 设定冲突：执行版改变逃生口、手性或声线要求，输入仍引用旧版本。先明确当前依据并撤出冲突参考。
- 参考冲突：正面双人图压过斜侧机位、旧临水窗口压过甲板出口、衣板面孔串入女主。减去冲突输入，保留每份参考的唯一职责。
- 能力不匹配：多图参考不等于精确首尾约束；音频参考不等于逐字复现或强制口型；普通编辑不等于遮罩局部修复。按真实接口改执行方案，不以提示词填补不存在的控制。
- 单元过载：一句恳求、看威胁、推送、转身和离开在过短窗口内互相争抢。允许按动作拆镜，但要保留完整因果链与接触过程。
- 生成误差：固定参考无冲突仍重复失败时，改为更可验证的镜头组织或已开放的控制方式；停止无差别重生整段。没有合格输出就保持未完成。

## 3. 台词、口型与声音年龄感分开验收

固定台词按角色逐句对照，记录实际起止、漏字/多字/重复、说话人、闭口与听者反应。ASR只提供可疑时码，不能仅凭识别错误判定人耳一定听错，也不能凭识别正确认定成熟度、身份和口型合格。口型至少核对起音、停顿、闭唇音及句末收口，结合原速播放；嘴仍在持续说话时不能靠替换音轨冒称同步完成。

参考音频在 Video 中的能力按预检和实测确认。若参考仅控制声线或风格，不许写成“逐字复刻已保证”。独立对白可以用于真正的画外音、背向镜头或嘴部自然不可见的镜头，但应保留剧情所需反应镜，不以掩住嘴替代用户明确要求的可见对白表演。

音色年龄感、声线身份与本场情绪是三项不同要求。用户反馈幼态时，先区分源声线和撒娇式演法；仅减少惊惧、增加平静不等于重设计年龄。后端不支持音色设计时明确限制，不能用整体降调/降速冒充成熟声音。新声音参考按独立候选保存，确认后同角色跨镜复用；不逐句各造一个声音。

## 4. 拆镜不能删掉因果

父女分离这类段落要有可见的请求、回应、外部刺激和决定。把“请求”从“听到威胁后转身”拆开，可以降低方向混乱；但后续必须补回回应、威胁声与定向反应，不能以剪掉失败尾部宣称整条动作已修复。

实际可用区间须同时覆盖完整台词、必要反应与可接画的终态。截取2秒好看的头部，若砍掉尾字、抓袖松开或落脚，就只是一段局部候选。时间线记录原始帧区间、声音边界及仍缺的节拍，不通过慢放、倒放、补静帧或溶解掩盖动作缺失。

追逃戏还需验证角色可达性：角色实际路径、障碍与间距使逃离机会成立；追兵不得无因停步，死者不得成为追兵。跳跃落点由起跳位置、方向与高度决定，空中轨迹接入水点；不能只验首尾图。白模给出空间依据，生成结果仍逐镜核对。

### 4.1 接触细节被遮挡时的插入镜头

主体动作已大致成立、关键落脚或交接被衣物／构图遮挡时，可补拍同一动作的另一视角。明确它是同时发生的动作切面，不能提示为“接着再做一次”。复用当前空间与材质依据，固定起始支撑点、承重脚、持物手和动作终态；白模中的占位人形不作为新增角色，已有白模视图也不能冒称新机位已在工程中落实。

匹配剪辑按动作状态选源帧：切入前后的持物、手脚接触、重心与朝向须可衔接；换角时另查轴线、左右手、服装和空间标志，不用水平翻图补救。允许排除原片的失败区间，但保留原片退回结论和选段依据，不能把局部候选等同整段通过。时间线记录每段来源哈希、起止帧及是否变速，复验输出帧率、时长和两个切点；首脚落地后仍须交代后脚越障与离手，不能剪掉必要动作掩盖缺口。

### 4.2 多道具同镜与持续持物

交接镜头不仅需要移动道具的参考，也要核对镜内仍被持有、佩戴或放置的关键道具。例如右手接木符时，左手原有货印虽不发生动作，仍需明确独立身份、形状材质和持物状态。逐件核对“人物／左右手或位置 → 入镜时已有物 → 本镜是否转移 → 出镜持有人”；多张参考中的同一物体不代表多件实物。来源形象不够清楚或已有串位时补独立参考，不能只用文字要求保留而让唯一的道具图片同时代表两件物品。

作为接画依据的上一镜终态，可能与本镜起态不同；标明参考用于开头、结尾、衣装还是空间。已有参考中若出现错误佩刀、重复道具或手性疑点，不把它整张作为无条件保留的基准。姿态、身份、衣装与道具参考各有职责；采用同一镜头参考不能替代逐物检查。后台预检只核对输入合法性，不证明角色绑定、道具关系或物理动作正确。

取物或散落镜头还要核对容器的开口状态：参考中的袋口、盒盖、封绳是否允许物体通过，起镜物体是否已在开口可见。扎紧布袋的材质图不能同时充当敞口散落的动作起态；需要时先准备打开状态参考，或明确拍出解绳／开盖，并与前镜接续。检查物体从容器内部经过真实开口到落点的连续路径，不能从袋底、侧壁穿出；可见来源并不等于正确出口。未拍摄开启动作时，不因单镜生成了敞口就认定跨镜状态连续。

局部修复先检查一个无遮挡帧和一个手指遮挡帧，核对完整轮廓、旧物残留、前景手指、接触阴影与材质；通过后才扩展时序跟踪。肤色阈值可能误删木纹，去物填充可能损坏腰带和衣褶；出现黑斑、残边或手指穿物就保留失败结论，不将静帧测试冒称视频修复。局部方法失败时可改变参考或镜头组织，但不能裁掉剧情必须交代的持物状态来掩盖问题。

### 4.3 检查失败源的参考继承

从已退回视频抽一帧，再标注“只参考空间／衣装”，仍会把该帧可见的错误人物、戒指、刀或灯传给模型。修改用途文字不等于排除像素。需要复用正确局部时，先做实际裁切或遮罩修复，查看派生图是否排除冲突，再保存独立范围审核；源片继续保留退回状态。

多次返修或参考较多时可运行 `python3 scripts/validate_reference_reuse.py imports.json reference-audit.json`。脚本核对实际导入清单的每个 `key`、SHA-256、来源文件及审核文件；漏项、文件变动、失败整帧复用返回非零。它不调用生成、不新增用户审批、不判断像素质量，也不证明派生操作本身真实执行。使用前把 `imports.json` 与实际请求的参考映射逐项核对，不能另写一份更容易通过的输入清单。

导入清单为 `[{"key":"POSE","sha256":"实际上传摘要"}]`。审核清单的 `references` 每项含 `key`、`role`、`input`、`source`、`source_review`；后三项均为 `{"path":"相对审核清单的路径","sha256":"文件摘要"}`。源审核的 `decision` 沿用实际 `approved`、`candidate`、`in_review`、`needs_revision` 或 `rejected`；不得为通过脚本把失败改成候选。源视频派生整帧用 `derivation: "frame"`，不会因为输入摘要不同就放行失败内容。

失败源派生的局部图另含 `derivation: "crop"` 或 `"masked_repair"` 与 `scope_review` 文件引用。实际看图后，该文件记录 `decision: "usable_for_scope"`、相同 `role`、`input_sha256`、`source_sha256`、具体 `excluded_defects` 列表及 `remaining_conflicts: []`。仍有冲突则如实列出，不填写空列表掩盖；不能使用其他裁图的审核代替当前输入。工具输出 `record_check_passed` 仅表示记录检查通过，`artistic_approval` 始终为false。无需此工具的一次性简单参考仍执行原有视觉核对，不把检查脚本变成所有创作的通用前置门槛。

### 4.4 人物遮罩与背景局部合成

表演已成立而背景漂移时，可评估人物分割配合独立背景底片；沿用当前模型范围，先确认本机或已授权服务实际可用。人物分割不等于深度，单帧遮罩也不证明视频时序稳定。保留原人物视频，另存遮罩、底片、几何映射及派生版本。

试验帧应包含静止、转头、接触释放及人物离画。除身体外轮廓，还要检查颈部与头发、手臂与躯干之间的背景空隙：填充全部外轮廓可能将旧灯光一起保护。软遮罩的低置信度也不能直接理解为人物透明度；离画或运动模糊时可能削掉头部和衣袖。阈值、膨胀和羽化按实际画面调整，不把一次有效数值固定为所有人物的规则。

局部像素不变校验必须说明保护范围：不透明人物核心、半透明边缘和背景分别处理；核心像素相同不代表轮廓、身份或接画已通过。扩宽保护区会留下旧背景光晕，收窄又可能损伤发丝。结合实际背景亮度、虚焦和当前帧雨纹检查边缘，再验连续帧与前后切点。同一地点换机位后仍须核对背景标志，修好一个窗口不能替代整场空间一致性验收。

## 5. 状态与交付

用户说“基本正确”只适用于明确接受的范围；后续指出的缺陷应撤回受影响选段的可用状态。失败保留源文件和原因，默认折叠，不与当前推荐候选并列冒充已修好。禁止重写不可变版本来源或change_note以抹去失败；按领域契约更新审核或追加返修版本。

本轮未解决时交付真实输出、失败证据、修改过的输入与剩余缺口。若完整回放或听审能力缺失，明确实际检查仅包括解码、抽帧或ASR，不写“全速验片通过”。这些记录是下一轮输入，不是把制作任务改写成只完成文档。
