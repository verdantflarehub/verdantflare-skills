# 实际输入与来源核验

## 1. 检查与证据

从已退回视频抽一帧，再标注“只参考空间／衣装”，仍会把该帧可见的错误人物、戒指、刀或灯传给模型。修改用途文字不等于排除像素。需要复用正确局部时，先做实际裁切或遮罩修复，查看派生图是否排除冲突，再保存独立范围审核；源片继续保留退回状态。

多次返修或参考较多时可运行 `python3 scripts/validate_reference_reuse.py imports.json reference-audit.json`。脚本核对实际导入清单的每个 `key`、SHA-256、来源文件及审核文件；漏项、文件变动、失败整帧复用返回非零。它不调用生成、不新增用户审批、不判断像素质量，也不证明派生操作本身真实执行。使用前把 `imports.json` 与实际请求的参考映射逐项核对，不能另写一份更容易通过的输入清单。

导入清单为 `[{"key":"POSE","sha256":"实际上传摘要"}]`。审核清单的 `references` 每项含 `key`、`role`、`input`、`source`、`source_review`；后三项均为 `{"path":"相对审核清单的路径","sha256":"文件摘要"}`。源审核的 `decision` 沿用实际 `approved`、`candidate`、`in_review`、`needs_revision` 或 `rejected`；不得为通过脚本把失败改成候选。源视频派生整帧用 `derivation: "frame"`，不会因为输入摘要不同就放行失败内容。

失败源派生的局部图另含 `derivation: "crop"` 或 `"masked_repair"` 与 `scope_review` 文件引用。实际看图后，该文件记录 `decision: "usable_for_scope"`、相同 `role`、`input_sha256`、`source_sha256`、具体 `excluded_defects` 列表及 `remaining_conflicts: []`。仍有冲突则如实列出，不填写空列表掩盖；不能使用其他裁图的审核代替当前输入。工具输出 `record_check_passed` 仅表示记录检查通过，`artistic_approval` 始终为false。无需此工具的一次性简单参考仍执行原有视觉核对，不把检查脚本变成所有创作的通用前置门槛。

已有固定身份／场景基线的短剧镜头调用，使用实际请求核验模式：

```text
python3 scripts/validate_reference_reuse.py imports.json reference-audit.json --request actual-request.json --locks shot-locks.json --require-request
```

`imports` 每项另含真实 `artifact_id`。`actual-request` 为实际 Image／Video 工具参数或含 `arguments` 的提交journal，检查 `source_artifact_id` 和全部 `reference_artifact_ids`，不能换成一份理想请求。`shot-locks` 含 `project_id` 与 `required_references`；每项为 `key`、`artifact_id`、`sha256`、`basis`（原始来源与适用依据）。固定锚点按本镜涉及的人物和空间取自项目基线，不能删掉难满足的锚点使检查变绿；中央与原生ID适配须保留真实字节摘要。两参数必须同时提供，漏参考、混入未审映射、错项目或摘要不符返回非零。

正式制作模式还要求 `shot-locks.input_bindings` 和 `request_sha256`：从真实请求读取每个输入槽位，逐项记录 `slot`、`artifact_id`、`key`、`sha256`；Video 项另含真实 `purpose`。Image 槽位为 `source_artifact_id`、`reference_artifact_ids.0`（按实际序号）及 `mask_artifact_id`；Video 为 `references.images.0`、`references.videos.0`、`references.audios.0`；换脸使用真实 target／source_identity 字段。导入登记顺序可变，槽位绑定不能随检查失败自动改写。重复使用同一输入只有在冻结槽位明确记录时才合法，不能用集合去重掩盖误传。

`request_sha256` 使用脚本的 `request_digest` 对已准备的完整 JSON 请求计算（含 journal 的工具名；UTF-8、键排序、无额外空白、禁止非有限数）。冻结前核对角色与槽位，再保存摘要；重跑核验不能顺便重算锁定值。提示词、模型、裁切、音频窗口或参数变化时，旧证据失效，只复核受影响项后更新同一制作记录。该字段是本地记录，不加入 MCP 参数。

只有本次 `--require-request` 返回零且 `production_input_check_passed=true` 才能证明正式模式的机械输入检查通过；`record_check_passed` 或 `actual_request_checked` 单独为真均不足。旧记录模式可用于追溯，不可代替正式提交核验。检查后的请求保持原字节和参数，交给媒体 Skill；实际供应商传输与视觉质量仍分别举证。Video 请求使用相同检查入口，按 images／videos／audios 保留真实顺序与用途，不能把图像锚点检查当成对白窗口或连续动作已经通过。

已否定源图可作为当前编辑的 `repair_target`：须正好对应实际请求的source，且完整请求和固定锚点检查通过；该例外不允许拿失败整图当下一镜的材质／身份参考。普通单次无基线创作不强加此模式。所有模式仍只检查记录与输入映射，不检测脸、保证空间或决定MCP权限；无图像证据不能以脚本通过放行视频。

参考传输须区分证据层级：客户端实际参数、渠道实际序列化、网关解析结果、供应商实际接收。已发现参考丢失、切换渠道或连续参考无效时，核对底图与所有参考的图数、顺序、摘要及独立遮罩，复用同版已验证证据，不要求每镜重复网络测试。接口支持多参考或任务成功不能证明全部图片被接受；已知丢失先修传输，再继续受影响生成。无法观测供应商接收时如实记录，不通过直接调用供应商或盲目重生绕过现有通道。

离线解析重放只能证明被测编码／解析规则的结果；部署源码存在修改、历史请求未捕获时说明边界。不能把离线通过写成线上已消费，不能从参考丢失的失败输出推断模型无身份保持能力。传输修复仍须用原始锚点和完整联合约束检查实际新输出，失败图继续保持否决。

已批准角色卡也可能与当前镜头状态冲突。局部服装参考逐项并看袖长、腕饰侧别、发型、干湿及姿态；“只参考衣层”文字不隔离这些可见像素。发现冲突先实际裁切／遮罩排除，再查看派生图，不能因来源已批准免检。排除后还须确认目标衣层仍可辨：若头发遮住背衫或裁切删掉关键接缝，只能记录该图支持的局部，不能宣称完整背面约束已齐备。生成后同时复查新增参考意图和可能带入的其他变化，一项改善不能抵消另一项漂移。

批准范围随来源继承，不随文件名扩大。用户仅批准接触姿态时，不能把后续衣料／地板合成称为“全外观已批准首帧”；分别保留姿态、身份、服装与空间的有效依据。局部像素恢复也不自动取得原图未曾拥有的批准。

有固定白模的镜头，空间依据须落到具体场景修订、机位及帧号，并与本次照片／视频的可见窗框、墙角、家具和人物落脚点核对。圆柱通道检查只证明其检查范围，不证明照片与相机对应；过肩候选不能充当全身双人镜的投影证据。先查看后续筛选与实际图像，不能仅凭最早失败记录断言没有可用机位。当前媒介请求未含白模并不必然错误：空间可以经已验证的照片基准继承，但须有对应证据；没有时标为未验证，先修交接，不机械追加白模图片或用提示词代替核验。

穿门、越窗或跨栏动作还须检查实际通行开口，不只比较外框位置：玻璃、窗扇、横档及新增道具是否挡住原路径，支撑边缘和落点是否仍存在。模型的 latent 编辑成功、参考摘要一致或大轮廓接近均不证明这些状态保留；有变化时先修该场景输入，不将新障碍继承到人物动作镜头。

涉及持长杆、前伸接触等跨镜位置时，先区分“白模坐标已记录”和“本次模型实际看到了姿态／构图依据”。若输出持续把长杆缩短、握点收回胸前，可把现有机位与接触点投影成明确标注用途的姿态辅助图，同时保留原脸、完整Look与道具参考；本地示意图不得冒称原生渲染，软参考也不保证严格遵守。只改变姿态输入后仍分别检查身份、衣层、接触、脚底和遮挡，不把某一几何改善当成全项通过。粗身体／可达性代理不是精确手指动画：按角色尺度、实际接触与前后镜连续性评估偏差，不能凭任意像素阈值放行，也不为追求逐像素重合而扭曲自然手臂或反复抽整图。
