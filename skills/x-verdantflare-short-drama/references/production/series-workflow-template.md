# 短剧端到端制作模板

用于新短剧项目的阶段编排和交接。复制阶段结构到项目入口，逐项填入实际来源、版本、负责人和审阅结论；空项保持待定。单场拆解、导演计划、Image、Video 等具体执行仍遵循各自 Skill 契约。

## 顺序、输入与输出

| 顺序 | 阶段与通过条件 | 输入 | 输出及下一阶段交接 |
| --- | --- | --- | --- |
| 0 | 建项：项目身份与访问范围可核对 | 作品名、类型、创建者、项目权限 | Studio `project_id`、初始修订、入口文档；服务不可用时仅建本地 `project_ref`，注明未同步 |
| 1 | 创作简报与来源：创作边界和素材使用依据清楚 | 委托目标、受众、平台规格、预算/周期、原著或原创声明、现有剧本与授权材料 | `brief.md`、`sources.md`、待决事项；区分原文事实、改编建议、权利未决项 |
| 2 | 故事开发：方向经作者选择 | 简报、来源、主题/类型诉求 | 故事梗概、人物关系与弧线、人物小传、核心悬念、世界规则、结局/剧透边界；人物小传作为独立可版本化文字资产记录来源与审核状态 |
| 3 | 分集设计：时长和悬念节奏成立 | 获批故事方向、集数与每集时长 | 分集大纲、每集目标/冲突/转折/钩子、场景清单、跨集连续性表 |
| 4 | 剧本写作：对白、动作、时空和声音意图可供表演与拆解 | 分集大纲、选定版本的人物小传与世界设定、制作约束 | 逐集逐场剧本草案、版本号、场景编号与内外景/昼夜、地点、人物站位和动作、明确说话者及台词/有意沉默、环境声/音效与音乐 Cue 表、角色/道具/服装状态、需要澄清的问题；摘要式逐镜提纲不可冒充完整剧本 |
| 4.1 | 剧本包配套设定与同步 | 当前剧本、人物身份、现有资产与来源 | 按[完整剧本 Skill](../writing/guide.md)补齐人物小传、地点与场次、道具、服装 Look、逐镜连续性；与正文组成六类文字资产，另交版本索引与审核记录，作为阶段 5—7 输入 |
| 4.2 | 剧本审核与锁稿：主线因果、人物、连续性及声画预算可审 | 剧本草案、人物小传、来源与改编记录、目标受众/发行约束、既有资产和审核决定 | 按[剧本审核标准](../review/script-review-standard.md)输出带镜号的 P0/P1/P2 发现、返修版本、人工审核结论与受影响下游；仅固定获批准的剧本和人物小传版本 |
| 5 | 逐场拆解：事实有来源且推断经核对 | 已审核固定版本的单场剧本；无依赖部分可按审核结论先行 | 人物/道具/地点/动作节拍清单；可用 Local Scene Breakdown 形成带证据草案，人工核对后交导演 |
| 6 | 导演与分镜：时间线和连续性可执行 | 已核对拆解、固定完整剧本包、片长/画幅及现有批准设定 | `treatment.md`、每集 `plan.json`、Shot 卡、资产需求、可选 Generation Unit；运行 Director 校验器，艺术选择仍待审 |
| 7 | 视觉与声音圣经：跨镜引用可固定 | 资产需求、角色/场景设定、音乐与声音方向、现有可授权资产 | 身份/当前 Look/场景/道具/声音规范及版本；Image 候选逐项审阅，锁定可引用 Artifact，不用候选代替批准 |
| 8 | 镜头制作：真实任务可追溯 | 已冻结 Generation Unit、批准的参考 Artifact、正式 `project_id`、可用模型/渠道、预算 | Video 预检、提示词、任务 ID、输入与结果 Artifact、候选镜头、逐秒验片记录；表演复杂镜头转 Character Performance |
| 9 | 后期与返修：叙事和技术同时通过 | 已选镜头、对白/配音、音乐/音效、剪辑方案、平台规格 | 粗剪/精剪、声音混录、字幕、调色、片头尾、技术 QC 与创作审阅；按问题定位到镜头或上游版本 |
| 10 | 交付与沉淀：版本、权利和访问范围可复核 | 审定母版、来源与许可、审核记录、交付规格 | 母版/平台版、封面与字幕文件、交付清单、哈希、项目修订；可复用资产候选另行确认后入数字世界，公开分发另行确认 |

阶段 2–4（含配套设定与审核）属于编剧与制片决策，不因模型生成了一版文本或通过镜号/时长检查就自动通过。阶段 5 可逐场并行，阶段 7 可按角色/场景并行，阶段 8 可按相互独立的 Generation Unit 并行；有依赖的版本必须顺序固定。审核不通过时回到产生该事实或画面的最早阶段，保留旧版本、任务 ID 和审核记录。审核 P0/P1 只暂停受影响的锁定与生成工作，独立资料整理可继续。

剧本、人物小传、分集大纲属于项目关键文字资产：以可编辑文本及固定项目修订保存，草案与获批版本分开。人物小传写清背景、外貌、身形、发型、服装、饰物、性格、关系、行动和跨场变化；图像身份与 Look 另行选版。项目内留存不等于已发布到数字世界；跨项目复用须从已固定的项目修订选择文件，完成来源、权利和审核后再登记 World AssetVersion。

## 每次交接的最小记录

```text
阶段 / 工作项：
输入：文件或 Artifact ID + 固定版本 + 来源/使用权
制作约束：时长、画幅、预算、禁区、连续性事实
输出：文件或 Artifact ID + 版本 + SHA-256（有二进制时）
执行记录：Skill/能力版本、模型/渠道、任务 ID（未调用则不填）
检查：结构/技术结果；创作审核人、结论、日期
状态：草案 / 候选 / 已批准 / 已锁定 / 已交付
待决与返修：问题、责任阶段、受影响的下游引用
```

## VF 能力路由

| 工作 | Skill 或能力 | 边界 |
| --- | --- | --- |
| 完整剧本与六类设计基础文档 | `x-verdantflare-short-drama` | 创作、返修和同步配套设定；交固定版本包，不提前称图像或成片获批 |
| 剧本与人物小传审核 | `verdantflare-short-drama-review` | 审核结论带版本和证据；不替代人工批准或实际观看数据 |
| 单场原文证据提取 | `x-verdantflare-short-drama` | 本机 Ollama 草案，人工核对后使用 |
| 导演方案、Shot 与计划校验 | `x-verdantflare-short-drama` | `plan.json` 是本地策划契约，不是 MCP 请求 |
| 跨阶段影视制作 | `x-verdantflare-short-drama` | 维护输入版本与交接，不代替专业工具 |
| 角色、Look、场景、分镜图 | `verdantflare-image` | 产出候选并核对 Artifact/哈希 |
| 表演难点 | `x-verdantflare-short-drama` | 单镜或相邻镜头的动作/情绪/对白 |
| 视频生成与恢复 | `verdantflare-video` | 从当前宿主解析模型/渠道，正式项目 ID 必填 |
| 原创歌曲、MV（按需） | `verdantflare-music`、`verdantflare-music-mv` | 独立审核歌曲与音色，不把配乐视为默认必做 |

模板验证只检查阶段覆盖和交接字段；真实项目还须逐集检查剧本、计划、资产、镜头及母版。不得用本模板的存在推断任何项目已获创作或发行批准。
