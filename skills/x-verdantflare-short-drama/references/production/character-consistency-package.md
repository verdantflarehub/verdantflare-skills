# 主要角色分拆资产与评分

适用于短剧主要角色的新设计、扩展和生成返修。用户明确要求主要角色均做此扩展；配角按镜头的辨识和连续性需求复用。沿用角色 ID，每个版本绑定输入参考和剧本状态，不以换衣、受伤或表情变换新建人物。

## 独立交付与参考职责

| 类别 | 拆分内容 | 必须保持／不能替代的内容 |
| --- | --- | --- |
| identity 人物身份 | 原始身份锚点；中性正面单人胸像；全身正、侧、背分别成图 | 面容、身材比例；演员基础设定与剧中角色年龄分开 |
| face_angles 面部角度 | 正面、左前3/4、右前3/4、左侧、右侧、后脑；需要时补俯仰 | 每图明确解剖朝向和视线；没有右侧不能镜像左侧补齐 |
| wardrobe 服装 | 每个 Look 的正侧背及领、袖、腰、鞋、饰品细节独立图 | 衣层、颜色、材质与穿戴侧别；可用无脸人台，不能替代身份图 |
| body_states 身体状态 | 剧本实际出现的健康、受伤、疲惫、消瘦、衰老、恢复等及局部细节 | 受伤部位/左右/程度/故事时间；疲态不能只换衣，年龄变化不能换脸 |
| wardrobe_states 服装状态 | 同一 Look 的湿、污、撕裂、烧毁、修补等 | 服装损坏和身体损伤分别编号，引用触发与接续镜头 |
| expressions 表情 | 所需表情逐张单图，含中性对照 | 同身份、镜头和光线；不要将角度变化当表情变化 |
| microexpressions 微表情 | 每项一张峰值图与表演卡，需要视频时附起落验证 | 按[微表情规范](../performance/microexpressions.md)写触发、眼口、呼吸、压回和余韵 |
| poses / hands 姿态与手部 | 所需姿态和每个手势分别成图 | 重心、关节、五指、持物与侧别；不凭空新增道具 |

总设定板保留作概览；下游按镜头选择少量职责明确的独立图，不把整张11模块板喂给模型锁脸。拆图须记录母图 SHA-256、原像素裁切框和实际尺寸。裁切不会增加细节：低清、带文字、遮挡或无法判断的图仅供索引/诊断，独立高质量图缺口应补生成。禁止放大后冒称原生高清。

完整矩阵先按角色和剧本列出来。每项填写独立 asset_key、类别、角色键、Look/身体状态/服装状态键、角度或表情键、版本、用途、源引用及摘要；缺失项也保留，但文件引用为空且明确 `missing`。不生成剧本完全不需要的年龄和受伤全排列。跨角色基线复用必须保留源项目/固定版本，不能让晴子和谢小娥互相覆盖年龄、身高和造型。

## 状态三视图与变装验收

主要角色每个实际需要锁定的身体状态与 Look 组合，交付同一状态的全身正面、严格侧面、背面三视图，并拆为独立文件。头部多角度、半身图、服装人台和总设定板均不能替代状态全身三视图。三视图须保持衣层、发型、伤势侧别、湿污程度、姿势与身体比例一致；显著姿势另列动作参考，不混成不同状态的三张图。

身体状态要在眼睑、肤色、肩颈、重心和体力姿态中可读；湿衣不等于耗竭，换装不等于磨砺。不得凭空添加伤疤、血迹或武器来强化效果。只能站立的参考姿势不代表游泳、跌落等动态已经验证。

剧本有男装／女装转换时，单独建立 Look 与发型版本，说明头发长度、束发方式、帽内收纳、鬓发、耳部和后颈轮廓；正侧背验证差异。保留同一身份脸型与体型，不靠换脸、加宽下颌或加胡须制造变装。戴帽与摘帽是不同状态，摘帽后的发型按剧情触发接续，不自动恢复旧女装长发。新候选明确标注待确认，不由生成成功推导人工确认。

用户否定的版本保留历史并记录不合格原因，不能继续作为已通过的下游身份／状态参考。返修包列明已补齐与仍缺失的状态，避免以局部完成声称整套齐全。

## 状态分开记录

- 制作：`missing / prepared / generating / available / failed`。
- 审核：`unreviewed / reviewing / needs_revision / passed / rejected / stale`。
- 选用：`unselected / selected / retired`，仅真实用户选用更新；评分通过不自动选用。
- 适用性：记录允许作为 `identity_reference / wardrobe_reference / state_reference / performance_reference / overview / diagnostic` 中的哪些用途及具体镜头范围。

技术缺陷可以判返修；没有图或没有观察证据不能给0分冒充已评。评分、人工批准、远端归档与模型运行状态不互相推导。基础身份或Look变更时，把依赖项标为需复核（stale），不覆盖历史分数和批准记录。

## 可落地的评分卡

这是制作默认量表，可按项目约束修改并固定 rubric_version。每维0–5级：0明确错误/不可用，1严重偏差，2明显问题，3基本可用但需修，4可用且只剩轻微问题，5在本次可见范围内无已发现偏差；未评为 null，不是零。每分必须有图或局部位置、对照基准、理由和返修动作。

| 维度 | 默认权重 | 评价内容 |
| --- | ---: | --- |
| 身份一致性 | 30 | 与原始锚点的脸型、眼鼻唇、体型与固定特征 |
| 侧别与连续性 | 20 | 酒窝、红绳、伤势、持物、衣层和状态是否接续 |
| 解剖与物理 | 15 | 五指、肢体、关节、头颈、布料和接触 |
| 目标表达 | 15 | 指定角度、服装结构、状态或微表情是否可读 |
| 风格与材质 | 10 | 风格、肤色、皮肤/布料质感及光线一致 |
| 技术可用性 | 10 | 实际像素、清晰度、裁切、无文字污染及文件完整性 |

总分 = Σ(单维分/5 × 权重)。某维确实不适用时写N/A理由并重新归一化适用权重；存在适用维度未评时总分为null，不计算虚高总分。无脸服装图可不评面容身份，但仍评绑定角色的比例、服装和左右。

默认候选通过条件：适用维度全部评分，总分≥85，各适用维度≥3，身份与连续性适用时≥4，且硬错误为零。85是本工作流制作阈值，不是市场或科学验证标准。错人、缺肢、多指、标志性左右颠倒、错误伤势、错误Look、明显穿模或违反用户指定内容均阻断受影响用途；总分再高也不能抵消。技术可用性按目标镜头和实际信息量判断，不靠统一分辨率阈值替代视觉检查。

每条记录保留 review_id、资产版本和SHA、量表版本、审核者类型/名称、时间、证据、分项、总分、硬错误、结论、返修要求与上轮记录。AI自评只能写实际执行的模型或助手观察，不伪造人工评分。未实际运行的视觉模型不能挂名。旧记录未存分数就写未登记，不反推历史分数。

## 交付及验证

交付独立图片目录、资产矩阵、评分记录、缺口表和可查看索引。输入选择清单按镜头绑定具体版本及用途；只有对应用途通过的候选才能列为已具备生成条件，用户明确采用带已知限制的图时保留例外说明。

新增线上评分字段须遵守 Studio 已注册契约。当前可先将矩阵与评分卡作为普通文件保存到既有角色对象的版本/扩展，回读核对；不能往严格 Schema 偷塞字段，也不能把文档可下载说成原生评分控件已上线。落地状态与界面设计见工作区角色评分专题。
