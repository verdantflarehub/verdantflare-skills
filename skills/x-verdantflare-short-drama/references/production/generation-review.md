# 生成准备与恢复

正式提交使用[执行入口](execution-gate.md)检查最终请求并消费同一冻结对象；旧任务恢复不受新生成准入影响。只运行检查再另手写请求不构成闭环。

## 1. 任务与调用授权

MCP Token 即调用授权，由 Studio 解析为授权用户。沿用用户当前任务、模型渠道、固定版本和明确的次数或费用限制，不增加独立审批、密码确认、批准清单或默认零额度。通过实际媒体工具执行，见[MCP 授权与恢复](https://github.com/verdantflarehub/verdantflare-skills/blob/e51e12f52023bbca00c706ef818efca6d7faba9d/skills/verdantflare-project/references/00.common.rules.md)。

人物、服装、道具、场景、声音与配乐按本轮任务保留完整依据。准备记录用于说明输入、用途与结果；它不是 MCP 调用许可证。生成结果保留为候选，选用和发布依照用户意图执行。

多轮修订、素材复用和批次依赖按[执行方案](execution-planning.md)维护当前依据。明确的用户追加授权覆盖对应旧额度；代理曾建议的数量不是用户硬上限。只在实际授权或依赖缺口处暂停，原任务查询、传输恢复与新收费生成分别记录。

## 2. 输入检查与可选准备文件

有角色的影视镜头在正式出图前执行[比例与调度预检](scene-keyframe-video.md#22-正式出图前的比例与调度预检)，提交视频前核对对应关键帧的实际画面检查。读取本次输入版本对应的证据，不能只写“保持一致”；失败或关键项未验证时，助手先修受影响输入，不把检查转交用户。独立身份图、文本工作及不依赖该镜头的任务继续。该质量检查与下述可选准备文件不同，不新增审批、调用参数或服务端自动拦截能力。

有固定人物／场景基线的镜头调用同时执行[联合约束](scene-keyframe-video.md#23-局部返修的联合约束)，将实际请求与导入映射交给参考复用校验，不只检查手写清单。恢复原始身份锚点和已否定引用；返回非零先修输入，不提交新生成。该检查不改变服务权限，不能把通过当像素质量或用户批准。

已知多参考丢失、切换渠道或反复出现参考无效时，按[传输证据分层](../performance/rework-evidence.md#43-检查失败源的参考继承)核验实际编码及接收能力，复用同版证据；已知丢失未修复前不提交依赖该参考的新生成。客户端字段齐全不等于下游接收，也不等于画面遵守约束。

传入视频动作参考时，在提交之前执行[动作参考的外观与占幅检查](../performance/rework-evidence.md#45-视频动作参考的外观继承)。裁切后重新核对比例、中心位置和景别；预检同时核对模型实际采用的帧区间是否包含动作终态。字段合法、字节完整和参考数量正确，不能抵消已知的比例污染风险。

需要固定准备文件时使用 `generation-preparation.schema.json`，校验固定修订和引用。用户没有要求制作准备文件时，不把它作为调用前置条件。旧记录中的 decision 仅保留来源说明，不决定 Token 权限；额度字段只记录用户明确给定的限制，不自行填零。

依赖 Python 3.10+ 和 jsonschema 4.x。从本技能目录运行：

```text
python3 scripts/validate_preparation.py preparation.json --project-open basis-open.json
python3 scripts/validate_preparation.py preparation.json --project-open basis-open.json --check-handoff
```

默认退出码 0 表示结构和所提供的固定引用校验通过；`--check-handoff` 只检查执行信息、明确限制和依据完整性，缺项退出 2，结构或引用错误退出 1。脚本不读取 Token、不判定调用授权，也不提供服务端预算控制。

### 2.1 跨镜制作的联合准备

先把整段的必要事件、相邻镜头起末状态和素材依赖在既有执行方案里排通，再准备各生成单元；不等每镜失败才发现缺走位、少动作或终态接不上。区分固定身份／Look／空间锚点、剧情必须改变的状态、允许的自然变化，检查“禁止变化”等约束有没有误禁发芽、收手或表情变化。白模负责比例位置和机位；外观、姿态和自然枝形使用相应真实参考，不把白模细节当正式外观。

每份送入模型的参考明确“控制谁、控制什么、哪些内容不能继承”。多人参考绑定稳定角色和实际槽位；若脸、手或目标在实际缩放裁切后已不可辨，增加提示词不能补足信息。先处理参考间的错脸、错误尺度、冲突背景和时间状态，再冻结实际请求；具体图像变换、mask 坐标及音画窗口与参考一起固定。软参考和相同 seed 均不保证硬锁身份／几何。

准备分两层：先固定全段控制方式、来源和上游产物用途；上游关键帧产生并通过对应联合检查后，再绑定其不可变内容并冻结下游实际请求。不存在的关键帧不做占位放行，也不要求全段所有新产物先存在。已就绪且互不依赖的单元按已有配额并行，不扩大生成次数。

证据复用按实际内容、参考角色、变换、有效参数和检查方法确定。只改字幕时复核叠字和时间窗；改身份锚点时复核所有引用它的画面；改机位时复核空间投影、遮挡和可见细节；新增视频动态时检查全段表演与接画。已有用户批准不重问，服务升级只重验受影响的传输或控制假设。一次联合检查提出所有关键缺陷，不将人物、空间、声音拆成连续返工轮次。

准备在可确定条件已查、有效参考齐备、生成依赖可执行、软风险和本轮明确限制已记录后结束。不为不可保证的模型表现无限加参考、重复全量审核；无新输入、缺陷或能力变化就复用证据。此节是制作行为要求，不新增准备文件格式、MCP 参数或用户审批。

### 2.2 先确认结果取回路径

首次使用或更换执行路径时，在生成／远端渲染前查清结果查询、导出、受控下载与实际审看的完整路径。若下载必须先创建 Project 修订，而用户限制上传，先核对现有授权是否包含这一步，选择已有可用的只读取回路径；确实缺少必要授权时一次说明准确文件范围和用途。不等结果已经生成后才发现无法审图，也不因取回受阻重复生成。相同路径已验证且未变化时复用证据，不逐轮重新检查或索取同一授权。

## 3. 提交与恢复

通过现有 Project／Artifact 技能保存本轮准备和成果，保留固定引用及 SHA-256。没有媒体输出时不登记成功候选。响应未知先查询原任务，保持原模型、渠道、任务 ID 与幂等键；不得重发生成来掩盖未知结果。

资源失败的恢复分两步核验：retryable或未执行对账只证明重试安全，不证明显存、拓扑或服务容量已恢复。同一资源原因再次失败后，先取得相关容量／配置恢复证据，再考虑追加生成；不要仅凭可重试标记反复消耗次数。记录采样时间，失败后的空闲显存不倒推排队时可用，物理空闲也不替代已预留预算。提交数、实际推理数和产出数分别记录，无产物的技术失败不进入画面质量首次通过率分母。

统计制作效率时按真实任务ID去重，将提交记录、实际推理、已有产物、整幅退回后局部抢救、整镜验收分别计数；目录数、下载次数和技术succeeded均不等于首轮合格数。首次通过率按稳定制作单元的第一次实际产出与当时完整验收计算，不用后期裁切或多轮拼接回填首轮成功。缺少单元映射或实际验片时不填推测百分比，当前工作片仍需逐段绑定实际选段及对应审核版本。

按用户指定的范围与次数执行，达到明确限制后保存进度；未提供的限制不自行编造。声音、配乐和画面分别保留候选与质量核验，MCP 执行授权不自动成为选用或公开发布指令。

已有固定身份／场景基线的正式镜头，交接 Image／Video 前按[实际请求检查](../performance/rework-evidence.md#43-检查失败源的参考继承)运行 `--require-request` 模式，核对其 `production_input_check_passed`，并交接同一份冻结请求。仅来源记录通过不能替代实际输入匹配；合法独立媒体与旧任务查询恢复不增加此要求。准备检查一次覆盖本镜涉及的全部角色、Look、空间、状态与声音，相关输入未变时复用证据，参数改变只复核受影响范围。

产物返回后的基础自检与送审按[身份和双臂产物证据](../performance/rework-evidence.md#47-产物证据身份与双臂归属)执行。输入检查通过不证明生成正确；用户退回即失效本候选的送审推荐与下游准备，不能保留旧肯定结论继续生产。
