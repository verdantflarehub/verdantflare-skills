# 执行方案编写模板

## 1. 使用方式

用于[多版本执行方案](execution-planning.md)中的新方案或实质重编。按当前交付保留适用章节，信息已存在时引用原记录，不另建重复台账。简短修复可只写依据、改动范围、验证与交付。以下是工作文档内容提示，不是待原样提交的占位文件或机器Schema。

## 2. 当前依据与目标

- 主方案及固定版本、最新用户修订、被取代的具体段落。
- 交付目的、受众、观众看完应理解或采取的行动；案例是演示还是事实。
- 本轮输出及规格、声音开关、允许修改的范围、不能改变的锚点。
- 用户硬约束、可自行决定项、假设及真正待决定项，分别说明来源。

## 3. 故事与风格

- 每段的信息任务和“问题／想法—工具—作品—使用结果”中实际需要的环节。
- 需要保留的情绪、停顿和高潮；参考的采用点与明确不采用点。
- 角色Identity、Look、场景、道具、设备朝向、作品版本及累计物体的连续性。
- 字形、配色、Logo和界面依据；哪些是原始设计，哪些只是生成占位。

## 4. 素材盘点与缺口

逐项填写稳定单元ID、来源版本、技术规格、实际可用区间、动作证据、可用／需返修／缺失。对比“方案要求的动作”和“素材实际发生的动作”，明确是否足够剪出本段。

## 5. 单元执行卡

按同一格式为实际需生成或返修的单元记录：

- 所属案例、目标剪辑区间、这一镜的信息任务。
- 依赖资产及批准状态；固定参考的用途、版本和可读位置。
- 起始状态、人物动作、摄影机运动、环境运动、结束状态。
- 使用白模时分别列出空间／关键站位／运镜锁定项、由视频模型完成的连续表演项；必要接触点、时间窗口和跨镜接点。精细预演仅按需追加，写明原因，不默认要求全套人物骨骼动画。
- 运镜参考与正式关键帧如何进入当前模型、哪些只是制作核对依据；不支持的控制不写成已锁定。
- 连续性必须保留项；修复项和可见的验收证据。
- 当前可用的模型、渠道、输入模式、生成时长与预计选段；未知能力写待核实。
- 明确的用户数量／重试／费用限制及来源；生成返回后补实际ID、结果和用量。

## 6. 顺序与检查点

说明本轮为何先做故事、声音或运镜；列出能直接推进的工作和需要等待的依赖。仅复用用户要求或任务确需的审核点。每个待决定项先给具体可审阅成果、影响范围和最小选择，不让用户批准空泛意向。

## 7. 声音与时间线

- 旁白：原文、读法、角色／voice profile、表演目标、语义分段、起点与可用窗口；生成后记实测时长。
- 音乐：画面段落、配器、密度、情绪、重击／停乐锚点；请求长度与实测长度分开。只作分析的参考不自动成为生成输入。
- 剪辑：主方案行到素材入出点的映射；时间原点、帧率解释、帧／采样边界及允许误差；不足时的授权处置。
- 混音：声源归属、独立轨、压低／增益策略和交付目标；不得从提示词推断已实现音乐拍点。

## 8. 验收、恢复与交付

- 技术证据：实际规格、完整解码、时长、响度／峰值、摘要等适用项。
- 创作证据：动作与因果、人物及作品连续性、可读性、配器与旁白听感；未看／未听写未知。
- 例外：对应要求、实际结果、采用办法、真实决定及其粗剪／最终适用范围。
- 交付：可观看成果、逐行对应、素材／take选用、原任务与用量、工程依赖、同一项目固定修订及回读结果。
- 恢复：当前阶段、已完成工作、待运行的原任务、剩余授权和下一动作；不为每次工具调用新建一套报告。
