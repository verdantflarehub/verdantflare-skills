# 短剧 Blender 白模制作与验收

本短剧流程依用户明确要求，以场景、全部镜头及复杂道具白模作为空间制作基线。只写剧本、人物小传、身份图或审核已有文本时，不把建模扩大为当前任务；推进镜头制作时执行本规范。产品字段仍以宿主现行 Project／Artifact 契约为准，不把本文业务要求当作已上线工具参数。

## 1. 范围与交付

- 场景：单位与尺度、门窗／通路、家具、锚点、遮挡、可通行空间；固定 `.blend`、平面与透视预览。同地点共用基线，破损／翻倒等剧情状态明确建版。
- 复杂道具：部件层级、尺寸、轴心、连接与接触锚点、开合／断裂／拆装状态；固定 `.blend`、正侧俯视与结构细节。同一实物跨镜固定结构，不按镜头另造形状。
- 每个镜头／必要镜内段落：固定场景／道具版本、人物代理与朝向、相机与焦距／画幅、轴线、帧率／帧范围；人物只设置必要起止与接触位置，运动相机设置路径和时间关键帧。可共用工程字节，但每镜必须定位 Scene／Collection、相机和帧范围。

复杂性按剧情用途判断：多部件、机构动作、精确接触、证据比对、断口、刻纹或受力路径影响连续性即需独立白模。即使体积小，证据戒纹、印章与断裂木符也不能用普通球块代替。简单背景物在场景中有正确尺寸代理即可。

白模使用中性材质验证几何，不等于完成纹理、毛发、角色面部绑定或高精模型。人物代理不替代身份多视图。未知尺寸可制定制作值并标来源，不宣称从图片准确测量。

## 2. 执行顺序

1. 从固定剧本与资产设定列白模覆盖表：地点／状态、道具／复杂性理由、镜头／段落、依赖与缺口。
2. 场景与复杂道具建模，先核尺寸、部件、通路和接触；镜头引用这些固定版本布置机位与代理调度。人物按稳定角色 ID 复用身高和体型，核对实际世界尺寸及脚底支撑点；跨镜代理副本不得自行改比例或无动作依据换位置。
3. 先发现实际能力和参数，通过可用的 Studio Blender MCP（`/mcp/{instance_alias}`）创建／编辑并保存工程，不执行 `kubectl exec` 直接操作容器：
   - 清理历史残留或异常目录时调用 `workspace.clean`；
   - 执行受控 `bpy` 场景搭建与多机位预演脚本时，先将脚本提交到 Studio 项目，再调用 `script.run_project`（可指定 `source_project_id`、`script_path`、`output_subdir`、`load_blend_as_active`）并通过 `operation.get` 轮询完成；
   - 服务缺失时交付明确建模说明与覆盖表，标未建模，不用占位文件冒充 `.blend`。
4. 从真实工程输出预览：场景平面／透视、道具结构、每镜相机画面；有运镜时输出覆盖镜头时长的相机预演（`.mp4`）及必要关键画面；人物代理可静止或仅示意关键位移，不要求完整骨骼动画。固定机位用关键位置图，复杂通路按需补路线预演，并注明代理运动仅用于空间核对。
5. 调用 `scene.inspect_file`（传入 `asset_id="exports/<subdir>/<name>.blend"`）在新进程无头重开固定工程，核验已打包依赖、单位制、分辨率、帧率、帧范围、前缀分类计数、全部摄像机焦距／位置／旋转／关键帧列表及关键对象世界包围盒尺寸；需要切换为实例活动场景时调用 `scene.open_file`。同时对全部预演视频（`.mp4`）执行完整解码（核验帧数、时长、分辨率）并逐机位抽帧检查画面主体可见、未被人物替身圆柱或天花板／墙体遮挡。保存实际检查证据，未执行检查标待验。
6. 调用 `project.export_assets`（共用实例向分篇项目归档时指定 `target_project_id` 并携带 `batch_operation_id` 记录来源溯源）将 `.blend`、多机位预演 `.mp4`、空间说明 `.json` 一次性归档至目标 Studio 项目，通过 `operation.get` 获取固定 `revision_id`、`provenance` 与 `content_ref` 并从中央 Project／Artifact 回读核验；闭环结束后调用 `session.close` 释放实例编辑租约，再将宿主真实支持的图像／视频参考交给后续生成。不能因为有 `.blend` 就宣称视频模型能读取工程或相机轨迹。

### 2.1 空间与运镜辅助、模型连续表演

默认分工：白模固定完整场景、人物比例位置、门窗通路、目标物位置及摄影机；生图控制人物姿态、表情、身体状态、Look、持物与动作起落；视频模型完成自然连续表演。人物占位以尺寸和所在区域表达，不将骨盆膝角、精细肢体轮廓或指端轨迹作为出图前置，也不要求模型复制代理的姿态。已有工程的场景、尺度与机位继续复用。

按镜头设置最少必要约束：起点、终点、行进方向、可通行路线、动作时间窗口与相邻镜头接点；交印、穿窗、翻栏等增加必要的中间接触位置、支撑点、持有人／左右手或落点。动作时间是表演目标，除确需同步的接点外不当作逐帧硬约束。简单转身、行走不因缺少精细白模动作而阻塞视频生成。

摄影机单独记录起止位置、朝向、焦距／画幅、运动路径、目标和速度变化，检查遮挡与构图舒适度。不为容纳人物任意扩舱、移墙或改变人物站位；全身、半身与远景按叙事和留白选择，不强求全身。人物路线不能穿墙或越过障碍；代理未模拟的步态、手指、衣料与自碰撞明确不在白模验收范围内。

正式关键帧取同版白模对应位置和相机，补身份、Look、材质、道具和剧情光线。站位不匹配的旧图只作外观参考。向模型提交前核实渠道实际支持首尾帧、多图、视频参考或相机控制的哪一种；只传支持的输入。白模视频若作为输入，明确用于空间与运镜参考，不要求复制僵硬肢体动作。不能可靠分离时优先采用正式关键帧和运镜描述，白模保留为制作核对依据。Ref2VA 是软参考，不等于严格首尾帧控制或逐帧重绘；不支持视频参考时不可声称已注入白模运动约束。

只有用户明确要求精确动作复现、复杂接触确需额外验证，或当前模型的实际控制接口需要时，才按受影响动作追加精细预演。记录追加原因、范围与实际输入方式，不把特殊镜头要求扩展为整集前置条件。

实际生成视频仍需检查身份、人数、持物手、动作自然度、时间与因果、接触穿模、路线、运镜和跨镜接画。空间错修白模或关键帧，表演僵硬修动作节拍和模型输入，避免以加密白模骨骼帧替代视频表演返修。空间检查通过不等于视频已通过。

机位试验先做几何筛查，再渲染：在完整物理墙体保留的同版场景中，检查相机是否落在墙内、最终画幅投影，以及人物起态、接触／最大位移、终态的遮挡。射线首命中与必要身体区域的投影用于排除确定失败机位；单条中心射线不能证明整个身体可见。确定被墙体挡住或关键关系出画的机位不进入渲染；筛查通过仍须看真实渲染确认构图与人物互挡。

检查范围按镜头信息选择，不默认头脚必须同时入画；半身镜可成立，但不能据此声称落步已验证。没有单机位容纳必要动作时，先设计同轴、状态可衔接的覆盖，不通过隐藏墙体、扩大舱体或挪动已批准站位绕过问题。白模检查止于空间与机位，不追加精细人体动画替代表演制作。

#### 2.1.1 运镜关键事件覆盖

对有运镜的单元固定同版工程与相机参数摘要。至少覆盖起幅、关键接触／揭示、最危险遮挡点、落幅；检查连续路径，不能只提交两张端点图。焦距、画幅、墙体或人物位置变化会使对应构图／遮挡证据失效。纯摄影机预演可作相机依据，含人物代理时明确其来源与空间用途，不能改名为自然表演视频。

工程缺少所需关键图或全路径预演时明确列缺口，先完成不依赖它的剧本、语气和参考整理；不伪造新渲染，不把旧B机位批准延伸到新运镜或人物动作。

### 2.2 派生工程与历史动画核验

修改已有网格前核对网格局部边界、对象缩放和世界尺寸；已将尺寸写入顶点的网格不能再次按标准立方体尺寸替换。保存重开后检查实际外形尺寸、净开口或接触间隙，射线通孔与变换未变不能单独证明结构正确。

复用历史运动参考时，检查实际 Action／NLA 帧域和求值后的世界变换，而非仅检查关键帧数量。预期有位移或转动但所有曲线值相同时，应标记静态或无效运动参考；若曲线与求值不一致，继续核对约束、父级、驱动和加载条件。静态位置参考本身有效时，无需为了通过检查新增动画。起止状态使用同版几何与机位实际渲染，核对遮挡、落地点与物体外轮廓，不能只比较对象原点。

### 2.3 片场包（Set Package v1.0）导出与机位对齐校验

当短剧或宣传片场景需要在 Studio 网页片场查看器（`viewer`）中进行三维环绕、第一人称漫游与实拍机位校对时，在完成 `.blend` 场景与多机位预演后追加片场包导出与校验步骤：

1. **导出片场包**：通过 `script.run_project` 调用 `scripts/set-package/blender_export_set_package.py`，从定稿 `.blend` 导出 `scene.glb`（+Y Up，1.0m 比例尺，节点数 $\le 180$）、`set.json`（Schema `1.0`，含出生点、可走碰撞盒、全部机位光学参数与灯光预设）、`poster.png` 及各机位参考图 `cameras/CAM_*.png`。
2. **归档至 Project 固定修订**：调用 `project.export_assets` 将片场包文件归档至目标项目 `sets/<package_id>/` 目录（严禁混入 `.blend`、`.blend1`、`.py`），取得固定 `revision_id` 并在 `finally` 中调用 `session.close` 释放实例编辑租约。
3. **运行包校验与机位对齐检查**：从中央 Project/Artifact 回读下载后，运行 `python scripts/set-package/validate_set_package.py <package_dir>` 与 `python scripts/set-package/check_camera_alignment.py --package-dir <package_dir> --output <report.json>`，确认包体积、节点数、SHA-256 哈希与机位投影误差全部符合契约，方可在短剧页通过“在片场查看器中打开”（`navigation.openApp` 锁定固定 `revision_id`）交付审片。

### 2.4 人物尺度与调度证据

有角色的正式镜头出图前，执行[比例与调度预检](scene-keyframe-video.md#22-正式出图前的比例与调度预检)。白模提供同版相机预览、人物世界尺寸／眼高／身体宽度、脚底或其他支撑接点、朝向、视线／手部目标，以及相邻镜头的坐标对应。读取求值后的世界变换和实际网格尺寸；对象原点不自动等于脚底，改高度不等于已修儿童体宽，设定值也不自动证明工程实际符合。

需要判断前后关系、窗台遮挡或目标距离时，补足以判别的俯视／侧视或尺寸标注；不能仅凭单张透视图判实高。白模核对人物所在区域、比例、地面及固定场景关系，实际姿态的自然性、肢体接触、持物和支撑由生图结果审核。不以精细人体求解替代生图，也不要求成片所有镜头都拍全身。

## 3. 每镜覆盖表模板

每个镜头／段落记录一项：

- 镜头与段落标识、地点状态和版本、复杂道具状态和版本。
- 固定工程引用、Scene／Collection、相机、帧率与帧范围。
- 对应预览／预演、空间核对结果与缺口。
- 白模锁定项、留给模型的表演项、必要接触锚点及目标时间窗口；实际模型支持的输入方式和未验证项。

空间说明同时记录单位、坐标轴、原点、尺度来源、代理到人物／Look／道具的映射、焦距／传感器或正交尺度、画幅、变换、动作与运镜、依赖、Blender 版本、源修订与输出 ContentRef。稳定业务键映射到本版对象；不能把自动对象后缀当跨版本身份。

## 4. 验收与变更

全部目标场景、复杂道具和镜头都在覆盖表中；相应 `.blend` 可恢复、预览来自同版、机位能复现，人物站位、左右手接触、道具轴心、运动通路、遮挡与画面轴线已核对，方可标为该镜头的有效空间输入。缺项只阻塞依赖该空间的最终关键帧／视频制作，其他独立工作继续。技术通过不代替创作选版。

只改机位产生镜头版本；改变共享空间或道具结构产生对应素材新版本。旧镜头继续固定旧版本，不随“最新工程”漂移；新预览必须对应新工程。历史成片缺白模时如实登记，不能补一句说明就追认通过。工程可以共享，不强制每镜复制一个 `.blend`。

交付包依约决定是否向外提供源工程，内部生产白模必备不等于自动公开全部模型。确认实际工程包含范围后再交付，不能通过界面隐藏未授权 Collection 掩盖仍在文件中的内容。
