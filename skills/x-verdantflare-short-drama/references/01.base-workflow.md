# 工作流

## 1. 从场次到请求

1. 恢复原项目与批准范围，固定每镜依据及已否定引用。合格成果优先复用，不从最新候选反推身份或服装。
2. 写完整场次：目标、阻力、转折、全部对白与语气、说者动作、听者在触发后的具体反应、离场状态。台词通过不等于听者表演通过。
3. 分镜写景别、轴线、起落幅、运镜动机和关键揭示点；白模预演同版关键位置、角度、全路径遮挡。先检查机位能否看清剧情所需接触。
4. 判断动作复杂性，拆前置状态、接触、受力、重心／支撑、释放、后果，组织一条主要因果链。可以在稳定状态切分，不能删掉解释结果的原因。
5. 组织每次真实输入：身份、当镜可见衣层（背面也算）、道具、空间摄影参考与声音。每份参考说明保留和排除范围。不支持的参考不能只写在提示词里当作已提交。
6. 按[执行入口](production/execution-gate.md)绑定最终请求、上游要求、证据和语义检查；变化则重验受影响项。用同一冻结请求提交，存在旧任务先恢复。

## 2. 产物到接画

助手先自检完整原速视频和声音，对快速接触加密抽帧；身份、左右、衣层、空间、道具、因果、听者反应任一严重失败均不得送审为可用。未能播放／听审须明确待验，播放日志不证明观看。

先定位失败维度，再修提示词、换冲突参考、局部编辑或拆镜。一次针对性返修后同缺陷仍在，停止仅换种子；重新审查方法与控制能力。环境问题另报bug，同时推进不依赖它的工作。

接画核对前后状态与音轨触发，静帧批准不得升级为视频批准。入口更新的是选段清单，后期还需装配、解码、原速带声看上下文；不能把清单成功写成整集完成。
