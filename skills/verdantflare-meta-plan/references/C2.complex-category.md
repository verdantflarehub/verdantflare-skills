# 复杂研发计划阶段结构与职责分工（C2.complex）

## 1. 五阶段法定结构（T1–T5）

标记为 `复杂研发计划` 的计划，第 4 章阶段安排（`4.1.1`～`4.1.5`）与第 5 章任务分组（`5.1`～`5.5`）必须严格固定为以下五项标准名称，不得跳步、改名、倒置或合并：

| 阶段编号 | 法定阶段名称与核心交付物                                                    |
| :------- | :-------------------------------------------------------------------------- |
| `T1`     | `完善计划与方案`：深化设计、补齐 TXT 图与受管配图、拟定考卷、闭环 `t1` 评审 |
| `T2`     | `分析影响范围`：跨仓/DB/集群/提示词扫描、刷新落点、闭环 `t2` 防漏审报 `CP0` |
| `T3`     | `实施子计划`：获 `CP0` 批准后分切片完成源码实现、单元集成测试与受控部署     |
| `T4`     | `验收子计划`：实跑全量场景填满 `accept_*.md`、完成双轨验真签署 `t4` 报告    |
| `T5`     | `人类验收子计划`：过 `cp1` 门禁呈报人类双抽检，批准后迁桶转正与同构归档     |

## 2. 多智能体与人类正交职责边界

- **执行智能体（如 Gemini）**：负责方案与 `TXT` 原理图编制、调用批准生图渠道制作高清架构图入库上图、全仓影响扫描、具体代码落地及 `T4` 场景实跑取证。
- **Claude（克劳德 · 纯架构核验与符合性审计官）**：仅在 `T1` 执行单次总体与技术架构核验（`claude_arch`），在 `T4` 仅基于 `<= 1,000` 字摘要单执行轻量架构符合性审计（`claude_arch_audit`），仅遇跨系统架构实质冲突时按 `<= 800` 字卡片单次裁决（`claude_escalation`）；零具体编码细节参与。
- **Codex（寇德X · 工程细节、防漏与脚本反作弊验真官）**：包办 `T1` CLI/AST/哈希/单测细节审、`T2` 全仓影响面防漏审（未变总体架构免调 Claude）及 `T4` 测试套件反作弊与双域哈希逐行验真。当 `Codex` 任主力实现作者时，按 `D4-A` 换用非作者的其他研发智能体替补细节审，严禁拉 Claude 替补。
- **人类（审批与极简双抽检）**：执行期固定收敛为 `CP0`（审核图文技术架构方案并核签锁卷哈希）与 `CP1`（线上系统抽检 + 验收文档抽检）两个门禁。
