# 复杂研发计划阶段结构与职责分工（C2.complex）

## 1. 五阶段法定结构（T1–T5）

标记为 `复杂研发计划` 的计划，第 4 章阶段安排（`4.1.1`～`4.1.5`）与第 5 章任务分组（`5.1`～`5.5`）必须严格固定为以下五项标准名称，不得跳步、改名、倒置或合并：

| 阶段编号 | 法定阶段名称与核心交付物                                                    |
| :------- | :-------------------------------------------------------------------------- |
| `T1`     | `完善计划与方案`：深化设计、补齐 TXT 图与受管配图、审定验收流程、闭环 `t1`  |
| `T2`     | `分析影响范围`：跨仓/DB/集群/提示词扫描、刷新落点、闭环 `t2` 防漏审报 `CP0` |
| `T3`     | `实施子计划`：获 `CP0` 批准后分切片完成源码实现、单元集成测试与受控部署     |
| `T4`     | `验收子计划`：执行者按流程取证，Codex 全面核验，Claude 抽查，签署 `t4`      |
| `T5`     | `人类验收子计划`：只设 `T5.1` 一项，人类批准或退回意见，批准后助手直接收尾  |

## 2. 验收的三个环节

验收不以怀疑执行者造假为前提。流程对了，谁执行都可以；关键是流程事先审定、结果按流程客观评价。

### 2.1 验收流程审定（T1，CP0 前）

每个待验收对象写一份验收流程（即验收文档第 2 章的一个 `S` 场景），有几个写几个。每份流程必须写清四项：

- **取证流程**：谁、在哪个环境、按什么步骤取证；默认由执行者本人取证。
- **证据内容**：交付哪些证据（日志、退出码、截图、哈希、页面等）及存放位置。
- **充分性判据**：量化通过条件，并说明这些证据为什么足以证明效果。
- **判定**：由 Codex 全面核验、Claude 抽查，分歧按第 2.4 节处理。

审定顺序固定为三步，每一步都可以直接改文档，不只提意见：

1. **执行者起草**：执行该任务的智能体（如 Gemini）写出“我干的活，我这样验收”。
2. **研发核验修订**：Codex 提意见并直接修改；Codex 是该任务执行者时，按 `D4-A` 换另一非作者研发智能体。
3. **Claude 修订**：Claude 在研发核验修订稿上直接修改并定稿。

审定结果登记在验收文档第 2 章开头的“验收流程审定记录”，随 `CP0` 一并锁卷，不另设人类审批。

### 2.2 取证（T4）

谁做的任务谁取证，按锁卷流程执行并把结果填入验收文档第 3～4 章。确需并发提速时可让 Codex 协同取证，但不作为默认做法：协同取证的智能体即成为作者，不能再担任该场景的核验方。

### 2.3 核验与抽查（T4）

- **Codex 全面核验**：逐项核对执行者交回的结果是否符合锁卷流程、证据是否齐全充分、结论是否成立，给出客观评价。这是合规评价，不是怀疑真实性，不重跑测试、不重拉产物、不另起一套取证。
- **Claude 抽查**：Codex 判定通过后，Claude 从中挑 `1～2` 项，审 Codex 的评价是否合理并核对对应证据；不做全面复核。抽查不通过即退回 Codex 重新核验，必要时退回执行者补证。

### 2.4 分歧上报

三方在流程审定或核验抽查中无法收敛时，才整理成候选项上报人类裁定。这属于例外，正常情况下不应出现。

## 3. 多智能体与人类职责边界

- **执行智能体（如 Gemini）**：方案与 `TXT` 原理图、配图入库、全仓影响扫描、编码，以及起草本人任务的验收流程并在 `T4` 亲自取证。
- **Codex（寇德X）**：`T1` 工程细节审与验收流程修订、`T2` 全仓影响防漏审、`T4` 全面核验执行者的验收结果。Codex 任该阶段作者时按 `D4-A` 由非作者研发智能体替补，严禁拉 Claude 替补。
- **Claude（克劳德）**：`T1` 总体架构核验与验收流程修订定稿、`T4` 抽查 Codex 评价 `1～2` 项、跨系统架构冲突时单次裁决；不审具体源码与测试脚本细节。
- **人类**：执行期只有 `CP0`（审核技术方案，含锁卷验收流程）与 `CP1`（最终验收）两个门禁；每个门禁只做一件事——批准，或不批准并给出意见。
