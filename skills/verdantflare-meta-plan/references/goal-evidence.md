# 用户目标来源完整性校验

## 1. 范围

[goal_evidence.py](../scripts/goal_evidence.py) 校验已捕获 Codex 目标事件、用户历史和目标服务读回的字节关联。它是委托门禁的准备模块，尚未接入 plan_lint，也不返回授权／批准结论；原 CP0、CP1 与归档行为不变。

匹配哈希及 user 角色包装不能证明文件真实，无法单独区分服务注入与用户粘贴的同形文本。非作者必须回查原生提供方、核对来源和计划归属；缺该步骤不能激活委托。不得把本模块返回值解释为无需最终人工审核。

## 2. 输入与拒绝条件

纯函数 `validate_goal_evidence` 接收两组 bytes：原生捕获及目标服务观察。捕获第一行为实际 session_meta，其余保留该会话全部 response_item/user，以及 event_msg 中的 thread_goal_updated／user_message 原始行，保持 UTF-8、原字节、顺序及 LF。不采集其他思考或工具参数。不得裁掉后续暂停、拒绝或未知指示以保持旧摘要有效；采集完整性必须由提供方回查证明。

调用方提供经独立复核的 session_id、目标事件行 SHA-256、政策用户历史 SHA-256 与目标服务观察 SHA-256。目标服务 user_goal 包装须紧随同会话 thread_goal_updated，目标和状态一致，事件时间不逆序；选择的目标必须 active。观察与最新原生目标状态／目标建立时间一致，updatedAt 不早于最新状态事件的秒时间与更新值；服务用量计数也会推进 updatedAt，因此不错误要求两者完全相等。暂停、替换或终止之后旧选择仍拒绝，即使传入重新计算的历史摘要；恢复应选真实新的 active 恢复事件，再由政策模块重新核对原授权范围。

政策历史摘要拼接全部原始用户行，但排除精确匹配已核实 source=goal 自动续跑模板的行：仅规范化三种预算数字，完整模板 SHA-256 必须命中代码常量、已有 active 原生目标，且不能伴随 user_message。这些自动续跑行仍保留在原始捕获及计数中，不能靠删除它们获得通过。未知模板、附加文本、人工粘贴同形模板仍计入政策历史，新增／删去／改序使旧摘要失效，需要重新核对范围。目标状态包装不属于可忽略的续跑模板。

重复字段、重复目标事件、缺伴生事件、异源 session、时间倒序、截断、空行、过大输入及非有限 JSON 值均拒绝。捕获最多 16 MiB，观察最多 1 MiB；原始私有内容不输出。支持的原生模板变化时按新提供方证据更新，不模糊匹配任意“用户批准”文本。

## 3. 输出与后续依赖

返回值仅为 session_id、目标事件摘要、政策历史摘要、全部用户事件／自动续跑数量和观察摘要，不返回原目标文本，不判定权限范围、不推断 H2、不直接调用外部服务。仓库／计划绑定、独立来源证明、逐门禁范围、恢复授权及最终交付包审核由后续正式政策模块负责；这些部分尚未实现。

[行为回归](../tests/test_goal_evidence.py) 全部使用标明 synthetic 的合成捕获，覆盖目标替换、暂停、跨会话、助手冒名、引用注入、历史截断／改序、重复 JSON 与完整性异常。合成测试通过不证明任何真实授权成立。
