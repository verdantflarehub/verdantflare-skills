# 简单计划快速执行流程（C1.simple）

## 1. 精简阶段结构（2～3 步）

简单计划保留八章四字外框，将第 4 章与第 5 章阶段收敛为 2～3 个轻量步序，末级复选框控制在 2～5 项：

- **两步极简流**（范围已由源码核查明确）：`T1 实施与验证` -> `T2 自验收与归档`。
- **三步探查流**（需先做小范围日志或接口核实）：`T1 核查与准备` -> `T2 实施与验证` -> `T3 自验收与归档`。

阶段标题必须带“实施与验证 / 自验收与归档”等轻量后缀，与复杂计划五阶段标准名称明确区分。

## 2. 标准推进步骤

### 2.1 初始化与草稿门禁

使用 [简单计划模板](../resources/templates/plan-simple.template.md) 或 `init --level simple` 创建计划，运行 `--gate draft` 确认无擅自降级与结构缺陷：

```text
python -X utf8 scripts/plan_lint.py init --level simple --slug bugfix-demo --title "修复示例问题" --owner Mengsk --cp-mode s0
python -X utf8 scripts/plan_lint.py check docs/plan/YYYY.MM.bugfix-demo.plan.md --gate draft
```

### 2.2 子任务变更执行与证据收口

每个末级子任务开始时新建 `docs/changes/change_YYYYMMDD_*.md`，将修改记录、单测输出与环境验证证据直接写入变更文档，完成后立即将该变更归入 `docs/archive/changes/` 并勾选计划复选框。简单计划免制重型架构配图，免建 `docs/reviews/` 与 `docs/acceptance/` 独立文档。

### 2.3 收尾归档与提交

- **`S0` 零人工阻塞流**：前置子任务全部完成验证后，在末步归档子任务运行 `archive-preflight` 预检，将计划状态置为 `已完成` 移入 `docs/archive/plan/`，修正入链并通过 `--gate archive` 后直接统一提交推送。
- **`S1` 单点确认流**：在 `S1-CP0`（实施前）或 `S1-CP1`（归档前）按检查点向人类做一次简洁请示，获准后记入第 7 章审批记录并按同流程完成归档提交。
