# 复杂研发计划标准执行流程（C2.complex）

## 1. T1–T2 方案深化、验收流程审定与 CP0

### 1.1 T1 方案、配图与验收流程审定

使用 [复杂计划模板](../resources/templates/plan-complex.template.md)、[研发评审模板](../resources/templates/rd-review.template.md) 与 [研发验收模板](../resources/templates/acceptance.template.md) 建立骨架。在专题设计补齐非空 `text` 原理图，调用批准的 ChatGPT Image 渠道生成高清架构配图并经 `.gdrive/managed/pending/` 入库嵌入正文。

验收流程按 [复杂分类](C2.complex-category.md#21-验收流程审定t1cp0-前) 第 2.1 节审定：执行者在 `accept_*.md` 第 2 章逐个 `S` 场景起草取证流程、证据内容、充分性判据与判定，Codex 直接修订，Claude 再直接修订定稿，三步登记在第 2 章开头的“验收流程审定记录”。

`t1` 评审同步完成：Codex 写第 3 章（工程细节审与验收流程修订），Claude 写第 2 章（架构核验与验收流程定稿），闭环落盘 `review_*_t1.md`（`已通过`）。

### 1.2 T2 影响扫描与 CP0 呈报

只读扫描涉及的代码仓、存量计划、数据库/部署清单与提示词预算，刷新计划第 4.2 节与 `T3 / T4` 任务落点。未改变 `T1` 总体架构时直接由 Codex 执行 `T2` 全仓防漏审，计算 `review-hash --stage t2` 写入 `review_*_t2.md`（`已通过`）。运行 `plan_lint.py check --gate cp0` 返回退出码 `0` 后呈报人类；人类批准或给意见。获批后将 `lock-hash` 写入第 7 章审批记录并将验收文档置为 `考卷已锁定`。

## 2. T3–T4 实施、取证、核验与抽查

### 2.1 T3 受控实施

未获 `CP0` 批准前严禁偷跑正式业务改造。获批后按子任务逐项新建 `docs/changes/change_*.md`，完成编码与单测验证即结项归入 `docs/archive/changes/` 并更新复选框。

### 2.2 T4 取证

执行者将验收文档状态置为 `实跑取证中`，按锁卷流程亲自逐景取证，把真实退出码、指标摘要与第 `4.1–4.4` 节锚点填入 `accept_*.md`（严禁触碰第 2 章字符）。

### 2.3 T4 核验与抽查

1. 计算 `review-hash --stage t4`，交 Codex 全面核验：逐景对照锁卷流程评价结果是否合规、证据是否充分，写入 `review_*_t4.md` 第 3 章。不重跑、不重拉产物。
2. Codex 判定通过后，Claude 挑 `1～2` 项抽查 Codex 的评价是否合理，写入第 2 章并注明抽查了哪几项、结论如何。
3. 二者均通过后签署 `review_*_t4.md`（`已通过`），把会话收据补入 `accept_*.md` 第 `4.5` 节，状态置为 `智能体已验真`。

## 3. T5 人类验收与收尾

`T5` 只设 `T5.1` 一项，人类只做一个决定：

1. 助手运行 `plan_lint.py check --gate cp1` 确认退出码 `0`，按验收文档第 5 章整理呈报包（结论、Codex 评价、Claude 抽查结果与查看入口）。
2. 人类批准，或不批准并给出意见。不批准时意见记入计划第 7 章，验收状态回退 `实跑取证中`，追加 `-r2` 返修任务修复后重新走 `T4` 核验抽查再呈报。
3. 批准后助手直接收尾，不再请示：验收状态置为 `CP1已通过`，`.gdrive` 配图由 `pending` 迁入 `approved`，设计转正；运行 `archive-preflight` 通过后把 `plan / reviews / acceptance` 同构移入 `docs/archive/`，全仓修正入链，勾选 `T5.1` 并通过 `--gate archive`，最后统一提交推送。
