# 复杂研发计划标准执行流程（C2.complex）

## 1. T1–T2 方案深化、配图上图与 CP0 锁卷

### 1.1 T1 方案、配图与预设考卷

使用 [复杂计划模板](../resources/templates/plan-complex.template.md)、[研发评审模板](../resources/templates/rd-review.template.md) 与 [研发验收模板](../resources/templates/acceptance.template.md) 建立骨架。在专题设计补齐非空 `text` 原理图，调用批准的 ChatGPT Image 渠道生成高清架构配图并经 `.gdrive/managed/pending/` 入库嵌入正文；在 `docs/acceptance/accept_*.md` 第 2 章前置定义 `S1..Sn` 场景判据。随后执行 `T1` Claude 单次架构核验与 Codex 工程细节评审，闭环落盘 `review_*_t1.md`（`已通过`）。

### 1.2 T2 影响扫描与 CP0 呈报

只读扫描涉及的代码仓、存量计划、数据库/部署清单与提示词预算，刷新计划第 4.2 节与 `T3 / T4` 任务落点。未改变 `T1` 总体架构时直接由 Codex 执行 `T2` 全仓防漏审，计算 `review-hash --stage t2` 写入 `review_*_t2.md`（`已通过`）。运行 `plan_lint.py check --gate cp0` 返回退出码 `0` 后呈报人类审核；获批后将 `lock-hash` 写入第 7 章审批记录并将验收文档置为 `考卷已锁定`。

## 2. T3–T4 切片实施、实跑取证与双轨验真

### 2.1 T3 受控实施

未获 `CP0` 批准前严禁偷跑正式业务改造。获批后按子任务逐项新建 `docs/changes/change_*.md`，完成编码与单测验证即结项归入 `docs/archive/changes/` 并更新复选框。

### 2.2 T4 全景实跑与独立验真审计

执行助手将验收文档状态置为 `实跑取证中`，逐景运行锁定命令，把真实退出码、指标摘要与第 `4.1–4.4` 节四维 `SHA-256` 锚点填入 `accept_*.md`（严禁触碰第 2 章字符）。随后计算 `review-hash --stage t4`，交 Codex 执行脚本反作弊与哈希证据链验真，同时向 Claude 投递经 `HO-CLAUDE-SCOPE` 校验的 `<= 1,000` 字架构符合性摘要单完成轻量审计，落盘 `review_*_t4.md`（`已通过`），把 `T4` 会话收据补入 `accept_*.md` 第 `4.5` 节并将状态置为 `智能体已验真`。

## 3. T5 人类双抽检与同构归档

- **`T5.1` 呈报 `CP1`**：运行 `plan_lint.py check --gate cp1` 确认退出码 `0` 并记入验收文档第 `5.1` 节，呈报人类执行线上系统抽检与验收文档抽检。
- **`T5.2` 迁桶转正与归档**：获 `CP1` 批准后将验收状态置为 `CP1已通过`，将 `.gdrive` 配图由 `pending` 迁入 `approved` 并把设计文档转正；运行 `archive-preflight` 通过后，把 `plan / reviews / acceptance` 同构移入 `docs/archive/` 对应目录，全仓修正入链并通过 `--gate archive`，最后统一提交推送。
