# 锁卷哈希、五档门禁与同构归档（03.gate-hash）

## 1. 输入与输出

- **输入**：需求描述或计划/设计/评审/验收文件路径、目标仓库根 `--root` 与仓库标识 `--repo-id`，以及可选的原生收据、目标来源与委托政策文件。
- **输出**：[plan_lint.py](../scripts/plan_lint.py) 输出的分级 JSON、脚手架文件、`sha256:<64hex>` 确定性哈希、五档门禁诊断与退出码，以及 [install.py](../scripts/install.py) 同步并校验的全局技能副本。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的锁卷哈希、双棘轮防降级与反自审红线，以及 [00.common.acceptance.md](00.common.acceptance.md) 中的退出码与 `PL-*` 规则码契约。

## 2. 分类

### 2.1 `plan_lint.py` 核心子命令

| 子命令 / 工具               | 职责与使用时机                                                       |
| :-------------------------- | :------------------------------------------------------------------- |
| `classify`                  | 立项分级探测，识别否定语境避免“不涉及数据库迁移”误加复杂分           |
| `init`                      | 基于内置模板原子生成简单或复杂计划及核心目录骨架                     |
| `lock-hash` / `review-hash` | 计算考卷第 2 章锁卷摘要与 `t2 / t4` 冻结切片评审对象哈希             |
| `check --gate <level>`      | 执行 `draft / cp0 / cp1 / archive-preflight / archive` 五档 AST 门禁 |
| `freeze` / `migrate-legacy` | 首次接入生成 `.legacy-plans.json` 存量冻结清单及单向迁出             |

### 2.2 原生证据与政策校验扩展专册

需要核对 Hub/CLI 原生会话收据、用户目标捕获或委托政策证据时，按需加载以下独立主题专册：

| 扩展校验专题                           | 主题专册                            |
| :------------------------------------- | :---------------------------------- |
| 绑定 Hub/CLI 原生记录与 T4 双轨收据    | [原生收据规范](native-receipts.md)  |
| 核对用户目标捕获完整性（非授权判定）   | [目标来源证据](goal-evidence.md)    |
| 核对委托政策、登记与原生来源（非门禁） | [委托政策证据](delegated-policy.md) |

## 3. 工作流

### 3.1 立项探测与脚手架初始化

```text
python -X utf8 scripts/plan_lint.py classify --text "<需求描述>" --json
python -X utf8 scripts/plan_lint.py classify --plan docs/plan/YYYY.MM.<topic>.plan.md --json
python -X utf8 scripts/plan_lint.py init --level simple --slug demo-fix --title "修复示例缺陷" --owner Mengsk --cp-mode s0
python -X utf8 scripts/plan_lint.py init --level complex --slug core-arch --title "核心架构升级" --owner Mengsk --with-core-docs
```

### 3.2 哈希计算与五档门禁递进检查

```text
python -X utf8 scripts/plan_lint.py lock-hash docs/acceptance/accept_YYYYMMDD_<topic>.md --json
python -X utf8 scripts/plan_lint.py review-hash --stage t2 --design docs/design/spec.md --accept docs/acceptance/accept.md
python -X utf8 scripts/plan_lint.py review-hash --stage t4 --accept docs/acceptance/accept.md
python -X utf8 scripts/plan_lint.py check docs/plan/YYYY.MM.<topic>.plan.md --gate draft --repo-id <org/repo>
python -X utf8 scripts/plan_lint.py check docs/plan/YYYY.MM.<topic>.plan.md --gate cp0
python -X utf8 scripts/plan_lint.py check docs/plan/YYYY.MM.<topic>.plan.md --gate cp1
python -X utf8 scripts/plan_lint.py check docs/plan/YYYY.MM.<topic>.plan.md --gate archive-preflight
python -X utf8 scripts/plan_lint.py check docs/archive/plan/YYYY.MM.<topic>.plan.md --gate archive
```

### 3.3 存量冻结、单向迁出与全局安装

```text
python -X utf8 scripts/plan_lint.py freeze --root . --repo-id <org/repo>
python -X utf8 scripts/plan_lint.py migrate-legacy docs/plan/2026.10.legacy-demo.plan.md
python -X utf8 scripts/install.py --replace
python -X utf8 -m unittest discover -s tests -p "test_*.py"
```

## 4. 规范

- **路径安全与原子写入**：`init` 先校验输出路径不逃逸 `--root` 且默认拒绝覆盖已有文件；`freeze` 在每个历史仓库首次接入时仅允许执行一次，重复执行返回退出码 `2`。
- **哈希确定性边界**：`review-hash` 归一化 CRLF、行尾空白与 `.gdrive/managed/<bucket>/` 桶名，豁免文首可变状态行及验收文档 `4.5` 节与第 `5` 章追加区；任何被审设计正文或验收第 `2～4.4` 节冻结证据改动均须重算哈希并重过评审。
- **异步等待与原生收据**：跨智能体评审优先使用阻塞等待（如 `launch.py --wait`），连接中断恢复时先查原 `task_id` 与 `session_id / thread_id`，严禁重复派发；终态收据须写入受控评审/验收文档并满足 [native-receipts.md](native-receipts.md) 契约。
- **证据与授权分离**：[goal-evidence.md](goal-evidence.md) 与 [delegated-policy.md](delegated-policy.md) 校验字节关联与完整性元数据，不签发权限，不替代人类 `CP0 / CP1` 或发布授权。

## 5. 验收

- 对应阶段运行 `plan_lint.py check --gate <level>` 返回退出码 `0`（完整退出码与 17 项 `PL-*` 规则码见 [00.common.acceptance.md](00.common.acceptance.md)）。
- 维护本技能源码后运行 `python -X utf8 -m unittest discover -s tests -p "test_*.py"`（覆盖 `test_plan_lint.py`、`test_native_receipts.py`、`test_delegated_*.py`、`test_goal_*.py`、`test_final_*.py`、`test_archive_relocation.py`、`test_cancellation_gate.py` 与 `test_process_receipts.py`）全部通过。
- 运行 `python -X utf8 scripts/install.py --replace` 同步至 `~/.agents/skills/verdantflare-meta-plan`，源码与安装副本逐文件 SHA-256 一致且 `lint_skill.py --style numbered` 返回 `0 errors`。
