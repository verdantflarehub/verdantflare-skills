# 研发计划共享分类与核心目录边界

## 1. 适用范围与不适用场景

本专册定义 `verdantflare-meta-plan` 的计划分级判据、跨等级迁移条件及四大研发受控核心目录职责边界：

- **适用场景**：新研发任务立项定级、编制或升级 `docs/plan/*.plan.md`、创建或维护 `docs/reviews/` 与 `docs/acceptance/` 文档、执行存量未分级计划受控冻结与单向迁出。
- **不适用场景**：单次对话即答即结且无代码或配置落盘的普通技术咨询；纯创作分镜看片与选片评审表（如 `*.review.md`，仍归属创作或设计目录）；具体业务架构细节设计本身。

## 2. 双轨计划等级判据

所有新建研发计划必须在文首 `助手` 字段之后、`计划状态` 字段之前声明必填字段 `计划等级`，取值仅限 `复杂研发计划` 或 `简单计划`。

| 计划等级       | 核心触发特征与对应分支                                                                      |
| :------------- | :------------------------------------------------------------------------------------------ |
| `复杂研发计划` | 跨仓多域耦合、公共契约或状态机变更、高风险实境防作弊验收，对应 [C2](C2.complex-category.md) |
| `简单计划`     | 单域收敛、契约稳定、验证命令确定，支持 `S0 / S1`，对应 [C1](C1.simple-category.md)          |

命中以下任一条件时，必须定级为 `复杂研发计划`：

- **用户显式指定**：用户在立项或审阅时明确要求按复杂研发计划管控。
- **跨仓与多域耦合**：改动跨越 2 个及以上仓库或微服务，或同时触及后端逻辑、数据库迁移、部署清单与前端交互，或新建完整技能包并联动修改全局提示词。
- **公共契约与并发状态机变更**：新增或实质修改跨服务契约、并发锁仲裁状态机、持久化数据模型或安全权限边界。
- **高风险防作弊实境验收**：涉及 GPU 显存调度、多宿主异步协同或集群滚动切换，需要独立智能体执行脚本反作弊与哈希证据对账。

## 3. 跨等级迁移与历史存量冻结边界

### 3.1 跨等级升级与特批降级

简单计划在推进中若范围扩展命中复杂判据，或评估需要设置 2 个及以上人类检查点，必须升级为 `复杂研发计划`：保留已归档的前序变更记录，将阶段结构重组为标准 `T1–T5`，补建 `docs/reviews/` 与 `docs/acceptance/` 文档，并在计划第 7 章登记升级依据。命中复杂判据却拟按简单计划执行时，必须取得用户显式批准并记入第 7 章，否则门禁以 `PL-LVL-DOWNGRADE` 阻断。

### 3.2 目标仓存量冻结清单

制度生效前已存在的未分级历史在途计划，由 `plan_lint.py freeze` 在目标仓库一次性生成 `docs/plan/.legacy-plans.json` 受控豁免（不向全局技能目录写入任何单仓状态）。未迁出计划（`migrated: false`）在 `--gate draft` 下豁免 `PL-LVL-REQ`，一旦补齐 `计划等级` 或调用 `migrate-legacy` 即永久单向退出豁免。

## 4. 四大研发核心受控目录

| 受控目录           | 生命周期职责与归档去向                                                  |
| :----------------- | :---------------------------------------------------------------------- |
| `docs/plan/`       | 维护 `YYYY.MM.<主题>.plan.md`，结项或废弃移入 `docs/archive/plan/`      |
| `docs/changes/`    | 维护单子任务 `change_YYYYMMDD_*.md`，完成即移入 `docs/archive/changes/` |
| `docs/reviews/`    | 驻留复杂计划 `review_YYYYMMDD_<主题>_<阶段>.md`，随计划同构归档         |
| `docs/acceptance/` | 驻留复杂计划 `accept_YYYYMMDD_<主题>.md`，随计划同构归档                |

复杂计划在途期间，`reviews` 与 `acceptance` 持续驻留核心目录并通过文首 `关联计划` 反向相对链接绑定所属计划；计划在 `T5` 结项或废弃时，四类受控文档同步归入 `docs/archive/` 对应子目录并全仓修正入链引用。
