# 复杂研发计划核心目录契约与门禁规则（C2.complex）

## 1. 研发评审文档契约（docs/reviews/）

文件名必须匹配 `^review_\d{8}_[a-z0-9.-]+_(t1|t2|t4)(-r(?:[2-9]|[1-9]\d+))?\.md$`；存在多轮 `-rN` 时门禁自动选取最大 `N` 作为当前有效报告。

### 1.1 七项文首必填字段

标题下依次包含 `负责人`、`评审助手`、`关联计划`（精确相对链接）、`关联阶段`（`T1 / T2 / T4` 及被审文档链接）、`评审对象哈希`（`sha256:<64hex>`）、`评审结论`（`待修订 | 复评中 | 已通过 | 已废弃`）与 `更新时间`（`YYYY-MM-DD`）。

### 1.2 五章固定正文

正文严格固定为：`1. 当前依据`、`2. 架构核验与抽查`（Claude）、`3. 工程细节、防漏与验收核验`（Codex 或 `D4-A` 替补）、`4. 架构疑难升级裁定`、`5. 问题闭环与放行结论`（存量报告沿用旧章名“总体架构核验与符合性审计 / 工程细节与防漏评审”时等效）（必须同时包含 `未闭环 HIGH/MEDIUM：<整数>` 汇总行与逐条 `[CLOSED] / [OPEN]` 状态，逐条 `[OPEN]` 高/中危数须与汇总行完全一致且为 `0` 方可签署 `已通过`）。

## 2. 研发验收文档契约（docs/acceptance/）

文件名必须匹配 `^accept_\d{8}_[a-z0-9.-]+\.md$`。

### 2.1 六项文首必填字段与六态状态机

标题下依次包含 `负责人`、`执行助手`、`验真助手`、`关联计划`、`验收状态` 与 `更新时间`。`验收状态` 严格限定为：`考卷草案`、`考卷已锁定`、`实跑取证中`、`智能体已验真`、`CP1已通过`、`已废弃`（支持驳回逆向回退：`智能体已验真 -> 实跑取证中`，`考卷已锁定 -> 考卷草案`）。

### 2.2 五章固定正文与五维防伪锚点

正文严格固定为：`1. 当前依据`、`2. 锁定验收场景与判据`（`CP0` 锁卷切片：开头为验收流程审定记录，每个 `### 2.x Sn` 场景写明取证流程、证据内容、充分性判据与判定）、`3. 智能体实跑与演示证据`、`4. 防伪锚点与双轨验真`（含 `4.1` 工作区基准、`4.2` 运行宿主环境、`4.3` 源码与测试脚本 `SHA-256`、`4.4` 安装态或线上制品 `SHA-256` 及 `T1/T2` 收据、`4.5` `T4` 核验与抽查原生会话收据签后追加区）、`5. CP1 呈报包`（存量文档沿用旧章名“CP1 双抽检核验单”时等效）。

## 3. CP0 硬门槛与驳回流转铁律

- **硬门槛缺一不可**：`PL-CP0-TXT`（非空 `text` 原理图）、`PL-CP0-IMG`（受管 `.gdrive/managed/` 配图 + 回执 + 64 位哈希校验）、`PL-CP0-ACC`（预设考卷场景齐备）、`PL-CP0-PROC`（审定记录含执行者起草、研发核验修订、Claude 修订三步，且每个场景四要素齐备）、`PL-CP0-REV`（`t1` 与 `t2` 最新有效报告均 `已通过`、`OPEN == 0`、`t2` 匹配实时 `review-hash` 且满足 `PL-REV-INDEP`）。
- **已废弃同构归档约束**：若复杂计划经用户决定终止并标为 `已废弃`，其反向关联的全部 `reviews` 与 `acceptance` 文首状态必须同步置为 `已废弃` 后方可同构归档。
