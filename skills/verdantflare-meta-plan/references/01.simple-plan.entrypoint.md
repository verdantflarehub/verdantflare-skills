# 简单计划轻量闭环（01.simple-plan）

## 1. 输入与输出

- **输入**：不触碰复杂判据的研发需求、负责人、主题 `slug` 与目标管控模式（`S0` / `S1-CP0` / `S1-CP1`）。
- **输出**：基于 [plan-simple.template.md](../resources/templates/plan-simple.template.md) 生成的 2～3 步简单计划文档、逐子任务结项归档的 `docs/archive/changes/change_*.md` 证据，以及通过 `--gate archive` 归入 `docs/archive/plan/` 的已完结计划。
- **公共约束**：遵循 [00.common.rules.md](00.common.rules.md) 中的双轨判据、防降级红线与四受控目录边界。

## 2. 分类

### 2.1 适用特征与升级触发边界

当研发任务不触碰 [00.common.rules.md](00.common.rules.md) 中的复杂判据且同时具备以下三项特征时，定级为 `简单计划`：

- **改动单域收敛**：修改范围限定在单一仓库、单一子服务或单一技能包内部，例如契约内缺陷修复、局部重构、样式微调、辅助脚本优化或文档规范整理。
- **外部契约稳定**：不改变既有跨服务公共 API、数据库表结构、安全鉴权边界或集群拓扑。
- **验证自闭环**：存在确定性单测、静态检查或离线复现实验命令，可由执行智能体独立完成闭环验证。

执行过程中一旦出现以下任一情形，必须立即升级为 `复杂研发计划` 并转入 [02.complex-plan.entrypoint.md](02.complex-plan.entrypoint.md)：排查发现根因跨越多个仓库、需同步变更公共契约或数据库结构；或需要同时设置前置方案审核（`CP0`）与结项验收审批（`CP1`）两个人类检查点。

### 2.2 人类参与模式（S0 与 S1）

文首在 `计划等级：简单计划` 下可紧随声明可选字段 `管控模式`：

| 管控模式 | 人类检查点数与适用场景                                                 |
| :------- | :--------------------------------------------------------------------- |
| `S0`     | `0 CP`（人类零参与）：目标与授权已在立项明确，智能体全自动验收归档推送 |
| `S1-CP0` | `1 CP`（前置确认）：编码前需人类确认外部凭据、口令或单一界面交互小取舍 |
| `S1-CP1` | `1 CP`（结项体验）：智能体验证通过后需人类做一次轻量桌面或页面视觉确认 |

## 3. 工作流

### 3.1 精简阶段结构（2～3 步）

简单计划保留八章四字外框，将第 4 章与第 5 章阶段收敛为 2～3 个轻量步序，末级复选框控制在 2～5 项：

- **两步极简流**（范围已由源码核查明确）：`T1 实施与验证` -> `T2 自验收与归档`。
- **三步探查流**（需先做小范围日志或接口核实）：`T1 核查与准备` -> `T2 实施与验证` -> `T3 自验收与归档`。

阶段标题必须带“实施与验证 / 自验收与归档”等轻量后缀，与复杂计划五阶段标准名称明确区分。

### 3.2 初始化、执行与归档

1. **初始化与草稿门禁**：使用 [plan-simple.template.md](../resources/templates/plan-simple.template.md) 或 `init --level simple` 创建计划，运行 `--gate draft` 确认无擅自降级与结构缺陷：

```text
python -X utf8 scripts/plan_lint.py init --level simple --slug bugfix-demo --title "修复示例问题" --owner Mengsk --cp-mode s0
python -X utf8 scripts/plan_lint.py check docs/plan/YYYY.MM.bugfix-demo.plan.md --gate draft
```

2. **子任务变更执行与证据收口**：每个末级子任务开始时新建 `docs/changes/change_YYYYMMDD_*.md`，将修改记录、单测输出与环境验证证据直接写入变更文档，完成后立即归入 `docs/archive/changes/` 并勾选计划复选框。简单计划免制重型架构配图，免建 `docs/reviews/` 与 `docs/acceptance/` 独立文档。
3. **收尾归档与提交**：
   - **`S0` 零人工阻塞流**：前置子任务全部完成验证后，在末步归档子任务运行 `archive-preflight` 预检，将计划状态置为 `已完成` 移入 `docs/archive/plan/`，修正入链并通过 `--gate archive` 后直接统一提交推送。
   - **`S1` 单点确认流**：在 `S1-CP0`（实施前）或 `S1-CP1`（归档前）按检查点向人类做一次简洁请示，获准后记入第 7 章审批记录并按同流程完成归档提交。

## 4. 规范

- **最多一个人类检查点**：简单计划全周期人类检查点数量必须 `<= 1`（`S0` 为 `0` 个，`S1` 仅允许设 `CP0` 或 `CP1` 之一，严禁二者并存）；第 3.2 节若定义 `>= 2` 个检查点，`plan_lint.py` 直接以 `PL-LVL-DOWNGRADE` 阻断。
- **严禁拆分掩盖复杂改动**：禁止将本属同一跨仓架构改造的任务人为拆成多份简单计划以规避 `CP0` 图文审核、独立评审与锁卷验收；命中复杂判据而未获第 7 章人类特批降级的计划一律阻断。
- **免独立目录但严守变更证据**：豁免 `docs/reviews/`、`docs/acceptance/` 与 ChatGPT Image 架构图不代表豁免验证；所有测试命令、退出码与回归结论必须完整记录在关联 `docs/changes/change_*.md` 第 4、5 章。
- **严禁调用昂贵架构陪跑**：简单计划由执行智能体自行完成代码核查与验证，除非遇到意外架构冲突需升级为复杂计划，日常推进中不拉起 Claude 执行架构评审。
- **收尾零残留**：计划结项归档时，`docs/plan/` 与 `docs/changes/` 下不得残留本计划活动副本，所有指向该计划或关联变更的相对链接必须同步更新至 `docs/archive/`。

## 5. 验收

简单计划适用 `draft`、`archive-preflight` 与 `archive` 三档门禁（`cp0` 与 `cp1` 为复杂研发计划专属门禁，对简单计划调用将返回阻断提示），规则码见 [00.common.acceptance.md](00.common.acceptance.md)：

| 门禁档位            | 简单计划通过条件                                                           |
| :------------------ | :------------------------------------------------------------------------- |
| `draft`             | `计划等级：简单计划` 合法、未触发 `PL-LVL-DOWNGRADE`、`CP <= 1`、步序 2～3 |
| `archive-preflight` | 仅末步收尾任务可为 `[ ]` 其余全 `[x]`；若为 `S1` 则对应单点检查点已通过    |
| `archive`           | 已移入 `docs/archive/plan/`、`100% [x]`、活动目录零残留、全仓入链无断链    |

报告完成前逐项确认：全部受影响模块单测、增量编译与静态格式检查（`md_format.py --check`、`check_md.py`）退出码均为 `0`；每个末级子任务的 `change_*.md` 已填 `结项结论：已完成` 并移入 `docs/archive/changes/`；`S1` 单点确认结论已登记第 7 章（或 `S0` 在第 3.2 节标明 `人类检查点（0 个）`）；运行 `plan_lint.py check docs/archive/plan/YYYY.MM.<topic>.plan.md --gate archive` 返回 `0`。
