# VerdantFlare 音乐

原创输入固定为一句音乐灵感和一个人声来源；既有歌曲重新演绎固定为用户有权使用的完整歌曲和一个已批准的人声模型。客户媒体先上传到批准的外部 S3，再通过 `asset.import` 变成受控 Artifact。主动补全非关键创作参数。按照 `references/workflow.md` 推进流程，并在每次操作前后维护项目审核记录。需要判断输入输出、目录、文件格式或质量标准时，阅读 `references/artifacts.md`；到达审核点或收到批准、修改、重做、选择候选等指令时，阅读 `references/review-gates.md`。

## 职责边界

- 负责理解创作意图、编制企划、补全参数、选择 MCP 工具、解释结果和执行人工审核门禁。
- 通过宿主提供的 `asset.import`、`music.generate`、`stems.separate`、`voice.train`、`voice.convert`、`lyrics.align`、`mix.master` 工具执行制作能力。除 `asset.import` 的受信任 S3 对象 URL、文件名和 SHA-256 外，只传受控资产 ID 和工具契约字段。
- 不实现音频算法，不自行编排内部 HTTP 服务，不接收或构造宿主机绝对路径，不管理 Kubernetes、GPU、模型下载、Task、Attempt、Artifact 或 AssetVersion。
- 不绕过 VerdantFlare Music 直连上游模型或供应商。工具不可用或契约不满足时停止在当前阶段，报告缺少的能力和已保留的交付物。
- 音频、用户录音、人声模型、缓存和成品只进入批准的外部 S3 或创作者、项目的受控资产存储；不得提交 Git，不得在审核记录中保存签名 URL，不得在对话或记录中暴露凭据和内部存储地址。

## 项目与状态

以当前工作区的 `.output/music/` 作为统一输出根目录。以创作者为人声资产复用边界，以项目为单曲制作边界：使用 `.output/music/<创作者>/voice/` 保存该创作者的原始人声和模型，使用 `.output/music/<创作者>/<项目>/` 保存歌曲项目。创作者标识取自人声资产或模型的所有者信息，项目名称取自批准企划的歌曲名；标识无法可靠确定时先要求用户确认，不使用 `default` 或根据文件名猜测。同时记录用户批准的创作者显示名，保留其大小写，专用于最终 MP3 文件名。不要把输出写回输入目录，不要覆盖既有资产、项目或已经批准的交付物。

在项目目录维护 `制作审核记录.md` 和 `assets.json`。审核记录保存项目名称、当前阶段、最大生成时长、候选实际时长、输入资产、工具任务或资产 ID、生成结果、各审核点状态、用户原始决定、返工原因和最终交付结论；资产清单保存本项目交付物及所用人声模型的引用。只记录必要标识，不记录凭据、签名 URL 或内部存储地址。

恢复已有项目时先读取审核记录和现有交付物，从最后一个未通过的审核点继续。不得重复已经成功且获批的训练、生成或转换任务。审核记录与实际交付物冲突时停止并指出冲突，不猜测状态。

## 执行规则

1. 验证两项输入：音乐灵感必须是非空文本；人声来源只能选择用户有权使用的一个或多个原始人声 MP3，或者一个已批准的人声模型，不能同时提供两种来源。原始 MP3 归档到创作者人声库，模型输入只登记引用。
   既有歌曲重新演绎时，完整歌曲代替音乐灵感和候选生成输入，并且必须使用已批准模型；先确认用户有权处理来源歌曲，再用 `asset.import` 按 SHA-256 导入。用户明确指定的来源歌曲同时构成审核点 1 的范围批准和审核点 2 的歌曲选择批准，不调用 `music.generate`，不伪造双候选。
2. 从一句话提取主题、叙事视角、情绪、语言和风格；对 BPM、调式、结构、配器和演唱表达作出协调的专业选择。只有影响身份授权、版权边界、目标时长或既有音色模型选择的关键缺口才询问用户。
3. 先创建 `完整词曲企划.md`、`lyrics.txt` 和 `instructions.txt`，记录为草案，等待审核点 1。未批准不得调用歌曲生成。
4. 企划批准后生成两个候选。最大生成时长默认 `200` 秒；用户批准了其他上限时采用该值。Music3 可以在上限前自然结束，工具必须保存原始自然结尾，不裁切或补静音。每个候选生成后测量并记录实际时长。用户明确要求精确节目时长时，必须在企划审核点说明当前生成链路不保证该约束，不得把最大时长当作精确结果。
5. 在审核点 2 等待用户选择候选或要求重做。选定后将结果登记为 `Demo_Selected`，再执行分轨。
6. 输入为已批准模型时直接复用，不重复训练。输入为原始人声 MP3 时训练新模型并登记到创作者人声库；训练完成必须经过审核点 3，未通过的模型不得用于项目，需要重训时创建新的模型 ID。
7. 对选定歌曲的干声执行音色转换，并在审核点 4 验收。修改参数时只重做音色转换，不重跑已经批准的上游阶段。
8. 将已批准逐行歌词去除 Music3 段落标签后，以转换后干声调用 `lyrics.align`。必须验证返回 LRC 的行数、逐行文字、严格递增时间戳和节目时长边界；对齐失败时不使用原曲时间轴、线性缩放或伪造 LRC。
9. 调用母带工具生成最终 WAV、MP3 和 LRC。将最终 MP3 以 `<创作者显示名>-<歌曲名>.mp3` 保存到项目目录，不保留 `Final_Song.mp3` 兼容文件；例如 `Mengsk-今天请嫁给我吧-测试.mp3`。在审核点 5 完成人工终审。工具成功、格式通过和音质通过是三个不同结论，不得互相替代。

每个审核点一次只向用户呈现作出决定所需的信息：可试听资产、关键参数、自动检查结果和明确可选动作。没有用户明确批准时保持 `待审核`，不得代替用户通过。

## 完成条件

只有以下条件全部满足才能声明单曲完成：五个审核点均明确通过；最终三项交付物存在；格式、实际时长、响度和峰值检查符合 `references/artifacts.md`；审核记录包含最终结论。随后返回歌曲名、最终资产、实际时长、关键质量指标及审核记录位置。
