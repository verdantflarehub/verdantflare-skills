## 2. 纯歌词双歌手计划与 `duet-score-v1` 机器校验契约

用户仅提供歌词时，先将每句编入 `female`、`male`、`both` 或 `instrumental`（双方各有独唱与同唱），默认声明 `duet_template="call_response_final_merge"`、首次 `both` 推迟至最后副歌/终段合流（`>= 65%`）且同唱占歌词时长 `<= 18%`。进入付费前检查真实工具，`workflow.preflight(workflow="duet_generate")` 的 `ready` 仅证明可调，不证明歌词、音色或隔离合格。

预混前以 `duet-score-v1` JSON 运行校验器（须支持 PCM 整数与 IEEE float WAV）：

```bash
python3 verdantflare-skills/skills/verdantflare-music/scripts/validate_duet.py \
  --plan <plan.json> --female <female.wav> --male <male.wav> \
  --instrumental <instrumental.wav> --report <validation.json>
```

计划核心字段示例：

```json
{
  "schema_version": "duet-score-v1",
  "duet_template": "call_response_final_merge",
  "both_policy": {
    "max_voiced_ratio": 0.18,
    "first_both_min_ratio": 0.65,
    "allowed_modes": ["unison", "third", "sixth", "lead_with_tail_harmony"]
  },
  "duration_seconds": 18.0,
  "sample_rate": 48000,
  "lines": [
    {"start_seconds": 0.0, "end_seconds": 3.0, "voice": "female", "text": "..."},
    {"start_seconds": 3.0, "end_seconds": 6.0, "voice": "male", "text": "..."},
    {"start_seconds": 6.0, "end_seconds": 12.0, "voice": "instrumental", "text": ""},
    {"start_seconds": 12.0, "end_seconds": 15.0, "voice": "both", "harmony_mode": "third", "text": "..."},
    {"start_seconds": 15.0, "end_seconds": 18.0, "voice": "instrumental", "text": ""}
  ],
  "chords": [{"start_seconds": 0.0, "end_seconds": 18.0, "root": "A", "quality": "min"}],
  "melody": {
    "female": [{"start_seconds": 0.0, "end_seconds": 0.5, "midi": 69, "lyric": "..."}],
    "male": [{"start_seconds": 3.0, "end_seconds": 3.5, "midi": 57, "lyric": "..."}]
  }
}
```

- `lines` 从 0 秒连续覆盖至计划时长，`female`/`male`/`both` 各至少出现一次，无演唱写 `instrumental`；两条 `melody` 逐字覆盖独唱与 `both` 句，经过音标 `passing: true`，`sample_rate` 提供则严格匹配三 WAV。
- `call_response_final_merge` 下另检首次 `both` 位置、同唱比例、每句 `harmony_mode`/纵向音程及独唱非重叠窗；缺字段的旧版 MCP 计划仅作诊断，禁进母带。
- 校验器拒绝缺声部、重叠/空洞、词音不符、和弦未覆盖、音符超界、时长/采样率不符、指定句静音、非本人窗漏声、伴奏区漏声及同唱极端失衡。**和弦检查仅比对计划声明，不分析伴奏音频**；报告 `qualification_scope` 为 `machine_only`，仍须核对实际伴奏逐小节和弦/低音落点并人耳听审。

## 3. 模型与后端能力边界

- **ACE-Step `duet.*`**：在《越过噪点》18s 样本中实测女声独唱窗无女声且原始轨伴奏泄漏，重绘与分离未恢复；仅可作明确范围诊断，**不作纯歌词自动对唱默认生产路线**。
- **SoulX-Singer `score` 模式**：2026-10-03 19.2s/179.2s 实测音准中位误差约 0.15/0.05 半音，但现句首漏识、吞字、同音替换与跨句合并，标为诊断失败；验证须同存独立干声、音符元数据与计划 LRC 并分报音准与歌词，官方示例声源仅作探针。容器若 `torchaudio`/TorchCodec 与 PyTorch 不匹配，可临时用 `soundfile` 并固定已验证 `transformers` 版本（仅解决可运行，不降验收门）。
- **YuE-2（`m-a-p/YuE2-3B`）**：公开接口仅支持歌词/风格到单曲及 `Vocal`/`Ins` 旋律计划，无逐句歌手 ID、性别/声纹条件或第二条独立歌手轨，`[Female]`/`[Male]` 仅提示词；可作单声部曲风/旋律研究对照，不进纯歌词自动对唱生产路由；权重受 CC BY-NC 4.0 及商业条款约束，部署前须单独核授权。
- **Seed-VC 本地原型**：须从原型工作目录启动或显式传一致 HF 缓存路径（解析 `./checkpoints/hf_cache`），确认声码器权重从本地缓存加载并完成采样；44 kHz F0 条件只改声线与保旋律，不修源轨错词、跑调或缺失演唱窗。
- **整歌无逐句控制模型**：先做一男一女两短句歌词保真探针，失败即停拼接路线；音频条件重编/cover 会改声部歌词旋律，未逐句人耳审过不作可用对唱。代码、权重、输出与歌唱参考授权须分别核对。

## 4. 风格、短样路由与 `mix.master` 多轨契约

- **风格描述**：写具体节奏语法、合成器/乐队音色、和声张力、转场、主副歌钩子与年代感（如先锋日系二次元写清速度、切分、音色突变与交接），不堆泛词。
- **短样核查**：先核两条干声目标句唱全、独唱有声、非本人静音、无伴奏泄漏与错词；角色遮罩、ASR 或低基频不代替人耳确认男女身份；短样未通过和声/歌词/自然度试听不扩整曲。
- **本地 `mix.master` 多轨参数**：`vocal_mode=duet` 加 1 条 `additional_vocal_asset_ids`，`vocal_mode=choir` 加 2–7 条（主唱仍用 `vocal_asset_id`），可用同位 `additional_vocal_gains_db`（默认 `-3 dB`）；可选 `backing_vocal_asset_id` 为经审核和声，不等于第二位歌手。调用前须检查实际部署签名，旧版不支持时不虚构参数。
