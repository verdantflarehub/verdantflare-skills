# VerdantFlare Music：公共工作流与预检

## 1. 当前依据

- [技能入口](../SKILL.md)：能力清单与 GPU 调度规则。
- [公共规范](00.common.rules.md)：输入契约、产物命名与 K09 内容分级。
- [公共验收与审核门](00.common.acceptance.md)：五大审核门与脚本验收指标。

## 2. 最小入口信息

写企划、歌词与本地检查可立即开始，不依赖远端预检；进入远端调用前在 `制作审核记录.md` 明确四项最小入口信息（已确认项不重复询问）：

- 本次目标阶段、新项目或待续项目（续作读取已有决定与 Artifact ID）。
- 人声来源：原始生成、已批准模型实际 ID（显示名不能代替 ID）或获授权录音。
- 已批准候选/重做数量、时长或预算，及必须保留的内容（原创默认最大生成时长 200 秒、默认候选 2 个）。
- 录音、既有歌曲、模型与艺术决定授权范围（局部重绘另确认区间外保持内容）。

## 3. 技术能力预检与旧版兼容

远端暴露 `workflow.preflight` 时，在首次付费或长任务前调用一次，进入下一昂贵阶段仅复核可能变化的条件：

| 任务目标       | `workflow` 与附加要求                                                                          |
| :------------- | :--------------------------------------------------------------------------------------------- |
| 仅生成候选     | `generate`：Music3 就绪，无需指定人声来源                                                      |
| 纯歌词对唱实验 | `duet_generate`：仅检 ACE-Step 可调；已有失败样本，`ready` 不授权标合格对唱                    |
| 原创完整歌曲   | `full_song`：必选 `voice_source`（`generated_voice`/`approved_model`/`authorized_recordings`） |
| 既有歌曲翻唱   | `cover`：必选 `voice_source`，禁止 `generated_voice`                                           |
| 人声训练       | `voice_training`：`voice_source=authorized_recordings`，RVC 就绪且授权见审核记录               |
| 局部重绘       | `redraw`：`require_local_redraw=true`，ACE-Step 1.5 `repaint` 就绪且许可已确认                 |

`voice_source` 取值规则：`generated_voice`（Music3 原始人声，仅原创不用于翻唱）、`approved_model`（必传实际 `voice_model_id` 并校验已安装，严禁在之外传 `voice_model_id` 或用显示名猜测）、`authorized_recordings`（先验训练链路，训完改 `approved_model` 复检转换）。

- **旧版 Music MCP 兼容**：先读实际工具清单；缺少 `workflow.preflight` 记为“旧版无此工具”，不写成故障也不伪称通过。按已批准范围推进旧版支持阶段（`music.generate` / `voice.convert`），失败时保存任务/错误与恢复入口，不重复收费；旧版无 `music.redraw` 或真实条件编辑后端时不得以整曲重生成冒充局部重绘。
- **GPU 冷启动与租约对账**：Music3 返回 `scaled_to_zero` 或 `waiting_gpu_lease` 且带 `wake_on_task` 时预检不启 GPU，直接调 `music.generate` 等待自动排队唤醒。冷启动失败时区分租约续期、真实进程绑定与模型就绪（心跳/TTL 延长不等于已绑定），先对账原请求、租约终态与是否进入推理再做有界恢复。
- **预检 `status=blocked`**：停止依赖该条件的收费或不可逆步骤，说明缺项、已完成可审内容、替代路径与恢复入口，继续独立本地工作；修复后只重跑受影响检查。

## 4. 分阶段复核要点

- **候选生成前**：企划已批准、Music3 就绪、候选数与预算有效。
- **分轨前**：选定 Artifact 与项目 ID 一致（分轨属技术检查，不另设用户批准点）。
- **音色转换前**：实际模型 ID 已批准且仍安装；选定候选后先识别需保留的和声/叠唱/空间层并核对分轨与混音接口承载力，不足时先披露预期损失。
- **局部重绘前**：源 Artifact 为 16-bit/24-bit PCM WAV、区间 `<= 60s`、保持范围、ACE-Step 后端、模型许可与重绘次数已确认。
- **对齐与母带前**：转换干声获批、LRC 输入为批准歌词、下游服务就绪。
- **换声细节返工前**：核对实际分轨包是否含可独立试听的和声/氛围轨，以及部署是否支持多轨或可审计预混。
- **对唱/合唱前**：纯歌词自动生成须有经真实音质验收的声源后端与两条全曲对齐独立干声；录音或模型路线核对每位歌手授权来源、独立声轨与 `mix.master` 多轨参数。

## 5. 项目记录、World 读取与恢复

- 开始时从当前 Studio 会话取 `project_id` 并打开最近修订；需已批准人声模型时，先以 `asset_id + asset_version_id` 调 `world.get` 核对 `voice-model.json`、权重、索引与配置都在固定版本授权集合内，写入当前歌曲 Project 的 `asset_refs`（不自动升级 World 或重训）。
- 创作者标识取自人声资产/模型所有者，项目名取自批准歌曲名，无法确定先问用户（禁用 `default`）；同时保存创作者显示名大小写供 MP3 命名。
- 恢复时先读 `制作审核记录.md` 与已有交付物，从最后一个未通过审核点续做；审核记录与交付物冲突时停下指出冲突不猜测；跨机以同一 `project_id` 的已提交修订恢复。
