# 制作前预检

先从用户要求和现有项目记录确认本次范围。企划、歌词与本地检查可立即开始；远端调用前只核对会影响当前阶段的授权、成本和可执行性，已确认的信息不重复询问。

## 最小入口信息

至少明确：

- 本次要完成的阶段、新项目或待续项目；续作读取已有决定和 Artifact ID。
- 当前阶段需要的人声来源：原始生成、已批准模型的实际 ID，或获授权录音；显示名不能代替模型 ID。
- 本次已批准的候选/重做数量、时长或预算，及必须保留的内容；缺省值按工作流约定。
- 录音、既有歌曲、模型与艺术决定的授权范围；局部重绘另确认区间外必须保持的内容。

这些信息写入已有的 `制作审核记录.md`，不为入口卡单独建文件。缺少非关键参数时自行补全；关键条件缺失只暂停依赖它的调用。

## 技术能力预检

远端服务暴露 `workflow.preflight` 时，在当前阶段首次付费或长任务前调用一次；进入下一个昂贵阶段仅复核可能变化的条件。无需在写企划前调用，也无需每次工具调用都重跑。参数按任务选择：

| 目标 | `workflow` | 附加要求 |
| --- | --- | --- |
| 仅生成候选 | `generate` | Music3 就绪；无需指定人声来源 |
| 纯歌词自动对唱实验 | `duet_generate` | 仅检查 ACE-Step 服务可调用；已有真实样本声部失败，`ready` 不授权将 `duet.*` 结果作为合格对唱 |
| 原创完整歌曲 | `full_song` | 必选 `voice_source`，见下表 |
| 既有歌曲重新演绎 | `cover` | 必选 `voice_source`；不能选择 `generated_voice` |
| 人声训练 | `voice_training` | `voice_source=authorized_recordings`，RVC 就绪，录音授权仍由审核记录证明 |
| 局部重绘 | `redraw` | `require_local_redraw=true`，ACE-Step 1.5 `repaint` 后端就绪，模型许可范围已确认 |

完整歌曲的 `voice_source` 在进入远端阶段前明确：

| 选择 | 值 | 预检行为 |
| --- | --- | --- |
| Music3 原始人声 | `generated_voice` | 不要求 RVC 或模型 ID；适用于原创完整歌曲，不适用于翻唱 |
| 已批准人声模型 | `approved_model` | 必须同时传实际 `voice_model_id`，并验证该 ID 已安装 |
| 已授权原始录音 | `authorized_recordings` | 先验证训练链路；训练通过后，用返回的实际模型 ID 改为 `approved_model` 再复检转换阶段 |

不要在 `approved_model` 之外传 `voice_model_id`，也不要用 “Jack” 等显示名猜测 ID。

预检只证明技术条件，不代替版权、人声授权或艺术审核。将结果摘要和必要的模型 ID、阻断项写入项目审核记录。

### 旧版 Music MCP

先读取实际工具清单。若缺少 `workflow.preflight`，记录为“旧版无此工具”，不要把它等同于服务不可用，也不要伪造就绪结果。按已批准范围继续旧版支持的阶段：生成前确认 `music.generate` 可用、输入和候选数量有效；已批准模型在 `voice.convert` 前核对真实 ID 与既有批准，若服务无法只读查询安装状态，则转换失败时只暂停转换及其下游，不重复生成或分轨。实际调用失败时保存任务/错误与恢复入口，避免未知结果下重复收费。

`music.redraw` 是独立能力：旧版没有工具或真实条件编辑后端时不得把整曲重生成称为局部重绘。用户已明确选择旧版服务时沿用该选择，不为升级或部署打断当前可完成的制作。

实际预检返回 `status=blocked` 时：

1. 不启动依赖该条件的收费或不可逆步骤。
2. 说明具体缺项、已完成且可审阅的内容、可选替代路径和恢复入口。
3. 继续不依赖该条件的企划、格式检查或资料整理。
4. 条件修复后只重跑受影响的检查，不重复已通过审核。

## 分阶段复核

进入下一昂贵阶段前只复核可能变化的依赖：

- 候选生成前：企划已批准、Music3 就绪、候选数量与预算仍有效。
- 分轨前：选定 Artifact 与项目 ID 一致；分轨是技术检查，不另设用户批准点。
- 音色转换前：实际模型 ID 已批准且仍安装，不根据显示名推断。
- 局部重绘前：源 Artifact 为 16-bit PCM WAV，区间、保持范围、ACE-Step 后端、模型许可与重绘次数已确认。
- 对齐与母带前：转换干声获批、LRC 输入为批准歌词、下游服务就绪。
- 换声细节返工前：核对实际分轨包是否含可独立试听的和声/氛围轨，以及当前部署是否支持多轨或可审计的预混；旧版双轨 `mix.master` 不因新增湿人声归档而具备这些能力。缺项只阻断依赖它的混音，不重新审核候选和已批准模型。
- 对唱/合唱前：纯歌词自动生成须先有经真实音质验收的声源后端、逐句计划、两条全曲对齐的独立干声和已确认预算；当前 ACE-Step `duet.*` 实测未达到该门槛，即使预检为 `ready` 也不能当作生产能力。若用录音或已批准模型，核对每位歌手的授权来源、独立声轨及实际 `mix.master` 多轨参数。单条混合主唱或待审核和声分离轨不能证明自动多人演唱。

指定音色换声也应在选定候选后识别需要保留的和声、叠唱与空间层，并核对当前分轨/混音接口能否承载；这是制作质量检查，不新增用户审核点。能力不足时先说明预期损失，再让用户决定接受双轨成品、提供独立分轨或等待支持该能力的服务，不默认把候选的丰富层次写成“已保留”。

仅在会产生无效成本或错误资产的边界检查，不要求用户一次填写所有技术细节。
