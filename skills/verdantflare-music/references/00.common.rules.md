# VerdantFlare Music：公共规范

## 1. 当前依据

- [技能入口](../SKILL.md)：能力边界、GPU 调度与入口路由。
- [共同接入规则](https://github.com/verdantflarehub/verdantflare-skills/blob/verdantflare-music-v0.4.1/skills/_shared/project-world.md)：Project、Artifact 与 World 归属规则。
- [World / Music VoiceModel 设计](https://github.com/verdantflarehub/verdantflare-design/blob/cce3dc47f0954bbce9c83ebc9c4a3a1aba81697f/docs/design/world/music/voice-model.md)与[VoiceModel Schema](https://github.com/verdantflarehub/verdantflare-design/blob/cce3dc47f0954bbce9c83ebc9c4a3a1aba81697f/docs/design/contracts/v2/voice-model.schema.json)：人声模型固定版本登记契约。
- [18+ 评估规范（rubric v1.0）](content-rating-rubric.md)：判定类别（S1–S4、V1）、音频与歌词判定标准及输出 JSON 格式。

## 2. 阶段输入与标准交付物契约

| 阶段         | 必需输入                                                                 |
| :----------- | :----------------------------------------------------------------------- |
| S3 资产导入  | 已批准 S3/CDN origin 的 HTTPS 对象 URL、安全音频文件名、SHA-256          |
| 候选生成     | 已批准 `完整词曲企划.md`、`lyrics.txt`、`instructions.txt`、最大生成时长 |
| 分轨         | 已选定的完整歌曲资产                                                     |
| 训练材料准备 | 1–20 个获授权原始人声音频 Artifact                                       |
| 音色训练     | 人工批准的 `voice-training.wav` Artifact、新模型 ID                      |
| 音色转换     | 原始干声、已批准人声模型                                                 |
| 歌词对齐     | 转换后干声、不含时间戳和段落标签的已批准逐行歌词                         |
| 混音母带     | 伴奏、转换后干声、实际对齐 LRC、BPM                                      |

严禁使用伪造企划、歌词、录音或 LRC 代替缺失真实输入，严禁凭文件名推断审核通过。工作副本位于 `.gdrive/output/music/<创作者>/<项目>/`（含 `.vf/project.json` 投影与 `.vf/local.json` 本机状态）：

```text
<music-workspace-root>/<创作者>/
├── voice/{recordings/, prepared/<批次>/, models/<模型ID>/}   # 原件、训练准备、模型包与 voice-model.json
└── <项目>/
    ├── 完整词曲企划.md / lyrics.txt / instructions.txt / 创作预审报告.md
    ├── Demo_Candidate_{1,2}.* / Demo_Redraw_<修订号>.wav / Demo_Selected.*
    ├── instrumental.wav / vocal_dry_original.wav / vocal_dry_cloned.wav
    ├── vocal_wet_original.wav / vocal_reverb_original.wav   # 服务返回时保留；非独立和声
    ├── Aligned_Lyrics.lrc / Final_Song_Master.wav
    ├── <创作者显示名>-<歌曲名>.mp3 / <创作者显示名>-<歌曲名>.lrc
    └── 制作审核记录.md
```

- **单事实源与归属**：`voice-model.json` 作为 Project 的 `domain_documents` 提交，审核后可登记至 World/Music 供多项目固定引用（`asset_id + asset_version_id`）；歌曲候选、分轨、母带默认留来源 Project；旧 `assets.json`、`model.json`、`recordings.json` 仅作历史导入或只读投影，不再编辑。任何情况下不把原始人声、模型或歌曲媒体提交 Git。
- **交付命名**：最终 MP3 与 LRC 必须同基名 `<创作者显示名>-<歌曲名>.mp3/.lrc`（保留批准拼写大小写，不含路径分隔符），不另存 `Final_Song.mp3/.lrc`。
- **制作状态单一记录**：关键用户决定、版本、任务、Artifact ID 与预检摘要统一追加写入 `制作审核记录.md`，不为每次工具调用另建报告；`vocal_wet_original.wav`、`vocal_reverb_original.wav` 与 `backing_vocals_unreviewed.wav` 不得标为“已批准和声”。

## 3. 成品技术规范

- **自然时长**：以批准最大生成时长为上限，保存 Music3 自然结束结果；不得裁切、补静音或反复抽 seed 填满上限；最终 WAV 与解码后 MP3 节目时长一致（允许容器采样级误差）。
- **母带 WAV**：立体声、48 kHz、24-bit PCM。
- **MP3**：立体声、320 kbps。
- **综合响度与 True Peak**：目标 `-14 LUFS`（容差 `±0.5 LU`）；True Peak 不高于 `-1.0 dBTP`（工具分辨率 `0.05 dB` 内偏差可记录后接受）。
- **LRC**：`lyrics.align` 输出 UTF-8 `Aligned_Lyrics.lrc`，毫秒级时间戳严格递增且落在节目时长内，逐行文字与批准歌词完全一致；禁用原曲时间轴或线性缩放 fallback。

## 4. 影视与 MV 交接约束

向影视／MV 交接时固定实际曲目版本、采用区间、节拍与对白避让要求，不按最新候选自动替换已选音乐。改变速度、裁段、编配或人声后，只使对应节拍剪辑、混音和口型依据失效；未变分轨及其已通过证据复用。新合成仍检查接缝、响度与声画关系，歌曲生成成功不等于成片混音已通过。

## 5. 生成后内容分级评估（K09 强制步骤）

每次生成、翻唱、局部重绘、音色转换或母带取得新音频产物后、进入审核门展示、交付摘要或 Project/World 同步前必须执行（多候选逐个评估提交；只读查询或恢复已评估任务不重复评估）：

1. **评估输入**：歌词（`lyrics.txt`）、制作指令与正向提示词（`instructions.txt`）、标题、LRC、企划正向描述（反向排除词不作依据），以及转写/对齐唱词与以性兴奋为目的的非语言声音（计入 S1/S2）。无转写能力或纯器乐/伴奏轨时仅依文本与可识别声音判定，并在 `reasons` 中注明 `"未转写音频"`。
2. **判定与提交**：对照[18+ 评估规范（rubric v1.0）](content-rating-rubric.md)判定（`rubric_version` 取自规范文首 `"rubric v1.0"`；不确定即标 `nsfw`，`reasons` 不引露骨原句），调用 `music.rate_content` 传 `task_id` 或 `content_ref` 与评估 JSON（`general` 与 `nsfw` 均须提交；幂等接口，超时用相同内容重试，严禁重新生成）：

```json
{
  "task_id": "<音乐生成任务ID>",
  "rating": "general",
  "rubric_version": "rubric v1.0",
  "evaluator_model": "<执行评估的模型标识>",
  "reasons": ["未触发类别", "未转写音频"],
  "evaluated_at": "2026-10-24T00:00:00Z"
}
```

3. **脱敏与阻断**：判为 `nsfw` 的产物在摘要与审核记录中只写“N 个产物已标记为 NSFW 并隐藏”，严禁展示试听、下载链接、`ContentRef`、文件路径、歌词或提示词全文，且不写入 `project.commit`、不调用 `world.register`。不提供撤销，误标由用户在 Studio 设置页开启 24 小时开关后人工取消。

## 6. 技能研发优化边界

用户要求研发或优化本技能时，面向跨项目通用契约，不以单首歌曲作默认交付，也不自动运行生成、转换或远端部署。按四层严格核对且不越层推断：技能层（文档步骤不等于工具已实现）、本地服务层（源码存在不等于镜像已发布）、当前部署层（连接可用不等于新参数可用）、音质层（单测/哈希/格式合格不等于好听）。配置示例仅写变量名与非密钥地址，严禁将 `.env` 令牌复制到 `config.toml`、命令行、日志或聊天。
