# 人工审核门禁

所有审核点初始状态为 `待审核`。有效状态为 `待审核`、`已批准`、`需修改` 和 `已否决`。只有用户的明确决定可以把状态改为 `已批准`；工具成功或自动检查通过不得自动批准。

## 审核点 1：词曲企划

呈现歌曲定位、最大生成时长、BPM、调式、结构、歌词、配器和声音方向。检查主题完整性、叙事一致性、押韵、可唱性和段落时长。

可接受决定：批准企划；针对歌词、结构或制作方向提出修改；终止项目。

## 审核点 2：旋律与编曲

同时提供两个可试听候选、编号及各自实际时长，不用文字评价替代试听。检查旋律记忆点、副歌力度、编曲层次、结构完整度和自然结尾；不得因为候选没有填满最大生成时长而判定失败。

可接受决定：选择一个候选；按批注重新生成；返回企划修改；终止项目。

## 审核点 3：人声模型

提供模型 ID 和由该模型真实转换得到的验证音频。检查人物音色辨识度、音域覆盖、咬字、底噪和明显伪影。

可接受决定：批准建库；补充录音并用新模型 ID 重训；改用另一个已批准模型；终止人物音色制作。

## 审核点 4：转换后干声

提供 `vocal_dry_cloned.wav`，必要时附原始干声用于对比。检查音色还原、高低音连续性、音准、咬字、换气和机械电音感。

可接受决定：批准干声；调整转换参数重做；返回音色模型重训。

## 审核点 5：最终母带

提供最终 WAV、MP3、LRC、自动测得的时长、采样格式、码率、LUFS 和 True Peak。试听检查人声与伴奏融合、空间感、动态、齿音、削波、开头结尾以及跨设备播放质感。

可接受决定：终审归档；只重做混音母带或歌词对齐；返回上游明确阶段返工。

## 记录格式

每次决定追加而不是改写历史，至少记录：

```markdown
## 审核点 N：名称

- 时间：ISO 8601
- 状态：待审核 | 已批准 | 需修改 | 已否决
- 审核资产：逻辑名称和资产 ID
- 自动检查：关键指标或“不适用”
- 用户决定：保留用户原始决定
- 批注：返工要求或批准范围
```

“继续”只在对话中唯一待审项目明确时等同于批准当前审核点；存在多个候选、多个项目或多个待审点时，必须先明确目标，不能猜测。
