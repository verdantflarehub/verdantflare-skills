# 制作工作流

## 开始与恢复

先从当前 Studio 会话取得 `project_id` 并打开该 Project 的最近修订。按 `preflight.md` 核对当前阶段的必要条件。原创企划可立即写；首次远端调用前，若 MCP 提供 `workflow.preflight` 则使用，否则按旧版兼容路径执行。已有项目从最后一项未完成且适用的决定继续，不重复已获批或已完成的任务。用户明确选择旧版服务时不转向部署排障。

ProjectManifest 由 Studio 生成并通过 `.vf/project.json` 投影；本 Skill 只维护领域文件、MD 和实际任务输入，不维护第二份通用库存。需要已批准人声模型时，先以 `asset_id + asset_version_id` 调用 `world.get`，检查 `voice-model.json`、权重、索引和配置是否都在该固定版本的授权文件集合内，再将解析的文件引用交给 Music MCP。使用模型只写入当前歌曲 Project 的 `asset_refs`，不会自动升级 World 或重训模型。

## 先选一个一键入口

不要从本文件的完整制作链直接猜用户意图，先按 `SKILL.md` 的一键能力路由选择入口：

- 新歌且没有参考音频：读[一键独立生成](one-click-independent-generation.md)。
- 只需要从音频得到可编辑曲谱：读[一键提取曲谱](one-click-score-extraction.md)。
- 有参考音频、风格和匹配歌词，但不要求锁定旋律：读[一键无曲谱翻唱](one-click-cover.md)。
- 需要锁定参考旋律：读[一键曲谱约束翻唱](one-click-score-constrained-cover.md)；只有需要单独查看曲谱时才直接读[一键提取曲谱](one-click-score-extraction.md)。
- 只替换既有歌曲中的一位歌手：读[一键单歌手换声](one-click-voice-replacement.md)。
- 需要男女声部：读[一键男女对唱](one-click-duet.md)；三人及以上改读[一键多人合唱](one-click-ensemble.md)。

一键入口只定义用户体验和验证边界；实际调用仍须以当前 MCP 工具签名、本地服务和部署状态为准。

## 既有歌曲重新演绎

当用户明确指定一首其有权处理的完整歌曲，并选择已批准的人声模型时，采用重新演绎分支：

1. 客户端将原始音频上传到批准的外部 S3，计算 SHA-256；不得将媒体提交 Git。
2. 调用 `asset.import`，只提供项目 ID、临时可读的 S3 对象 URL、安全文件名和预期 SHA-256。导入完成后只记录 Artifact ID、文件名、大小和 SHA-256，不记录签名 URL。
3. 用户指定该歌曲即明确批准制作范围和源歌曲选择。在审核记录中将审核点 1、2 分别记为“已批准（用户指定既有歌曲）”，保留用户原始决定；不创建伪企划、不调用 `music.generate`、不生成无意义的双候选。
4. 将导入 Artifact 登记为 `Demo_Selected`，从阶段 2 的 `stems.separate` 继续。分轨、已批准模型复用、音色转换、歌词对齐、母带和审核点 3 至 5 继续使用下述标准流程。

若用户未确认有权处理来源歌曲，或既有人声模型未批准，停在导入或转换前，不用其他素材替代。

## 阶段 1：企划与候选

完整制作需要音乐灵感；人声来源可以是 Music3 原始人声、用户有权使用的录音，或已批准的人声模型。仅当指定人物音色时才需要后两者。参考素材与其他约束属于补充内容，不构成新的必需输入。将非关键参数补全为一套内部一致的创作选择，输出：

- `完整词曲企划.md`：主题、叙事、曲式、最大生成时长、BPM、调式、配器、演唱设计、完整歌词和交付目标。
- `lyrics.txt`：使用 Music3 支持的段落标签，只包含送入生成模型的歌词。
- `instructions.txt`：描述风格、速度、调式、配器、声音表现、结构发展和制作质感，不写供应商或内部部署信息。
- `创作预审报告.md`：记录五级专业预审的证据、修改和结论。

三份草案完成后，在内部依次检查：

1. `全局-审核规范.md`：Music3 契约、输入完整性、时长与跨文件一致性。
2. `歌词-审核规范.md`：通用歌词质量。
3. 对应曲风的歌词规范（若已有）：歌词语感与节奏。
4. `编曲-审核规范.md`：通用作曲编曲质量。
5. 对应曲风的编曲规范（若已有）：编曲语汇。

按依赖关系检查适用内容；专属曲风文件缺失时用通用规范补充判断。自行修正可修复问题，只复查受影响的项目与跨文件一致性。`创作预审报告.md` 汇总结论与真正影响决定的风险，不把每一级写成一次用户确认。

审核点 1 通过后按批准数量生成候选，默认两个 `Demo_Candidate_1` 与 `Demo_Candidate_2`。候选使用同一份批准企划和最大生成时长，不在候选之间暗改歌词或制作目标。模型可以在上限前自然结束；下载后测量并分别记录实际时长，不要求两个候选等长。

纯歌词男女对唱先按 [多声部制作](multi-vocal.md) 形成逐句角色计划。现有 `duet.*` 声源后端有真实失败样本，不能直接作为生产默认路径；只有新声源方案产出两条歌词清楚、音质合格、全曲对齐的男女干声并经逐轨试听，才把预混提交候选审核。Music3 单轨、文件数量和静音窗口都不能证明对唱已成立。

候选进入审核点 2 前运行 `scripts/analyze_tail.py`，将实际时长与企划时长预算比较，并检查最后 4 秒到最后 1 秒的能量坍缩和最后 250 毫秒的硬切风险。提前自然结束本身不是失败，但缺段、未完成终止式、尾奏不足或突兀停机属于结构问题，必须在用户选择前警告。

审核点 2 选定一个候选后登记 `Demo_Selected`。若请求完整指定人声歌曲，分轨技术检查通过后直接用已批准模型转换，再提交转换干声供审核点 4 听审；不要为分轨单独停下。要求重新生成时保留此前候选及决定，生成新的候选编号，不覆盖旧资产。

## 阶段 2：分轨与音色

对 `Demo_Selected` 调用 `stems.separate`，预期得到：

- `instrumental.wav`
- `vocal_dry_original.wav`

若服务额外返回 `vocal_wet_original.wav`、`vocal_reverb_original.wav`，也要保存其 Artifact ID。这两轨不是独立和声。指定音色换声时按 [换声保真与返工](vocal-replacement-mix.md) 对照候选层次；发现损失后只返工受影响的分轨或混音。

分轨后核对格式和时长；能试听时检查伴奏漏声与干声残留，不能试听则把该风险带到转换干声审核，不把哈希通过当成音质通过。已知问题只返工分轨。若输入为已批准的人声模型，登记并复用，不重复审核点 3。若输入为原始人声录音，将录音归档到 `<创作者>/voice/recordings/`，按 `voice-preparation.md` 调用 `voice.prepare`。预期得到逐来源 WAV、合并训练 WAV、分段 ZIP 和分析报告；训练材料需经用户审核。批准后才以 `voice-training.wav` Artifact 调用 `voice.train`，预期得到不可覆盖的新模型 ID、模型权重、检索索引和真实转换验证音频，再归档到 `<创作者>/voice/models/<模型ID>/`。训练仍需确认录音授权。

训练材料审核不是新的歌曲编号审核点，也不替代审核点 3。它只控制是否允许训练：用户可以批准当前材料、剔除指定来源后重新准备、补充录音后重新准备，或终止训练。每次重新准备都保留新的 Artifact ID 与报告，不覆盖历史结果。

新训练模型在审核点 3 评价音色，不把歌曲转换质量混入该结论；既有批准模型直接复用。模型可用后调用 `voice.convert` 将 `vocal_dry_original.wav` 转换为 `vocal_dry_cloned.wav`，然后进入审核点 4。选择 Music3 原始人声时不执行分轨、训练和转换。

对唱或合唱时按 [多声部制作](multi-vocal.md) 为每位歌手准备独立且全曲对齐的轨道，分别转换和审核；不能从单条混合主唱推断出多个人声模型。

## 阶段 3：歌词对齐与母带

以 `vocal_dry_cloned.wav` 为音频依据，将已批准歌词去除 Music3 段落标签和空行后，调用 `lyrics.align`，得到 `Aligned_Lyrics.lrc` Artifact。输出必须保持歌词行数和逐行文字完全一致，毫秒级时间戳严格递增且不超过实际人声时长。任一检查失败时阻止错误结果进入母带，自主排查并在已授权范围内修复、复验；不使用原曲 LRC、线性缩放时间轴或手工伪造时间戳。

调用 `mix.master` 时提供：

- `instrumental.wav`
- `vocal_dry_cloned.wav`
- `Aligned_Lyrics.lrc` Artifact 的已校验文本
- 批准的 BPM

按当前 MCP 工具签名传参，响度与 True Peak 是成品检查目标，不虚构调用参数。输出 `Final_Song_Master.wav`、`<创作者显示名>-<歌曲名>.mp3` 和 `<创作者显示名>-<歌曲名>.lrc`。如果工具 Artifact 使用 `Final_Song.mp3` 或 `Final_Song.lrc` 内部文件名，下载到项目交付目录时直接使用最终名称，不保留兼容副本。自动格式检查通过后进入审核点 5；有原候选可对照时，重点比较和声、叠唱、空间尾音、编曲瞬态与段落层次。人工终审通过后归档。

## 返工路由

- 企划、歌词或制作方向问题：返回阶段 1，修复并复查受影响的预审项；若改变已批准创作方向或歌词，重新经过审核点 1。
- 旋律或编曲问题：保留企划，从候选生成重做并重新经过审核点 2。
- 有界区间问题且预检确认局部重绘可用：按 `local-redraw.md` 调用 `music.redraw`，保留源资产，以新修订号进入审核点 2；若能力不可用，在付费前说明只能切换候选或整曲重生成。
- 分轨污染：只重做 `stems.separate`。
- 训练材料含空白、噪声、伴奏、错唱或音域覆盖不足：调整来源集合或补充授权录音，重新执行 `voice.prepare` 并再次完成人工材料审核；不得用 AI 修音改变训练事实。
- 人物音色不像或已批准材料仍不足：补充授权录音，重新准备后用新模型 ID 重训并重新经过审核点 3。
- 原始干声清楚、转换后出现音高、咬字或机械感问题：调整转换参数，只重做 `voice.convert` 并重新经过审核点 4。
- 原始干声已有快句吞字或不可辨识歌词：返回审核点 2 修改歌词密度或重新生成候选，不能靠 RVC 或母带修复。
- 字幕时间问题：只重做 `lyrics.align`；单纯响度、峰值或编码问题只重做 `mix.master`。人声融合或候选和声、编曲层流失时按 [换声保真与返工](vocal-replacement-mix.md) 定位，不把重复双轨混音当作修复。返工成品均重新经过审核点 5。

不得为了方便返工而重复已经批准且与问题无关的昂贵阶段。

## 项目记录与恢复


本地可沿用工作区的 `.output/music/<创作者>/<项目>/` 目录，但它只是 Project 工作副本，不是服务端事实源。项目目录应包含 `.vf/project.json` 和 `.vf/local.json`；前者是当前服务修订的清单投影，后者只保存本机连接与下载状态。创作者标识取自人声资产或模型的所有者信息，项目名称取自批准企划的歌曲名；标识无法可靠确定时先要求用户确认，不使用 `default` 或根据文件名猜测。同时记录用户批准的创作者显示名，保留其大小写，专用于最终 MP3 文件名。不要把输出写回输入目录，不要覆盖既有资产、项目或已经批准的交付物。

在项目目录维护 `制作审核记录.md`（或既有入口 MD）和领域 `voice-model.json`（仅在模型项目需要时）。审核记录追加阶段、关键用户决定、候选实际时长与风险、任务/资产 ID、返工原因及最终结论；通用文件和 Artifact 引用由 ProjectManifest 保存，不再新增或编辑 `assets.json`。只记录必要标识，不记录凭据、签名 URL 或内部存储地址；保存到服务端须通过 `project.commit`。

恢复已有项目时先读取审核记录和现有交付物，从最后一个未通过的审核点继续。不得重复已经成功且获批的训练、生成或转换任务。审核记录与实际交付物冲突时停止并指出冲突，不猜测状态；换电脑时从同一 `project_id` 的已提交修订恢复，不依赖旧机器的隐藏目录或缓存。


## 创作默认值

最大生成时长默认 200 秒，不能当作精确成品时长保证；保持自然结尾，不裁切或补静音来伪装达标。候选默认两个，遵循已批准的候选数量和预算；只请求企划、歌词或单阶段修复时无需运行完整歌曲链路。
