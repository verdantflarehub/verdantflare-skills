# 男女对唱与多人合唱

当用户要求对唱或合唱时，先明确每位歌手的身份、已获批准的人声来源、负责的歌词段落，以及共同演唱的区间。性别和声部属于创作要求，不由 `vocal_mode` 自动推断；不要把同一条干声复制成多人冒充对唱。

默认的男女流行对唱模板是“接力后合流”，详见[《水晶》参考拆解](duet-reference-water-crystal.md)。除非用户明确要求全程同唱或交错重叠，主歌、预副歌和前两轮副歌都应由单一声部完成；`both` 只在已写明的终段同唱、尾句和声或齐唱 Hook 中使用。

## 纯歌词输入的双歌手计划

用户只提供歌词时，可由创作阶段将每句编入 `female`、`male`、`both` 或 `instrumental`，并检查双方各有独唱句及共同演唱句。采用默认接力模板时，计划还要声明 `duet_template="call_response_final_merge"`，将首次 `both` 推迟到最后副歌或终段合流，并将同唱占有歌词时长限制在 18% 以内。角色划分、每句小节数、BPM 和现代曲风描述写成一份可审阅计划。进入付费生成前检查实际部署的工具与后端；`workflow.preflight(workflow="duet_generate")` 的 `ready` 只证明服务可调用，不证明歌词落点、歌手音色或干声隔离合格。

### 自然演唱源的逐句换声编排

2026-10-04《越过噪点》的自然演唱源 v7 已获用户认可。只替换男声的 Mengsk v18 经用户听审反馈“可以了，音质还需要再完善”；这确认当前版本的对唱与换声方向可用，**不等于音质无损或最终母带批准**。该路线适用于源歌曲已经把全部问答歌词唱对、旋律和编曲自然，且每句角色可从时间轴明确划分的情况：分离源演唱干声，以同一条时间轴转换其中一位歌手的音色，按逐句职责保留原声或转换声；终段同唱须从另一遍歌词和旋律相符的真实演唱句取第二声部并对齐。源演唱承担咬字、音准与表情，换声只改变音色，不能补出未唱的歌词或创造第二套独立表演。逐轨保存来源、转换模型、句子时间窗和实际试听结论。这个已有合格源演唱的分支不能证明纯歌词直接生成两位独立歌手已可用。

逐句替换前先核对干声、伴奏和原混音的每段能量。分轨模型可能把编曲或空间尾音放进人声轨，使伴奏在个别句尾接近静音；此时直接用“分离伴奏 + 新声线”替代原混音会让音乐骤降，即使双轨窗口校验通过也不合格。未换声的句子可保留自然源混音；换声句须检查分离损失、转换空洞、原声泄漏和相邻句交接，再决定是否能替换。不能用硬门控、整句增益或旧湿人声叠回去掩盖源轨缺损。

若一版分离伴奏在目标句失去乐器或立体声细节，可用另一种分离器制作全曲对齐的伴奏，并先对照原伴奏的频带、侧声道和旧歌手泄漏。**只有**获认可版的伴奏可由原分离伴奏乘以逐时增益重建时，才调用 `scripts/prepare_duet_replacement_backing.py`：传入原分离伴奏、获认可版的伴奏和新分离伴奏；脚本检查重建误差，再在有音乐且两版高度相关的时段估计新分离器的全局比例，输出带有原版电平自动化的新伴奏。校准区间可选，但不能拿人声残差作校准或凭响度相近推断乐器完整。重建或相关性检查失败时，回到原工程分轨或重新分离；生成成功后仍逐句听新伴奏有无旧声和空间损失。示例：

```bash
python3 verdantflare-skills/skills/verdantflare-music/scripts/prepare_duet_replacement_backing.py \
  --source-backing <原分离伴奏.wav> \
  --approved-backing <获认可版伴奏.wav> \
  --replacement-backing <新分离伴奏.wav> \
  --output <校准后伴奏.wav> --report <校准报告.json>
```

用 `scripts/audit_performance_voice_source.py --plan <plan.json> --source <source.wav> --backing <instrumental.wav> --dry <separated_dry.wav> --candidate <converted.wav> --role male --report <audit.json>` 对拟替换声部做覆盖审计；替换女声时将 `--role` 改为 `female`。脚本以原混音与伴奏的残差作为逐句参照，报告干声和候选换声的持续能量缺口；`coverage_passed=false` 时回到声源或转换环节，不能靠混音电平补救。两轨长度差在 30 毫秒内可按尾部补零检查，超出则先解决对齐。残差只有在原混音与伴奏确实同轴、且单独试听确认没有明显乐器污染时才能作为新的转换输入；不能把未转换的残差直接混回去，因为会带回原歌手。审计只检查覆盖，近音错词、声纹、音准与自然度仍须分别听审。旧 RVC 实例在 37–39 秒及 88–89 秒有覆盖缺口；新的残差源候选通过该机器检查，但指定音色成品仍待用户听审。

已有合格对唱基线且只替换一位歌手时，使用 `scripts/replace_performance_duet_voice.py --plan <plan.json> --baseline <approved-preview.wav> --backing <aligned-backing.wav> --other-voice <untouched-singer-track.wav> --converted <new-full-timeline-vocal.wav> --role male --output-prefix <new-version>` 生成新试听和角色窗口诊断轨。`--other-voice` 必须是另一位歌手全曲对齐的实际轨，特别要覆盖 `both` 句；目标歌手在非本人句自动静音，已有另一声部与其独唱段保持基线。输出后仍要以**上一版获认可的试听**作为 `--source` 运行 `validate_performance_duet.py`，并等响度对照基线听完整歌曲；候选自身不能充当电平参照。人声包络匹配时，若原声在接唱处近乎静音而转换轨明显有声，应平滑压住转换轨的提前冒声；仅两边都很安静时保持原增益。不能用整句压低来掩盖这一局部问题，以免损伤后续歌词。

自然源编排可能在独唱句保留原立体声混音，导出的 `Female`、`Male` 只是角色窗口轨，并非一定可相加的纯净干声。另传 `--backing` 检查 `stems_reconstruct_preview`；要把轨道送入需要独立分轨的重混服务时加 `--require-reconstructible`，使重建失败返回非零。该值为 `false` 时，不将三轨送入 `mix.master`，也不以轨道文件名宣称已获得可重混双轨。2026-10-04 的已认可 v7 试听对此项实测残差为 `-7.93 dB`，Mengsk v18 为 `-10.03 dB`；这不否定两版的对唱听感，但它们都不具备无损重建的分轨资格。即使相加误差很小，仍要单独检查原声泄漏和乐器污染，不能只凭重建通过宣称干声独立。

电平验收覆盖整首歌，使用约 100–200 毫秒窗口比较原候选与预混的响度、关键频带、每次交接和句尾，并单独查看异常处的干声、伴奏与原混音。修正短时波动时优先做受限、平滑的全曲电平自动化和等响度 A/B；单独抬高一个半秒窗口可能让随后几秒主观上变小。机器扫描只能定位，不替代从头到尾的人工听审；技术通过后仍应保留“待听审”状态，不能以某段 RMS 匹配宣称整曲已完成。

以 `duet-performance-v1` JSON 保存源歌曲时长与逐句时间轴，调用 `scripts/validate_performance_duet.py --plan <plan.json> --female <female.wav> --male <male.wav> --backing <backing.wav> --preview <mix.wav> --source <prior-approved-mix.wav> --report <validation.json>`。脚本检查角色轨的独唱静音、同唱平衡、整曲短时电平偏差、交接、峰值及三轨重建误差；`qualified` 只覆盖角色窗口和电平，`stems_reconstruct_preview` 另报三轨能否复现试听，两者都不能判断错词、音准、声纹、转换伪影和曲风。2026-10-04 用 v7 作参照时，Mengsk v15 在 `2.92` 秒出现额外交接跳变；v17 在 `26.3` 秒出现约 100 毫秒的转换人声凸起。只修正这些局部问题后，v18 的角色、电平、交接和持续覆盖机器检查通过，并获用户认可为可用试听，音质仍需优化。这里不凭空为自然演唱源填写音符或和弦来凑 `duet-score-v1`。
运行这些音频脚本的 Python 环境需已有 `numpy`、`scipy`、`soundfile`；全频掩膜脚本还需 `librosa`。先用同一解释器检查导入，缺失时在项目音频环境中运行，不把依赖错误写成歌曲通过或失败。

### 原混音局部换声：已有完整男女对唱

2026-10-04 `videoplayback` 的 Mengsk 男声 v2 获用户试听认可为可用。输入 MP4 实际只有 AAC 音频流；先探测流类型、声道、采样率与时长，再解码为同轴 WAV，不凭扩展名推断有视频。该路线需要原曲已唱全、男女职责可辨，以及获授权的目标音色参考。单曲试听认可不等于其他歌曲也可用，更不等于音质无损。

1. 从原混音提取人声，建立目标歌手逐句时间轴，记录独唱/同唱、歌词和置信度。自动转写、声纹聚类只辅助定位，低置信同唱句需人工核对；另一位歌手的独唱不能进入换声源。
2. 独唱句直接取目标人声；同唱句先得到两人的低采样率估计，再调用 `scripts/lift_duet_singer_mask.py`，把互补时频掩膜应用到原采样率的人声片段，得到两条全频轨。先用已知两位独唱的合成叠唱测试分离器，再单独试听两轨的身份、串音和字音缺失。两轨能重建原人声只证明掩膜互补，不证明分对歌手；高频掩膜外推仍可能串音。
3. 将目标片段放回原采样率、原样本位置的整曲时间轴，以已批准音色做 F0 条件换声。逐句核对转换长度、覆盖、歌词、声纹和音准。通用 pYIN 的八度跳变须用歌唱音高提取器复核，不能单凭一次检测就降八度。
4. 用 `scripts/replace_singer_in_mix.py` 在目标句以短淡化执行 `original_mix - isolated_original_singer + converted_singer`。浮点混音的非目标区与原曲逐样本相同，导出 PCM24 时仅有量化误差；另一歌手、乐器与空间感因此优先保留。同唱分离若误含另一位歌手，减法仍会误伤，必须回到分离环节。可逐句限定补偿增益；湿声轨只接受已检查没有原歌手泄漏的换声效果。
5. 对照原曲等响度听完整首歌，重点查低置信同唱、每次接唱、漏字、原声泄漏、换声伪影、音准和短时电平。机器报告用于找异常，用户听审确认自然度与音乐性。保留原曲、分轨、换声、报告和试听，不覆盖已认可版本。

同唱区间的两个估计须为同采样率的单声道音频，并与输入人声的指定区间对齐：

```bash
python3 verdantflare-skills/skills/verdantflare-music/scripts/lift_duet_singer_mask.py \
  --source-vocals <整曲人声.wav> --target-estimate <目标低采样率.wav> \
  --other-estimate <另一歌手低采样率.wav> --start-seconds <起点> --end-seconds <终点> \
  --target-out <目标全频片段.wav> --other-out <另一歌手全频片段.wav> \
  --report <分离报告.json>
```

局部换声计划包含 `duration_seconds` 和 `male_phrases` 或 `female_phrases`；每句含秒单位的 `start`、`end`，建议另存 `source`（`solo` / `separated`）、`confidence` 和人工听审备注。可选 `max_gain` 限制该句的补偿，默认 `1.0`，允许 `1.0` 至 `1.5`。原混音、目标原声和换声轨须同采样率、同帧数：

```bash
python3 verdantflare-skills/skills/verdantflare-music/scripts/replace_singer_in_mix.py \
  --plan <逐句计划.json> --role male --source-mix <原混音.wav> \
  --target-singer <全曲同轴原男声.wav> --converted <全曲同轴换声.wav> \
  --output <新试听.wav> --report <换声报告.json>
```

可选 `--wet <全曲同轴换声空间轨.wav> --wet-gain <比例>`；不要将原歌手湿声混回。脚本不负责分人声模型、换声模型或听审，也不能从单人歌曲凭空创造第二位独立演唱者。

### 机器校验契约

把短样或整曲计划保存为 `duet-score-v1` JSON，并在任何预混前运行：

```bash
python3 verdantflare-skills/skills/verdantflare-music/scripts/validate_duet.py \
  --plan <plan.json> \
  --female <female.wav> \
  --male <male.wav> \
  --instrumental <instrumental.wav> \
  --report <validation.json>
```

计划至少包含以下字段：

```json
{
  "schema_version": "duet-score-v1",
  "duet_template": "call_response_final_merge",
  "both_policy": {
    "max_voiced_ratio": 0.18,
    "first_both_min_ratio": 0.65,
    "allowed_modes": ["unison", "third", "sixth", "lead_with_tail_harmony"]
  },
  "duration_seconds": 18.0,
  "sample_rate": 48000,
  "lines": [
    {"start_seconds": 0.0, "end_seconds": 3.0, "voice": "female", "text": "..."},
    {"start_seconds": 3.0, "end_seconds": 6.0, "voice": "male", "text": "..."},
    {"start_seconds": 6.0, "end_seconds": 12.0, "voice": "instrumental", "text": ""},
    {"start_seconds": 12.0, "end_seconds": 15.0, "voice": "both", "harmony_mode": "third", "text": "..."},
    {"start_seconds": 15.0, "end_seconds": 18.0, "voice": "instrumental", "text": ""}
  ],
  "chords": [{"start_seconds": 0.0, "end_seconds": 18.0, "root": "A", "quality": "min"}],
  "melody": {
    "female": [{"start_seconds": 0.0, "end_seconds": 0.5, "midi": 69, "lyric": "..."}],
    "male": [{"start_seconds": 3.0, "end_seconds": 3.5, "midi": 57, "lyric": "..."}]
  }
}
```

`lines` 必须从 0 秒连续覆盖到计划时长，女声、男声和 `both` 各至少出现一次；没有演唱的区间显式写成 `instrumental`。两条 `melody` 都要逐字覆盖自己的独唱句和 `both` 句，音符按时间排序并落在计划内；经过音必须标记 `passing: true`，不能用缺失和弦表或固定音阶代替伴奏核对。`sample_rate` 可省略，但提供后会严格匹配三个 WAV。

当 `duet_template` 为 `call_response_final_merge` 时，还必须检查首次 `both` 的位置、同唱覆盖比例、每个同唱句的 `harmony_mode` 或纵向音程，以及独唱句的非重叠窗口。没有这些字段的旧版 MCP 计划只能作为诊断输入，不能进入最终母带。

校验器会拒绝缺少声部、计划重叠或空洞、歌词与音符不一致、和弦未覆盖、音符超界、轨道时长/采样率不一致、指定句静音、非本人窗口漏声、伴奏区间漏声和同唱段极端失衡。和弦检查仅比较计划中声明的和弦与音符，**不会分析伴奏音频**；凭空填写一个和弦即使通过机器检查，也不能证明人声与伴奏合调。报告中的 `qualification_scope` 固定为 `machine_only`；`qualified: true` 仍不代表歌词、音准、自然度、歌手身份或现代曲风已经通过，必须继续人工听审并记录结果。

## 实验性本地双轨路线（OpenUtau）

2026-10-03 在《越过噪点》179.2 秒实验中只验证了双轨文件和角色时间窗，**没有验证出合格歌曲**。用户听审明确否决完整混音，指出其远逊于单人歌曲。女声使用 `Qixuan_v2.7.0_DiffSinger_OpenUtau`，男声使用 `LongWei_Symphonia_zh` WORLDLINE-R 声库；两条歌声在同一个 `.ustx` 中保持独立轨道，女声使用中文歌词，男声使用逐字普通话拼音。`both` 句必须写入两条不同音符线，不能复制干声或只改声像。

运行前检查：

1. LongWei 目录必须有完整 `oto.ini`、5 个 subbank 和约 4161 个 OTO；只有空根目录的残缺包不能使用。
2. Qixuan 的 `pc_nsf_hifigan_44.1k_hop512_128bin_2025.02` 声码器目录和 OpenUtau 的 Worldline 原生库必须存在；模型输入签名要能由当前 OpenUtau 核心加载。
3. General Phonemizer 的字典是异步加载的。创建男声音符前等待字典加载完成并用普通拼音探针确认 VCCV 音素；`?t y i N` 之类强制别名只可诊断，不能作为最终歌词。
4. 无头 `WaveMix.Mix` 循环每次调用前必须清零输出缓冲区；否则无声窗会复用上一个块，伪造重叠和尾音。

渲染后固定执行：

- 分别输出女声、男声和预混干声；记录有效音素数、OTO 命中、render phrase 数和真实 WAV 时长。
- 先调整音符、发音和交接间隙，让辅音与尾音自然结束；只在确认不会截断字词后使用短淡入淡出处理越界噪声，并将两轨补齐到同一计划时长。不能用硬门控掩盖编排或时序错误。
- `validate_duet.py` 必须能读取 PCM 整数和 IEEE float WAV；机器通过后才加入伴奏。验证器的 `qualified` 仍只代表结构、时长、能量窗和谱面契约，完整歌曲仍需人耳听审。

失败诊断资产为 `.output/music/VF-对唱/越过噪点/VF-对唱-越过噪点-OpenUtauFull-Final.wav` 及同目录的两条 gated 干声、伴奏、`duet-score-v1` 计划和计划时间轴 LRC。文件名中的 `Final` 是历史命名，不表示获批母带。该计划将每句汉字等分为近乎相同的音长，按固定音阶循环取音，并用单个 `Am11` 标签覆盖整首歌；没有核对实际伴奏的逐段和声，也没有设计可唱的乐句或副歌 Hook。旧校验器还把 F 错算成 Am11 的和弦音，导致计划错误地通过机器检查。修正后保留旧报告作为历史记录，新的失败复核另存。下一次只能从真实伴奏和声、可唱旋律与字级节奏出发做 12–20 秒试听样本；用户认可前不得再次扩成完整歌曲。模型、声库和输出许可仍分别核对。

风格描述写具体的节奏语法、合成器或乐队音色、和声张力、段落转场、主副歌钩子及制作年代感。用户要求先锋日系二次元时，要明确当代动画音乐的速度、切分、音色突变与人声交接设计，并在试听时对照这些要素；不要仅用“日系”“燃”或“现代”几个泛词，也不要把模型服从提示词视为已达到曲风。

现有 ACE-Step `duet.*` 路径已在《越过噪点》18 秒样本中实测失败：女声独唱窗口没有女声，原始轨还出现伴奏泄漏；重绘与分离未恢复缺失的人声。该后端当前只可用于有明确实验范围的诊断，不作为纯歌词自动对唱的默认生产路线。保留旧计划、任务与诊断 Artifact，不重复提交收费任务。另行评估的歌声合成或转换后端须先产出可单独试听的两条干声，再接入 MCP。

工作区若有纯歌词对唱技术路线草案，可作为研究资料参考；安装后的技能不依赖该文件。检验顺序是歌词与真实旋律对齐、各自歌声干声的咬字和音质、逐句静音与同唱、最后才是预混和现代曲风。把同一条失真人声复制并换两种音色，只能验证声纹与结构，不能证明有合格的两位演唱者或独立和声。任何一项未过都保持未通过候选；不要回退 Music3 单轨冒充对唱。

### 模型能力不足时的短样路由

先制作包含女声独唱、男声独唱和两人同唱的短样，各保存干声、伴奏与预混。每位歌手须有不同且获授权的实际歌唱声源；仅将同一声源降八度或调 formant，不能证明音色成为另一位歌手。歌词加音符合成要给出可编辑的旋律、字级时值、句中休止及句尾长音，同唱段分别编写两条音符线；等长字音和无休止的机械乐谱只适合链路探针。

先检查两条干声的目标句是否唱全、独唱窗口是否有声、非本人的窗口是否静音，以及是否有伴奏泄漏、错词或多余句。可用自动转写、时长、音高、相关性和峰值发现失败；声区不同不等于音色自然，转写基本正确也不等于好听。人工听审分别比较原始干声、后处理干声和预混的咬字、伪影、男女可辨性与同唱层次，失败时回到声源或乐谱，不用混音遮盖。

乐谱还须与**实际伴奏**核对：记录可编辑的逐小节和弦/低音落点、两条逐字旋律和同唱区间的纵向音程，再试听长音、强拍与非和弦音的进入和解决。只写 BPM、调性名称或凭空套用固定音阶轮廓，不构成伴奏与歌声同调的证据；干声音高贴近指定 MIDI 音符，也不能证明这些音符适合伴奏。短样未通过和声、歌词及自然度试听时，不扩展成整曲。

MCP 的角色遮罩只验证时间窗和能量，不能证明生成轨是目标性别或目标声纹；`both` 会有意让两轨重叠，只有用户明确需要同唱时才保留。若用户要求逐句接唱，必须把 `both` 改成单一角色并在预混前检查另一轨的 RMS 接近静音。男声/女声身份须用人耳和独立参考 A/B 确认，不能用“male/female”请求字段、较低基频或轨道名代替。

即使参考歌声由本项目生成，歌声合成仍可能吞掉句尾字或把快句唱成近音词。短样的每条独唱和同唱段须逐字核对，自动转写只作筛查；若漏字、错词或人耳听出明显合成缺陷，就标记为失败诊断，不因参考声源可追溯、静音窗口正确或两人音高不同而扩展成整曲。先修正字级时值、休止、旋律和声源；同一模型连续失败时停止微调混音，重新评估声源技术路线。

SoulX-Singer 的 `score` 模式可以把手写音符锁在目标音高，但这不等于歌词和音色通过。2026-10-03 的 19.2 秒与 179.2 秒实测中，女/男音符中位音准误差约 0.15/0.05 半音，仍出现句首漏识、吞字、同音替换和跨句合并；两轨应标为诊断失败。使用该模型验证时必须同时保存独立干声、音符元数据和计划 LRC，并分别报告音准与歌词结果。官方示例声源只能做技术探针，未核对录音与输出授权前不得作为项目歌手。

容器兼容性也要单独验证：若 `torchaudio`/TorchCodec 与当前 PyTorch 版本不匹配，SoulX 原型的音频加载可临时改用 `soundfile`，并固定已验证的 `transformers` 版本；先在日志中确认模型加载和实际采样，再判断推理结果。这个兼容性修复只解决“能否运行”，不改变歌声自然度、歌词或音准验收门。

整歌模型若没有逐句歌手控制，逐行标签只是提示词，短句分开生成也可能漏唱或编造歌词；先用一男一女两个短句做歌词保真探针，失败即停止该拼接路线。音频条件重编或 cover 可以作为已形成双轨结构后的质量实验，但会改写声部、歌词和旋律；在对照短样逐句检查并经人耳听审前，不把重编结果视为可用对唱。模型代码许可、权重许可、输出许可和歌唱参考素材授权分别核对，任何一项不允许目标用途时不接入生产服务。

## 已有人声或指定音色

每位歌手需要一条独立、覆盖整曲时间轴的干声或转换人声轨；不演唱的区间保持静音，重叠演唱的区间保持真实对齐。若只有单条混合歌曲而没有可靠的分人声来源，先说明不能保证自动分出不同歌手，再选择取得原工程分轨、提供获授权录音或使用实际具备分人声能力的后端。已批准模型按歌手分别复用，不重复训练。

当前本地 `mix.master` 扩展使用 `vocal_mode=duet` 加 1 条 `additional_vocal_asset_ids`，或 `vocal_mode=choir` 加 2 至 7 条；首条主唱仍使用 `vocal_asset_id`。各追加轨可用同位置的 `additional_vocal_gains_db` 调整音量，默认 -3 dB。可选 `backing_vocal_asset_id` 是另一路经审核的和声，不等于第二位歌手。实际调用前检查部署工具签名；旧版不支持时不要虚构参数或重复生成混音。

### YuE-2 路由边界

YuE-2（`m-a-p/YuE2-3B`）的公开接口只支持歌词/风格到单首歌曲，以及可编辑的 `Vocal` 与 `Ins` 旋律计划。它没有逐句歌手 ID、性别或声纹条件、独立 vocal stem 或第二条歌手轨导出；`female vocal`、`male vocal` 和 `[Female]`/`[Male]` 只是提示文本。不要把 YuE-2 的整曲质量、可编辑 ABC 或 `Vocal`/`Ins` 两声部误认为男女对唱能力。它可以作为单声部曲风/旋律研究对照，但不进入纯歌词自动对唱生产路由，除非外部流程已先提供两条独立歌声并完成逐句人工听审。YuE-2 权重另受 CC BY-NC 4.0 及商业许可条款约束，部署前必须单独核对目标主体的授权。

### 推荐生产架构：三段式双轨

将任务拆为“伴奏/旋律 → 女声干声与男声干声 → 混音母带”。伴奏模型只负责当代曲风、节奏、和声和结构；歌声合成使用逐字音素、音符、时值、休止、力度和气口，分别用两套获授权声库渲染完整时间轴。优先评估 OpenVPI DiffSinger、Fish Diffusion 或 NNSVS 类音符驱动路线；OpenVPI DiffSinger 的 pitch、energy、breathiness 控制有利于把音准和表现力单独验收，但声库本身的许可证必须另查。代码、声库和输出许可分别记录。副歌的两条音符线要有明确和声关系，不能复制同一条干声再降八度。

没有合格声库时，改用两位获授权演唱者的同步干声；`voice.convert` 只可对已经唱对歌词和旋律的干声做音色统一。RVC/SVC、UVR5 和混音不能凭空制造第二位歌手，也不能修复源录音的错词和跑调。`mix.master(vocal_mode="duet")` 只在两条干声分别通过听审和结构校验后调用。

默认技术探针固定为 12–20 秒：女声独唱、男声独唱、两人同唱，并额外做无重叠接唱对照。逐字歌词、自然度、音准、男女可辨、独唱静音窗、伴奏泄漏、同唱平衡全部通过后，才扩展到整曲；角色遮罩、自动转写或低基频只能筛查，不能替代人耳验收。

使用本地 Seed-VC 原型时，必须从原型工作目录启动推理，或显式传入与脚本一致的 Hugging Face 缓存路径；该脚本按当前工作目录解析 `./checkpoints/hf_cache`。启动后要看到声码器权重从本地缓存加载并完成采样，不能把卡在权重下载的进程当作模型失败或成功。Seed-VC 的 44 kHz F0 条件只改变声线与保留旋律，不修复源轨错词、跑调或缺失的演唱窗口。

先单独审核每位歌手的模型音色、咬字与音区，再听交替段、同时演唱段、声部平衡、伴奏避让与尾音。系统会检查轨数、音量范围和各轨时长，不能替代错词、原唱泄漏、音高与相位的人工听审。歌词时间轴必须对应实际合唱/对唱内容；当前单人 `lyrics.align` 不会自动对齐多人的重叠歌词，必要时使用已批准的真实多声部时间轴，不伪造或线性缩放 LRC。试听通过后才做最终母带与审核点 5。
