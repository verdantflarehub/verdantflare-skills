# VerdantFlare Speech：公共规范

## 1. 当前依据

- [技能入口](../SKILL.md)：能力边界、Studio MCP 工具清单与入口路由。
- [18+ 评估规范（rubric v1.0）](content-rating-rubric.md)：判定类别（S1–S4、V1）、音频与文本判定标准及输出 JSON 格式。

## 2. 能力发现与运行边界

- **统一入口**：通过宿主 Studio MCP 读取 `STUDIO_MCP_URL` 与 `STUDIO_MCP_BEARER_TOKEN`，从实际工具目录确认能力和 Schema。Bearer 由服务端解析身份，不附加用户／组织头，不索取内部服务凭据或新增生成审批令牌。
- **已接通工具**：`speech.capabilities`（返回按引擎的能力声明数组 `engines`）、`speech.voices`（同时列出项目引用的 World `reference-voice` 资产 `world_voice` 与项目候选配置 `voice_profile`）、`speech.create`、`speech.status`、`speech.result`、`speech.rate_content`。每次执行重新发现 Schema 与就绪状态；缺工具时报告当前入口缺口，继续可独立完成的准备和已有结果整理。
- **GPU 调度与冷启动**：不启动 GPU 服务、不读取 Kubernetes Secret、不直连内部运行时。`speech.create` 调用 IndexTTS2 时由 Speech MCP 自动向 Station GPU 调度器（`:5056`）申请 `6144 MiB` 显存租约并执行按需冷启动（`0 -> 1`）。`speech.status` 返回 `queued`（`waiting_gpu_lease`）、`phase: loading_model` 或 `error.code: model_load_timeout` 属正常排队或冷启动等待，继续轮询原任务 ID，不换键重提。
- **跨技能边界**：Music 歌曲接口或视频自带音轨不自动替代独立对白生成。参考音频是声线的版本化组成，不能伪称为新训练权重；RVC `.pth/.index` 权重不能直接加载到 IndexTTS2。原始录音、权重、生成媒体和凭据不进入技能包或 Git。

## 3. 任务提交、恢复与项目归档

1. `project.open` 取得当前可写项目及固定 `revision_id`，再调用 `speech.capabilities` 检查 `engines` 就绪状态、模型清单摘要和限制。
2. `speech.voices(project_id, revision_id)` 列出该修订可用的两类声线：`voice_source: "world"`（传 `world_voice: {"asset_id": ..., "version_id": ...}`）与 `voice_source: "project_candidate"`（传项目内 `speech/voices/<voice_id>/profile.json` 的完整 `voice_profile` ContentRef）。两者严格互斥，须检查 `compatible: true` 后再提交。
3. `speech.create` 传入 `project_id`、`revision_id`、`world_voice` 或 `voice_profile`、稳定 `utterance_id`、完整 `text`、`language: "zh-CN"`、固定 `idempotency_key`，以及可选同修订 `script_ref`、`lexicon_ref`、`shot_window_seconds` 和至多一种情绪输入。
4. 持久保存业务 `task_id` 与内部 `runtime_task_id`（`runtime_task_id` 不替代业务 `task_id`），用 `speech.status(project_id, task_id)` 轮询。
5. 成功后调用 `speech.result(project_id, task_id)`，取得 `original.wav`、`editing.wav`、`report.json`、`generation.json` 四份中央 ContentRef，用 `artifact.read` 受控下载并核验大小与 SHA-256。
6. 执行第 6 节 K09 生成后内容分级评估，通过后方可展示摘要并归档。

恢复与故障处理规则：

- 同键同输入恢复原任务；同键异参冲突时保留旧请求，返修另建 take。
- 网络超时先查询原记录；首次响应丢失且尚无 `task_id` 时，按保存的完全相同 create 请求和幂等键恢复；查不到不等于未执行，不换键自动重发。
- 已生成但上传／Project 保存失败，只恢复传输或提交，不重新推理。
- 服务明确返回 `recovery_required` 时保留原因，新尝试与旧任务建立对应关系，不无限自动重试；`phase: archive` 暂时故障由服务按原 `write_id` 恢复；权限丢失先解决既有项目权限，不更换主体绕过；`model_version_changed` 或 `unverified_voice_engine` 保留旧配置和任务，核对实际模型后再决定新 take。

项目归档与依赖：

- 四份返回文件已是 `task_output/service_id=speech` 原生产物，直接复用中央 ContentRef，不重复上传。`project_archive: pending` 表示仍需显式提交最小 Project changes（如 `speech/episodes/<ep>/takes/<utterance_id>/<take_id>/` 及汇总表 `speech/episodes/<ep>/dialogue-delivery.json`），请求前固定 `commit_id`／`write_id` 与真实 `expected_revision_id`，冲突先合并，未知结果查询原提交。
- 涉及传输或提交恢复可读取已安装的同名技能；未安装时可参考固定源码：[Artifact 受控传输](https://github.com/verdantflarehub/verdantflare-skills/blob/e51e12f52023bbca00c706ef818efca6d7faba9d/skills/verdantflare-artifact/references/01.transfer.entrypoint.md)与[Project 修订恢复](https://github.com/verdantflarehub/verdantflare-skills/blob/e51e12f52023bbca00c706ef818efca6d7faba9d/skills/verdantflare-project/references/01.project-ops.entrypoint.md)。

## 4. 过期 take 检出与音频技术报告

每条生成的 `generation.json` 持久保存：

- `input_digest`：由 `sent_text`、`voice_source`、`model_manifest_sha256` 与情绪输入计算的规范化 SHA-256。
- `voice_source`：实际使用的 `world`（`asset_id`、`version_id`、`reference_sha256`）或 `project_candidate`（`voice_profile`、`profile_sha256`）。
- `resolved_emotion_vector`：实际生效的八维情绪向量；`text`：`{source, sent, lexicon_hits}`。
- `timings`：`{queue_seconds, load_seconds, execution_seconds, execution_source, inference_seconds, turnaround_seconds, queue_wait_seconds}`（`execution_seconds` 优先读取 `report.json` 顶层 `elapsed_seconds`，次选 `report.metrics.elapsed_seconds`，缺失为 `null`，`inference_seconds` 与之保持一致，严禁以墙钟 `turnaround_seconds` 冒充 GPU 推理耗时）。

过期检出与返修：短剧合入或声线升级后，回读已选 take 的 `generation.json` 并比对当前目标声线版本、当前词典计算出的 `sent_text` 与 `model_manifest_sha256`。任一变化即标 `stale: true` 并写明原因（如 `world_voice_version_changed`、`voice_profile_changed`、`text_changed`）；只对过期或听审标 `needs_revision` 的 `utterance_id` 递增幂等键后缀（如 `-take-2`）重录，保留其他已选 take，不重跑整集。读音错误先更新 `speech/lexicon.json` 提交新修订再带新 `lexicon_ref` 重录；情绪或超窗调整对应参数重录。

`report.json`（`schema_version: 2`）核验口径：

- `original`（原生 22.05 kHz PCM16，零改动）与 `editing`（48 kHz PCM24 单声道纯线性增益剪辑副本：目标 `-16 LUFS`、真峰值上限 `-1.0 dBTP`，峰值优先，正增益上限 `+12 dB`，近静音 `<= -60 LUFS` 不放大；当 `editing.limited_by != "none"` 时实际响度可能达不到 `-16 LUFS`）分别记录时长、采样率、声道、峰值、4 倍过采样真峰值（`true_peak_dbtp`）、综合响度（`integrated_lufs`）、满幅采样数、首尾静音，以及 `editing` 的 `applied_gain_db` 与 `limited_by`（`none | true_peak | max_boost | silence`）。
- `asr`（SenseVoiceSmall 回写文本、标准化文本、字错率 `cer`、`transcript_mismatch`）、`speaker_similarity`（WeSpeaker 余弦相似度）、`shot_window_seconds` / `window_diff_seconds`、`warnings`（`clipping`、`true_peak_over`、`transcript_mismatch`、`window_overrun`）。
- 原生与剪辑副本分别核对真峰值和削波数；满幅或明显失真保留问题标记，不靠后期降音量宣称修复削平波形。

## 5. 短剧与视频交接约束

- 与视频交接时固定角色、逐字台词、声线版本、实际音频及有效窗口；字幕以最终采用音轨为准。
- 只改语气仍保留人物与台词依据；改台词／声线／裁段则标记依赖它的口型与字幕待复核。允许采用模型原生对白时保留配对声画，不为凑时长任意拉速后仍称口型通过；声音更换不静默解除已有声音策略。相同 take 的听审证据复用，最终剪辑新增接缝和时序风险单独检查。
- AI 短剧将每句对白候选关联到真实角色、声线来源（`world_voice` 或 `voice_profile`）、场景／镜头（`shot_id`）、时间窗口、客观 QC 指标、听审状态与 `file_refs`。

## 6. 生成后内容分级评估（K09 强制步骤）

每次 `speech.result` 取得新生成的语音 take 后、在交付摘要展示与 Project/World 归档之前必须执行（批量生成逐个 take 评估提交；只读查询或恢复已评估 take 不重复评估）：

1. 收集评估输入：转写文本（优先 `report.json` 的 `asr`）、配音原文（`text.source`）、发音替换文本（`text.sent`）、情绪描述（`emotion_text`）、标题与可识别非语言声音（以性兴奋为目的的模拟性行为声音计入 S1/S2；普通低沉、气声不构成 `nsfw`）。缺少转写能力且无 ASR 时仅依文本与已有信息判定，并在 `reasons` 中注明 `"未转写音频"`。
2. 对照[18+ 评估规范（rubric v1.0）](content-rating-rubric.md)判定，不确定即标 `nsfw`（O2），`rubric_version` 固定取自该规范文首版本号（当前 `"rubric v1.0"`）。
3. 调用 `speech.rate_content` 提交 `task_id` 或 `content_ref`（二选一）与评估 JSON（`general` 与 `nsfw` 均须提交；幂等接口，超时用相同内容重试，严禁重新生成）：

```json
{
  "task_id": "<语音生成任务ID>",
  "rating": "general",
  "rubric_version": "rubric v1.0",
  "evaluator_model": "<执行评估的模型标识>",
  "reasons": ["未触发类别"],
  "evaluated_at": "2026-10-24T00:00:00Z"
}
```

4. 交付与归档约束：判为 `nsfw` 的产物在摘要与阶段记录中只写“N 个产物已标记为 NSFW 并隐藏”，严禁展示音频试听链接、`ContentRef`、文件路径或露骨台词原文，且跳过 Project 归档（不调用 `project.commit`）与 World 登记（不调用 `world.register`）。MCP 与本技能不撤销标记；误标由用户在 Studio 设置页开启 24 小时本机“显示 NSFW 内容”开关后人工取消。

## 7. 报告口径

生成成功、客观质量测量（`report.json` v2）、内容分级评估（`speech.rate_content`）、项目归档、声线选用与人耳听审分别报告；技术通过不替代人耳听审，候选归档不自动批准或发布 World。
