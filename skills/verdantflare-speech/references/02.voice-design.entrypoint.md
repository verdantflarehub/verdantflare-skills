# verdantflare-speech：新声线登记、音色设计与实验性声谱融合

## 1. 输入与输出

- **输入**：已核验的说话参考录音（或两条同文参考源）、声线标签与 `voice_id`、参考特征与修改目标描述（音色设计场景）、当前项目修订与 `speech.capabilities` 实际输出。
- **输出**：新声线候选配置（`speech/voices/<voice_id>/profile.json`、`intake.json`）、固定修订回读确认与跨文本试音 take；音色设计方案与候选记录；或实验性融合生成的 `reference.wav` 与 `morph-report.json`。
- **公共依据**：[公共规范](00.common.rules.md)（能力发现、提交恢复、`report.json` v2 与 K09 内容分级）、[参考接收规范](01.dialogue-narration.entrypoint.md#31-参考录音接收与声线选定)。

## 2. 分类

- **新声线登记与试音**：将新的说话参考录音保存为稳定 `voice_id`（IndexTTS2 参考条件生成，不训练权重），登记到固定 Project 修订并做跨文本试音。
- **参考特征指导的音色设计**：基于原参考特征改变年龄、性别、明亮度或设计不同身份；与参考复用并存时分别保留独立 `voice_id`，不覆盖原声线。
- **实验性参考声谱融合**：用户明确要求“以 A 声音为主，融入 B 的音色，形成新参考”时，用 WORLD 对同文源做声学对齐与声谱插值生成新参考候选。
- **不适用场景**：仅借鉴另一参考的语气节奏用[01.dialogue-narration.entrypoint.md](01.dialogue-narration.entrypoint.md)；RVC 模型训练与换声转 `verdantflare-music`。

## 3. 工作流

### 3.1 新声线登记与跨文本试音

1. 通过 Studio 发现 Schema，保存解包后的 `speech.capabilities` 结果（不含完整 JSON-RPC 信封），读取当前 `model_manifest_sha256` 与参考限制。
2. 按[参考接收规范](01.dialogue-narration.entrypoint.md#31-参考录音接收与声线选定)核验录音；M4A、多声道或过长参考在已授权 5090 dev 环境派生合格 WAV 并记录原件摘要、处理与选段（本机仅做静态检查）。
3. 经 Artifact 用户导入流程保存有效 WAV，核对回执、SHA-256 与大小，将完整 ContentRef（仅含 `store_id/artifact_id/version_id`）保存为 `reference.contentref.json`（不手写 ID）。
4. 在技能目录运行配置准备工具（输出目录必须尚不存在，仅用 Python 标准库）：

```sh
python3 scripts/prepare_voice_profile.py \
  --reference reference.wav \
  --content-ref reference.contentref.json \
  --capabilities speech.capabilities.json \
  --voice-id narrator-b \
  --label 旁白B \
  --out voice-candidate-v1
```

工具校验 PCM/WAVEX 结构并输出 `profile.json` 与 `intake.json`（退出 0 仅表示配置准备成功；满幅警告保留在 intake，转写默认未知，听审与登记默认 pending；不执行转码、上传、推理或远端归属查询）。5. 将有效参考、`speech/voices/<voice_id>/profile.json` 与来源说明作为最小变更提交至原 Project 固定修订（两者须同修订；更新已有路径沿用文件身份并保留旧 revision/ContentRef 与旧 take；跨项目复用须经受控 Artifact/Project 引入，不直接复制外部 ContentRef）。6. 用返回的真实 `revision_id` 调用 `speech.voices` 回读，核对 `voice_id`、标签、`reference.sha256`、模型摘要、完整 profile ContentRef 与 `compatible=true`；完整回读成功才记为“已登记”，候选保持 `candidate/pending`。提交未知按原 commit 查询恢复，不重复上传或新建相同提交。7. 按[公共规范](00.common.rules.md#3-任务提交恢复与项目归档)用登记后的 `voice_profile` 提交跨文本试音（采用不同于参考内容的简短文稿，多声线对比用同一句如“下一段旅程即将开始，请和我们一起，看看新的可能。”，若参考已读此句则另选），完成 K09 分级与保存。确认选用后，换声仅重录受影响句子并复核真实时长与窗口。

### 3.2 参考特征指导的音色设计

1. 先核对 Studio 工具与 `speech.capabilities`：当前 IndexTTS2 无音色设计字段，严禁向现行 `speech.create` 发送 `target_description`、年龄或性别参数；开发中 VoxCPM2 候选运行器未通过 GPU 验证且非 Studio 已开放能力，不启动集群任务、不安装模型、不直连内部运行器，不以其他收费模型静默替换。
2. 固定设计输入：沿用原参考的 ContentRef、大小、SHA-256 与来源记录，分别记录三项文字——参考实际可判断音色特征、用户要求改变的特征、综合目标音色描述（例：参考“低沉、沉稳、略沙哑” + 修改“更年轻、更清亮” → 目标“年轻男性，清亮而沉稳，轻微沙哑”）。未听到参考不声称已听辨，标明用户描述依据；音色描述与表演、正式台词严格分离。
3. 后端开放前保存上述输入与能力缺口，继续已授权的其他准备；后端开放后按实际 Schema 提交。收到的候选核对原始音频、派生参考、请求、来源、模型版本与摘要；VoxCPM2 的 `reference_technically_eligible` 仅表示格式可用，不等于台词完整或听感通过。
4. 选定候选按第 3.1 节导入固定修订并跨文本试音；候选生成模型与后续朗读模型分别绑定（IndexTTS2 profile 取当前 `speech.capabilities` 摘要，VoxCPM2 来源单独保留，不混填摘要）。

### 3.3 实验性参考声谱融合

1. 准备同文源：优先复用两种 `voice_profile` 已有的相同文本 `original.wav` 与 `generation.json`；无同文源时在已授权试音范围内经 Studio 为两声线生成同一句短文。要求完整、清楚、无配乐、1–15 秒、同采样率、单声道 PCM16/24 WAV，按摘要核对 `generation.json`，不拼接不同文本冒充同文源，不改写 provenance。
2. 在已授权 5090 dev 环境核对 `numpy/scipy/soundfile/pyworld` 实际版本后运行（输出目录必须全新；技能不自行装包、起服或建镜像，本机仅做静态与单元测试）：

```sh
python3 scripts/morph_voice_reference.py \
  --base source-a/original.wav \
  --base-generation source-a/generation.json \
  --donor source-b/original.wav \
  --donor-generation source-b/generation.json \
  --weight 0.35 \
  --out morph-candidate-v1
```

`0.35` 仅作试验值（有用户指定则沿用，不固定套用或自动生成多档）。脚本拒绝不同文本、摘要不符、静音、采样率不一致、无共同浊音与覆盖旧目录，音高分析范围 65–450 Hz（不承诺高音演唱或极端表演）；输出 `reference.wav` 与 `morph-report.json`，保持主声采样数，最多衰减至 `-3 dBFS`（不宣称修复源削波）。3. 先试听融合参考的可懂度、清辅音、声码器感与音色方向，再按第 3.1 节将参考、报告与 profile 登记到固定修订并以新 `voice_id` 回读，用**另一句不同文本**试音验证。

## 4. 规范

- **双路线并存与不可覆盖**：用户同时需要原参考复用与设计候选时，保留各自独立 `voice_id`、版本与试听，不覆盖原 A/B 声线或已选对白。
- **诚实边界**：仅调整情绪或后期变调不等于音色设计；VoxCPM2 文字设计不消费原参考波形，克隆模式自然语言主要控表演，均不承诺百分比相似度；WORLD 融合权重仅为声谱插值权重，不宣称身份比例或通用稳定融合模型。
- **截尾与不兼容处理**：疑似截尾、过长或超字节限制时保留原件，不截尾字凑长度；回读发现模型摘要不兼容时修复引用或新建绑定版本，不篡改旧配置摘要消警。
- **不造虚假权重**：无真实训练过程、权重包与加载证据时，不创建虚假训练 run 或 World voice-model。

## 5. 验收

- **登记验收**：`prepare_voice_profile.py` 退出 0 且固定修订 `speech.voices` 回读全部字段匹配、`compatible=true`；仅本地脚本通过不算登记完成。
- **跨文本试音与 K09 验收**：新声线使用不同于参考的文稿完成 `speech.create` 与 `speech.rate_content` 提交，分别评估错漏词、描述是否被念出、音色一致性、目标方向、自然度、清辅音与声码器感。
- **状态与交付**：无听审依据保持 `candidate/pending`；候选归档不自动批准、选用或发布 World；失败保留诊断，不把部分输出当作成功候选。
