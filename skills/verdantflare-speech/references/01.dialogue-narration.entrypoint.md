# verdantflare-speech：对白、旁白与参考声线复用

## 1. 输入与输出

- **输入**：剧本修订或录制表（稳定 `utterance_id`、角色 `speaker`、`shot_id`、原文 `text`）、目标声线（`world_voice` 或项目 `voice_profile` 或原始参考录音）、可选发音词典 `lexicon_ref`、可选 `shot_window_seconds` 及至多一种情绪控制参数。
- **输出**：每个 `utterance_id` 对应的 `original.wav`、`editing.wav`、`report.json`（v2）、`generation.json`、`speech.rate_content` 分级记录，以及归档至 Project 修订的 take 与汇总表 `dialogue-delivery.json`（或本地只读方案）。
- **公共依据**：[公共规范](00.common.rules.md)（能力发现、提交恢复、过期 take 检出、`report.json` v2、短剧交接与 K09 内容分级）。

## 2. 分类

- **参考录音接收与复用**：提供最短录制文稿、核验用户上传的参考录音，或复用已有 World `reference-voice` 资产（`world_voice`）与项目内 `voice_profile`。
- **逐句对白与发音词典配音**：按剧本修订逐句配音、维护 `speech/lexicon.json` 解决人名/古地名/多音字、配置情绪控制、检出过期 take 并按听审定向返修。
- **旁白方向、长句拼接与时间窗控制**：宣传片旁白、多句连贯表演、长句语义分段拼接及实测超窗处理。
- **不适用场景**：需要把新录音登记成独立 `voice_id`、按参考特征设计新身份音色或融合两种参考声谱时，转[新声线登记与音色设计](02.voice-design.entrypoint.md)；歌曲与 RVC 换声转 `verdantflare-music`。

## 3. 工作流

### 3.1 参考录音接收与声线选定

1. 用户需要尽量短的普通话参考时，提供 29 字最短录制文稿（自然语速约 8–12 秒，实际时长以录音为准）：
   > 清晨的风吹过竹林，远处传来几声鸟鸣。你先坐下，喝杯热茶，我们慢慢说。
   > 每种声音独立文件、单人近讲、保留原件，不加配乐、混响或变声，不要把声线名称念进录音；手机 M4A 可直接接收，优先原始 WAV，已有可用录音时不要求重读。
2. 保存原件及 SHA-256，核验可解码、实际时长、采样率、声道、位深／编码、峰值与满幅；实际转写未知就记录未知，不把建议文稿填成已核验台词。IndexTTS2 0.1.3 已验证参考范围为 PCM16/24 单声道 WAV、16/22.05/24/44.1/48 kHz、1–15 秒、`<= 2 MiB`（每次调用复核 `speech.capabilities`）。
3. 确需单声道转换、选段或重采样时另存派生文件并记录来源、选段与处理；不覆盖原件、不静默截断、不默认降噪/归一化/生成式增强；双声道合并后核对相位抵消、峰值与可懂度。
4. 调用 `speech.voices(project_id, revision_id)` 选定兼容声线：`world_voice`（跨项目 World `reference-voice` 资产，服务端自动校验 `service_id: "speech"`、`result: "passed"` 与字节摘要，不读 `consent.evidence_path`）或 `voice_profile`（项目修订内 `speech/voices/<voice_id>/profile.json`，与参考 WAV 同修订）。需要把新录音登记为新 `voice_id` 时转[02.voice-design.entrypoint.md](02.voice-design.entrypoint.md)。

### 3.2 发音词典、情绪控制与逐句生成

1. 固定剧本修订与 `utterance_id`、角色、`shot_id`、原文，不自行改写或拆换说话人，不把表演说明念进正文；复用固定声线或词典前核对 `voice_profile`、其录音引用与 `lexicon_ref` 均属于本次指定项目修订。
2. 包含易错人名、古地名、专有名词或多音字时，维护同修订 `speech/lexicon.json`（结构：`{"schema_version": 1, "language": "zh-CN", "entries": [{"term": "解县", "replacement": "懈县", "note": "古地名读法"}]}`），提交时传 `lexicon_ref`；服务端按最长词条优先匹配生成 `text.sent`、保留 `text.source` 并记录 `text.lexicon_hits`，且用 `text.source` 作 ASR `expected_text`。词典命中须按新句子实测验证，整句纠音不自动覆盖单字呼喊或标点不同的短句。
3. 对照 `speech.capabilities` 的 `engines`（当前 `indextts2` 支持 `zh-CN`、300–500 字以内文本），从以下三种互斥情绪输入中至多选一（普通旁白可全省略）：
   - `emotion_vector`：八维数组 `[happy, angry, sad, afraid, disgusted, melancholic, surprised, calm]`，每项 `0..0.8`、总和 `<= 0.8`。
   - `emotion_text`：1–200 字简短描述（如 `"克制隐忍，尾音略微发紧"`），由 QwenEmotion 解析写入 `resolved_emotion_vector`。
   - `emotion_reference`：`{"content_ref": <同修订 WAV ContentRef>, "alpha": 0.1..1.0}`。
4. 按[公共规范](00.common.rules.md#3-任务提交恢复与项目归档)提交 `speech.create`、轮询 `speech.status`、通过 `speech.result` 获取四份产物，并完成 K09 内容分级与 Project 归档。

### 3.3 旁白方向、长句分段与超窗处理

1. 区分“以 A 音色为主、借鉴 B 节奏”与“融合 A/B 音色”：前者用已选 `voice_profile` 与支持的表演参数验证，后者转[02.voice-design.entrypoint.md](02.voice-design.entrypoint.md)；单参考 TTS 不支持多声线融合。选声时可用代表性平稳句与情绪句做短试听。
2. 旁白情绪服从语义（起句、转折、重音、句末收束），不逐词卡音乐鼓点、不做口号式强调；字母简称读法按用户要求记入录制表并实听确认（ASR 近音字不能独自定对错）。
3. 长句在语义和呼吸边界分段，保留上下文目标与同一声线版本；检查各段音色、音高、语速、响度、停顿与接缝，先听完整句再排时间线，不裁尾字凑时间，候选数与语义子任务数分别统计。
4. 录制前记录句 ID、原文、画面窗口（`shot_window_seconds`）、可移动范围及停止锚点；录制后按真实采样数算时长。超窗（`window_overrun`）时在允许范围内调进出点；超出锁定窗口则汇总受影响句子、实际长度、可用窗口与建议（移动起止、缩减重复文案或授权重录），集中请用户决定，不默认加速、改词或延长全片。批准后直接排入新旁白轨并保留原完整 take，换句只重建该句及依赖混音。

## 4. 规范

- **文本与参数边界**：原文（`text.source`）、模型读法（`text.sent`）与表演说明分离；不把哭泣、喘息、笑声或精确时长/语速假映射为普通文本或任意情绪向量；某项目的 `calm=0` 不升格为通用规则。
- **情绪解析复核**：取得结果后按 `emotion_vector_order` 核对 `resolved_emotion_vector` 主导维度与剧情阶段（含“不要惊恐”等否定描述时尤其核查）；若教学／安抚被解析为高恐惧，先退回该语气，改用显式向量或情绪参考仅重调情绪，不因 ASR 正确而合入。
- **配置与版本严谨性**：项目 `profile.json` 必须含 `schema_version: 1`、小写 `voice_id`、`label`、可选 `speaker`、`engine: indextts2`、实测 `model_manifest_sha256`、`reference.content_ref`、`reference.sha256`、`candidate_state`、`listening_review`；不塞未声明字段，不把计划版本写成已运行，无训练证据不创建虚假训练 run 或 World voice-model。
- **既有素材复用**：不重复索取已有授权，仅对过期（`stale: true`）或听审 `needs_revision` 句子生成新 take。

## 5. 验收

- **客观初筛**：核对 `report.json` v2 中 `original` 与 `editing` 各自的时长、采样率、真峰值、综合响度、满幅采样数、`asr.cer`、`speaker_similarity`、`window_diff_seconds` 与 `warnings`；确认 `timings.execution_seconds` 口径真实。
- **情绪与词典核验**：确认 `text.lexicon_hits` 命中实际新句、`resolved_emotion_vector` 符合剧情意图、未念出表演说明或词典注释。
- **听审与分级门禁**：完成 `speech.rate_content` 提交并按 `nsfw` 规则脱敏阻断；人耳试听连贯性、句间变化、清辅音、句尾完整与整片听感（母带响度或信号指标通过不替代听审，单一说话人与噪声需实听确认）。
- **交付齐套**：交付可试听文件（`general`）、选用表、时码、原任务及固定修订版本、技术问题与听审状态（缺少听审能力时明确标 `pending`），遵循[公共规范](00.common.rules.md#7-报告口径)分别报告。
