# Blender 会话与恢复

## 1. 接入与会话

连接使用同一个用户的 Studio Bearer，由环境或宿主管理；不要求额外登录，不向 worker 传递客户端 token。
以目标实例工具列表为准。直接 HTTP 调用也只访问该 Studio 实例 MCP，检查 JSON-RPC error、isError 及业务结果。
当前实例工具可在 content 的 text 块中返回 JSON；按工具响应解码，不强制要求 structuredContent，也不把响应格式差异误报为操作未执行。
现行实例入口使用 JSON MCP，不假定 GET/SSE 或 Mcp-Session-Id 可用；传输连接不是编辑会话。

session.open 输入 project_id、mode（read/edit），项目须与实例已绑定项目一致。
返回 editing_session_id、instance_id、project_id、generation、mode、lease_ttl_seconds（默认 1800 秒，即 30 分钟）、expires_at，保存这些实际值，不从别名推算实例 ID。
技能不通过修改绑定绕过 PROJECT_OR_MODE_DENIED 或 WORKING_COPY_PROJECT_MISMATCH。

只读任务申请 read。edit 失败为 INSTANCE_EDIT_LEASE_HELD 时，保留请求范围并报告占用，不关闭现有 GUI 或其他会话。
注意：`script.run_project`、`scene.inspect_file`、`scene.open_file` 与 `project.export_assets` 执行及完成时均保持当前编辑租约并自动顺延 30 分钟，不会自动释放会话；单次任务或批处理闭环结束时必须调用 `session.close` 释放本次 editing_session_id（不停止 Blender）。

## 2. 写操作与结果未知

按工具 Schema 提供 editing_session_id、幂等键和需要的 scene_version；不要额外传可覆盖 URL 实例的 instance_id。
原请求在发送前保存在不含凭据的操作记录中。每个不同操作用自己的幂等键，相同键必须保持完全相同的参数。

object.create、object.update_transform 完成后用 object.get 或 scene.get 核对真实对象。
对象删除仅用于用户明确指定对象，或本次测试创建且已确认身份的测试对象。

响应丢失但已有 operation_id 时，先 operation.get。
若没有收到 operation_id，只可重发保存的完全相同请求找回幂等结果；不得换会话、改场景版本或新建键重做。
旧会话已失效而无法找回时，保留为结果未知，核对检查点与场景，不盲目重放。

operation.get 可能推进已登记保存的恢复，不应当作对任意未知操作的纯元数据探测。
running 需有界轮询；completed 才能继续结果核验；unknown、冲突或失败保留原记录，不重复执行变更。

单个旧操作返回 `unknown / WORKER_UNAVAILABLE` 不足以判定整个实例当前不可用。在已有权限内，用原实例只读会话核对 generation、scene 与工作副本，随后关闭本次会话；该读取成功不证明旧操作完成。旧结果继续按原 ID 对账，不能换键重做。确有独立诊断需求且当前实例已可读时，可在原实例以独立幂等键、不冲突输出名和固定检查点执行不依赖未知结果的诊断，仍服从服务并发保护；不能把旧动作换名伪装成独立任务。指定输出不存在只证明观察时未找到，不能据此声称未执行。

批处理前按当前配额和目录清单核对总目录数、目标目录文件数及预计新增量；日志、嵌入纹理和报告也计入文件数。脚本实际输出路径须与请求的 `output_subdir` 一致。目录已满时优先复用有余量的同任务诊断目录并使用不冲突文件名，清理仍遵循用户范围和备份要求。配额拒绝本身不证明服务Bug；先核实是否已产生文件，不重跑成功渲染只为取得导出文件。

复用导出目录时，`build.log`可能仍属于旧脚本或已被后续运行覆盖。核对正文中的实际脚本、输入及可用时间信息，再归因当前操作；导出时附带的`batch_operation_id`只是关联记录，不证明文件由该批次生成。旧日志或文件下载404都不足以证明未知操作未执行，保留未知状态并核查实际派发与输出，不据此盲重放。

## 3. 代次与能力缺口

STALE_GENERATION 或会话过期后，旧写请求不得迁移到新会话重放。
先确认检查点和实际场景，再按后续任务重新申请会话；不承诺恢复所有未保存内存变更。

Blender 0.1.5 起，首次 edit 会话可从绑定 Project 的固定修订恢复 blender/main.blend。服务校验内容、保留原场景检查点并禁用自动执行脚本加载，返回加载后的 generation；随后读取场景及关键对象验证。已存在工作副本不会自动追随最新 head。

只读首次打开仍可能返回 INITIAL_PROJECT_RESTORE_REQUIRED，需要有编辑权限且已获授权的任务初始化；纯读取任务不擅自升级为 edit。旧版服务也可能返回此错误，按实际版本报告。
首次恢复超时可重试同一实例和项目的 session.open 以对账；服务固定原修订，不由客户端重新上传。若收到 INSTANCE_EDIT_LEASE_HELD，可能是先前会话已建立，停止并核对会话；RESTORE_STATE_UNKNOWN 表示无法证明加载结果，保留记录排查，不重启或清空工程重做。
不删除文件引用、清空工程或改绑项目以假装恢复成功。

跨Scene读取几何时，`bpy.data.objects`中存在对象不证明它属于当前渲染Scene或参与当前依赖图。诊断先核对Scene／Collection归属、可见性与父级关系；隔离复制或链接后更新当前依赖图，再取求值后的世界变换与包围盒，不能拿未参与求值的对象局部坐标当船体间距。保留源对象与主工程，实际查看渲染结果，避免“数据存在而画面漏物”。

相机构图检查不能只测人物中心、头顶和脚底的投影；靠近画边时还要检查身体轮廓及本镜动作所需留边。代理柱在框内不证明抬臂或抛绳不会裁切，诊断区分色只帮助辨认空间，不作为正式摄影风格。

越窗或跨栏反复弄错内外腿时，检查起态、跨越中态与落态的实际可见性：两只脚、被跨边缘和支撑关系是否能在画面中分别辨认。数值净空或脚中心射线通过不证明整条腿可读；若关键腿始终被栏杆或身体遮住，先调整有空间依据的机位，再制作对应起态，不继续仅靠左右措辞重试。诊断姿态仍只作空间参考，不强加精确骨骼求解或替代写实表演验收。

近景匹配先核对实际头顶、眼线与肩线的投影，再判断人物是否需要缩放或重生；全身圆柱半径及宽松方框不能直接当作头部遮挡证据。确需细化时记录头部代理的尺寸假设，以实际轮廓和道具投影宽度复核，保留旧失败结果，不为放行而直接取消净空断言。

水域远景中，有限水面网格的边缘不是地平线。先核对相机水平、俯仰和水面范围；将该边缘直接转为写实海天线，会把建模边界错误带进画面。可在诊断中扩展水面，或按既有天气处理不可见的远界，但不改变船体和人物支撑位置。

同一实例写操作串行处理。多实例测试依赖真实独立实例；当前 A 可用不代表 B 已部署。
桌面流媒体、TURN、离线登录和市场交付由应用维护，MCP 场景操作通过不代表这些全部通过。

只核对机位、遮挡和支撑而无需重新着色时，可从已核验的固定检查点一次性导出必要对象的世界顶点与三角面，在本地复用投影和射线检查；仍保留工程摘要、对象来源、单位、相机及主工程未改证据。对象变换或包围盒不等于真实网格，甲板内落点用实际三角面核验。本地展示应使用深度缓冲或等效正确遮挡，不能仅按整块大面平均深度排序，否则甲板可能错误盖住落物；数值射线通过仍要看实际投影。该方式不重放结果未知的旧任务，也不证明写实图严格锁定空间。

世界坐标投影的照片材质与切线空间法线须使用匹配的切线基准；默认UV并不自动跟随材质节点中的坐标轴、缩放或物体变换。仅在检查实际节点后发现该疑点时，用同一几何、机位、光照、曝光和采样种子做单变量对照，核对UV退化面、轮廓和主工程未改。技术上纠正坐标不等于摄影改善；实际对照若变化很小且原问题仍在，排除其作为主要修复方向，不继续改变法线强度或重生整镜来证明原假设。
