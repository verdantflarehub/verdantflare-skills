# Blender 实时场景编辑、批处理与恢复（01.live-edit）

## 1. 输入与输出

- **输入**：用户明确的 Studio Blender 实例连接（如 `/mcp/blenderA`）、绑定 `project_id`、读写模式（`read`/`edit`）、场景修改或数字片场批处理脚本任务描述与预期输出目录。
- **输出**：经回读核验的场景对象与 `scene_version`、批处理产物（`.blend`、`.mp4`、`.json`、`build.log`）或诊断结论、操作与恢复记录，以及任务收尾后已释放的 `editing_session_id` 状态。

## 2. 分类

按访问权限与执行形态选择会话分支：

- **只读检视与诊断（`mode=read`）**：读取基线场景、检查 `scene.inspect_file` 结构或核对故障实例状态；纯读取任务不擅自升级为 `edit`。
- **交互式实时对象编辑（`mode=edit`）**：基于基线 `scene_version` 与固定幂等键执行 `object.create`、`object.update_transform` 等定向场景修改并回读对象。
- **数字片场批处理与多机位预演（`mode=edit`）**：通过 `workspace.clean`、`script.run_project`、`scene.inspect_file`、`scene.open_file` 执行受控 `bpy` 中模搭建与多机位预演渲染。
- **结果未知与故障恢复**：针对超时、`unknown / WORKER_UNAVAILABLE`、`STALE_GENERATION`、`WORKSPACE_BINDING_CONFLICT` 或首次工程恢复执行只读核对与受控对账，不盲目重放或重建实例。

## 3. 工作流

### 3.1 实例选择与会话开启

1. 从已有连接或受控目录取得用户明确的 Studio 实例地址（如 `/mcp/blenderA`），与中央 `/mcp` 分别发现真实 `tools/list`，核对绑定 `project_id` 与任务范围；现有工具包括 `session.open`、`scene.get`、`object.create`、`project.save` 及 v0.1.14 的 `workspace.clean`、`script.run_project`、`scene.inspect_file`、`scene.open_file`、`project.export_assets`，不套用早期 `blender.*` 草案名。
2. 调用 `session.open` 传入 `project_id` 与 `mode`（`read`/`edit`），保存返回的真实 `editing_session_id`、`instance_id`、`project_id`、`generation`、`mode`、`lease_ttl_seconds`（默认 1800 秒，即 30 分钟）与 `expires_at`，不从别名推算实例 ID。
3. 使用 `scene.get` 读取基线；Blender 0.1.5 起首次 `edit` 会话可从绑定 Project 的固定修订恢复 `blender/main.blend`（服务校验内容、保留原场景检查点并禁用自动执行脚本加载），加载后核对返回 `generation`、场景及关键对象。

### 3.2 实时对象操作与数字片场批处理

1. 变更前在不含凭据的操作记录中固定幂等键、原参数与 `scene_version`；每个不同操作使用独立幂等键，相同键保持完全相同参数，不额外传可覆盖 URL 实例的 `instance_id`。
2. `object.create`、`object.update_transform` 完成后使用 `object.get` 或 `scene.get` 核对真实对象与 `scene_version`；对象删除仅用于用户明确指定对象或本次测试创建且已确认身份的测试对象。
3. 数字片场批处理无需 `kubectl exec` 直接操作 Pod，统一使用实例 MCP 扩展工具：
4. 清理目录用 `workspace.clean`：先传 `dry_run=true` 预览 `would_clean_paths` 清单，再传 `dry_run=false` 执行；支持受控导出子目录 `export_subdirs` 与家目录异常残留白名单 `stray_home_names`（仅限 `"C:"`、`"D:"`，默认不删除任何家目录路径）。
5. 批处理建模与预演用 `script.run_project`：从已授权 Studio 项目（`source_project_id`，默认会话项目）拉取受控 `bpy` 脚本（如 `blender/scripts/saw_set_v1.py`），在 `/workspace/exports/<output_subdir>/` 隔离运行（单实例最大并发 1，`timeout_seconds` 默认 300s、上限 600s，受目录数与文件数容量配额约束），输出 `.blend`、`.mp4`、`.json` 与 `build.log`，可按需指定 `load_blend_as_active` 加载为当前活动场景；返回 `running` 时通过 `operation.get` 有界轮询直至 `completed`。
6. 结构核验用 `scene.inspect_file`：对当前活动场景或指定工作区 `.blend`（`asset_id` 如 `exports/<subdir>/xxx.blend`）读取单位制、分辨率、帧率、帧范围、前缀分类计数、全部摄像机参数（焦距、传感器宽度、位置、旋转、关键帧列表）、标签与关键对象世界包围盒尺寸。
7. 切换活动场景用 `scene.open_file`：在保留当前活动场景检查点前提下将工作区受控 `.blend` 加载为当前活动场景并递增 `scene_version`。

### 3.3 响应未知与故障恢复

1. 响应丢失但已有 `operation_id` 时先调 `operation.get`（注意 `operation.get` 可能推进已登记保存的恢复，不作任意未知操作的纯元数据探测）；未收到 `operation_id` 时只重发保存的完全相同请求找回幂等结果，不换会话、不改 `scene_version`、不新建键重做。
2. 单个旧操作返回 `unknown / WORKER_UNAVAILABLE` 不足以判定整个实例不可用：在已有权限内用原实例只读会话核对 `generation`、`scene` 与工作副本并关闭本次会话（读取成功不证明旧操作完成）；旧结果继续按原 ID 对账，确有独立诊断需求且实例可读时以独立幂等键、不冲突输出名和固定检查点执行，不把旧动作换名伪装成独立任务。
3. 同剧短剧沿固定实例接续，故障不另开实例；恢复先区分管理台账、实际工作进程、工作卷与工程加载证据，经原实例受控恢复路径核对终态、精确 UID、租约和保存后再读原场景。
4. `STALE_GENERATION` 或会话过期后，旧写请求不得迁移到新会话重放；首次恢复超时可重试同一实例与项目的 `session.open` 对账（服务固定原修订，不由客户端重传）；遇到 `RESTORE_STATE_UNKNOWN` 保留记录排查，不重启或清空工程重做。

### 3.4 收尾释放租约与 GPU 驻留协同

1. `script.run_project`、`scene.inspect_file`、`scene.open_file` 与 `project.export_assets` 均保持当前编辑租约并自动顺延 30 分钟，不会自动释放会话；单次任务或“跑脚本 → 核验 → 归档”闭环结束时，必须调用 `session.close` 显式释放本次 `editing_session_id`（仅长期交互按用户要求保留；释放失败记录恢复入口，不关闭他人会话）。
2. 释放编辑租约且无人类 GUI 视口连接时，实例由受保护活动态（`S1`：`active_compute` / `human_dirty`）转入可安全回收态（`S2`：`idle_evictable`）；重型任务需要显存时，Station GPU 调度器自动将 `S2` 实例安全休眠至零显存待命（`S3`：`zero_vram_standby`，预先写出独立 `pre_hibernate_*.blend` 检查点，绝不覆盖用户 `main.blend`），并在下次 `session.open` 或打开视口时透明唤醒恢复。

## 4. 规范

- **连接与协议边界**：复用同一用户有效 Studio Bearer，不要求额外登录，不向 worker 传递客户端 token；不得因实例 A 不可用转到 B，不使用独立下游公网 MCP；`project.save` 与 `project.export_assets` 属于实例入口不发中央 Project 域；直接 HTTP 调用只访问目标实例 MCP，检查 JSON-RPC `error`、`isError` 及业务结果，按工具响应解码 `content` 文本块 JSON，不强制要求 `structuredContent`，不假定 GET/SSE 或 `Mcp-Session-Id` 可用（传输连接不是编辑会话）。
- **租约、权限与显存红线**：GUI 或其他编辑者占用返回 `INSTANCE_EDIT_LEASE_HELD` 时保留请求范围并报告占用，不抢占控制权或关闭现有会话；不通过修改绑定绕过 `PROJECT_OR_MODE_DENIED` 或 `WORKING_COPY_PROJECT_MISMATCH`；`INITIAL_PROJECT_RESTORE_REQUIRED` 需有编辑权限且已授权的任务初始化，旧版服务按实际版本报告；连接失败或 `WORKSPACE_BINDING_CONFLICT` 不单独证明卷丢失，严禁直接删 Pod、改绑、清空工程或以最新项目文件覆盖未核实工作副本；严禁为“腾显存”调用实例停止或销毁管理接口，严禁抢占 `human_protected` 实例。
- **配额与日志归因**：批处理前按当前配额与目录清单核对总目录数、目标目录文件数及预计新增量（日志、嵌入纹理与报告均计入文件数），脚本实际输出路径须与 `output_subdir` 一致；目录已满优先复用有余量的同任务诊断目录与不冲突文件名；配额拒绝本身不证明服务 Bug，先核实已产生文件，不重跑成功渲染只为取导出文件；复用目录时 `build.log` 可能属旧脚本或被覆盖，须核对正文脚本、输入与时间信息再归因，`batch_operation_id` 仅为关联记录，旧日志或下载 404 不足以证明未知操作未执行。
- **白模交接与空间诊断准则**：影视白模固定工程版本、统一尺度、相机、路径与遮挡依据，仅依赖空间或运镜时准备预演，相同工程/相机预演可复用，改空间或相机才使下游投影失效；人物姿态皮肤、真实枝条与陈设外观交图像参考，粗模不宣称精细接触。跨 Scene 读取几何先核对 Scene/Collection 归属、可见性与父级关系，隔离复制或链接后更新依赖图再取求值后世界变换与包围盒，实际查看渲染结果避免“数据存在而画面漏物”。
- **构图、遮挡与材质诊断准则**：相机构图除人物中心、头顶与脚底外，靠近画边须查身体轮廓与动作留边（诊断区分色不作正式摄影风格）；越窗/跨栏弄错内外腿时核对起态、中态、落态两脚、被跨边缘与支撑关系可见性，被遮挡先调有空间依据的机位再做起态，不靠左右措辞重试；近景匹配先核头顶、眼线与肩线投影，不用宽松方框替代头部遮挡，细化时记录尺寸假设并保留旧失败结果；水域远景有限水面网格边缘不是地平线，先核相机水平、俯仰与水面范围；局部核对机位遮挡可从固定检查点导出世界顶点与三角面复用投影和射线检查（甲板落点用真实三角面，本地展示须用深度缓冲不按大面平均深度排序，保留主工程未改证据）；世界坐标投影照片材质与切线空间法线须核对实际节点与切线基准，用同几何/机位/光照/曝光/种子单变量对照，变化很小则排除该方向，不靠改法线强度或重生整镜证明原假设。
- **并发与系统边界**：同一实例写操作串行处理；多实例测试依赖真实独立实例，A 可用不代表 B 已部署；已存在工作副本不自动追随最新 head；桌面流媒体、TURN、离线登录和市场交付由应用维护，MCP 通过不代表全部通过。

## 5. 验收

- 所有写操作与批处理均已读取真实回读结果（对象、`scene_version`、输出清单或结构检查），`completed` 态与 `unknown`/失败态严格区分。
- 单次任务或批处理闭环结束时已显式调用 `session.close` 释放 `editing_session_id`（或记录用户明确保留长期交互的依据）。
- 交付明确报告实例、操作状态、来源溯源及已知缺口，技术成功不代替创作或视觉验收。
