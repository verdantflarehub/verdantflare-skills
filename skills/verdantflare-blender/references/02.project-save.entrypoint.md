# Blender 工程归档与片场包导出（02.project-save）

## 1. 输入与输出

- **输入**：处于有效 `edit` 会话的指定 Blender 实例（含 `editing_session_id`、`scene_version`）、目标归档范围（当前活动场景 `.blend`、跨项目批处理导出文件列表或 Set Package v1.0 片场包）及目标 `target_project_id`。
- **输出**：经 `operation.get` 确认 `completed` 的固定 Project `revision_id`、每个文件的 `ContentRef`（`size`、`sha256`）、来源溯源 `provenance` 记录、中央 Project/Artifact 回读核验结论；片场包场景另产出经校验脚本通过的 `sets/<package_id>/` 与相机对齐报告。

## 2. 分类

按保存作用域与交付形态分为四类：

- **实例本地保存（`scene.save`）**：仅写入实例持久工作区，证明实例内保存，不等于已同步 Project。
- **绑定项目工程归档（`project.save`）**：生成当前活动场景不可变 `.blend` 检查点，由 Blender 服务经 Artifact 写入并提交实例绑定 Project 的新修订。
- **跨项目多文件批量归档（`project.export_assets`）**：将实例工作区 `exports/` 或 `project/` 下多个导出文件（`.blend`、`.mp4`、`.json`、`.glb` 等）原子上传并提交至 `target_project_id`（默认绑定项目，支持跨项目指定有写权限的分篇项目），同步写入来源溯源且不改变实例 `project_id` 绑定。
- **三维片场包导出（Set Package v1.0）**：面向 Studio 网页片场查看器（`viewer`），通过无头导出器生成 `set.json` + `scene.glb` + `poster.png` + `cameras/CAM_*.png` 并归档校验。

## 3. 工作流

### 3.1 发起工程保存与跨项目归档

1. 核对工具在线 Schema 与打包完整性：当前归档单位是单个 `.blend`，贴图等用户资源须由制作者在 Blender 中打包，仅处理本工程明确引用且在授权范围内的资源；资源路径或交付范围不明先澄清，已有授权不重复确认。
2. 绑定项目单文件保存：调用实例 `project.save`，传入 `editing_session_id`、`scene_version`（来自本次读回或已完成操作，不猜测）与稳定 `idempotency_key`；先保存原请求再发送，记录返回的 `operation_id`。
3. 跨项目或多文件归档：调用实例 `project.export_assets`，传入 `editing_session_id`、`idempotency_key`、`target_project_id`（跨项目必填）、`batch_operation_id`（关联前序 `script.run_project` 操作 ID 生成溯源）、`provenance_path`（可选，如 `blender/provenance.json`）、`files`（`[{asset_id, project_path, role}]` 列表）与 `commit_message`。
4. 在同一实例调用 `operation.get` 有界轮询直至明确 `completed`（初始 `running` 不代表归档完成），从 `result` 读取 `target_project_id`、`revision_id`、`provenance` 与各文件 `content_ref`、`size`、`sha256`；超时保留 `operation_id` 供恢复，不另起保存。归档完成后如无后续写操作，立即调用 `session.close` 释放编辑租约。

### 3.2 中央回读与内容验证

1. 使用中央 Studio `/mcp` 的 `project.open` 打开返回结果中的固定 `revision_id`，在 `manifest.files` 中定位本次 `.blend` 或导出文件及其 `content_ref`（不根据文件名构造版本 ID），同步核对 `provenance` 溯源记录。
2. 调用中央 `artifact.read`（`mode=metadata` / `download`），传入固定 `ContentRef` 与完整 `project_id`/`project_revision_id` 访问路径，仅沿同一 Studio 受控相对路径下载至临时文件并校验 `size` 与 SHA-256，以不覆盖原文件的方式保存。
3. 无宿主中央工具时，使用 Studio 0.5.50 的 `studio-workspace call/fetch`（`call` 参数为 `{name, arguments}`，环境变量为 `STUDIO_MCP_URL` 与 `STUDIO_MCP_BEARER_TOKEN`，不把实例 URL 填入中央管理连接）；缺客户端或中央权限时保留已取得保存结果并明确回读未验证。

### 3.3 三维片场包（Set Package v1.0）导出与校验

1. 确认目标 `.blend` 已通过 `scene.inspect_file` 核验后，经 `script.run_project` 在 `/workspace/exports/<subdir>/` 运行 `scripts/set-package/blender_export_set_package.py`，产出 `scene.glb`（`+Y Up`，`1.0m`，静态同材质网格合并后节点数 `<= 180`）、`set.json`（Schema `1.0`）、`poster.png` 与 `cameras/CAM_*.png`。
2. 调用 `project.export_assets` 将上述文件写入目标项目 `sets/<package_id>/`（`set.json` 的 `role` 设为 `set_package` 或 `metadata`，`scene.glb` 的 `role` 设为 `model`），记录固定 `revision_id` 并在 `finally` 中调用 `session.close`。
3. 从中央 Project/Artifact 回读下载至本地目录后执行两项校验：

```text
python scripts/set-package/validate_set_package.py <package_dir>
python scripts/set-package/check_camera_alignment.py --package-dir <package_dir> --output <alignment.json>
```

### 3.4 异常与恢复

1. 上传或提交响应丢失继续查询原 `operation_id`（应用复用原检查点、`write_id` 与 `commit_id`）；返回 `unknown` 先对账，不把新建检查点当作恢复。
2. 遇到 `PROJECT_EXTERNAL_DEPENDENCIES`（保存检查点或恢复前拒绝，未满足单文件交付要求）：记录原失败结果，在授权范围内使用实际可用 Blender 能力补齐并打包资源，读取新 `scene_version` 后以新幂等键重新提交；实例无打包能力时不臆造工具或任意 Python 入口，明确列出制作者在 Blender 中需执行的步骤。
3. 遇到 `PROJECT_FILE_INVALID`（恢复预检无法读取工程）：保留原文件并核对来源，不宣称已恢复。

## 4. 规范

- **服务端归档边界**：`project.save` 与 `project.export_assets` 均由 Blender 应用服务完成 Artifact 上传与 Project commit，客户端不得重复上传或重复提交同一检查点；不得将实例 `project.save`/`project.export_assets` 发送到中央 Project 域。
- **基线与冲突保护**：保存使用会话工作副本基线，不因远端 head 前进把旧场景强行基于新 head 提交；发生冲突保留检查点、原 `operation_id` 和提交信息，明确处理差异后再继续，不覆盖他人修订。
- **外部依赖与下载安全**：未打包贴图、链接库等外部依赖即便当前路径可读也不能作为可移植工程归档；不扫描或打包任意用户目录；中央回读下载拒绝重定向与跨域凭据转发。
- **首次恢复红线**：首次恢复必须使用服务提供的受控流程，不得删除文件引用、清空工程或改空项目绕过。

## 5. 验收

- 交付记录完整包含实例、固定 `revision_id`、`ContentRef`、字节数与 SHA-256 核验结果、来源溯源 `provenance` 及已知缺口。
- 哈希正确仅证明字节完整；需证明可继续编辑时须实际加载 `.blend` 核对对象、变换与外部资产依赖；对预演 `.mp4` 视频须完整解码核验帧数与时长，并逐机位抽帧检查画面主体可见、未被替身或天花板遮挡。
- Set Package v1.0 通过 `validate_set_package.py`（无 `.blend`/`.py` 源文件混入、文件数 `<= 32`、`scene.glb <= 25 MiB`、节点数 `<= 180`、`fov_y_deg` 换算误差 `<= 0.05°`、SHA-256 100% 匹配）及 `check_camera_alignment.py`（网页 Y-up 相机与 Blender 渲染参考图对齐）。
