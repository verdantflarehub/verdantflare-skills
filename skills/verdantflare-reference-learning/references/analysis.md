# 完整分析与拆解方法学习

## 1. 输入与覆盖

先识别原作品、已有拆解文档、标注演示与新创作成果的角色。固定可获得的文件摘要、时长／全文范围、时间基准、版本与来源。默认分析本次提交作品的完整范围；明确局部任务才缩小。内部先概览再分段可以，但概览不作为默认交付终点。

每个适用维度记录已分析范围、证据和 `pending/complete/failed/unsupported/not_applicable`。不适用需说明理由；未知结论可在完整检查后保留为未知，不伪造确定值。全部适用维度实际完成才声明完整拆解；缺能力时交付已验证部分及缺口，不反复要求用户逐项续拆。

## 2. 按作品类型组织成果

### 2.1 视频、宣传片与电影片段

涉及视频原片、标注版和制作表对照时，先读[视频证据与时间定位](video-evidence.md)。先建立叙事／沟通目的与段落，再划分剪辑镜头；镜内的新信息、动作变化与注意力转移记录为节拍。镜头与节拍使用稳定局部 Key 和时间范围关联，不把每帧自动变成独立资产。

逐镜描述主体、动作起落、构图、场景／道具、相机观感、光色与信息目的。相机运动、主体运动、剪辑切换、二维图形运动分别判断；固定镜头同样成立。仅凭成片不能确定焦距、空间尺寸和相机轨迹时标推断。

旁白、对白、字幕、音效、音乐、图形分别定位，再建立声画同步。测量需明确单位、帧率、偏移正负与来源；未实际听取的音轨不能凭画面补写为事实。完整性核对包括时间覆盖、空隙／重叠理由、镜头与节拍对应、原作字卡与分析标注区别。

交付可编辑镜头／节拍表、声画关系、可迁移规则、实际提示词及模型适配草稿。用户要求工程时形成明确重建任务：白模尺度假设、场景对象、连续相机起落和关键帧、ComfyUI 输入与预期控制输出；工程由实际生产能力生成并重开／执行验证，不能把说明或空 JSON 当成可用工程。

### 2.2 剧本与短剧

按幕／场／事件定位原文或实际视听证据，提取角色目标、阻力、知情顺序、关系变化、冲突升级、反转和悬念。逐字对白有来源，概括标为概括。再创作时把背景、角色、社会关系、关键物件替换映射到因果与场次，检查动机、信息先后和连续性；交付具体改写内容或可执行的改写提示词，不能仅改人物名字就声称完成新剧结构。

### 2.3 歌曲、配乐与 MV

歌曲按曲式、动机、节奏、配器、人声、情绪推进和制作听感拆解；歌词／文本、听感推断和测量分别举证。未分轨不能交付假 Stem，未识谱不能称已获得 MIDI 或准确和弦。可用成果包括曲式／配器方案、声音参考约束与目标音乐模型提示词。

MV 还需镜头与乐句、重拍、段落变化的时间对应，区分剧情、表演和视觉段落；完整视频分析不能代替音乐分析。实际音乐生成与 MV 制作分别交给可用生产技能。

### 2.4 风格、人物与场景

风格体系拆成叙事、表演、构图、光色、运动、剪辑与声音规则，给适用条件、例外和模块配合。单一片段只能支持该样本观察；不能据此宣称已经总结某导演全部风格。规则可独立修改与组合，不靠作者姓名代替可执行描述。

人物区分演员身份和剧中角色，提取外观、造型、表演与连续性；场景区分空间、物件、材质、光线和调度。二维可见信息不等于完整三维模型，缺失侧面、背面、遮挡和尺度保留假设。

## 3. 学习一份已有拆解

先读取表格结构与图例，区分真实记录、汇总和说明行；对照原片同一定位，分别保存作者声明与本次独立核验。只有拆解文件时可以学习其组织方法，但不声称核实原作事实。

Roadster 案例可迁移的方法：镜头与镜内节拍分层；多声画轨单独定位后建立同步；“看到什么／为何有效／新作品如何使用”分开；提示词由结构、动作、节奏、约束导出。原作自身可能已有字卡、箭头和图形，不能都当作拆解者叠层；标注版的重配音也不能归入原音轨。

该案例的车辆外观、镜头数量、帧率、颜色及具体时码都不是通用默认。将候选方法用于新作品或反例后记录实际效果；已有答案重放只证明读取和组织，不证明自动分析泛化。

## 4. 方法候选与资产交付

内容成果保留可编辑正文、来源定位、事实／推断／新创作状态、类型和复用条件。提示词按[模型适配说明](model-prompts.md)独立交付；不以长报告替代可复制正文。

方法候选记录解决的问题、输入、步骤、输出、适用范围、例外及新输入试用证据。没有验证时标候选；在用户要求的技能维护任务中才更新通用流程。作品私有内容和本轮 Prompt 不自动进入可分发 Skill。
