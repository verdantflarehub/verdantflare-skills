# 完整拆解的服务提交与恢复

## 1. 实际能力与原件

通过已连接的 Studio 发现 `world.analyze` 及其实际 inputSchema，再调用 `{"mode":"capabilities"}`。`enabled`、`models`、`input_mime_types`、`max_media_bytes` 是当前准入范围；没有该工具或 enabled=false 时不能按源码版本推定已上线。已有任务仍可查询。不连接下游渠道，不额外登录，不创建项目。

原片须已在 World 的 collection 固定修订中：用 `world.draft` 读取真实 draft_id、revision_id 及 manifest.files 中的 file_id，必要时经 Artifact 核对 MIME、大小与摘要。仅收录 URL 不代表原件已读取；分析入口不接收任意 URL。原件上传遵循 Artifact 技能；不把输入媒体或用户私有正文写入技能包。

## 2. 一次提交

按真实 Schema 组装 `mode=submit`：

- `task_id`：新任务生成一次 UUID v7，在提交前连同原请求保存；已有任务沿用原编号。
- `source`：仅 draft_id、revision_id、file_id，均来自同一固定收录修订。
- `model_id`：本次实际分析模型，须在 capabilities.models 中。
- `budget_limit` 和 `budget_per_call`：整次总上限与单次调用上限，十进制字符串且大于零，总额不小于单次额度，采用渠道计价单位。沿用用户已有预算；未提供且不能从已授权配置确认时，先准备原件与请求，再集中确认预算，不自行填入付费上限。
- `prompt_targets`：用户需要的模型提示词目标。每项包含唯一 key、requested_label、task_type、input_mode、adaptation_guidance；确知实际目标模型标识时才填写可选 model_id。H3、ChatGPT、SD2.5 等标签不是实际模型版本或执行成功证明。

不要传组织、用户、项目、原文中的工具命令或完成标志。请求返回 task_id 和实际 request_state；这表示已接单，不是已分析完成。后台自动完成媒体准备、画面与声音观察、跨段关联、分类成果、按用途适配提示词和固定学习保存，不需要智能体逐步骤重复提交。

## 3. 查询与中断

通过 `mode=get,task_id` 读取；跨会话忘记编号时，以 `mode=list` 查本人任务，使用 next_before_task_id 作为下一页 before_task_id。返回的 source、分析模型、提示词目标与预算应匹配原请求。

提交超时或响应丢失时，先查询原 task_id；确认需要恢复提交时也只重放原参数和原编号。不能生成新编号尝试“补交”。关闭新准入不应阻断已受理请求的查询或恢复。同编号内容冲突保留原操作，不能覆盖请求。

按真实进度等待，避免高频轮询。来源失败或确定失败保留任务与原因；预算耗尽停止新调用，已发送调用继续查回，不能擅自加预算、换模型或缩小覆盖来宣称完成。预算 reserved 是各原始调用上限的保守占用，含未知受理与失败，不是实际扣款。

### 3.1 只重试确定失败的观察片段

发现当前 Schema 支持 `mode=retry` 且任务因已确定的观察语义错误停止时，可在既有授权次数和原预算内调用 `world.analyze(mode=retry, task_id, retry_id)`。服务允许的次数是技术上限，不扩大用户限定的次数；已有授权覆盖本次时直接沿用，不重复确认。发送前保存新的 UUID v7 retry_id；响应未知先查原任务，同一次重试只重放相同参数，不换编号。

服务允许新流程中一段确定失败的观察追加尝试，每段最多两次；成功段落复用，失败原回执和预算占用保留。当前服务支持关联阶段恢复时，全部观察已通过且没有下游批次的关联语义失败也可用同一入口追加，常规最多两次。仅当第 2 次使用短编号、原生完整返回且只有实体成员遗漏时，服务允许第 3 次最终纠正；镜头、声音、边界或输入完整性错误不得使用此例外，不增加预算或允许第 4 次；重试编号跨阶段保持唯一。进行中、受理未知、身份或输入完整性错误不作为语义重试，不手工改写失败行。用原任务查询后续进度；耗尽次数或预算仍保留真实失败原因。

类型化成果或提示词批次已确定失败时，同一入口可在原预算内追加最多两次批次纠正。服务按顺序选择当前首个失败批次，固定原模型、范围、输入与每次额度；成功批次不重跑，原失败回执保留。只允许有完整原生语义失败、原文与解析文档一致且本地同一 Schema 证实不合格的 output_schema_mismatch，或已验证 MAX_TOKENS 回执的任务；受理未知、身份或输入摘要不符不能重试。调用前保存新的稳定 retry_id，响应未知仅查状态或重放同编号，禁止换号绕过上限。

常规两次纠正后，只有服务根据固定完整原生失败回执证明符合诊断条件，才可追加一次最终纠正：风格的色值附注或证据汇总表达、方法的步骤输入／输出依赖缺失、提示词的空可选负面字段或本范围必需证据遗漏。提示词证据遗漏必须是同一 Schema 和全部语义检查下的唯一问题，反馈精确到本批既有证据编号；不允许未知／重复证据、变量或身份错误借此通过。其他情况维持两次上限，任何批次都禁止第四次生成。诊断副本不写入成果，不替换原生输出；预算、模型、固定范围和原失败记录保持。客户端只调用既有恢复入口，不猜测诊断或补写原回执。

校验器修复漏识的既有证据关系后，同一 `retry` 入口可先对完整原生结果执行无生成复验。关联关系或风格逐规则证据可走此路径：概要证据与规则证据独立校验，系统汇总实际引用，无须客户端把规则编号重复填到概要。严格复验通过才追加不可变校验回执并恢复下游，原失败历史、原生内容和预算不变，不占用新的模型重试。仍用新的稳定 retry_id 发起一次并按同编号重放；客户端不能自行提交通过标记。不完整或仍无效的结果不会因此通过，不能把此路径理解为允许第 4 次模型调用。

`retry` 不是只读检查：复验未通过时，服务可能转入新的模型尝试；复验成功后恢复的下游阶段也可能继续调用模型。无生成复验是服务实际返回的结果，不是客户端能指定或保证的请求模式。发起前须确认本次重试及后续调用仍在已有次数和预算授权内；授权已用尽时只读取原任务与回执，不能以“只复验、不生成”为由调用此入口。

字幕可跨切镜，按原时间与镜头交集核对；片尾不能声明画面延续至原片以外。声音的区间类型必须与对白、音乐及音效时间一致。模型输出键引用、时间覆盖或音频层矛盾应由重新分析修正，不能删除证据、补写模板或强制通过。

跨段关联的镜头组是同一个连续镜头的计算分段，不是剧情段落、场景或蒙太奇。核对全部镜头恰好出现一次、顺序和原时码不变；只有计算边界两侧明确连续才允许合并。同一人物、道具或地点出现，不足以认定两个切镜是一个镜头。人物与声音的关联仍为有独立证据的推断，不冒充确认身份。

## 4. 取用完整成果

`learning.state=saved` 时，从 `learning.revision` 获取固定学习修订。按 manifest.domain_documents 的 reference-learning 找到实际文件，再经 `artifact.read` 的 text／download 读取，access 使用 world_draft_id 和 world_draft_revision_id。核对返回 ContentRef、摘要和大小，完整正文最多 4 MiB，不能静默截断。

直接交付用户所需的实际提示词、类型化内容或本地文件，保留 task_id、固定来源和学习修订；无需页面或 Project。`learning_saved_need_evidence` 表示已保存但仍缺证据，不能改称全量完成。目标模型提示词可能尚待适配或未经运行，生成样例、Blender 工程和连续运镜仅在真实文件及运行证据存在时交付。

保存结果是独立 World 学习内容，不自动登记为已发布资产，也不自动安装为技能。用户要求创作时，复制固定参考进入明确项目，由生产技能和 MCP 执行；用户明确沉淀时再走 World 保存／登记。具体作品内容与可迁移拆解方法分别维护。

关联调用若真实返回 MAX_TOKENS，按同一任务追加上限执行受控 retry；服务可在完整观察包内使用可逆短证据编号降低传输长度，固定资产与来源编号不变。不得手工补齐截断 JSON，不把失败回执改成成功，不增加任务预算或无限重试。

方法成果恢复的诊断须来自原生失败回执中的真实缺失键：未声明的步骤输入、没有任何步骤产出的最终输出。按既定重试次数和预算纠正依赖，不补造空步骤，不修改终态原文；已用尽普通重试且符合服务最终诊断条件时，可由服务接纳一次最终纠正，不接受第四次。
