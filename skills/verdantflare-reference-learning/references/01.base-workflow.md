# 执行流程

## 1. 前置与分流

先读[分类与边界](01.base-category.md)及[规则约束](01.base-rules.md)，再按本次意图读取对应主题专册。读取、分析、保存及生产交接分别按实际能力执行；失败恢复沿原固定版本和请求。

## 2. 可直接交付的成果

按类型给出可编辑内容、来源定位、适用条件和使用方法。提示词是核心独立成果，保留共同创作意图与各模型／任务变体。另有结构、角色关系、节奏、风格规则和工程提案等类型，不能全压成一段 Prompt。

用户明确要求制作时，按目标交接实际可用的 `x-verdantflare-short-drama`、`verdantflare-video`、`verdantflare-image`、`verdantflare-music`、`verdantflare-speech` 或工程技能；只读取需要的生产技能。传递固定来源、模型变体、目标变化、参考绑定和输出去向。服务缺失则保留可用成果及缺项，不用伪造任务 ID 或成功状态补齐闭环。

世界样例只读，可复制正文及完整配置；修改提示词、改图或其他创作先交接 `verdantflare-project` 新建真实项目，再由生产技能经 Studio MCP 执行。成果先保存项目修订并回读，不直接创建世界资产或用 World creation 草稿替代项目。明确要求沉淀后才选择固定项目成果登记 World。收藏与分析仍可独立保存。受控上传交由 `verdantflare-artifact`；当前接口若要求项目来源，不能创建假项目绕过独立 World 保存缺口。结构化成果的格式与离线检查见[独立保存说明](world-save.md#2-准备可编辑成果)，检查通过不等于完成分析或实际运行。

## 3. 方法沉淀

内容资产可直接作为本次创作知识使用，不必每份知识建一个 Skill。可迁移的流程先保存方法候选：来源、输入输出、步骤、例外、实际验证和失败；明确要求维护技能时才将可靠方法纳入对应技能，不自动改写已安装包。
