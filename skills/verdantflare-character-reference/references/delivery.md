# 交付、保存与恢复

## 1. 图像记录与展示

每图记录稳定编号、身份基准哈希、源视频任务与时间码、原帧哈希、编辑输入及提示词、实际模型与任务ID、输出哈希与解码尺寸、用户评价及批准范围。编号变更保留旧新映射，不能按新编号误认历史帧。

成果按正面／平视回头／俯视／仰视等实际类别组织，使用 `[![编号](图片路径)](图片路径)` 可点击缩略图。图片少时不强建空组；原帧、正脸纠正、纯提示词对照放历史区，成果区仅显示获准展示项。用户要求单表多图时遵循指定布局，默认遵守所在仓库的表格约定。

Studio原角色设定下追加参考图组，同页滚动，点击共用全局灯箱。不要引入Tab、审阅状态或“查看可复用版本”；制作记录不变成产品新业务。

## 2. 保存现有项目

沿Project／Artifact技能读取目标固定修订和最新Schema，保留原角色属性。可选 `character.reference_groups` 是组数组，每组 `key/title/images`，每图 `key/label/file_id`。当前契约每组最多32图、组key唯一、组内图片key唯一；文件属于目标修订Manifest。跨项目复用经授权ContentRef复制或规范导入，不能照搬源file_id。

更新仅影响指定组／图片。保存前核对并发变化，必要时重读合并；保存后读回固定修订、核验每张图片可读取及字节哈希。原始资产和历史修订保留。项目展示不自动发布World资产或覆盖角色基线。

## 3. 恢复

保存已有任务ID、幂等身份、已完成编号、错误原因和恢复入口。查询旧任务并下载已产生结果后再判断缺项；禁止因网络超时重发。复用未变输入和验证证据。

两张表情不符：只建立两张返修输入，读回验证其他引用保持不变。身份基准本身错误或全库系统性漂移：说明证据及重建范围，保留旧库，等待已有授权范围内的用户决定。仅要求编写技能时，交付技能与设计，不提交媒体任务。
