# 画布冒烟与参数化工作流 API 发布调用（03.workflow-api）

## 1. 输入与输出

- **输入**：真实 UUID `project_id`、待校验与固化的画布草稿或已发布的 `(endpoint_slug, semver)` 与受控入参（标量或 `artifact_*` ID）。
- **输出**：冒烟成功的 `smoke_task_id` 与峰值显存回执、不可变发布的 `WorkflowAPISpec v1`（含 `endpoint_slug@semver`、`prompt_sha256`、`canonical_model_lock_v1`、`vram_budget_mib`），或无头生产调用产出的 Studio `Artifact` 列表与 `resolved_seeds`。

## 2. 分类

- **研发冒烟与 API 发布**：必须经交互实例通道 `/mcp/comfyui<id>` 完成（`workflow.validate` -> `task.submit` -> `api.extract_spec` -> `api.publish`）。
- **无头生产批量调用**：必须经固定别名 `/mcp/comfyui-api` 完成（`api.list` -> `api.describe` -> `api.invoke` -> `task.get`），与个人画布编辑锁逻辑隔离，原实例休眠或被编辑时仍可稳定调用。
- **已投影至媒体目录的 `本地` 渠道模型**：只需标准文生图/图生视频接口时直接移交 `verdantflare-image` 或 `verdantflare-video`。

## 3. 工作流

### 3.1 静态校验与沙箱冒烟

1. 确认模型依赖全部 `ready`（否则先执行[模型依赖齐套](01.model-deps.entrypoint.md)）。
2. 在交互实例通道调用 `workflow.validate` 检查节点类型白名单、连线拓扑、模型引用与输入尺寸边界。
3. 校验通过后使用固定 UUID `idempotency_key` 调用 `task.submit` 提交沙箱冒烟任务，并通过 `task.get` 轮询至终态。若冒烟失败或卡住，转[白盒诊断与自愈](02.diag-repair.entrypoint.md)定位修复后重新冒烟，直至取得状态为 `succeeded` 的有效冒烟 `smoke_task_id` 及实测峰值显存回执。

### 3.2 提取契约并锁定发布不可变 API 版本

1. **提取参数化规格**：调用 `api.extract_spec`（传入 `project_id`、草稿版本或刚通过校验的工作流及暴露参数声明），获取包含 `exposed_inputs`、`model_dependencies`（锁定 `sha256` 与许可元数据）、`topology_sha256` 及服务端按 `ceil(smoke_peak_vram_mib * 1.10)` 权威推导的 `vram_budget_mib` 的 `WorkflowAPISpec v1` 草案。
2. **发布不可变版本**：核对暴露参数默认值、类型范围与 `output_modality` 后，生成新 UUID `idempotency_key` 调用 `api.publish`（传入 `project_id`、`idempotency_key`、`endpoint_slug`、`semver`、`smoke_task_id` 与规格正文；仅当调用者具备组织/站点管理员权限且用户明确要求投影至媒体目录时，才将 `mount_channel` 设为与 `output_modality` 一致的 `"image"` 或 `"video"`，否则固定传 `"none"`）。已发布的 `(endpoint_slug, semver)` 永久不可变，后续调整须递增 `semver` 发布新版本。

### 3.3 无头生产调用与异常对账恢复

1. **查询契约后调用**：在 `/mcp/comfyui-api` 先调用 `api.list` 与 `api.describe(endpoint_slug, version)` 核对必填入参、整数种子上限（`0..9007199254740991`）、枚举集合与参考图 `artifact_id` 要求。
2. **提交与归档回读**：使用绑定当前业务请求的稳定 UUID `idempotency_key` 调用 `api.invoke(project_id, idempotency_key, endpoint_slug, version, inputs)`；返回 `task_id` 后通过 `task.get` 轮询至完成（必要时可调 `task.cancel`），读取服务端自动归档的 Studio `Artifact` 列表与实际 `resolved_seeds`。若上游业务流程（如短剧或公共世界同步）要求生成后执行 18+ 内容分级评估，在展示或同步项目前按对应媒体治理规范完成分级登记。
3. **超时或断线先对账**：遇到网络超时、`502` 或 `409 OPERATION_IN_PROGRESS` 时，先用原 `task_id` 调用 `task.get` 或以完全相同的 `(tool_name, project_id, idempotency_key, 参数载荷)` 重放对账，严禁更换新 `idempotency_key` 盲目重复提交导致双倍 GPU 计费与重复产物。

## 4. 规范

遵循[公共规则](00.common.rules.md)，重点约束：

- **`WorkflowAPISpec v1` 防注入与类型约束**：`api.invoke` 仅允许传入 `exposed_inputs` 白名单内的标量或受控 `artifact_*` ID，严禁传入未知键、节点连接数组（如 `["4", 0]`）、用浮点数 `1.0` 或布尔值冒充整数、超出 `0..9007199254740991` 的随机种子、底层文件路径、`[input]/[output]` 后缀或覆盖锁定模型名。
- **显存预算与可复现级别**：`vram_budget_mib` 采用服务端 `ceil(smoke_peak_vram_mib * 1.10)` 推导值，不手工压低；含固定种子与确定性采样器时 `reproducibility_level` 设 `"strict"`，含非确定性算子时标 `"best_effort"`。
- **管理员投影门禁**：`mount_channel` 默认 `"none"`；设为 `"image"` 或 `"video"` 仅限组织或站点管理员且须与 `spec.output_modality` 完全一致。
- **幂等铁律**：`task.submit`、`api.publish`、`api.invoke` 均须携带标准 UUID `idempotency_key`，同键禁改参（否则返 `409 IDEMPOTENCY_CONFLICT`）；遇 `409 ADMISSION_RESERVATION_EXPIRED` 生成新 `idempotency_key` 重提。

## 5. 验收

满足以下客观回执方可报告发布或调用完成（并按[公共规则第 5 节](00.common.rules.md#5-标准错误码与交付报告必填要素)汇报）：

- **工作流 API 发布完成**：`api.publish` 成功返回不可变 `(endpoint_slug, semver)`、`prompt_sha256`、`canonical_model_lock_v1` 摘要及 `vram_budget_mib`；通过 `/mcp/comfyui-api` 调用 `api.describe(endpoint_slug, version)` 可完整回读该版本契约。若启用了 `mount_channel` 投影，还须在对应媒体目录可见 `本地` 渠道条目。
- **无头生产调用完成**：`api.invoke` 关联的 `task.get` 到达 `succeeded`，产出的每个 Studio `Artifact` 均返回有效 `artifact_id`、非零字节大小、合法媒体尺寸与 `sha256`；需落盘核验时实际下载解码确认非黑图、非空帧。技术校验通过不代替人类审美或业务终审。
