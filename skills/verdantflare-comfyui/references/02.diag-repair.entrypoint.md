# 白盒故障诊断与单实例自愈（02.diag-repair）

## 1. 输入与输出

- **输入**：真实 UUID `project_id`、目标交互实例通道 `/mcp/comfyui<id>`（或无头池仅限 `diag.execution_trace`）、失败 `task_id` 或异常现象描述。
- **输出**：精确失败节点与异常堆栈（`diag.execution_trace`）、绑定 `boot_id` 的脱敏日志证据（`diag.logs`）、软卸载或换代重启后的新 `(generation, boot_id)` 回执，以及修复后重新冒烟成功的 `task_id`。

## 2. 分类

按故障影响从轻到重分四级处置，严禁越级直接重启或跨通道误调：

- **只读白盒诊断（零副作用）**：`diag.execution_trace`（双通道可用）、`diag.object_info`（冷备休眠态走免 GPU 缓存字典）、`diag.logs`、`diag.runtime_spec`、`instance.status`。
- **低影响显存软自愈**：`repair.free_vram`（不丢会话，需确认无活跃任务且未持有他人编辑租约）。
- **高影响单实例换代重启**：`repair.restart_worker`（仅限 `free_vram` 无效、死锁或内核崩溃，严禁在他人持有编辑租约时强抢）。
- **排除项**：运行时缺失第三方自定义节点禁止 `git clone` / `pip install`，记录 Commit SHA 与依赖清单转镜像版本评审。

## 3. 工作流

### 3.1 前置核验与租约管理

1. 确认真实 `project_id` 并执行 `tools/list`；调用 `instance.status` 与 `diag.runtime_spec` 读取当前 `lifecycle_state`、`generation`、`boot_id`、`profile_id` 与白名单节点集摘要。
2. 仅只读诊断时不申请写租约；需修改实例工作区或画布草稿时调用 `session.open` 申请编辑租约，收尾显式调用 `session.close` 释放。

### 3.2 分层白盒诊断与受控自愈排障

严格按影响从轻到重逐级执行：

1. **定位精确失败节点（零副作用）**：优先调用 `diag.execution_trace(project_id, task_id)` 获取失败 `node_id`、`class_type`、异常类型、结构化堆栈与各节点耗时及峰值显存；再调用 `diag.object_info(project_id, class_types=[...])`（休眠态自动走零显存缓存字典，不唤醒 GPU）核对输入槽类型与可选枚举值。若发现缺少合规模型，先转[模型依赖齐套](01.model-deps.entrypoint.md)。
2. **增量拉取脱敏日志（强制绑定 `boot_id`）**：首次调用 `diag.logs(project_id, tail_lines=100)`（深层堆栈可调至 `200..500`）记录返回的 `boot_id` 与 `next_seq`；后续增量拉取传入 `since_seq` 时**必须同时原样携带同一 `boot_id`**。若收到 `409 BOOT_ID_MISMATCH`，说明实例已发生换代重启，立即丢弃旧游标并重新不带 `since_seq` 拉取新纪元首屏日志。
3. **两步软卸载回收显存（不丢会话）**：当日志或追踪显示 CUDA OOM 或模型缓存碎片且无活跃执行任务时，使用全新 UUID `idempotency_key` 调用 `repair.free_vram(project_id, idempotency_key, unload_models=true, wipe_Soft_cache=true)` 触发内层释放权重并归还物理显存，随后复查 `diag.runtime_spec`。
4. **单实例安全换代重启（仅限死锁或内核崩溃）**：仅当 `free_vram` 无法恢复或内层进程失联时，生成新 UUID `idempotency_key` 调用 `repair.restart_worker(project_id, idempotency_key, reason, force_after_drain_timeout_seconds)`（默认 `30` 秒，允许 `5..120` 秒）。调用后轮询 `instance.status` 等待 `generation` 递增且新 `boot_id` 就绪；若返回 `503 RECLAMATION_UNVERIFIED_QUARANTINED`，表明底层 GPU 回收三重证明未通过、实例已被安全隔离保护，立即停止重试并上报运维核查，严禁循环重发重启指令。

## 4. 规范

遵循[公共规则](00.common.rules.md)，重点约束：

- 100% 通过 Studio MCP `diag.*`、`repair.*` 完成，严禁 `kubectl exec`、写集群、读 `Secret` 或原始 `pods/log`；无头通道 `/mcp/comfyui-api` 禁止调用 `session.*` / `repair.*`（必返 `403 TOOL_NOT_ALLOWED_ON_HEADLESS_ALIAS`）。
- `diag.logs` 携带 `since_seq` 必须绑定 `boot_id`；不得探测其他项目日志或尝试解码 `[REDACTED]`。
- 遇到 `409 INSTANCE_EDIT_LEASE_HELD` 时只读诊断可继续，严禁调用 `repair.free_vram` 或 `repair.restart_worker` 中断他人编辑。
- 处于冷备休眠态仅需核对节点签名时直接调 `diag.object_info`，不为查参数强行唤醒 GPU Worker。

## 5. 验收

满足以下客观回执方可报告排障与自愈完成（并按[公共规则第 5 节](00.common.rules.md#5-标准错误码与交付报告必填要素)汇报）：

- **执行层排障**：修复后重新提交 `task.submit` 取得 `status == "succeeded"`，且 `diag.execution_trace` 零节点异常。
- **实例换代重启**：`instance.status` 显示 `lifecycle_state` 恢复就绪、`generation` 较重启前严格递增、返回全新 `boot_id`，且未落入 `quarantined` 状态。
- 遇到 `503 RECLAMATION_UNVERIFIED_QUARANTINED` 或缺失第三方节点时，以阻塞如实结项并附证据，严禁伪造恢复成功。
